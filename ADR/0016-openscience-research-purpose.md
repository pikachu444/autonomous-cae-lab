# ADR 0016: Declared OpenScience research purpose over existing Core operations

Date: 2026-10-01. Status: accepted for the bounded P1.3 source unit;
actual new-source research acceptance is a separate gate.

## Context

The historical native Acceptance profile admits nine CAD tools, three steps
and one exact requested call. Its verified CAD/GUI/cancellation unit does not
establish question-driven solver selection, changed conditions, comparison or
numerical campaigns. Core already implements these operations and numerical
engines; recreating them or testing only another solver example misses the
owner's requested connected research system.

## Decision

- Preserve the historical Acceptance purpose and add an explicit Research
  purpose to the same owned native launcher, project/source grant and selected
  `openai-codex/gpt-5.6-sol` transport. Authentication is reused without copying
  credentials, changing the model or adding a fallback.
- Pin the research definition in intent/context/settings: a fourteen-tool
  universe, bounded capabilities, runtime environment and work budgets. A
  profile may admit a subset. Existing source/model/config/session/project/
  permission/stage/Stop checks remain; legacy settings cannot admit new tools.
- OpenScience follows questions through planning, registered variables, new
  experiments, comparison and interpretation. No single tool is required for
  an ordinary research turn. Missing inputs and unsupported physics must be
  identified before execution; capability metadata is not installation proof.
- Initially admit the reused roller-support CadQuery/exact-STEP CalculiX
  route, seeded SciPy differential evolution, and bounded scalar linear
  elliptic FEniCSx forms on the unit square. Numerical engines generate adaptive
  candidates. Backend syntax and native references stay behind existing
  adapter/registration boundaries; Core schemas/MCP operations are unchanged.
- Declare 24 model steps, 3600-second MCP/command bounds, one generation with
  population five, at most two structural mesh levels, and at most three PDE
  levels with 32 cells per axis. Native before-hooks refuse unsupported backend
  or work-budget arguments. These limits bound this profile, not all future
  platform capabilities. Do not change numerical references to fit a limit.
- Forward only `MPLBACKEND=Agg`, `OMP_NUM_THREADS=2`,
  `QT_QPA_PLATFORM=offscreen` and `CAELAB_FENICSX_PYTHON=/usr/bin/python3` to the
  existing resident WSL runtime. Existing adapters retain actual executable,
  version, source, model and artifact provenance. The definition adds no new
  version/provenance API and does not copy the whole environment.

## Alternatives and requirement impact

Expanding the old acceptance allowlist silently changes historical proof.
Allowing every registered tool conflates implemented metadata with accepted
research scope. Building another optimizer in the agent violates R03 and
duplicates working code. Keeping only exact one-call prompts fails R02/R03's
control plane and the owner's requested conditional research workflow.

R02/R03 gain executable research-purpose admission; R08/R09 retain invalid-CAD
execution gates, invalid metrics, `UNKNOWN` and `NOT_RELEASED`. R16/R18/R27/R28
reuse registered-variable numerical optimization and backend-owned PDE
mathematics. R34 keeps numerical/reference evidence distinct from source tests.
The full 52-section ledger and sequential phase order are unchanged.
`openscience/contract.md` gains purpose admission, not a new operation schema.

## Verification and limits

Source admission: 45 native PowerShell checks, 89 Node guard/Git checks, and
47 existing launcher ownership/cancellation mocks pass separately. They make
no provider/solver claim. The actual driver reuses the fixed references in
`verify_optimization.py` and `verify_pde.py`: missing/unsupported no-execution,
38/40 mm CAD/structural comparisons, seeded numerical next candidates, and
reaction 0/3 PDE recalculation. It checks actual native hook/tool receipts,
parent STEP bytes, immutable results, journals, analytical errors and source
identities in a new store. Independent source/output review is required.

One generation is not a global/converged optimum. Assumed material/load,
physical/strength qualification, arbitrary physics/geometry, CFD, PDE input
optimization, MPI/HPC and in-flight solver/campaign cancellation remain open.
Historical CAD cancellation is not evidence for solver cancellation. Exact
source CI and actual new Research execution are recorded separately; the known
OpenRadioss upstream download 404 is not solved by this source unit.
