# ADR 0034: Explicit fixture refinement inputs and truthful research answers

Date: 2026-10-04. Status: accepted scope; actual native/user acceptance remains a separate gate.

## Problem and evidence

On source dd3a254a8c5a4bb0b8fdef3c7f82cb038fb280da, an ordinary Lab question
reached the approved official OpenScience model and created two verified CAD
experiments. A continuation reached the same owned conversation, but its six
analysis requests used invented settings and lacked mesh.max_sizes_mm. The
guard refused them before Core/solver. Its historical two-level budget would
also exclude the requested 4/3/2mm refinement. No analysis ran.

The existing descriptor did not communicate the actual adapter input contract
or fixed boundary idealization clearly enough. The UI also presented raw
Markdown and used a completion headline for a completed CLI turn containing
errors. One failed MCP registration had transport status completed.

## Decision

Add opt-in FixtureRefinement/schema7/fixture-refinement-v1. Preserve all six
historical descriptors, their canonical fingerprints and the default
FixtureScalar/schema1 two-level budget. The new scope retains the same fourteen
tools, three backends, approved model/auth, managed project, immutable store,
source/grant/single-writer and cleanup gates. Only its analysis mesh work count
expands from two to three. This is a resource admission change; it does not
change execution time policies or any numerical acceptance threshold.

The descriptor and research instructions document the existing analysis_run
four-argument signature and exact load/material/mesh structure, material names,
CAD bounds registration, parent reuse and supported idealization. Native guard
validates its exact canonical descriptor and existing resource counts. Domain
retains scientific-invalid requests as rejected evidence. Core/Domain/adapter
behavior, the pinned upstream implementation and 5% displacement/1% signed
reaction criteria remain unchanged.

For the single roller support, bottom X/Y/Z is fixed and the negative-Z total
force is distributed over the central24mm saddle using the existing clipped
surface-area discretization. Global CAD X/Y/Z is the actual material frame;
axes text is provenance and cannot request tensor rotation. Arbitrary bolt,
contact, rotation or original assembly mechanics are outside this scope.

Render actual response text with a small inert Markdown formatter using DOM
elements/text nodes. Preserve raw text, numbers, units, UNKNOWN, NOT_RELEASED
and separately derived Core experiment links. A completed turn containing an
error uses an error headline without changing verified continuation/cleanup
admission. Actual phase information supplements waiting text; it never replaces
the authoritative job or numerical verdict.

## Alternatives and requirement impact

Changing the legacy budget would invalidate its frozen intent. Splitting 4/3/2
into overlapping two-level runs would duplicate numerical work and distort the
requested refinement record. Supplying hand-written settings per user question
would leave the ordinary research path defective. A new backend or LLM client
would duplicate implemented behavior and bypass the accepted control plane.

R02/R03/R05 keep control-plane/Core/Domain/adapter ownership. R11/R13/R20/R21/
R25/R33/R34/R43/R48/R51/R52 advance only through explicit input, same-record
execution, truthful presentation, independent review and retained evidence.
Whole52, original assembly P2.4, broader research and Phase6/7 remain OPEN.
Peak stress remains an invalid diagnostic; physical/material/strength/durability
UNKNOWNs prevent release. Three levels alone do not prove asymptotic convergence.

## Acceptance

Check actual PS/JS canonical parity, all six historical fingerprints, two/three
level admission, four/missing/empty list refusal for analysis and numerical
planning, descriptor tampering and unchanged source/grant/Stop gates. Check raw
and formatted answers, unsafe text, partial/final consistency and error/session
states independently. These source checks are not native or user success.

On reviewed committed source, a fresh store and owned runtime must execute a
real browser question, produce actual CAD/analysis evidence and readable linked
answers, then a changed-condition continuation and observed busy cancellation.
Preserve earlier CAD/failures and distinguish all actual, failed and NOT_RUN
gates. Do not interpret CLI completion or solver exit as engineering approval.
