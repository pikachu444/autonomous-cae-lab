# ADR0027 — bounded material-point research through existing operations

Status: accepted for bounded source integration after independent review; actual connected research remains NOT_RUN.

The qualified source3a/native02 SVK material point exists behind the common
model_analysis_run boundary, but existing research profiles intentionally refuse
it. Add the case-sensitive MaterialPoints/schema4/material-points-v1 profile.
It offers the same six existing StructuralFamilies tools and only the
material.mfront.hyperelastic/saint_venant_kirchhoff capability. Core's31 MCP
operations, schemas, registry, optimizer and adapter scientific contract remain.
The selected openai-codex/gpt-5.6-sol provider/auth has no automatic fallback.

PowerShell and Node share an exact canonical descriptor with the existing
StructuralFamilies pinned SIF/runtime and transport budgets24steps/3600seconds.
The material cap is3..12history entries,594signed probes and65536parsed-JSON
request bytes, declared before research from the completed native02 workload.
These are admission/resource bounds, not numerical convergence criteria or the
native worker's wall timeout. Native wall defaultNone/CPU86400 remains distinct.

Require exact settings/case/material/temperature/history/limits keys, finite
numeric physical9F values and strictly increasing time with firsttime0. Domain
retains determinant, Green-strain, identity/loading and signed-probe physics.
All FIXED_LIMITS and all3orderedFD steps remain exact. No arbitrary native code,
paths, CAD registration, optimizer or job tool is introduced. Preserve old
FixtureScalar/StructuralFamilies/PDEFields canonical outputs and existing
source/model/project/grant/default-guard/owned Stop boundaries.

OpenScience plans from the supplied question, executes fresh experiments,
inspects/summarizes/compares returned IDs/revisions and interprets recorded
validity/UNKNOWNs. Deterministic engines remain the owner of numerical search;
this profile provides bounded supplied-condition comparisons. Full measured
F/P/A/W histories reside in original hash-bound artifacts. The current common
summary does not expose them, so an interpretation cannot invent their values
or present an analytical prediction as a measured full-history observation.
The generic original-record Results view is available; a dedicated material
history viewer and constitutive FE/physical release remain separate gates.

Alternatives: widening StructuralFamilies contradicts its frozen structural
settings; FixtureScalar bypasses explicit backend admission; new common MCP
operations duplicate an existing route. A separate immutable profile preserves
those accepted contracts. This is transport capability admission, not a new
Domain equation, numerical optimizer, runtime installation or release verdict.

Requirement impact: R02/R03/R05 preserve control/Core/Domain/adapter/engine
ownership; R17/R29 gain bounded material research; R19/R20/R21/R33/R34/R43/R48/
R51/R52 govern exact evidence/GUI/review/contracts and actual execution. R01,
R32/R35 and all52 retain wider system, measured physical/deployment gaps.

Source acceptance: canonical PS/Node parity, exact limits/runtime/tool/budget
mutations, actual12-state and second-E admission, malformed/extra/nonfinite/
boolean/string/overbudget refusal and old scopes/default/late-source/model/
project/Stop controls. Retain failed preparation/test attempts. Root reviews
frozen source and an independent audit before publishing. Actual acceptance is
a fresh clean-source official5.6Sol one-question study/two supplied conditions,
original inspect/summary/compare/evidence interpretation, same-record GUI,
exact owned Stop and hash retention. Source/cold tests alone do not close it.

Physical/material/strength/durability/constitutive FE/binary-source/remote raw
remain UNKNOWN; NOT_RELEASED and whole52/Phases5-7 OPEN. Native01 failure and
native02 qualification remain immutable distinct records.
