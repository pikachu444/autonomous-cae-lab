# 4절 회전 기구

이 예제는 **고정 링크 1개, 가동 링크 3개, 회전 관절 4개, 독립 회전 구동 1개**다.
원통 관절이나 숨긴 개방 연결로 바꾸지 않는다. 최초 형상만 기하적으로 배치하며,
모든 운동은 설치된 **FreeCAD 1.1.4 Assembly의 native 계산**을 사용한다.

첨부된 Windows FreeCAD 1.1.4 실행에서 정상 계산 22프레임과 저장·재열기는 동작했다.
다만 실패 입력도 반환값 0이었고 실제 관절/구동은 맞지 않아 성공 게시를 교정했다.
이번 교정 환경은 첨부 원출력의 읽기 전용 대조와 Python 회귀만 실행했다.
**교정 코드의 FreeCAD 재실행은 아직 하지 않았다.** 아래 `native_check.py`로 Windows에서 확인한다. 새 solver, 유료 API, WSL, 추가 구독은 필요하지 않다.

## 열기

수정 파일을 적용한 전체 저장소의 기존 Windows Pre 실행 방법으로 FreeCAD를 연다.
기존 **CAE 작업 → 조립 운동** 패널을 사용한다. 이 소스 ZIP은 전체 제품 설치본이
아니므로 ZIP 폴더만으로 공통 `caelab` 모듈을 새로 설치하려고 하지 않는다.

FreeCAD의 **매크로 → 매크로…**에서 같은 폴더의
`create_four_bar.FCMacro`를 선택하여 실행한다. 매크로는 형상과 구동 정의까지만
만든다. 계산을 자동 실행하지 않는다. 매크로 파일을 이동하지 말고 저장소의
`examples/assembly_closed_loop` 안에서 실행한다.

매크로 경로를 지정하기 어려운 경우 FreeCAD의 **보기 → 패널 → Python 콘솔**에서
아래처럼 실제 저장소 경로 한 곳만 바꾼다.

```python
from pathlib import Path
import sys, runpy
repo = Path(r"C:\work\autonomous-cae-lab")
sys.path.insert(0, str(repo))
factory = runpy.run_path(str(repo / "examples/assembly_closed_loop/create_four_bar.py"))
M3 = factory["open_example"]()
```

네 링크는 mm 단위로 고정 링크 100, 입력 링크 60, 연결봉 70, 출력 링크 50이다.
A가 고정 링크와 입력 링크를, B가 입력 링크와 연결봉을, C가 연결봉과 출력 링크를,
D가 출력 링크와 고정 링크를 잇는다. 모든 회전축은 초기 세계 Z축이다.
입력 링크의 최초 절대 각도는 60°이며, 두 연결 좌표계의 초기 방향을 맞췄으므로
구동값 0은 이 최초 자세를 뜻한다. 이 예제의 회전 식은 절대 링크 각도가 아니다.

## 정상 계산과 읽기

**조립**에서 `4절 링크`를 고른다. **부품과 관절**에는 고정 1개와 회전 A/B/C/D가
보인다. **시간과 구동**은 다음 값이다.

| 항목 | 값 |
|---|---|
| 시작 / 끝 / 출력 간격 | 0 / 1 / 0.05 s |
| 구동 관절 / 종류 | 입력 회전 A / 회전 |
| 시간식 / 단위 | `10*pi/180*time` / rad |
| 계산 오차 허용값 | 기존 값 `1e-6` |
| 경로점 | 연결봉 중앙, 연결봉 로컬 (35, 0, 0) mm |

기존 정의를 검토한 후 **운동 결과 → 다시 계산**을 누른다. 성공하면 **최근 성공**에
시각별 프레임 표가 나타나고 **검사** 열에 초기조건 이후 **충족**이 표시된다. 프레임을 고르고 **자세 보기**로 실제 조립의 자세를
확인한다. 표 선택만으로 모델을 움직이지 않는다. **재생 / 일시정지**는 미리보기,
**설계 자세 복원**은 현재 편집 설계로 돌아가는 동작이다.

프레임 0은 물리 시각이 없는 설계 자세다. 이후 시각은 기존 1.1.4 출력 규칙과
native 프레임 수를 대조한 결과다. 일치하지 않으면 시간을 만들지 않고 **시각 미확인**으로
남긴다. 끝 시각을 맞추기 위한 보간이나 반올림은 하지 않는다.

**점 경로**에서 연결봉 중앙을 선택한다. 계산 직후 모든 설정 경로가 이미 보존되어
있으므로 창을 처음 열어도 표와 곡선을 읽을 수 있다. 기존 전체/구간 읽기, 공간 투영,
CSV 저장, Data에서 열기를 그대로 사용한다. 이 읽기는 native 계산을 호출하지 않는다.

## 중복 구동, 과구동과 도달 불가능 자세

먼저 한 번 정상 계산한다. 이전 결과 보존을 확인하려면 **점 경로 탭을 열지 않고**
다음 실패를 만들어도 된다.

**동일 관절 중복:** 시간과 구동에서 A의 회전 구동을 한 행 더 추가한다. 두 행에 중복
입력 오류가 표시되고 적용이 차단된다. 이는 native 계산 실패가 아니라 입력 검사다.
잘못된 초안도 **저장**할 수 있다. 새 문서로 재열면 중복 두 행이 남아 있으며, 두 번째
행을 삭제하고 **구동 적용**한다. 이 중복은 실제 입력으로 특정할 수 있지만 B/C/D를
원인 관절로 표시하지 않는다.

**서로 다른 관절의 과구동:** 정상 A 구동에 D의 회전 구동 `0` rad를 추가하여
**구동 적용 → 다시 계산**한다. A를 움직이면서 D의 방향을 고정하는 서로 다른 두
조건이다. native 거절 또는 실제 관절·구동 불일치이면 계산 이력에 실패 시도와 당시 두
구동이 남는다. **최근 계산 실패 — 성공 결과 보존**과 **불일치 원자료**를 구별한다.
첨부 실행에서는 반환값 0이어도 B가 최대 약 9.7428 mm 벌어졌다. 교정 코드는 이를
성공으로 게시하지 않으며 반환값 0과 원출력 22프레임을 그대로 보존한다.

**도달 불가능 입력:** D의 추가 구동을 삭제하고 A의 시간식을 `pi` rad로 바꾼 뒤
적용·계산한다. 최초 60°에서 반 바퀴 떨어진 위치에서는 B–D 거리가 140 mm로
연결봉+출력 링크의 120 mm보다 길어 닫힐 수 없는 기하 입력이다. 반환값과 실제 결과는
native가 결정한다. 첨부 실행은 반환값 0인데 실제 상대각이 0에 머물러 입력 `pi`와
약 3.14159 rad 어긋났다. 교정 코드는 실제 상대각 차이를 검사해 성공 게시를 거절한다.
실패의 원인 관절이나 정확한 실패 시각을 이 기하 설명만으로 solver 진단이라고 표시하지 않는다.

실패 직후 **운동 결과**에서 이전 성공을 선택하고 프레임을 고른다. 실패 계산의
일부 프레임을 이전 성공의 곡선에 붙이지 않는다. **저장** 후 문서를 닫고 저장한
`.caepre`를 새 문서에서 연다. **다시 계산을 누르지 않고** 이전 성공의 프레임·경로를
열어 확인한다. 현재의 실패 입력도 남아 있으므로 이전 결과가 현재 입력의 성공처럼
표시되지 않는다.

복구는 A의 식을 `10*pi/180*time`으로 되돌리고, 다른 구동 행을 제거한 뒤
**구동 적용 → 다시 계산**한다. 성공하면 새 결과가 추가되고 이전 성공과 실패 이력은
별도로 남는다. 모델을 움직여 놓은 상태에서 저장해도 저장 대상은 현재의 설계 자세다.
보존 결과를 보는 것만으로 그 옛 자세를 현재 설계로 채택하지 않는다.

## 특이 자세 입력

`set_case(owner, context, 'singular')`는 동일 길이의 B–C–D를 일직선으로 배치한다.
이것은 초기 CAD 위치 생성이지 별도 운동 계산이 아니다. 이 입력에서 native가
실패할 수도, 반환값 0일 수도 있으므로 반환을 그대로 기록한다. 첨부 출력은 D가 최대
약 9.42789 mm 벌어져 교정의 출력 검사를 통과하지 못한다. 특이성 자체를 판정한 것이
아니며 **특이 실패 시각 자동 식별과 원인 관절 자동 식별은 UNKNOWN**이다.

소유권이 중복되지 않도록 실행 중인 제품 문서에 새 `Owner`를 만들지 않는다.
Codex의 별도 FreeCAD 확인 인스턴스에서 아래 검사 함수를 호출하면 기존 `Owner`
하나로 정상·실패·특이 입력·복구·새 문서 재열기를 순서대로 수행한다.

```python
from pathlib import Path
import sys, runpy
repo = Path(r"C:\work\autonomous-cae-lab")
sys.path.insert(0, str(repo))
check = runpy.run_path(str(repo / "examples/assembly_closed_loop/native_check.py"))
receipt = check["run"](r"C:\caelab-tests")
```

이 함수는 사용자가 명시 호출할 때 실제 native 계산을 한다. 실행마다 새 폴더에
`native-check.json`, `attempts.json`, `after-failures.FCStd`를 남긴다. 실패 파일을
삭제하거나 성공으로 바꾸지 않는다. 동일 native 프레임을 직접 읽은 배치와 저장
배치·경로를 비교하며 허용치를 느슨하게 하지 않는다. 이 함수의 FCStd 확인과 별도로
위 제품 패널의 `.caepre` 저장·재열기 및 마우스·키보드 확인이 필요하다.

## 보존 및 참조 경계

성공 출력과 불일치 원출력은 기존 문서의 `motion_paths`에 각각 저장된다.
직전 성공 포인터는 충족 검사된 성공만 가리킨다. 예전 버전에서 잘못 성공으로 저장한
세 출력도 열 때 원자료를 덮어쓰지 않고 재검사해 구별한다. 전체 native 배치는 무손실
압축된 JSON이고 경로·시각은 기존 구조다. 파일을 외부 임시 경로에 맡기거나 결과
DB를 추가하지 않는다. 기존 8 MiB 문서 메타데이터 제한을 그대로 지키며 한도 초과를
숨기거나 이전 이력을 자동 삭제하지 않는다. 한도 초과는 결과 보존 실패로 남긴다.

재생은 정확히 같은 부품 occurrence와 형상을 확인한 후 저장 배치를 적용한다.
다른 Link나 원부품으로 자동 대체하지 않는다. 형상을 바꾸거나 부품을 삭제한 경우
옛 3D 자세의 표시를 거절할 수 있지만 원래 좌표·시각·경로는 읽을 수 있다.
바깥 부모가 이동·회전했을 때는 저장된 세계 배치를 유지하도록 선택 조립의 루트만
현재 부모 좌표로 변환한다. 부모나 형제 부품은 움직이지 않고 복원 시 현재 설계로
돌아간다. M2의 계층·부품 참조 확인은 그대로 사용한다.


## 불일치 원자료와 편집 중 읽기

**운동 결과**에서 **불일치 원자료**를 선택하면 각 표본의 검사 상태를 읽는다.
관측 관절과 표본 시각은 **계산 이력**에서 확인한다. 예를 들어 `0.05 s / 관절 벌어짐`은
그 출력 표본에서 관측했다는 뜻이지 native의 정확한 실패 시작 시각이 아니다.
**점 경로**는 불일치/미확인 프레임 사이를 정상 선으로 연결하지 않는다. 좌표는 삭제하지
않으며 CSV에는 원좌표를, Data에는 같은 행의 제외·품질 표시를 함께 전달한다.
불일치 원출력의 저장 자세는 읽기 전용이며 설계 자세로 채택하지 않는다.

관절 또는 구동의 **미적용 편집**이 있으면 자세 보기·재생·현재 자세 채택·계산을
GUI와 명령 API에서 모두 막는다. 현재 조립의 실제 저장 결과에 들어 있는 경로점의
표·곡선만 계속 읽는다. 존재하지 않는 결과/경로점이나 저장되지 않은 새 경로는 이
예외를 쓰지 않는다. 편집 적용/취소는 기존 동작이다. 재생을 누른 직후 경로를 읽어도
타이머부터 멈추며, 경로 읽기 완료 뒤 자동으로 자세가 다시 움직이지 않는다.

허용값은 원래 `1e-6` 그대로이며 출력 검사에서 위치 `1e-6 mm`, 각도 `1e-6 rad`로
대조한다. 단위 근거와 검사 범위는 [조립 사용법](../../docs/ASSEMBLY_WORKFLOW.md)의
**검사식과 범위**를 따른다. 시간 표본 사이의 연속 폐합·누적 회전수나 특이점 검증을
통과했다고 확대하지 않는다. 어떤 실패 입력도 통과시키기 위해 변경하지 않았다.
