Autonomous CAE Lab — 로컬 최신 main에서 통합 완성

사용자가 선택한 로컬 폴더에서 pikachu444/autonomous-cae-lab의 원격 최신 main을 가져오고, 로컬 변경을 보존한 구현 브랜치에서 작업하라. 과거 PR #1에서 다시 시작하지 마라. Git 작업은 직접 수행하라. 이번 작업은 Codex Cloud가 아닌 사용자 로컬 Windows/WSL 환경에서 실제 앱·솔버를 연결하는 작업이다.

AGENTS.md를 읽고 다음 참조를 실제로 읽어라.
- docs/WORKBENCH_RECOVERY.md 전체: 이번 R1–R5의 수정 위치·분업·완료 행동과 9절 A–F 사용자 흐름.
- docs/WORKBENCH_REDESIGN.md 개정 4: W1–W5 전체, 특히 4.4·7.1·12·12.8·13절.
- docs/WORKBENCH_USE_CASES.md: 다양한 연구와 UC17 외부 ASCII 연구.
- docs/CODEX_WORKFLOW.md 및 docs/DEVELOPMENT_SKILLS.md: 모델·분업·스킬·재개.
- docs/WORKBENCH_PROGRESS.md 및 docs/WORKBENCH_REUSE.md: 이전 실행·미확인·재사용 판단. 완료 표현을 실제 연결 증거로 가정하지 마라.

주 담당은 Astra High로 전체 요구·공통 API·직접 구현·통합을 책임져라. 보조 A는 로컬 솔버·reader·수치 작업, 보조 B는 전문가 도구 계약·승인 화면·대화를 Sol High로 맡겨라. 동시 보조는 기본 2개다. 한 보조가 끝난 자리에 Astra High 독립 검토자를 사용하라. 각 보조에 문서 절·입력·수정 파일·계약·산출물·종료점을 전달하고 같은 파일 동시 수정과 재귀 위임을 하지 마라. 어려운 수치/설계 문제만 Extra High로 다뤄라. 실제 모델 설정과 기능을 확인하고 제품 LLM 인증을 Codex 로그인과 혼동하지 마라.

구현할 결과:
R1. 로컬 OpenRadioss·Code_Aster·FEniCSx·MFront/MGIS를 조사·준비하고 실제 계산하라. OpenRadioss 404, Code_Aster FACTOR_57, PDE 격자 수렴 문제를 원인별로 해결하라. doctor는 선택 backend의 경로·버전·의존성·작은 실제 계산을 구분하라. pip/import/CI 성공을 로컬 solver 준비 완료로 쓰지 마라.
R2. _outcome_evaluation의 metrics 중심 변환을 보완해 native 이력·장과 ASCII 채널을 같은 응답으로 연결하라. 단위·성분·위치·시간축·원본을 보존하고 곡선 선택→시험 비교→DOE/동정→전문가 읽기를 연결하라. 원래 솔버 없이도 저장 결과를 읽게 하라.
R3. 도구별 필수 인자·구조·오류 스키마를 실제 LLM에 제공하라. GUI가 자문 대상, 공개 검색, 계산/변수/자원 범위와 새 결과 읽기를 전달하게 하라. 승인된 범위 안에서 매 후보 재승인 없이 실제 LLM의 자료 읽기→변수/DOE 제안→사용자 편집/허용→계산→영향도 해석→후속 연구를 수행하라. 긴 해석은 job으로 추적하고 완료 후 결과를 읽어라.
R4. MFront의 일반 평가를 과거 E-only/고정 이력/설치 지문 제약과 분리하라. 실제 DE 후보 병렬화를 연결하고 workers 숫자만 바꾸지 마라. 상태·캐시·실패/event·기록/메모리 비용을 확인하라. 작은 계산의 직렬 사용은 허용하며 의미 없는 미세 최적화를 반복하지 마라.
R5. 한글 파일명, 큰 로컬 파일 경로, 채널/단위·변수/시험 조건 편집, 계획 승인, 같은 job의 실행·중단·재열람·보고서를 실제 화면에 연결하라. 대표 흐름을 수동 JSON 편집만으로 남기지 마라. 로컬 서비스를 다시 실행할 수 있는 기존 스크립트/명령과 환경을 인계하라.

AI·MCP·OpenScience·CAD 없이 직접 계산·조회하는 경로와 재료/PDE/구조/충격/자료/불량 자문의 폭을 유지하라. LS-OPT는 사용하지 마라. 외부 파일 읽기, 후보 내보내기/결과 회수, 등록 프로그램/추출기 자동 실행을 구분하라. 회사 DYNA 세부 연결이 없더라도 일반 실제 프로세스→ASCII→오차→다음 후보를 구현하라. 칩 충격과 예시 숫자를 새 프로필로 고정하지 마라.

기존 research 스킬과 공식 소스를 필요한 재사용 결정에 사용하라. 기존 수치·solver·reader·Haystack 구현을 재사용하고 새 framework·스킬·스케줄러부터 만들지 마라. grill-me는 미결정 사용자 쟁점에만 사용하라. 실제 영향도와 목적함수는 수치 도구가 계산하며 LLM이 만들지 않는다.

9절 A–F의 실제 사용자 흐름과 기존 회귀를 확인하라. mock/scripted 모델, 예상 출력 복사, HTML 교육용 계산기, 테스트 수, PR 병합을 전체 완료 증거로 쓰지 마라. 실제 명령·입출력·도구 요청/응답 요약·화면을 남겨라. 계정/관리자/설치 승인 등 필요한 사용자 조치만 구체적으로 한 번 요청하고 독립 작업은 계속하라. 실제 연결이 남으면 미완료/외부 조건 대기로 남기고 전체 완료라고 말하지 마라.

기능 묶음 검토와 필요한 검사 후 기존 승인 범위에서 PR로 통합하라. 보호 규칙을 우회하거나 강제 push/사용자 변경 폐기를 하지 마라. 작은 수정만 끝내고 중단하지 마라. 세션 한계에는 기존 진행 기록 한 곳에 완료·미완료·로컬 환경·현재 프로세스·다음 코드 위치를 남겨라. 짧게 환경과 분업을 정리한 뒤 구현을 시작하고, 또 다른 감사/계획 문서만 작성하고 종료하지 마라.
