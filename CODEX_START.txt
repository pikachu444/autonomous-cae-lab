Autonomous CAE Lab — 저장소 기반 개발 시작

내가 선택한 폴더에서 pikachu444/autonomous-cae-lab을 작업해. 저장소가 없으면 연결된 GitHub 또는 Git 도구로 가져와. redesign/research-workbench-20261007과 PR #1의 현재 상태를 확인해. 이미 병합됐으면 현재 main의 해당 내용을 사용해. 로컬 변경을 보존하고 최신 문서가 있는 상태에서 구현 브랜치로 이어가. reset이나 force-push로 사용자 변경을 버리지 마. 사용자에게 Git 명령이나 커밋 번호 확인을 떠넘기지 마.

병합을 영구 금지하지 마. 사용자가 구현과 병합까지 맡겼다면, 주 담당이 변경 내용·해당 기능의 실제 동작·필수 검사를 확인한 뒤 기능 묶음별 PR을 main에 병합하고 다음 작업으로 이어가. 같은 범위의 작은 커밋마다 승인을 다시 묻지 마. 병합 지시가 없으면 PR을 제출해. 보호 규칙 우회나 무관한 변경 병합은 하지 마. 이전 문서의 ‘임의 병합 금지’는 승인 없는 변경 방지이지, 사용자가 맡긴 통합 작업의 금지가 아니다. 일부 기능을 병합했다고 W1–W5 전체를 완료 처리하지 마.

AGENTS.md를 진입점으로 다음 문서를 실제로 읽어:
- docs/WORKBENCH_REDESIGN.md: W1–W5 전체 구조와 구현·완료 조건.
- docs/WORKBENCH_USE_CASES.md: 다양한 CAE 연구와 불량 자문의 실제 사용 흐름.
- docs/CODEX_WORKFLOW.md: 모델·추론·토큰·분업·통합·세션 재개 기준.
- docs/DEVELOPMENT_SKILLS.md: 원본 스킬, 호출 시점·범위, 미설치 선택 도구.

개발 기본 설정은 .codex/config.toml에 있다. Astra High 주 담당, Sol High 보조, 동시 보조 최대 2개다. 어려운 공통 설계·수치 문제에만 Extra High를 사용해. 실제 계정·클라이언트가 지원하고 선택한 값인지 확인하고, 미확인 설정을 적용됐다고 말하지 마. 기존 사용자 선택과 인증·권한·전역 설정·제품 연구 모델을 조용히 바꾸지 마. Fast/Ultrafast·Max/Ultra·API 추가 과금을 자동으로 켜지 마.

.agents/skills의 research, grill-me, grilling을 확인해. 새 공통 기반/중요 의존성은 기존 코드와 공식 외부 자료를 조사한 뒤 연결해. 필요한 연구에는 research를 명시적으로 사용해. grill-me/grilling은 아직 결정하지 않은 중요한 쟁점에만 사용하고 이미 합의한 제품을 재인터뷰하지 마. find-skills, search-first, Context7, Ouroboros는 DEVELOPMENT_SKILLS.md의 선택 기준을 따라. 설치·새 스킬 제작부터 별도 프로젝트로 시작하지 마.

주 담당은 전체 목표·공통 API·직접 구현·통합을 책임져. .codex/agents의 역할 중 필요한 것만 골라 입력, 담당 범위, 결과와 종료점을 전달해. 보조의 재귀 위임과 같은 파일 동시 수정은 하지 마. W1–W5를 다섯 에이전트에게 동시에 통째로 맡기지 마. 독립 검토는 중요한 변경 묶음에 사용하고 매 작은 수정에 최고 모델 리뷰를 반복하지 마.

현재 문서의 설계와 사용자 요구를 구현해. CAD·AI·OpenScience·MCP 없이 계산·조회할 수 있어야 해. 재료/시험 동정, CAD 없는 방정식·수치 연구, 기존 결과 분석, 전문가의 자료·문헌 자문과 계산 위임을 함께 추적해. 기존 solver·수치·검색 라이브러리를 재사용해. 예시 숫자나 HTML 계산기·규칙 기반 자문을 제품 제한 또는 실제 solver/LLM 완료 증거로 쓰지 마.

짧게 현재 상태와 다음 기능을 정한 뒤 바로 구현을 시작해. 실제 입력→계산/검색→결과→API/화면이 연결된 묶음을 완료하고 W1 이후 W2–W5로 계속해. 작은 검사·형식·과거 profile 보존을 전체 목표로 바꾸지 마. 자료 손상, 수치 오류, 권한, 실제 종료 문제는 해결해. 외부 계정/runtime이 막히면 그 실제 연결만 미확인으로 남기고 독립 구현을 진행해.

사용량 경고나 세션 한계에서는 CODEX_WORKFLOW.md의 인계 형식으로 완료 결과·브랜치·남은 작업·현재 프로세스·다음 위치를 현재 진행 기록 한 곳에 남겨. 추가 크레딧 구매·유료 API·다른 계정으로 몰래 우회하지 마. 결과는 사용자가 할 수 있게 된 일과 실제 실행/근거로 보고해. 전체 재설계 감사나 문서 작성만 반복하지 마.
