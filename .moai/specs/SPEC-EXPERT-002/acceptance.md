# User completion and bounded checks

1. From independent Expert, open Connection, inspect the actual configured
   service/model/roles, and select a supported existing subscription runtime.
   Cancel leaves the current document and operator settings unchanged.
2. Save/apply the connection and explicit role selection through the maintained
   local service lifecycle. Reopen the app with the same configuration and
   discussion. Unrelated settings and active work survive the operation.
3. Missing installation, unavailable login, unsupported model and usage limit
   present distinct actionable states. Saved sources and discussion stay usable.
   No paid fallback or provider call occurs during setup/status checks.
4. A bounded explicit real round, when entitlement/authentication are verified,
   retains the actual reply and citations. Existing Plan/result-return code is
   reused. Unit doubles prove only their stated configuration/UI behavior.

During development use focused setup/configuration/UI unit checks and a real
desktop render. Broad solver campaigns and repetition of already implemented
Numerical/Study tests are not prerequisites. Live inference remains NOT_RUN
until the actual supported subscription route is verified and explicitly used.
