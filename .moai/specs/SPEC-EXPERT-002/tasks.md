# 구현 작업과 인도 조건

현재 배정·순서·예상일과 실제 상태는 [CURRENT_STATE](../../../CURRENT_STATE.md)가 원본이다.
이 파일은 MoAI run에 적용할 고정 작업 분해다. 기존 Pro 작업을 다시 시작하지 않는다.
제품 코드는 실제 ChatGPT Pro, 독립 검토는 Astra, Windows 확인·통합은 Codex가 맡는다.

| 작업 | 사용자가 얻는 결과 | 구현 대상 | 완료 확인 |
|---|---|---|---|
| E1 | 연결 상태에서 빠진 준비를 구별한다 | Expert 창, 기존 readiness/host | 패키지 없음·프로필 없음·인증 미확인·역할 없음·추론 가능을 구별하고 실제 수정을 안내한다. 상태 조회가 질문을 보내지 않는다. |
| E2 | 기존 설치와 구독 프로필·모델·역할을 고른다 | native 연결 대화상자, 기존 role 정의 | JSON을 직접 편집하지 않고 설정하며 취소 시 기존 값이 남는다. 새 API 키·유료 경로를 만들지 않는다. |
| E3 | 저장한 연결을 현재 창에 적용한다 | 로컬 설정 쓰기, 기존 service lifecycle/assistance cache | 다른 설정·작업·초안을 보존한다. 진행 중 작업 때문에 적용할 수 없으면 구체적인 재시도 동작이 있다. Windows에서 wslpath 없이 실행한다. |
| E4 | 보낼 질문과 자료 범위를 직접 정한다 | 기존 논의·자료 선택·operator permission | 연결만으로 전송 허가를 얻지 않는다. 원격/MCP 요청은 실행 파일·인증·운영자 정책을 바꾸지 못한다. |
| E5 | 실제 연구 응답을 받고 실패 후 이어 쓴다 | 기존 Request round/pause/continue | 유효한 기존 구독에서 제한된 질문 1회와 실제 응답을 확인한다. 한도·연결 실패 시 초안과 자료를 보존한다. 대역 결과는 이 조건을 충족하지 않는다. |
| E6 | 제안을 계산 계획으로 고치고 결과로 토론을 잇는다 | 기존 Numerical Plan·Expert·Study 이동 | 제안 편집→기존 실제 수치 계산→선택한 결과를 원 논의에서 열기→저장·새 창 재열기를 확인한다. 이미 구현된 owner/명령을 재사용한다. |

E1–E4 구현 후 한 번에 검토 가능한 변경물과 관련 검사를 회수한다. E5–E6의 실제 실행은
Codex의 사용자 환경에서 확인한다. 기존 서비스 보존·설정 권한·수치 의미를 바꾸는 부분만
Astra가 독립 검토한다. 다른 solver 벤치마크나 새 backend 조사는 이 인도의 선행조건이 아니다.

새로 발견한 개선 중 이 여섯 작업의 성공을 막는 결함만 이번 수정에 포함한다.
추가 기능은 후속 인도로 분리하며, 사용자에게 미해결 상태를 숨기거나 완료 기준을 낮추지 않는다.
