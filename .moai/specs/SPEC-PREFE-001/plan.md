# 전처리·해석 작업 배정표

## 배정 단위와 순서

이 표는 기존 15행의 구체화다. 신규 기능 제안을 섞지 않는다. 코드 기준 `1820cf1`.
진행 담당/완료 표시는 CURRENT_STATE에 두며 본 표의 번호는 고정된 작업 범위를 뜻한다.
부분 구현6행을 아래 **22개 추가 개발 묶음**으로 나눴다. 별도로 확인보류2행은
Q1/Q2, 기존 완료7행은 B1–B7의 수용 조건을 유지한다. 22묶음은 모두 미구현이라는
뜻이 아니라 각 행의 기존 구현을 재사용해 남은 동작을 닫는 단위다. 설정과 실행이
서로를 기다리지 않도록 N1+S1은 NS1, N2+S3은 NS2로 합쳤다. 이 별칭을 중복 집계하지 않는다.

공통 인도물은 코드·관련 최소 검사·따라 하기·저장/재열기 결과다. 물리 기능은 선택한
법칙의 실제 입력과 출력 연결이 있어야 닫힌다. 백엔드 가능성 조사만 끝내서는 닫지 않는다.
모든 솔버 조합을 무한히 곱하지 않고 아래 명시 조합을 먼저 구현한다. 기존 명세의
다른 요구는 삭제하지 않으며 추가 조합은 원 요구와 연결해 별도 범위를 적어 배정한다.

[달성 조건의 22개 직접 확인 사례](acceptance.md#22개-개발-묶음별-직접-확인할-사례)가
각 작업 ID에 일대일 대응한다. 단순히 '지원', '연결', '저장 가능'이라고 보고하지 않고
해당 사례에서 사용자가 얻은 결과와 아직 안 된 동작을 보고한다.

### 구현 배정 전 채울 착수 카드

| 항목 | 적어야 할 내용 |
|---|---|
| 이번 인도 | 위 작업 ID, 사용자가 시작할 화면과 끝낼 결과. 남겨 두는 범위도 명시 |
| 기존 동작과 변경 | 재사용할 코드·기존 결과, 이번에 새로 연결하거나 수정할 동작 |
| 시험 자료 | 저장소 내 공개 모델/데이터 경로, 정상·오류 사례. 시험 입력값과 실제 물성을 구별 |
| 실행 조합 | 솔버/버전/요소/법칙/운영체제와 무료 실행 경로. 미확정이면 먼저 기술 선택을 닫음 |
| 합격 조건 | acceptance의 해당 행에 맞춘 관측값/단위/위치·실패복구·재열기. 수치 비교의 기준 자료와 원 허용치 |
| 책임과 통합 | 기준 소스, 작성자 소유 파일, 공통 변경 협의 대상, 독립 검토자, 통합 담당 |

카드의 기술 선택은 담당자가 조사해 채운다. 매번 사용자의 재승인을 받는 절차가 아니다.
파일 경로나 지원 조합이 비어 있는 넓은 항목을 '구현 착수 준비 완료'로 세지 않는다.
현재 착수·완료 상태는 CURRENT_STATE에서만 관리한다.

착수 카드에는 정확한 solver/version/element/law 조합, 공개 입력 모델, 이번에 관측할
채널과 단위, 수정할 파일을 채운다. 담당자가 코드·공식문서로 기술 선택을 확정하며
사용자에게 일반 기술 선택의 재승인을 요구하지 않는다. 그 조합을 입력→출력까지
지원하지 못하면 배정을 완료로 닫지 않는다. 원 요구 밖 기능을 임의로 추가하지 않는다.
표의 '의존'은 기본적으로 완료 선행이며, '계약'이라고 적은 것은 공유 필드/단위/상태의
합의만 선행한다. 계약 확정 후 양쪽 구현은 병행할 수 있다.

### M1 첫 인도에서 직접 확인할 동작

첫 지원은 FreeCAD 1.1.4의 회전/이동 관절과
`종속값 = 비율 × 기준 관절값 + 오프셋`이다. 기존 시간 구동식을 재사용하되
기준 관절과의 관계 자체를 저장한다. 서로 독립적인 시간식 두 개로 대신하지 않는다.
일반 다변수 비선형 관계식은 이 첫 인도의 완료 범위에 포함하지 않고 M1의 잔여로 둔다.

| 시작·조작 | 달성 조건 |
|---|---|
| 기준 회전 관절을 `90 × 시간` 도, 종속 이동 관절을 `2 mm/도`, 오프셋 `0 mm`로 설정 | 1초에서 기준 90도·종속 180mm가 실제 native 자세와 경로에 나타남. 계산 구간은 두 관절의 허용 범위 안으로 설정 |
| 기준 구동을 `45 × 시간` 도로 수정하고 다시 적용 | 종속식을 다시 입력하지 않아도 1초에서 90mm로 변경됨 |
| 기준 관절 삭제, 서로를 참조하는 순환, 같은 자유도의 중복 구동 또는 맞지 않는 단위 입력 | 해당 행과 원인을 표시하고 계산 차단. 입력 초안은 저장·재열기해 수정 가능 |
| 계산 구간에서 관절 한계를 넘거나 전체 구간의 한계 준수를 확인할 수 없는 식 입력 | 계산 차단. native 운동 계산이 무시하는 기존 관절 한계도 포함하며 값을 임의로 잘라 맞추지 않음 |
| 유효 관계 저장 후 새 문서 소유자로 다시 열기 | 관계·단위·한계·초안/적용 상태·선택을 유지. 읽기만으로 재계산하지 않으며 기존 저장 형식도 변경하지 않음 |

끝 자세와 시간별 경로는 별도로 판정한다. 위 1초 조건은 native frame의 실제 시각과
좌표가 연결되어야 통과한다. 설계 자세/초기 자세의 중복 frame을 단순 행 번호에
시간 간격을 곱해 표시한 결과로 대신하지 않는다. 현재 끝 자세 확인만으로 M1의
시간 이력 조건을 완료 처리하지 않으며 해당 차이는 CURRENT_STATE에 남긴다.

관절 ID와 자유도별 의존관계를 정리한 뒤 native Formula로 전개한다. 도→라디안
변환은 native 경계에서 한 번만 수행한다. Sol과 Astra가 이 설계에 합의했으며,
합의 자체가 코드 구현이나 실제 운동 확인의 완료를 뜻하지 않는다.

### Q1: 끊어진 CAD 치수를 다시 연결하는 작업

기준 소스는 `db0461e`, 실행 환경은 Windows의 FreeCAD 1.1.4다. 사용자는
설계 변수 목록에서 연결이 끊어진 치수를 선택하고, 현재 모델의 치수를 직접 골라
다시 연결한다. 다른 정상 치수는 계속 조회·편집할 수 있어야 한다.

기존 안정 이름 기반 치수 추적과 등록 정보를 재사용한다. 바꿀 곳은
`apps/desktop_pre/parameters.py`, `parameter_panel.py`와 관련 검사다.
Sol이 이 파일과 작은 공개 Sketcher 예제를 작성하고, Codex가 공통 명령 등록
`pre.parameters.rebind`를 통합한다. Astra가 완성된 변경을 독립 검토한다.
진행 상태는 CURRENT_STATE의 MoAI t15 배정을 따른다.

공개 시험 모델은 `examples/cad_parameters` 아래 생성 코드와 실행법으로 남긴다.
이 경로는 **작성 대상**이며, 파일과 실제 실행 결과를 확인하기 전에는 준비 완료로
세지 않는다. fixture 외 두 모델의 조건은 Sketcher 치수 모델과 직접 편집 가능한
속성 모델로 확인하고, 가져온 BRep에 없는 치수를 만들어 낸 것처럼 표시하지 않는다.

합격은 acceptance의 Q1 사례 전체다. 변수 ID·이름·범위·모드를 유지하고 현재
모델에서 새 치수의 변경 효과를 확인한 뒤 명시 적용한다. 취소와 실패는 기존
등록을 바꾸지 않는다. 수정 가능한 목록 조회만 완화하며, 필수 등록 치수를 쓰는
후보 생성·변수 변경 실행의 엄격한 검사는 유지한다. 이 변수들을 사용하지 않는
독립 FEM 작업까지 막는 새로운 전역 제한은 추가하지 않는다.

## 병렬 작성과 통합

M1–M3는 motion 한 작성자가 묶고 M4 후보 adapter는 공통 좌표 계약 확정 뒤 분리 가능하다.
E1/E2/E3는 FE 표현 공통 스키마를 Codex가 조정하고 writer를 파일별로 나눈다.
C1/C2/C4는 접촉법칙 공통파일을 같은 작성자가 소유한다. C3는 projection 독립 작업으로
분리한다. N3의 단계/상태 계약을 먼저 고정한 뒤 E6/C5와 NS1/NS2/S2를 분리한다.
R1/R2는 reader/Post 전용 파일을 소유하며 선행결과 형식이 정해지면 작성과 병행한다.
Core/registry/공통 schema는 Codex가 통합한다. Pro는 물리·데이터 변환이 큰 묶음을,
Sol은 명확한 GUI/연결 묶음을 작성하고 Astra는 독립 검토한다. MoAI는 이 SPEC과
배정 카드를 관리하는 도구이며 별도 작성 주체가 아니다.

첫 배정 후보는 Q1/Q2의 좁은 현재경로 정리, M1/M2, NS1, E1이다. 진행 중인
Pro 충격 입력 및 Sol 후처리 인도와 같은 파일을 동시에 수정하지 않는다.
각 인도는 관련 최소 검사 뒤 통합한다. 물리별 폭넓은 벤치마크는 기능이 갖춰진 뒤
수행하며 다른 묶음 개발의 선행조건으로 만들지 않는다. 새 범위 발견은 현재 묶음에
몰래 합치지 않고 원 요구·필요 코드·완료조건·의존을 적어 다음 배정으로 분리한다.

## 아직 결정해야 할 기술 사항

법칙/요소별 exact native card와 backend의 자유 구현 가능성은 각 묶음 착수 시
설치된 upstream source/공식 문서로 확인한다. C1/C2/C5/C6, E3/E5/E6, S2의 조합별
가능성은 이 문서로 확인 완료를 주장하지 않는다. 무료 경로 미확정은 해당 묶음의
구현 위험이며 요구 삭제나 미지원 표시만으로 완료할 이유가 아니다. 알려지지 않은
재료 수치·공학 허용치는 UNKNOWN으로 남기고 임의 기본값을 채택하지 않는다.
