# 실험 자료와 보고서 구현 인계

이 문서는 D9 구현 준비다. 실제 Pro 배정은 CURRENT_STATE에서 확인한다.
원 범위는 구현표의 FN-05-01, FN-05-02, FN-32-01, FN-35-01 네 행이다.
특정 장비가 없다는 이유로 파일 기반 측정 작업과 보고서를 미루지 않는다.

## 기존 코드에서 이어갈 곳

기준 main `94f952b`. D8 작성자는 이 기준을 포함한 별도 충격·손상 브랜치에서 작업
중이므로 이후 D9 인계 시 실제 통합 기준과 충돌 파일을 다시 명시한다. 아래는 소스 조사
결과이며 임의 계산·장비 실행을 확인했다는 뜻은 아니다.

| 사용자 작업 | 재사용할 제품 코드 | 추가할 연결 |
|---|---|---|
| 파일과 시험 조건 열기 | `apps/research/data_window.py`, `caelab/data_document.py`, 기존 파일 등록·보존과 `source_preview` | 기존 CSV 진입을 유지하며 채널별 교정, 시편·장착·게이지 조건을 해당 Data에 연결 |
| 원값과 보정값 비교 | 기존 mapping의 scale/offset, `caelab/data_comparison.py`, Data 그래프 | 단위가 있는 교정식·유효범위·원자료·행 마스크와 개정. 단순 scale/offset을 완성된 교정 기록이라고 부르지 않음 |
| 해석과 측정 비교 | `apps/desktop_post/measurements.py`, 저장 measurement와 같은 결과를 여는 desktop 연결 | 선택 게이지/물리량/좌표/시각을 비교 입력으로 유지. 원측정과 보간·필터 결과를 구분 |
| 미식별 계수와 다음 시험 | 기존 Numerical Plan·민감도 결과, `StudyDocuments`, `StudyWindow.request_followup`, `DesktopLinks.study_followup` | 실제 계산이 제공하는 식별/상관 진단과 고정·미식별 상태를 선택해 후속 관측에 기록 |
| 보고서 편집·읽기 | Study의 정확한 저장 참조, `apps/research/costorm_report.py`, `apps/lab/reporting.py`, `caelab/campaign_report.py` | 서로 다른 보고서의 전용 모델을 구분하여 선택 섹션·미리보기·초안 저장·재열기를 구현 |
| 수집 설정 저장 | 기존 Data/Study/Runner 문서·명령 | 채널 역할·샘플링 계획·시간 정렬과 파일 입력을 연결. 미확인 장비의 연결·물리 중지를 지어내지 않음 |

Data의 현 `test_metadata`는 test_id/specimen/protocol/temperature 문자열만 허용한다.
필요한 구조를 이 저장 기반에서 확장하되 모든 내부 속성을 폼으로 노출하지 않는다.
Report 전용 제품 도구는 아직 없으며 시안의 ReportWindow/AcquisitionWindow는 참고다.

Lab 보고서는 기존 experiment의 HTML/JSON/ZIP 묶음이고, campaign 보고서는 통계 선언과
결과에 한정되며, Co-STORM 보고서는 토론과 인용 자료를 읽는 도구다. 어느 하나를 이름만
바꿔 Study 보고서 편집이 완성됐다고 하지 않는다. 결과 참조·표·인용 이동·출력 구현은
재사용한다. 보고서 초안에 작은 문서 타입이 필요한지는 Pro가 기존 owner 기반과 비교해
결정한다. 별도 공통 프레임워크나 저장 시스템을 만드는 요구는 아니다.

## 구현 순서와 사용자 조작

1. Data에서 시험 파일을 연 뒤 채널을 선택하고 **교정…**으로 원본 교정표, 입력/출력
   단위, 계수와 영점, 사용 범위 및 관측 시각을 지정한다. 원값·보정값·범위 밖 행을
   표와 그래프에서 같이 보고 저장한다. 제공되지 않은 불확실성은 비어 있는 이유를
   표시하며 자동 추정하지 않는다. V/mV/count 변환과 입력 영점 x−x0, 출력 offset b의
   단위·순서를 명시하고 교정식 사용 범위와 센서 포화 범위를 따로 다룬다. 제공된
   불확실성의 표준/확장 구분·포함인자·상관은 유지하며 모르는 정보를 생성하지 않는다.
   기본값이 실제 측정 조건으로 오해되지 않게 한다.
2. **해석과 비교…**에서 저장된 결과와 같은 물리량을 고르고, 필요한 게이지 위치·길이·
   방향·좌표 및 시간 정렬을 지정한다. 사용자에게 서로 다른 관측량의 차분을 보여 주지
   않으며, 필요한 정의가 없으면 그 항목의 입력으로 돌아갈 수 있게 한다. 같은 원행과
   해석 위치를 다시 열 수 있어야 한다.
3. Numerical의 동정 결과를 선택해 식별 진단과 고정한 계수를 보고, 다음 시험이 무엇을
   구분하려는지 Study에 기록한다. 선택한 결과를 가져오며 이 동작이 새 최적화를 실행하지
   않는다. fit/holdout의 원본 행 겹침 방지를 유지하며 최적화 성공이나 작은 잔차만으로
   재료 계수와 지그 영향을 구분했다고 하지 않는다. 새로운 실제 관측을 얻으면 이전
   판단을 남기고 후속 판단으로 연결한다.
4. Study나 독립 결과에서 **보고서 만들기…**를 연다. 왼쪽은 섹션 순서, 가운데는 실제
   페이지 미리보기, 선택 섹션의 근처에는 표·곡선·설명·원자료 열기 작업을 둔다. 섹션
   추가/제거/이동, 포함 범위와 설명 편집, Undo/Redo, 저장·재열기를 지원한다. 배치
   대안은 배정된 desktop specialist가 기존 Qt와 시안을 비교하고 Astra와 논의해 결정한다.
   긴 설명 목록을 주 화면으로 만들지 않는다. 선택 시점에 적용한 자료·field/time/row를
   고정하고 다른 창의 시간 변경을 따라가지 않는다. 새 Study 내용으로 편집 섹션을 바꿀
   때는 명시 적용과 Cancel/Undo를 제공한다.
5. PDF/Markdown과 필요한 표·그림을 명시적으로 내보낸다. 원자료가 빠진 섹션은 표시하고
   내보내기 정책을 적용한다. 출력 취소·실패가 이전 파일이나 보고서 초안을 지우지 않는다.
   작은 창·한글·큰 표와 페이지 넘김을 실제 Qt로 확인한다. 그림 크기·필터·표본 축약이
   있다면 독자가 수치를 오해하지 않도록 해당 그림 설명에 남긴다.
6. 파일 입력용 수집 설정에서 채널 추가/수정/제거, 역할·단위·교정, 샘플링 계획과 시간
   오프셋을 저장하고 다시 연다. 재생한 기존 파일을 실시간 측정으로 표시하지 않는다.
   장비 모델·driver·권한·물리 정지 확인 전에는 장비 동작을 수행하지 않는다.

## 역할과 인도

실제 Pro가 Data/보고서/수집 설정의 도메인·owner와 주요 기능·관련 검사·사용법을 작성한다.
기존 desktop specialist에게 프로젝트 `.agents/skills/cae-desktop-ux/SKILL.md`와 해당
참고 자료를 전달해 시각 설계·범위가 정해진 Qt 구현·실제 창 확인을 맡긴다. Pro와 Qt
파일을 동시에 쓰지 않도록 API·소유권을 배정 전에 나눈다. Codex는 기준 소스·사용자
파일 보존, 정확한 명령 연결, Windows 실행과 Git 통합을 맡는다. Astra는 원요구·실제
화면·수치 의미와 실패 복구를 독립 검토한다. 공통 owner와 registry도 동시에 수정하지 않는다.

인도는 적용 가능한 제품 코드와 무료 로컬 실행 방법이어야 한다. 작은 합성 자료로
교정/미식별·식별 사례와 보고서 저장·재열기를 확인하되 광범위 솔버 캠페인은 반복하지 않는다.
실제 장비 미제공은 미결정으로 남기며 D9 네 작업 전체를 완료했다고 표시하지 않는다.
완료 조건과 실행 시점은 [acceptance.md](acceptance.md)에 있다.
