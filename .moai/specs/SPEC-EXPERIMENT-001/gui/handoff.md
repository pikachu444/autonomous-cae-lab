# D9 Qt 배치와 조작 인계

2026-10-14. 제품 작성은 Pro 소유다. 이 폴더의 `layout_proposal.py`는 편집 가능한
Qt 사본이고 제품 owner, 교정 계산, 저장, PDF/Markdown 출력과 연결되지 않았다.
그래프와 표는 공개 합성 fixture다. 보고서 36행은 페이지 나눔 확인용 반복 합성값이다.
원 제품 파일, 공통 인터페이스, 사용자 설정은 수정하지 않았다.

## 합의한 배치

교정은 위에서 파일/채널을 고르고, 중앙의 같은 원행 표와 V/N 분리 축을 보며 오른쪽의
선택 채널 교정을 편집한다. 1100 폭에서도 2열이다. 입력 영점[V], 계수[N/V], 출력
오프셋[N]과 적용 순서를 함께 읽고 교정식 범위와 센서 포화 범위를 구별한다.
큰 원본/교정값 표를 가리는 전체 wizard와 세 번째 채널목록 열은 두지 않는다.

범위 밖 532 N/포화 632 N도 숫자를 보존한다. 그래프의 정상 교정 구간은 실선,
범위 밖은 속이 빈 표시, 포화는 ×이며 범례와 행 상태가 같은 의미를 가진다.
범위 밖 점으로 이어지는 점선은 추정식의 시안 표시이며 유효 측정값으로 인용하지 않는다.
제품에서는 이 표시를 기존 quality/calibration mask에 연결한다. fit/holdout과 화면 숨김은
별도 의미를 유지한다. 미완성 `1e`를 입력하면 표/그림은 이전 교정, 편집은 미적용임을
보인다. `교정 적용`은 명시 실행이며 단순 입력마다 계산/저장하지 않는다.

보고서는 왼쪽 섹션 포함/순서, 중앙 페이지 미리보기가 기본이다. 설명 편집 때만 넓은
창은 옆, 작은 창은 아래에 3~4줄 작성부를 연다. 편집 중 창폭 변경으로 작성부를 강제로
옮기지 않는다. 기본 본문은 595px A4 비율이며 한글·숫자를 읽는 크기와 세로 스크롤을
유지한다. 전체 페이지를 화면 높이에 작게 맞추지 않는다. 전체 편집/미리보기 탭은 반복
왕복을 늘리므로 채택하지 않았다. 섹션 선택은 해당 페이지와 제목 위치로 이동한다.

`설명 적용`은 선택 섹션 본문에만 적용하고 `닫기`는 미적용 buffer를 보관한다.
`수정 취소`는 선택 섹션의 마지막 적용 본문을 복원한다. 제품은 기존 section ID로
순서와 편집 buffer를 보존한다. 사본의 index 기반 순서 이동 보류는 제품 규칙이 아니다.
보고서 표에도 교정 상태를 넣어 원값·교정값·범위 밖·포화가 출력에서 사라지지 않게 한다.
누락 원자료는 섹션 이름을 가리키고 기존 본문을 보존한다. 최신 결과로 자동 대체하지 않는다.

## 메뉴와 연결 packet

새 공통 API를 여기서 확정하지 않는다. 다음은 Pro가 기존 owner/명령에 붙일 UI 동작이다.

| 사용자 동작 | 연결과 보존 조건 |
|---|---|
| Data 파일 열기 → 채널 → 교정… | 기존 파일 등록/retention과 Data 원행 선택을 재사용. 교정 원자료·계수 단위·영점·오프셋·유효범위·관측 시각을 같은 초안에 보존 |
| 교정 적용 | owner 검증/명시 처리로 새 처리 revision 생성. 원자료와 옛 결과는 유지. 미완성 초안 저장은 허용하되 처리 실행은 차단 |
| 자료 저장 / Ctrl+S | 교정 선택, 품질 사유, 관측 정의를 같은 Data 저장본에 보존. 미제공 불확실성을 0이나 독립으로 채우지 않음 |
| Study 또는 독립 결과 → 보고서 만들기… | 선택한 저장 참조/값/단위/행/위치/시각을 보고서 선택에 고정. 다른 창의 이후 선택을 따라가지 않으며 solver/provider 호출 없음 |
| 보고서 단독 진입 / 열기… | 같은 ReportWindow와 저장 owner. desktop/도구 등록은 Pro, Windows launcher/시작 메뉴는 root 책임 |
| 섹션 포함/추가/제거/위아래, 설명 적용/수정 취소 | 기존 Undo/Redo와 섹션 키를 사용. 새 Study 내용으로 바꾸기는 명시 교체/취소/Undo. 편집 제목으로 source identity를 대체하지 않음 |
| 원자료 열기 | `StudyWindow.open_reference`/기존 `ReferenceWindow`의 exact saved ref 경로 재사용. 누락 시 해당 섹션/같은 참조 재시도, 원문과 편집 buffer 보존 |
| 저장 / Ctrl+S, 내보내기… / Ctrl+Shift+E | Report 초안 저장과 출력은 별도. PDF/Markdown/미리보기는 같은 적용 선택을 사용. 실패·취소는 초안/이전 출력 유지; 누락 정책은 owner의 명시 정책 사용 |

`costorm_report.ReportView`는 Markdown/인용 이동 재사용 후보이지만 토론 보고서
전용이므로 일반 편집 보고서 owner로 이름만 바꾸어 사용하지 않는다. 수식/링크 경계도
기존 읽기 경로를 보존한다. 보고서의 raw ID/SHA는 원자료 상세에서만 확인한다.

## 실제 시안 확인과 한계

주 화면은 `calibration-small.png`, `report-small.png`; 같은 소스의 1440×900 렌더도 있다.
`calibration-unapplied-small.png`, `report-editing-small.png`는 작은 창의 미적용 편집,
`report-second-page-small.png`는 큰 표의 두 번째 페이지,
`report-missing-source-small.png`는 누락 섹션/제목/이전 본문이다. 새로운 시안은 더 추가하지 않았다.

Windows 설치 글꼴 Segoe UI/맑은 고딕과 기존 `apply_appearance`를 사용한 Qt 6.9.1
offscreen 렌더이며 요청 크기 1100×780/1440×900을 실제 유지했다.
`render-peer-corrected.txt` exit 0, receipt의 작은 확인은 미완성 숫자 focus/text,
설명 닫기/재열기 buffer, 수정 취소 복원, 보고서 교정 상태, 실제 Qt 2페이지다.
초기 focus 확인 실패는 다른 시안 창이 활성 상태인 helper 문제였으며 현재 로그와 구분했다.
최종 소스의 마지막 변경은 게시 위치에서도 repo를 찾는 부모 경로 해석과 실제 조작용
`--show` 분기이며 기본 렌더의 배치는 바뀌지 않아 재렌더하지 않았다.

Astra와 실제 이미지로 논의해 보고서 상태 누락, 설명 취소 동선, 교정 적용 명칭을 교정했다.
VIS-SPACE/WIN-COMMAND는 밀도·주명령/메뉴 위계, QT-PANELS는 요청 시 작성부와
편집 중 위치 보존, PV-VIEW는 화면 선택과 저장 근거 분리에 적용했다.
저장/교정/내보내기/owner 수명/OS 입력의 제품 완료는 확인하지 않았다.
새 solver/provider/장비/서비스 실행과 설치는 0이다.

실행: 기존 Windows runtime Python으로 `layout_proposal.py`를 실행하면 같은 폴더에 렌더한다.
`python layout_proposal.py --show`는 offscreen을 강제하지 않고 두 편집 가능한 시안 창을
열어 닫을 때까지 유지한다. 저장·교정 계산·내보내기는 연결되지 않았다는 상태를 유지한다.
repo를 찾는 경로는 `pyproject.toml`과 `apps/research`가 있는 부모로 정해
`.moai/specs/SPEC-EXPERIMENT-001/gui/`로 복사해도 같은 프로젝트를 재사용한다.
