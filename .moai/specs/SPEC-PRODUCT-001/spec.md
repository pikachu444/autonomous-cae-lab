# 범용 CAE·수치 연구 환경 전체 설계

**상태: 사용자 검토용 설계안. 이 문서는 구현 완료나 구현 시작 승인을 뜻하지 않는다.**

현재 승인된 작업은 전체 제품의 설계 명세 작성이다. 제품 코드·설정 변경, 빌드,
GUI 실행, solver 실행, 테스트·CI는 이 작업에서 수행하지 않는다.
설계 확정 후 현재 저장소를 계속 사용할지 분리할지 결정한다. 기존 코드와 사용자 파일은 보존한다.
사용자의 최신 지시와 [AGENTS.md](../../../AGENTS.md)가 이 문서보다 우선한다.

## 1. 사용자가 쓰는 제품

사용자가 자신의 CAD·메시·해석 입력·시험 데이터·재료 법칙·방정식으로 모델을 만들고,
계산하고, 비교하고, 연구를 저장하는 **하나의 Windows 프로그램**이다.
필요하면 같은 작업을 놓고 실제 LLM 전문가들과 토론한다. AI 연결이 없어도
모델 작성·자료 처리·계산·수치 연구·결과 확인·보고서·저장 기능을 쓴다.

전체 범위는 다음과 같다. 개발 순서는 이 범위를 줄이는 근거가 아니다.

| 연구 작업 | 사용자가 끝낼 수 있어야 하는 일 |
|---|---|
| CAD와 해석 모델 | FreeCAD의 스케치·부품·조립·형상 편집, 가져온 CAD·메시·입력 파일, 집합·재료·단면·조건·단계·출력 편집 |
| 구조·열·동역학 | 선형·비선형 정적, 재료·기하 비선형과 접촉, 모드·좌굴·과도 동해석, 열·열-구조, explicit 낙하·충돌 |
| 데이터와 시험 | 원표·채널·단위·교정·제외 구간·처리·비교, 기존 취득 기능의 측정자료 연결, 원자료와 처리 결과 보존 |
| 재료 연구 | 사용자 법칙과 시험 경로의 정의, 재료점 계산, 계수 추정·불확실성·비교, 선택한 법칙과 계수를 해석 재료에 적용 |
| 수치 연구 | 모델의 선택한 값을 변수로 등록하고 DOE·최적화·역추정·감도·UQ·대리모델·다목적 연구 수행 |
| 방정식과 연성 | 사용자 방정식·PDE·약형·경계/초기조건, 외부 계산기, 물리 간 값·장·시간 이력 전달 |
| 토론과 판단 | 실제 자료 읽기, 여러 전문가의 근거·반론, 합의점·남은 이견, 제안·계획 편집과 사용자 실행 |
| 이어 쓰기와 전달 | 원본·계산 당시 입력·결과·대화·선택을 함께 저장하고 이동·재열기·복구, 표·곡선·설명·보고서 내보내기 |

새 연구를 반드시 CAD에서 시작하지 않는다. 이미 계산한 결과만 열어 비교하거나,
시험 데이터에서 재료 연구를 시작하거나, 방정식만 작성할 수 있다.
예제는 도움말과 CI의 시험 입력이며 새로 만들기의 기본 선택지가 아니다.
기존 [원 요구](../../../PROJECT_SCOPE.md)의 유지되는 연구 범위와 GUI/CLI/Python/MCP 공통 사용을 보존한다.

### 인터뷰에서 확정한 사항

- 제품 전체 설계를 먼저 확정한다. 저장소 분리는 그 뒤 결정한다.
- 모델링은 **FreeCAD의 기존 도구 선택과 화면 구성을 기본으로 유지하고 연구 기능을 연결**한다.
- 결과 비교는 **나란한 화면에서 3D 선택·시간 이동을 연결하고 표·곡선을 함께 보는 방식**을 기본으로 한다. 한 결과를 크게 보며 비교 대상을 바꾸는 방식도 제공한다.
- 시험 데이터 처리·재료 계수 추정은 **단계별 안내를 기본**으로 한다. 필요하면 데이터·그래프를 자유롭게 편집하고 같은 작업을 이어 간다.
- 여러 전문가가 서로의 근거와 반론을 읽고 논의하며 합의점과 남은 이견을 보여 준다.
- 연구 주제와 선택한 모델·결과에 맞춰 전문가를 추천하고 사용자가 구성을 바꾼다.
- **참여 전문가 전원이 한 번씩 발언하는 한 바퀴가 1턴**이다.
- 사용자가 턴 수를 바꾸고 토론 도중 질문·의견으로 참여한다.

이 설계안은 기본 분량을 **3턴**, 빠른 선택을 **5턴**, 그 밖의 분량은 직접 입력으로 제안한다.
기본 3턴은 설계자의 제안이며 사용자에게 이미 확정받은 값으로 취급하지 않는다.
모델링·결과 분석·데이터·재료·수치 연구·방정식·보고서의 세부 사용 방식은 인터뷰를 이어 간다.
아래 설계자의 제안을 모두 사용자가 확정한 요구로 취급하지 않는다.

## 2. 제품 경계와 한 주 창

### 2.1 채택할 구조

**FreeCAD의 주 창과 문서 편집 수명을 제품의 GUI 기반으로 사용한다.**
기존 메뉴·도구 모음·Workbench 선택, Sketcher·PartDesign·Assembly·FEM 명령,
모델 트리, 객체 선택, 속성 편집기, Task panel, Undo와 FCStd 저장을 기본으로 유지한다.
별도로 정리한 CAE 메뉴나 중복 편집 폼을 기본 조작으로 대체하지 않는다.
연구 편집기와 결과 작업면은 같은 창의 문서 페이지·도크로 연결한다.

ParaView는 reader, ServerManager, pipeline, Properties, 필터와 렌더 뷰를
네이티브 라이브러리·위젯으로 사용한다. 외부 실행파일의 창을 강제로 붙이지 않는다.
Material·Numerical·PDE·Data의 기존 controller와 편집 QWidget을 같은 호스트에 연결한다.
새 전처리 폼, 자체 CAD 모델러, 자체 결과 렌더러를 만들지 않는다.

Windows 사용자는 제품 실행과 파일 열기를 이용한다. 화면마다 다른 앱을 찾아
실행하거나 결과를 전달하기 위해 내부 문서 ID를 입력하지 않는다.
한 프로그램은 단일 프로세스라는 뜻이 아니다. solver·수치 worker·연결 서비스는
기존 방식으로 격리할 수 있지만 기본 사용자 작업은 한 주 창에서 끝나야 한다.

독립 FreeCAD 사용·저장·계산과 기존 파일의 직접 열기는 계속 허용한다.
그 동작에 연구 생성, job 등록, 실시간 감시, LLM 연결을 요구하지 않는다.
독립 도구의 호환 진입은 통합 작업면과 같은 편집·저장·실행 명령을 쓴다.

### 2.2 공통 네이티브 SDK

현재 배포본을 같은 프로세스에서 그대로 import하거나 DLL 검색 경로로 섞지 않는다.
다음 GUI 구성요소는 하나의 Qt·Python·VTK·컴파일러·런타임 조합으로 맞춘다.

| 구성요소 | 통합 경계 |
|---|---|
| FreeCAD | 문서·선택·명령·Undo 소유, Gui::MDIView와 MainWindow::addWindow()를 통한 연구 페이지 |
| ParaView | pqCore / pqComponents / pqApplicationComponents, pipeline·Properties와 pqRenderView의 QWidget |
| Qt 연구 편집기 | 기존 controller와 편집면을 호스트에 제공, 별도 QApplication 생성 금지 |
| Data / LabPlot | 기존 Qt Data 편집면을 같은 문서 계약으로 연결하고, LabPlot backend·frontend 라이브러리 어댑터로 완성된 작업면을 이관 |
| solver·수치 worker | 기존 JobManager의 소유 프로세스로 실행, 각자의 수치 의존성·실행 환경 유지 |

현재 Post SDK의 **출발 후보**는 ParaView 6.2.0, Qt 6.9.0, CPython 3.12.14,
동봉 VTK 9.7.1, Windows x64 Release / MSVC 19.43이다.
이는 현재 체크아웃 밖 SDK 메타데이터와 CMake 캐시의 값이며 새 통합 제품의 확정 배포 조합이 아니다.
현재 연구 UI의 PySide6 6.9.1과 LabPlot의 별도 Qt 6.11.1 / KF 6.31 빌드도 정합 대상이다.
SDK를 최종 고정할 때 FreeCAD와 그 FEM/SMESH 의존성까지 같은 조합으로 실제 빌드한다.

첫 통합 묶음 안에서 다음을 좁게 확인한다.

1. 같은 Qt·Python·VTK로 FreeCAD와 ParaView 모듈을 링크하고 한 QApplication에서 실행한다.
2. CAD 뷰와 ParaView 뷰를 전환·크기 변경·저장·종료하며 Python·OpenGL 초기화/종료 충돌이 없는지 확인한다.
3. FreeCAD 문서와 연구 페이지의 활성 선택, 키보드, Task, Undo, 미저장 닫기를 확인한다.
4. 기존 Post 종료 플러그인의 별도 ParaViewMainWindow 가정을 호스트의 저장·닫기 수명에 연결한다.

위 공존은 아직 입증되지 않았다. 개별 앱이나 SDK의 빌드 성공은 이 확인을 대신하지 않는다.
공존이 안 되면 같은 사용자 동선 안에서 호스트 경계를 수정하고 사용자에게 중요한 설계 변경을 설명한다.
별도 창 launcher를 완성된 통합 GUI로 대체 선언하지 않는다.

LabPlot의 기존 frontend·어댑터는 GPL-2.0-or-later 고지를 갖는다.
인프로세스 배포 경계를 정할 때 per-file 라이선스·고지·대응 소스와 Qt/KDE 등 전이 의존성을 확인한다.
추가 유료 서비스·상용 SDK를 도입하지 않고, WSL을 기본 GUI 설치 조건으로 만들지 않는다.
Windows에서 사용할 수 없는 solver의 실행 환경 문제는 기존 자료·결과 열람을 막지 않는다.

## 3. 계층과 책임

~~~mermaid
flowchart TB
  UI["한 주 창: 모델 · 결과 · 표/곡선 · 재료 · 수치 연구 · 방정식 · 토론"]
  CMD["기존 문서 명령 / 선택 / 저장 / 실행 요청"]
  DOC["각 문서 소유자: FreeCAD · Data · Material · Numerical · PDE · Study · Discussion"]
  PORT["기존 입력 연결 · 파라미터 등록 · 실행/결과 계약"]
  JOB["기존 JobManager"]
  SOL["solver 변환기와 수치 엔진"]
  RES["원본 결과 + 의미를 보존한 reader"]
  LLM["실제 전문가 호출과 읽기 도구"]
  UI --> CMD --> DOC --> PORT --> JOB --> SOL --> RES
  RES --> DOC
  DOC --> LLM
  LLM -->|"제안만"| CMD
~~~

| 책임 | 소유하는 것 | 맡지 않는 것 |
|---|---|---|
| GUI | 표시·선택·편집 조작·사용자 명령·작업 문맥 | solver deck 생성, 계산값 생성, 별도 모델 사본 관리 |
| 문서 명령 | 객체 변경, Undo/Redo, 저장, 제안 적용, 실행 요청 검증 | feature별 solver 선택 우회 |
| 도메인 문서 | 해당 영역의 원본 정의·단위·참조·편집 개정 | 모든 영역을 하나의 구조 해석 JSON으로 변환 |
| 변환기 / reader | solver별 지원 조합, 입출력 변환, 실제 결과 의미 | 업무별·예제별 별도 제품 정의 |
| 수치 엔진 | 후보 생성·최적화·통계·추정 | LLM 답변으로 후보 평가값 대체 |
| JobManager | 기존 프로세스 소유·대기·취소·실행 결과·재연결 | 두 번째 scheduler 또는 대화 전용 실행 시스템 |
| LLM | 질문·계획·근거 해석·반론·제안 | 모델의 임의 자동 변경, 사용자 대신 실행 승인, 물리 계산 |

의존 방향은 GUI → 문서 명령 → 도메인/연결 계약 → 기존 adapter다.
solver와 reader를 GUI에서 직접 호출하지 않는다.
GUI·CLI·Python·MCP는 같은 지원 연산과 문서 명령을 사용한다.
새 범용 event bus·ORM·저장소·LLM framework를 도입하지 않는다.

각 문서 페이지는 소유 문서·선택·편집·저장 명령을 호스트에 제공한다.
저장·닫기·Undo는 활성 페이지와 실제 입력 초점에 전달한다.
Data나 대화 탭을 편집하는 동안 마지막 FreeCAD 문서가 활성 상태라는 이유로
그 모델을 저장·수정하지 않는다. ParaView application core는 호스트 수명에 하나만 두고,
결과 탭을 닫는 동작이 공유 Python/VTK를 종료하지 않게 한다.

적용할 패턴은 기존 문서 명령/Undo, solver adapter, 문서 참조와 실행 입력의 분리다.
이름을 정리하기 위한 전면 class 이동보다 실제 사용자 기능을 연결하는 변경을 먼저 한다.

## 4. 원본 문서와 연구 연결

### 4.1 편집 원본은 영역마다 하나

| 영역 | 유일한 편집 원본 | 다른 문서에서 사용하는 방식 |
|---|---|---|
| 구조 모델 | FreeCAD 문서의 형상·FemMesh·Analysis와 참조 가능한 FEM 객체 | 해당 문서·객체·속성·적용된 개정을 참조 |
| 데이터 | 기존 DataDocuments와 연결된 원표/처리 정의 | 원 채널·행/범위·마스크·처리 개정 선택 |
| 재료 | MaterialDocuments의 법칙·계수·시험 경로·상태 정의 | 선택한 법칙 개정과 solver별 실제 표현을 적용 |
| 수치 계획 | NumericalDocuments의 변수·목표·제약·방법·예산 | 선택 모델 입력과 응답을 기존 evaluator에 연결 |
| 방정식/연성 | PDEDocuments / EvaluationDocuments의 고유 정의 | 필드·단위·영역·시간·전달 규칙을 명시해 연결 |
| 결과 표시 | 원 결과 파일과 ParaView 상태·선택 | 계산 당시 입력, 실제 프레임·배열·성분·위치와 연결 |
| 연구와 대화 | 기존 Study / Discussion 문서 | 위 문서와 결과의 선택 참조 및 연구 판단을 보관 |

Workbench는 이 연결을 보여 주는 제품 작업면이다. 모델 정의의 두 번째 원본이나
모든 문서를 재저장하는 새 데이터베이스가 아니다. QSettings는 창 배치·최근 파일에만 사용한다.
파생 실행 표현, solver 입력, LLM 요약은 편집 원본으로 동기화하지 않는다.

### 4.2 선택과 개정

공통으로 전달할 최소 의미는 소유 문서, 대상 객체/범위, 당시 개정, 실제 단위와
결과의 위치·성분·단계/시각이다. 기존 문서 참조와 선택 계약을 확장해 사용한다.
내부 식별자를 사용자가 입력하거나 외워야 하는 화면을 만들지 않는다.

현재 편집본, 계산 당시 입력, 실제 계산 결과, 대리모델 예측은 별도로 유지한다.
같은 경로에 새 결과 파일이 생겨도 이전 대화의 근거는 바뀌지 않는다.
기존 저장소의 원본 보존과 개정 기능으로 이전 입력·결과를 읽을 수 있게 한다.
선택을 미리 보는 것과 대화에 자료로 추가하는 것은 구분한다.

파일은 연결만 할지 연구와 함께 복사할지 사용자가 선택할 수 있다.
파일 위치가 바뀌면 해당 문서에서 새 위치를 지정한다. 없는 파일을 성공 상태로 만들지 않는다.

### 4.3 CAD·메시·inp에서 시작하기

CAD와 FEM 형상은 FreeCAD의 기존 가져오기·스케치·부품·조립·모델 편집을 이용한다.
형상 없이 가져온 메시도 요소·집합·재료·단면·조건을 작성할 수 있다.
표면 메시의 경계 면과 실제 구조 셸·보 요소는 서로 다른 역할로 보존한다.

inp 가져오기는 원문을 보존하고 지원하는 항목을 같은 FEM 객체로 해석한다.
GUI가 표현하지 못하는 블록은 원문과 위치를 남기며 전체 지원으로 표시하지 않는다.
원문 편집을 선택하면 그 입력 파일이 해당 실행의 원본이며 GUI는 가능한 항목을 읽는다.
GUI 모델 편집과 원문 deck 편집을 동시에 별도 원본으로 유지하지 않는다.
표현하지 못한 블록을 잃는 재작성은 막고, 원문 실행 또는 해당 항목 편집 위치를 안내한다.
구문을 아직 읽지 못한다는 사실을 solver가 그 기능을 지원하지 않는다는 뜻으로 바꾸지 않는다.

## 5. 하나의 구조 모델

### 5.1 문서 트리

아래는 논리 구조다. FreeCAD FEM 객체와 Abaqus inp 어휘를 우선하며
기존 객체가 부족한 정보만 동일 문서 안의 참조 가능한 객체와 Task/속성으로 보완한다.

~~~text
모델 문서
  형상 / 부품 / 조립
  메시 / 이름 붙은 절점·요소·면 집합
  재료 / 고체·셸·보·적층 단면 / 국부 좌표계
  해석
    단계
      절차 / 하중·구속 / 접촉·연결 / 출력
    초기조건 / solver 설정
  계산과 결과
~~~

재료, 접촉, 볼트 예하중, 스프링, 셸·적층, 초기장은 같은 모델의 옵션이다.
이를 선택했다고 다른 모델 종류·backend key·작성 창·계산 저장소로 전환하지 않는다.
한 모델에 가능한 옵션을 조합하고, 실제 호환되지 않는 조합만 해당 객체에서 설명한다.

### 5.2 파생 실행 입력과 작성

실행 요청 시 적용된 문서에서 읽기 전용 실행 입력을 만든다.
객체 수집, 요소 번호·집합, 재료·단면·조건·단계·출력 작성을 한 경로로 수행한다.
solver별 변환은 그 뒤에 둔다. 기존 native writer·카드 작성·reader를 필요한 단위로 재사용한다.
기능별 전체 deck 작성기 중 하나를 우선순위로 골라 반환하는 구조는 이 경로로 대체한다.

| solver | 출력 경로 | 변환기가 책임지는 것 |
|---|---|---|
| CalculiX | inp → CalculiX → 기존 결과 변환/reader | 요소·재료·조건·다중 단계·출력의 전체 연결 |
| OpenRadioss | 지원하는 inp → 고정 inp2rad → Starter / Engine | 변환된 요소·재료·접촉·초기조건·시간/질량 제어 확인과 결과 의미 |
| Code_Aster | MED + .comm → Code_Aster | 메시 그룹, AFFE_MODELE 정식화, 재료·단면·단계·출력 및 MED 결과 |

기존 FreeCAD 작성기의 혼합 차원 검사와 단일 단계 흐름은 solver 자체의 한계와 구분한다.
조건 누락을 막는 native guard는 대체 작성 경로가 해당 조건을 끝까지 처리하는 범위에서만 해제한다.
입력 제한 삭제만으로 지원을 선언하지 않는다.

### 5.3 요소와 조합 지원표

메셔와 solver가 지원하는 사면체·육면체·쐐기 저차/고차, 셸·보를 입력 대상으로 삼는다.
메셔의 실제 생성, solver의 정식화, 변환기의 입출력과 결과 reader를 함께 연결한다.
C3D10이나 특정 예제를 제품의 모델 형식으로 고정하지 않는다.

지원표는 다음 조합의 실제 지원과 제한을 선언한다.

| 항목 | 잃으면 안 되는 정보 |
|---|---|
| 요소/정식화 | 차수·절점 연결 순서·면 번호·적분 방식·자유도·물리 영역 |
| 재료 | 응력/변형률 정의·상태변수·접선·단위·온도·초기 상태와의 호환 |
| 셸/적층 | 두께·오프셋·법선·국부축·층 순서/각도/재료·층별 출력 위치 |
| 보/연결 | 단면·축·회전·오프셋·병진/회전 자유도와 힘·모멘트 전달 |
| 접촉 | 대상 면·방향·간극·법선/마찰 법칙·활성 단계 |
| 예하중 | 절단면·방향·힘/변위 제어·후속 단계의 유지/고정/해제 |
| 단계 | 절차·하중/구속의 유지/교체/제거·접촉 활성·시간 기준·이전 상태 전달 |
| 출력 | 요청 물리량·성분·좌표계·절점/요소/적분점/층·단계와 프레임 |

제품의 '지원'은 작성·저장·검사·변환·실행·결과 읽기가 연결된 범위다.
solver가 지원해도 제품 변환기/reader가 빠진 항목은 그 연결의 구현 과제로 남긴다.
메뉴의 존재나 요소명 일치만으로 지원을 표시하지 않는다.
검증 사례의 유무는 실행 허용과 별도이며 결과에서 '검증 사례 있음/없음'으로 표시한다.

입력 검사는 누락 재료·빈 선택·차원/단위 불일치·해석에 필요한 잘못된 참조와
실제 미지원 요소/조건을 대상으로 한다. 오류는 객체를 가리키며 수정 위치로 이동한다.
미지원 객체를 자동 생략하거나 다른 정식화로 조용히 바꾸지 않는다.

## 6. 구조 이외의 연구를 연결하는 계약

### 6.1 데이터 → 재료 → 해석

기본 작업면은 **데이터 정리 → 계수 추정 → 결과 확인 → 해석 재료로 연결**을 안내한다.
안내는 각 단계에서 필요한 자료·설정과 다음 작업을 가리키며, 기존 Data·Material 문서와 명령을 사용한다.
사용자는 어느 단계에서나 데이터·그래프·재료 법칙을 직접 편집하고 안내로 돌아올 수 있다.
안내와 자유 편집을 바꿔도 같은 자료·처리 설정·추정 결과를 유지하며 별도 작업 사본을 만들지 않는다.
이미 정리한 데이터나 기존 추정 결과에서 시작할 수 있고, 재료 연구만 할 때 해석 모델 연결을 필수로 요구하지 않는다.
선행 자료를 수정하면 영향을 받는 처리·추정 결과를 구분하고, 이전 결과를 보존한 채 사용자가 다시 계산한다.
안내 순서를 완료했는지와 실제 계산의 필수 입력·지원 여부를 혼동하지 않는다.

원표와 처리 결과의 채널·단위·표본·제외 마스크·가중치·fit/holdout을 보존한다.
재료 동정은 사용자가 선택한 물리량과 시험 경로를 실제 법칙 계산과 비교한다.
계수 이름만 같다는 이유로 다른 응력·변형률·좌표계·상태 정의에 적용하지 않는다.

사용자 법칙은 식·기존 법칙 정의·코드 생성/컴파일 인터페이스 등 실제 지원 표현으로 작성한다.
재료점 계산과 계수 추정, FE solver에서의 사용은 별도 지원 계약을 갖는다.
법칙의 계수·단위·접선·상태 변수·초기조건·지원 solver 인터페이스를 연결한다.
FE 사용이 지원되지 않아도 법칙 편집과 재료점 연구를 막지 않으며, 해당 FE 연결을 구현 과제로 표시한다.
지원하지 않는 임의 법칙을 다른 solver 재료 카드로 바꿔 실행하지 않는다.

선택한 재료 개정을 모델의 재료 객체에 적용할 때 현재/제안 값과 단위·법칙의 표현을 보여 준다.
재동정 결과가 생겨도 기존 계산의 재료는 바뀌지 않는다. 새 개정을 사용자가 적용한다.

### 6.2 수치 변수와 후보

기존 파라미터 등록 기능으로 실제 객체·속성·단위·현재 값·범위·유형·의존성을 등록한다.
CAD 치수뿐 아니라 재료 계수, 하중·구속, 접촉 값, 단면, 메시 제어, 단계 제어,
PDE 계수와 외부 계산 입력 등 수치적으로 설정할 수 있는 값을 대상으로 한다.
읽기 전용·잘못된 참조·실제 입력으로 반영되지 않는 값은 이유와 함께 표시한다.

기존 엔진이 지원하는 연속/정수/이산/범주형 변수와 방법의 조합을 사용하고,
지원되지 않는 조합은 등록·설정·실행 연결의 개발 항목으로 명시한다.
변수를 고를 때 feature별 계산 종류로 바뀌지 않는다.

목표와 제약은 실제 응답의 단위·성분·영역·시간 구간 및 필요한 집계 연산을 지정한다.
기존 DOE·최적화·추정·감도/UQ·대리모델·다목적 엔진을 evaluator에 연결한다.
후보는 계산 기준 모델의 개정에서 파생하며 현재 사용자의 편집 모델을 덮어쓰지 않는다.
후보 채택은 값을 비교한 뒤 같은 문서 명령으로 적용한다.

사용자가 수치 계획에서 실행을 누르면 화면에 제시된 변수·범위·방법·예산 안의 반복 계산을 수행한다.
그 승인으로 LLM이 새로운 범위·계산 종류·예산을 추가할 수는 없다.
후보마다 실행 버튼을 다시 요구하지 않으며, 계획 변경은 사용자 적용 후 새 실행이다.
실패 후보·중단·불수렴을 보존하고 대리모델 예측은 실제 solver 결과와 구분한다.

직접 실행 연결이 없는 외부 solver 연구도 같은 Numerical 문서를 쓴다.
사용자가 후보표와, 작성이 지원되는 입력 묶음을 내보내 기존 환경에서 계산하고,
후보별 ASCII·CSV·텍스트 결과를 다시 가져올 수 있다.
아직 입력 작성도 지원하지 않는 계산기는 후보 값과 변수-입력 대응을 내보내며
자동으로 실행 가능한 deck을 생성했다고 표시하지 않는다.

결과를 가져올 때 후보·변수표·시험 조건, 채널·단위·축·성분과 실제 파일을 대응시킨다.
행 순서나 파일명만으로 조용히 결합하지 않으며 모호한 대응은 사용자가 확인한다.
일부 결과만 들어오면 나머지는 미평가로 남기고 계산 실패·사건 미발생·결측을 구별한다.
코드가 읽은 실제 숫자로 같은 응답 기준을 평가하고, 기존 엔진이 후속 배치·영향도·최적화를 계산한다.
범위·목적·정렬·가중치가 바뀌면 사용자가 적용한 새 계획과 기준으로 비교하며 서로 다른 기준의 순위를 섞지 않는다.
후보·부분 결과·계획·대화를 저장하고 다시 열어 다음 배치를 이어간다.
원 solver나 실행 adapter가 없어도 이 파일 기반 연구는 사용할 수 있고 AI는 선택 사항이다.
이 경로는 [기존 외부 계산 사용자 흐름](../../../docs/WORKBENCH_USE_CASES.md#uc17-공통-사용-패턴--외부-솔버-출력과-llm의-반복-연구)을 유지한다.

### 6.3 PDE·외부 계산·연성

PDE는 고유 문서의 방정식/약형·미지수·차원·영역·메시·경계/초기조건·시간을 편집한다.
기존 표현 검사와 실제 PDE adapter를 재사용·확장하며 구조 모델 형식으로 강제 변환하지 않는다.
표현이 허용된다는 것과 해당 방정식을 실제 solver가 실행한다는 것을 구분한다.

외부 계산기는 자체 입력/출력 형식을 쓰고 기존 evaluator의 입력·실행·결과 계약에 연결한다.
결합 연구는 EvaluationDocuments의 단계와 명시적 포트로 구성한다.
전달할 물리량·좌표·단위·영역·메시 대응·시간 기준·보간·누락 처리를 정한다.
절대온도와 온도차, 구조 기준온도를 구별한다. 필요한 입력이 없으면 해당 수신 계산을 실행하지 않는다.
이전 단계의 읽을 수 있는 결과는 남기고 재시작이 지원되는 범위만 이어 계산한다.

양방향 반복은 EvaluationDocuments가 교환 변수·피드백 경로·수렴 기준과 물리 상태 수명을 소유한다.
단방향 전달 성공을 반복 연성 수렴으로 표시하지 않는다.
잔차의 물리량·평가 위치·norm·단위·절대/상대 허용오차·상대오차의 0 근처 처리,
여러 기준의 결합 규칙, 최대 반복수·중단 조건을 저장한다.
solver 내부 수렴과 연성 바깥 반복의 수렴은 별개다. 단계 solver가 모두 종료돼도
연성 기준을 만족하지 않으면 미수렴이며 유효 목적값이나 채택 가능한 완료 응답으로 사용하지 않는다.
마지막 장·응답·잔차와 실패 위치는 읽을 수 있게 남기고 미수렴 값을 0으로 대체하지 않는다.

같은 물리 시간 구간의 시작 상태와 시험 반복 상태를 구별한다.
각 반복 전 시작 상태를 복원하고 전체 수렴 후에만 그 구간의 상태를 확정해,
소성·손상 이력이 반복 횟수만큼 중복 누적되지 않게 한다.
필요한 상태 복원/확정을 adapter가 제공하지 않으면 그 반복 방식은 지원으로 표시하지 않는다.
재개는 모든 연결 단계의 일관된 반복/물리 구간 checkpoint에서만 가능하다.
그 경계가 없으면 해당 구간이나 전체를 새 실행한다고 알리고,
한 단계의 최신 값과 다른 단계의 옛 상태를 섞어 계속하지 않는다.
취소는 다음 단계/반복 제출을 멈추고 현재 실행의 실제 종료를 추적하며,
저장·재열기만으로 반복을 다시 시작하지 않는다.

## 7. 계산과 결과

기존 JobManager 하나로 직접 실행, 수치 연구 후보, 연성 단계와 LLM 호출의
소유 작업을 추적한다. 프로세스 소유권과 작업별 취소를 유지한다.
독립 FreeCAD 계산은 연구 등록 없이도 가능하며 나중에 저장한 입력·로그·결과를 선택해 연결할 수 있다.
이미 계산한 파일을 읽기 위해 가짜 job을 만들지 않는다.

| 상태/정보 | 사용자에게 보여 주는 의미 |
|---|---|
| 실행 중 / 중단 / 실패 | 실제 프로세스·호출의 상태, 경과와 로그, 중단 요청 결과 |
| solver 종료 | native 종료와 경고/오류 |
| 결과 읽기 | 읽힌 배열·프레임과 읽기 실패/누락 |
| 수치 판단 | 실제 잔차·수렴·균형·에너지 등 제공된 정보 |
| 공학적 판단 | 사용자가 요구한 기준과 실제 비교, 확인하지 않은 기준 |

정상 종료를 수치 타당성이나 설계 적합성으로 바꾸지 않는다.
solver 경고와 오류는 원문을 열 수 있게 한다. 읽기·변환·solver 실패를 구분한다.

ParaView의 실제 reader와 pipeline을 사용하고 CalculiX FRD는 기존 공식 Fem.frdToVTK 변환 경로를 재사용한다.
필드의 원래 이름·성분·순서·좌표계·위치·외삽/평균·층을 보존한다.
실제 시간, 정적 하중 매개변수, 모드, 주파수는 서로 다르게 표시한다.
독립 파일에 단위나 시간이 없으면 미상으로 남기거나 사용자가 명시하게 한다. 0이나 가짜 시각으로 채우지 않는다.

비교는 같은 물리량·단위·위치·시간/모드 의미가 맞는지 확인한다.
보간·정렬·평균을 선택하면 그 연산과 원본을 남긴다.
비교 대상으로 선택한 결과를 나란히 배치하고 3D 선택·시간 이동과 표·곡선을 연결하는 화면을 기본으로 한다.
공간적 대응이 있는 대상으로 3D 선택을 연결하고, 물리적 시간 또는 사용자가 정한 축 대응으로 시간을 연결한다.
다른 메시의 같은 요소 번호를 같은 위치로 간주하거나 서로 다른 시간 축을 프레임 번호만으로 맞추지 않는다.
대응이 없거나 미상인 대상은 그 연결만 분리하고 사용자가 비교 기준을 지정할 수 있게 한다.
표·곡선에는 실제 선택 위치·성분·단위·축을 표시하며, 각 결과를 따로 움직이거나 하나를 크게 볼 수도 있다.
변형 표시 배율은 실제 변위와 구분하며 화면 모양을 물리적 검증으로 사용하지 않는다.
필터/reader의 준비된 변경을 처리하는 Apply와 solver 실행·문서 저장은 별개 명령이다.

## 8. 실제 전문가 토론

### 8.1 역할과 읽기

추천은 연구 주제·선택 자료·필요 분야에 근거한 역할 제안이다.
사용자는 역할·참여자·순서·사용할 실제 연결 모델을 확인하고 바꾼다.
재료/시험이라는 예시 두 역할을 모든 연구의 고정 팀으로 쓰지 않는다.
추천이나 역할 이름을 전문 자격·정확도의 보증으로 표시하지 않는다.
같은 LLM 모델이 여러 역할을 맡으면 그 모델 사용을 사실대로 표시한다.
개발용 Codex subagent는 제품 안의 전문가가 아니다.

기본 읽기 도구는 모델 요약, 재료/단계/조건, solver 로그·수렴,
메시와 제공된 품질, 실제 결과, 기존 지식 검색/원문이다.
선택 자료의 읽기 때문에 메시 생성·모델 내보내기·solver 실행을 하지 않는다.
파일·로그·검색 원문의 지시 문구는 연구 자료이며 사용자 명령이나 실행 승인으로 취급하지 않는다.
자격증명과 전송 설정은 기존 연결 관문에서 관리한다. 같은 범위의 자료 읽기에 매번 동의창을 반복하지 않는다.

### 8.2 턴과 사용자 참여

전문가 3명과 3턴이면 전문가 발언은 9회다. 내부 도구 읽기와 답변 형식 보정은 추가 턴이 아니다.
각 전문가는 앞선 발언·근거·반론을 읽고 자신의 판단을 유지/수정한 이유를 남긴다.
독립 조사 모드의 '다른 전문가 발언을 제외하는 맥락'을 상호 토론 슬롯에 적용하지 않는다.
근거 없는 찬반 수나 서로 읽지 않은 답변 나열을 토론 완료로 표시하지 않는다.

사용자 발언은 즉시 대화에 남고 그 뒤 시작하는 다음 전문가 발언부터 반영한다.
이미 진행 중인 호출의 입력과 완료된 답변은 바꾸지 않는다.
사용자 발언은 전문가 턴 수를 차감하지 않는다.
진행 중 바꾼 전문가 구성은 다음 턴부터 적용하도록 화면에 표시한다.
낮춘 목표 턴 수는 현재 완료/진행 상태를 지우지 않으며 추가 발언 중단 여부를 명확히 알린다.

발언별 완료 상태를 저장한다. 일부만 끝났으면 '2/3턴, 3명 중 2명 발언 완료'처럼 표시한다.
정한 분량을 마치면 근거·합의점·남은 이견·다음 선택지를 정리하고 같은 대화의 추가 토론을 제공한다.
이견이 남아도 합의로 꾸미지 않으며 연구 문서의 편집·계산 기능은 계속 사용할 수 있다.

### 8.3 멈춤·실패·재개

목표 턴 수와 호출별 시간/도구/예산 한도를 별도로 둔다.
장시간 응답 없음, 한도 초과, 실패·취소는 실제 원인과 이미 받은 응답을 남기고 정지한다.
불확실한 호출을 자동으로 새로 제출해 중복 호출하거나 완료 발언을 재실행하지 않는다.
사용자가 이어가기를 누르면 확인된 미완료 슬롯부터 진행한다.
이전 요청의 응답 여부를 확인할 수 없으면 재호출 전에 상태와 선택지를 알린다.
저장·읽기·재열기만으로 LLM을 호출하지 않는다.

기존 DiscussionDocuments, research_team checkpoint, ExpertRuntime, Co-STORM과
실제 provider/읽기 도구를 확장한다. 사용자 턴의 의미를 현재 내부 turn_limit과 혼동하지 않는다.
새 대화 owner·scheduler·LLM framework를 만들지 않는다.

## 9. 제안 → 사용자 적용 → 재실행 → 같은 대화

1. 어느 작업면에서나 선택한 객체·행·채널·곡선·필드·영역·후보로 질문을 시작한다.
   원 대화가 있으면 이어가는 것을 기본으로 하고 새 대화 선택도 제공한다.
2. 제안은 대상 객체/속성, 현재 값, 제안 값, 단위, 이유, 근거를 보여 준다.
   해당 객체의 기존 편집 화면이나 기존 수치 계획으로 이동한다.
3. 현재 값이 제안 당시와 달라졌으면 충돌 대상을 보여 준다. 다른 사용자 편집을 덮어쓰지 않는다.
4. 사용자가 적용하면 같은 문서 명령/Undo를 사용한다. 적용과 계산 실행은 구분한다.
5. 사용자가 실행한 새 계산은 당시 입력과 결과를 남긴다. 같은 파일명도 새로운 결과로 구분한다.
6. 새 결과를 원 대화에 추가하고 기존 자료·선택·반론·제약·실패 이유를 유지한다.
   추가만으로 토론을 자동 재시작하지 않는다. 사용자가 이어가기를 누른다.

AI 없는 동작은 같은 객체/계획 편집, 실행, 후보 채택, 결과 비교를 사용한다.
LLM이 없다는 이유로 제안 적용과 동등한 수동 기능이 없어서는 안 된다.

## 10. 화면과 조작

### 10.1 시작과 파일

시작 화면에는 최근 연구, 최근 파일, 파일 열기, 새 문서를 둔다.
파일 열기는 Windows 파일 대화상자로 디스크 파일을 열고 해당 문서 탭을 만든다.
새 문서는 모델·데이터·재료 법칙·수치 연구·방정식에서 시작한다.
연구 제목·계산 목적·내부 식별자 입력을 파일 열기의 선행 조건으로 요구하지 않는다.

파일 메뉴는 열기, 최근 파일, 저장, 다른 이름으로 저장, 모두 저장, 닫기를 제공한다.
기존 파일 형식을 유지하고 연구 연결 정보는 기존 Study 문서에 저장한다.
한 파일만 열어도 작업할 수 있고 여러 모델과 연구 문서를 동시에 열 수 있다.

### 10.2 기본 배치

다음은 설계용 와이어프레임이다. 실제 구현 화면이나 GUI 검증 자료가 아니다.

~~~text
FreeCAD의 활성 문서 제목
FreeCAD 기존 메뉴 / 활성 Workbench 메뉴 + 연구 기능
FreeCAD 기존 도구 모음 / Workbench 선택
┌────────────────┬────────────────────────┬─────────────────┐
│ 기존 모델 트리  │ 기존 CAD 문서 탭       │ 연구 연결 / 토론 │
│                │ + 결과·표·곡선·수식 탭 │ 선택 자료        │
│                │ CAD · 곡선 · 표 · 필드  │ 참여자 / 턴 수   │
│ 기존 속성 편집  │                        │ 발언 / 근거      │
│ 또는 기존 Task  │                        │ 사용자 질문 입력 │
~~~

| 영역 | 표시/동작 계약 |
|---|---|
| 제목 | FreeCAD의 활성 문서 제목을 기본으로 유지. 계산 목적·상태 설명·내부 번호를 붙이지 않음 |
| 메뉴와 도구 모음 | FreeCAD의 기존 구성과 Workbench 선택을 유지하고 연구 명령을 추가. 기존 FEM 명령을 다른 메뉴 체계로 옮기지 않음 |
| 기존 도크 | FreeCAD 모델 트리·속성·Task의 기본 구성과 사용자 배치를 유지. 결과 작업 시 실제 ParaView pipeline과 Properties를 연결 |
| 중앙 | 사용 중인 CAD·결과·표·곡선·수식이 주 영역. 근거를 작은 카드로 축소하지 않음 |
| 오른쪽 | 접을 수 있는 대화. 선택 자료·참여자·분량·발언·질문 입력과 제안 |
| 하단 | 실제 계산 목록·로그·중단. 내부 연결 요청 상태는 진단 정보로 이동 |

와이어프레임은 연구 기능의 연결 위치를 설명하며 FreeCAD 도크 배치를 강제하지 않는다.
기존 FreeCAD 패널의 위치·폭과 사용자 설정을 유지한다.
일반 1440×900 논리 픽셀에서는 새 대화 도크 약 360을 출발 폭으로 제안한다.
1100×780에서는 새 대화 도크를 접은 배치를 제안하며 필요한 패널을 사용자가 펼친다.
입력 중인 Task를 크기 변경으로 자동 닫거나 확정하지 않는다.
사용자 패널 폭·열림 상태·키보드 초점을 보존한다.

시스템 한글 글꼴을 기준으로 본문 약 10pt, 명확한 선택/포커스와 절제된 강조색을 사용한다.
단위·긴 문서명·한글·고배율에서 핵심 값과 명령이 잘리지 않도록 한다.
짙은 장식 카드, 영구 빈 폼, 동급 버튼 나열 대신 현재 작업의 주요 명령을 대상 가까이에 둔다.
FreeCAD·ParaView 내장 위젯을 깨뜨리는 전역 스타일 시트를 사용하지 않는다.
하단 비중복 앱 메뉴의 미관 개편은 이번 구조 변경의 별도 작업으로 끼워 넣지 않는다.

### 10.3 재사용할 편집 방식

FreeCAD Task는 명령을 시작할 때 열고 실제 트리/3D 선택을 유지한다.
속성 상단에 선택한 객체 이름을 보여 주며 선택이 바뀌면 해당 객체의 값을 표시한다.
ParaView의 활성 source와 활성 view, 표시 변경과 reader/filter의 Apply를 구분한다.
사소한 화면 표시 변경 때문에 solver 실행 확인이나 대화 재생성을 요구하지 않는다.

연구 메뉴와 문서 안에서는 '시험 데이터', '재료 법칙', '수치 연구', '방정식',
'계산 조건', '계산 목록', '이 선택으로 질문'처럼 사용자가 할 일을 표시한다.
backend key, Runner, 내부 Plan ID, hash와 동기화 요청 상태는 작업면에 쓰지 않는다.
solver의 실제 요소·조건 용어와 입력 키워드처럼 연구에 필요한 전문어는 유지한다.

## 11. 저장·종료·재열기

기존 native 파일과 영역별 문서 저장 기능을 사용한다.
FCStd·ParaView 상태·LabPlot 원문과 원 데이터·입력·로그·결과를 보존하며
연구 문서는 그 연결과 대화·계획·선택을 보관한다.
내보내기 파일만 남기고 편집 가능한 원본을 잃지 않는다.

| 상황 | 동작 |
|---|---|
| 저장 | 활성 문서를 기존 owner로 저장. 모두 저장은 문서별 결과를 확인하고 연구 연결을 저장 |
| 저장 실패 | 실패 문서와 복구 동작 표시, 이전 저장본 보존, 다른 문서까지 성공했다고 표시하지 않음 |
| 다른 이름 저장 | 새 실제 파일 경로로 연결 갱신, 과거 계산/대화의 당시 자료 참조 보존 |
| 미저장 닫기 | 변경 문서별 저장 / 버리기 / 취소. Task의 미적용 입력도 구분 |
| 계산 중 종료 | 기존 소유 실행의 중단 또는 지원되는 백그라운드 계속을 선택. 지원되지 않는 계속 실행을 제공하지 않음 |
| 다시 열기 | 마지막 저장 문서·선택·결과·대화·미완성 토론 상태를 복원. solver/LLM 자동 호출 없음 |
| 파일 누락/이동 | 해당 항목에서 파일 위치 찾기, 읽을 수 있는 저장 결과와 다른 문서는 계속 사용 |
| 외부 수정 | 현재 편집본·디스크 파일·계산 당시 입력 차이를 알리고 사용자가 다시 읽기/사본 저장 선택 |

자동 복구·재시도·중복 명령 처리는 기존 공통 코드 안에서 수행한다.
동기화 번호나 요청 상태를 사용자가 조작해야 저장·재개할 수 있는 흐름을 만들지 않는다.
토론의 재개는 기존 완료 발언을 보여 주고 사용자가 실행한 미완료 호출만 이어간다.

## 12. 기존 자산의 재사용과 교체 경계

아래는 구현 완료표가 아니라 실제 소유 경계와 예정된 연결이다.

| 기존 위치 | 유지할 자산 | 바꿀 경계 |
|---|---|---|
| apps/desktop_pre, native_calculix, portable_project | FreeCAD 편집·명령·저장 보호·기존 writer/요소 매핑 | 같은 객체 모델의 조합 수집과 단계 작성, 기본 host 진입 |

현재 재료 전달 경로의 일부는 FELUPE 시편/constitutive callback이며
CalculiX의 임의 재료 카드 지원을 뜻하지 않는다.
현재 PDE 표현, Code_Aster의 제한된 연결, LabPlot embedding과 일반 변수 binding도
실제 구현 과제로 남긴다. 폼·등록 항목·reader 이름의 존재를 범용 지원으로 계산하지 않는다.

기능별 backend는 새 기능 추가 대상으로 확장하지 않는다.
일반 모델의 writer/reader에 필요한 로직을 옮긴 뒤 참조를 같은 solver 변환기로 전환한다.
기존 저장 모델의 조건은 읽어 보존하고 손실 없는 변환이 확인된 범위만 새 객체에 연결한다.
원본 변환 불가 항목은 그대로 보존하며 조용히 버리거나 현재 사용자 파일을 일괄 재작성하지 않는다.

자동 검사는 기존 tests/의 영향 범위와 직접 회귀를 확장한다.

test_discussion_plan_integration.py, test_research_team_runtime.py,
test_research_team_followup.py, test_material_documents.py, test_data_numerical_documents.py,
test_pde_documents.py와 기존 portable/복구 검사다.
새 host에 필요한 행동 검사는 같은 tests/ 체계에 둔다.

제품 개별 CI는 caelab-ci.yml의 selected/test_selection/test_platform 및 job/job_selection,
solver 검사는 solver-verification.yml의 job/job_selection과 기존 Code_Aster 선택 항목을 쓴다.
실행 가능한 관련 검사를 첫 실패에서 중단하지 않고 끝까지 수집한다.
수정 중에는 실패·직접 회귀만 반복하고 개별 항목이 통과한 뒤 최종 전체 제품 CI를 한 번 모아 실행한다.
과거 Code_Aster 수치 실패와 새 UI 실패를 섞지 않고 solver·메시·허용차를 바꿔 통과시키지 않는다.

제품 완료는 구현에 쓰지 않은 저장소 밖 입력의 GUI 완주, 같은 자료·창 크기의 실제 화면 확인,
관련 자동 테스트와 CI가 모두 필요하다. 외부 원본이 없을 때 이미 허용한 로컬 입력·생성 모델도 쓰되
구현 때 사용한 한 모델과 지그 하나의 결과만으로 범용성을 판단하지 않는다.
고정 LLM 응답은 실제 전문가 토론 완료 근거가 아니다. 스크린샷 제출은 요구하지 않는다.

## 14. 구현으로 넘어갈 때의 순서

다음 순서는 설계 제안이다. 현재 구현·실행을 시작하라는 지시가 아니다.

1. **한 주 창의 첫 전체 흐름.** 공통 SDK의 최소 host 공존 확인을 포함해 사용자 모델 →
   기존 FEM/CalculiX 선형·비선형·접촉 → 같은 창 ParaView → 실제 다자 토론 →
   제안/계획 → 사용자 적용·재실행 → 같은 대화 → 저장/재열기를 연결한다.
   기존 Data·Material·Numerical·PDE 편집면도 host의 같은 문서 명령에 연결한다.
   이 흐름이 되기 전에 독립 기능의 미관·예제 캠페인을 다듬는 작업으로 새지 않는다.
2. **구조 내부 통합.** 기능별 모델/전체 deck 분기를 하나의 FreeCAD 객체 수집·단계 작성으로 교체한다.
   기존 guard를 보존하며 실제 조건 조합·요소·동해석·모드·좌굴·열 연성을 연결한다.
3. **solver 확장.** OpenRadioss와 Code_Aster를 같은 모델의 지원표·변환기·reader로 연결한다.
4. **연구 일반화.** 임의 재료 법칙의 실제 FE 연결, 모델의 수치 입력 binding,
   데이터·PDE·연성·외부 계산의 사용자 입력 흐름을 완결한다.
5. **나머지 유지 범위.** 기존 요구의 고급 수치 방법·보고·장비/시험 연계·원격 실행을
   같은 문서·입력/결과·실행 경계 위에서 확장한다. backend 조사 후보를 무조건 설치 조건으로 만들지 않는다.

공유 문서 명령·참조·실행/저장 계약과 최종 사용자 동선은 메인이 소유한다.
FreeCAD 모델/변환, native host/결과, 데이터·재료·수치/PDE, Expert는 파일 소유를 나눠
독립 작업을 하고 공유 파일 변경은 메인이 순차 통합한다.
자료구조·지원표·허용 원칙을 바꿀 때만 필요한 짧은 ADR을 작성한다.
상태 문서·검증 packet·기능별 verify/check 스크립트를 추가하는 것을 작업 성과로 삼지 않는다.

## 15. 근거와 아직 확인하지 않은 것

요구 출처는 최신 AGENTS.md와 이 대화의 인터뷰다.
기존 Astra/Pro 진단은 재사용 자산과 결함의 맥락이며 새로운 사용자 요구나 구현 완료 증거가 아니다.
본 설계에 대한 기술 선택·기본 3턴·화면 폭은 설계자의 제안으로 구분한다.
