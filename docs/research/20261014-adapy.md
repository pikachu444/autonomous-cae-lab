# ada-py 재사용 검토

확인일: 2026-10-14. 제품 요구 매핑은 조사 시점 제품 `main` commit `9c0e8090d987f2178116b04cc71b1d6aab75a0f7`의 [implementation map](../design/20261012-desktop-planning/pro-ux/implementation_map.csv) 기준이다. 공개 upstream 기준은 ada-py `v0.116.0`, commit [`2e6638b3736974ba725dcf5a2c567252fd734441`](https://github.com/Krande/adapy/commit/2e6638b3736974ba725dcf5a2c567252fd734441)이다. 로컬에 공개 저장소를 shallow clone해 소스·테스트를 읽었으며 설치, 서버 실행, solver 실행은 하지 않았다. 결론은 **제품 의존성으로 도입하지 않고, 파일 카드 지원 범위를 참고한 뒤 필요가 남는 solver adapter만 별도 평가**하는 것이다.

## Windows 설치와 통합 비용

PyPI 패키지는 `ada-py`이고 CLI 이름은 `ada`다. 프로젝트 메타데이터는 Python `>=3.10`, GPL-3.0-or-later로 표시하지만 `Requires-Dist` 의존성은 비어 있다. 따라서 `pip install ada-py`만으로 기능 의존성이 설치된다고 볼 수 없다. upstream은 Pixi/conda 환경을 권하며, 그 환경에는 IfcOpenShell, Gmsh, NumPy, trimesh 등 CAD/mesh 종속성과 별도 solver 패키지가 들어간다. upstream `pixi.toml`은 `win-64`를 선언하고 일반 제품 환경의 Windows Python을 `3.12.13`으로 고정한다. upstream PR workflow에는 Windows FEM job이 있고 CalculiX와 Code_Aster를 실행하며 관련 reader까지 확인한다고 설명한다. 이는 해당 upstream 환경의 Windows 검증 근거이지, 현재 제품 Python에 무충돌로 import할 수 있다는 증거가 아니다. 특히 제품은 FreeCAD와 ParaView native 프로세스를 분리하므로 ada-py를 앱 공용 Python에 넣을 이유가 없다. [PyPI 메타데이터](https://pypi.org/pypi/ada-py/json), [pyproject.toml](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/pyproject.toml), [Pixi 환경](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/pixi.toml), [Windows FEM CI](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/.github/workflows/pr-tests.yml).

라이선스 메타데이터는 GPL-3.0-or-later다. 현재 제품 저장소에는 루트 `LICENSE`가 없으므로, GPL 코드 의존·포함 또는 배포가 제품 배포 정책과 맞는지 확정하기 전에는 도입하지 않는다. 이것은 법률 판단이 아니라 도입 전 배포 정책 검토 조건이다. Solver도 각각 별도 실행물·조건이다. Code_Aster는 GPL로 배포되고, CalculiX 소스는 GPL 계열이며, Abaqus는 SIMULIA 라이선스 서버 구성을 요구한다. 무료 solver를 쓸 수 있다는 사실이 ada-py 의존이나 전체 사용 경로를 무비용으로 만들어 주지는 않는다. [ada-py LICENSE](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/LICENSE), [Code_Aster 라이선스](https://code-aster.org/en/product/main), [CalculiX 라이선스 소스](https://github.com/GeneralElectric/CalculiX/blob/master/LICENSE), [Abaqus 라이선스 설정](https://docs.software.vt.edu/abaqusv2025/English/EstiInstallMap/esti-m-licensing-sb.htm).

## 지원하는 파일 카드 범위와 경계

upstream의 CLI 설명 및 `FEATypes` registry 기준으로 FEM 입력 reader는 Abaqus, Sesam, Code_Aster다. CalculiX 전용 reader는 registry에 없다. Abaqus와 CalculiX의 `.inp` 확장자가 겹쳐도 별도 CalculiX reader의 근거가 되지 않는다. FEM writer/runner/result reader는 Abaqus, CalculiX, Code_Aster, Sesam 및 OpenCourant 일부 경로를 가진다. 기본 API는 `Assembly.to_fem(..., execute=False)`로 deck 쓰기와 실행을 분리하고, `from_fem`/`postprocess`로 해당 소스에 정의된 입력·결과 경로를 연다. 변환 중 빠진 카드, 근사, 의심 입력을 모으는 conversion report도 구현돼 있다. 실제 재사용을 주장하려면 report에 기록된 결과를 검사해 생략된 모델을 정상 지원처럼 취급하지 않아야 한다. [README의 변환 범위](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/README.md), [FEM registry](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/src/ada/fem/formats/general.py), [Assembly FEM API](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/src/ada/api/assembly.py), [conversion report](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/src/ada/fem/formats/conversion_report.py).

|---|---|---|
| FN-12-01/02 region·material·BC 편집 | FE 레코드, set/section/load, 일부 solver writer의 카드 구현을 조사할 참고가 된다. | FreeCAD의 실제 face/element 선택, geometry revision, draft 편집·저장·preflight는 ada-py가 제공하지 않는다. 직접 완료를 줄이지 않는다. 도메인별 exporter를 선택하는 작은 spike 후보만 남는다. |

upstream 자체 테스트는 beam/shell, 선형·일부 기하 비선형 static, CalculiX와 Code_Aster 결과를 다루며, FEM CI는 Linux와 Windows에서 해당 free solver를 실행하도록 구성돼 있다. 이는 제한된 독립 사례에 대한 유용한 검증 자료다. 전체 Abaqus/Code_Aster/CalculiX 입력 호환이나 우리 제품의 selection→run→Post→재열기 통합을 보증하지 않는다. 손실 없는 왕복이라고 일반화할 수 없다. 예를 들어 현재 열린 upstream 이슈는 Abaqus shell surface의 `SNEG` 쓰기 문제(#412)와 beam flush alignment 유실(#419)을 기록한다. [테스트 workflow](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/.github/workflows/pr-tests.yml), [solver reference tests](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/tests/fem/test_calculix_code_aster_solve.py), [이슈 #412](https://github.com/Krande/adapy/issues/412), [이슈 #419](https://github.com/Krande/adapy/issues/419).

## 제품의 권장 경계

writer/reader 재사용의 직접 대상은 FN-15-02의 solver 연결이다. FN-15-01의 단계 편집
화면에는 필요한 입력 항목을 확인하는 간접 참고이며, ada-py가 그 UI를 제공하지는 않는다.

이번 조사만으로 기존 기능의 완료 판정은 바꾸지 않는다. 개발을 줄일 후보는 빔·셸의 section/set/load를 solver 카드로 쓰는 부분, 접촉 상호작용 카드, 변환 중 생략한 항목을 알려 주는 conversion report다. 이를 기존 exporter와 비교하면 중복 작성할 카드 처리와 지원 범위 조사량을 줄일 수 있다. 구체적인 절감량은 선택한 모델과 카드의 적합성을 확인한 뒤 판단한다. **FN-12-02, FN-14-02, FN-15-01/02**의 제한된 adapter 후보이며, **FN-16-01**은 현재 Windows 경로보다 우선할 이유가 약하다. FreeCAD 선택·편집과 **FN-27/28**의 ParaView 저장·결과 비교는 별도로 완성해야 한다. 다음 개발에서도 Pro의 제품 구현 책임과 현재 Windows OpenCourant/CalculiX 경로를 유지한다.

제품 쪽 경계는 현재 `apps/desktop_pre/freeze_analysis.py::freeze_analysis`의 native CalculiX snapshot, `caelab/simulation_document.py::SimulationDocuments`, `caelab/workbench.py`의 `JobManager`/`_execute`, `apps/desktop_post/bridge.py::Owner`가 소유한다. 기존 Windows OpenCourant 실행 경로도 제품이 소유한다. 향후 한 기능을 시험한다면 별도 환경의 선택형 worker에서만 ada-py를 부르고, 입력은 제품이 저장한 revision 고정 FreeCAD/FEM snapshot, deck은 기존 JobManager run directory와 provenance에 귀속, 실행 capability는 제품 registry가 결정, 결과는 제품 artifact/evidence를 거쳐 ParaView에 넘기는 경계가 적절하다. FreeCAD selection/조건 editor, 공용 Core schema, JobManager identity, Post native project를 ada-py 결과 object로 바꾸지 않는다. 첫 적합성 시험은 작은 shell/beam 모델 하나를 골라 원 모델 참조, exported cards/conversion report, solver 결과, path-with-spaces 동작, 실패 뒤 재열기까지 비교해야 한다. README는 Windows에서 solver executable path에 공백이 있으면 short path를 쓰라고 안내하므로 사용자 작업 폴더가 공백을 포함한 경우도 별도로 확인해야 한다. [Windows 실행 안내](https://github.com/Krande/adapy/blob/2e6638b3736974ba725dcf5a2c567252fd734441/README.md).
