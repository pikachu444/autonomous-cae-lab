# 보존한 처리 결과를 피팅 계획에 추가

Data의 저장된 처리 결과에서 응력 채널을 선택한 뒤 **피팅 계획으로…**를 누른다. 이름과 시험·변수 수를 보고 기존 피팅 계획을 열거나 **새 계획…**에서 피팅할 재료를 명시적으로 선택한다. 미리보기에는 이 연결 버튼이 없으며 보존한 응력 결과에서만 활성화된다.

Data는 Numerical의 공개 `can_stage_processed_trial()`, `processed_trial_stage_pending()`과 `stage_processed_trial(source, result)`를 사용한다. 같은 Plan 소유자의 읽기가 끝난 뒤 원본 입력 네 항목, 처리 차수, 선택 응답과 전체 보존 결과를 복사해서 한 번 전달한다. 기존 시험 조건 창에서 관측·측정 변형·조건·용도·가중치를 확인하면 로컬 시험 초안에 추가된다. 원자료의 제외 구간은 곡선에서도 연결하지 않는다. 보존한 계보가 커서 읽기가 오래 걸려도 별도 15초 타이머가 정상 요청을 실패로 바꾸지 않는다. 창이 닫히거나 소유자 읽기가 실패하면 연결을 끝내며 기존 오류를 보존한다.

계획 적용, 표본 정책 채택, 저장과 피팅 실행은 각각 해당 창의 명시적 동작이다. 이 연결은 그 동작을 대신 수행하지 않는다. 새 계획 생성만 사용자의 명시적 재료 선택 후 기존 `document.open`을 호출한다. 취소, 닫힌 창, 다른 Plan으로 바뀐 창은 원래 Data 결과를 변경하지 않는다.

검증은 GUI 대역의 호출·선택 계약과 실제 HTTP 서비스의 보존 결과/Plan을 구별한다. Windows 실제 Qt에서는 실제 owner가 보존한 처리 결과를 복제한 검사 store로 열어 결과→Plan 선택→실제 시험 조건 검토→로컬 시험 추가를 확인했다. 정상/좁은 창의 한글·선택·미확정 `1e` 입력을 읽었고 기존 표본 정책, 원 Data/Plan 초안과 실행 이력은 바뀌지 않았다. 검사 프로세스는 종료했다. 이 결과는 C2 canonical 피팅 소비·표본 정책 채택·저장/재열기 전체 인도를 증명하지 않는다.

의존성은 Numerical의 공개 처리 시험 GUI API이며 해당 API가 없으면 소유자 생성 전에 연결을 안내하고 중단한다. C01 원문 복구나 닫기 보호를 우회하지 않는다.

`ExperimentDialog(..., selected_result_reader=None)`는 기존 호출과 호환된다. 선택 읽기를 제공한 호스트에서는 **선택 채널 확인**을 누르면 관측과 측정 변형 채널 이름만 작업 스레드의 readonly callback에 한 번 전달한다. 실제 Core가 반환한 정확한 응답 집합과 `SUCCEEDED` 결과로 기존 `measured_protocol` 검증을 수행한다. 원래 전체 처리 상태와 원문 입력은 변경하지 않는다. 읽기 실패는 입력을 그대로 편집할 수 있게 하며 취소 후 늦은 성공은 수락되지 않는다. 호스트는 정확한 원본/처리 차수와 Plan 세대를 별도로 검증한다.

2026-10-15 후속의 대역 기반 Qt 13개 검사는 선택 읽기 성공·실패·취소, 원문 보존, 미완성 결과 거절, owner read 대기·종료 및 기존 직접 입력 경로를 확인했다. 현재 root의 141표본/14 MB 계보를 사용한 실제 HTTP 검사는 처리 창 두 크기만 캡처한 뒤 Plan background read 대기에서 막혔다. 위 교정과 Numerical 후속을 합친 실제 HTTP/Qt 정책 동선은 별도 확인 전이며 이 13개 검사로 대체하지 않는다.
