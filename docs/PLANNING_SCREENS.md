# 프로그램별 화면·조작 명세

2026-10-08. `PLANNING_DESIGN.md`의 전체 구성과 `PLANNING_CONTRACTS.md`의 파일/버전 경계를 화면 명령으로 내린다. `prototypes/desktop-lab/`은 Windows용 Qt Widgets 네이티브 시안이다. 전처리·실행기·후처리·최적화·전문가·Workbench를 별도 프로세스로 시작하고 각각 파일 문서를 다룬다. 전체 제품 구현이나 최신 화면 조작 검증을 완료했다는 뜻은 아니다. 이전 `prototypes/design-lab/` 웹 시안은 사용자가 거부한 설계의 기록으로만 남긴다.

아래 명령·상태 표는 **제품 목표 명세**다. 현재 시안은 한 창 한 문서, 기본 1480×940와 작은 창 1100×760, 파일/편집/보기 및 앱별 메뉴, 두 도구막대, Ctrl+K 명령 검색, 네이티브 파일 대화상자, 저장·과거 버전·다른 이름 저장·Undo/Redo를 구현했다. 최근 파일 시작 화면, OS 파일 연결, 창 안의 다중 문서 탭, 임의 backend의 계산/시각화, 실행 지속 서비스는 아직 없다. 저장 충돌은 로컬 예외를 대화상자로 표시하며 HTTP 409는 선택적 API 계약이다. 도구막대가 좁으면 Qt 확장 메뉴를 사용한다. 최신 6개 앱의 실제 조작 및 크기별 화면 검수는 검은 캡처 문제로 대기 중이며 사용자 수용도 미확인이다.

## 공통 창과 문서 수명

각 프로그램은 Windows 시작 항목을 갖고 직접 시작한다. 시작 화면에는 해당 프로그램의 최근 문서, 새 문서, 열기, 지원하는 외부 파일 가져오기가 있다. 다른 프로그램이나 Workbench의 실행을 요구하지 않는다. 문서는 앱 창의 상단 탭에 열린다. 메뉴/도구막대/왼쪽 객체 트리/중앙 작업 대상/오른쪽 속성/하단 진단·로그/상태막대가 기본이다. 중앙은 메뉴 이동 때 교체되는 긴 양식이 아니라 작업 문서의 대상이다. 뷰어가 없는 대상에는 3D 장식을 표시하지 않는다.

기본 1440×900에서 객체 20%, 중앙 58%, 속성 22%, 하단 140 px다. 좌우 패널 크기를 조절하고 접을 수 있다. 1100×760에서는 도구막대가 가로 스크롤되고 중앙 폭을 우선 보존한다. 전문가 채팅 입력은 화면 하단에 고정하고 타임라인 내부만 스크롤한다. 높은 수치 밀도를 위해 변수/응답 표에는 단위와 유효숫자를 열 제목에 표시한다. 선택은 색과 윤곽 및 텍스트 상태를 함께 써서 드러내며 오류는 항목 ID와 수정 위치를 표시한다. 키보드는 Ctrl+O 열기, Ctrl+S 저장, Ctrl+Z 미저장 편집 취소, Esc 대화상자 닫기, 화살표로 트리 이동, Enter로 선택/열기, Delete로 삭제 확인을 기본으로 한다. 기능별 숨은 단축키는 두지 않는다.

모든 편집은 문서의 ID와 revision에 속한다. 선택·프레임·카메라·패널 배치는 문서의 `view_state`에 저장하지만 계산 입력 fingerprint에서는 제외한다. 저장 요청의 기대 revision과 디스크 revision이 다르면 409와 최신 revision/변경 시각/비교 버튼을 보여주고 현재 편집을 보존한다. 최신 읽기, 별도 사본 저장, 수동 재적용 중 선택한다. 과거 revision은 읽기전용이며 복제 후 편집한다. 닫을 때 dirty면 저장 후 닫기/버리기/계속 편집을 제공한다. 앱 창을 닫는 것이 실행 취소는 아니다.

| 상태 | 공통 표현과 복구 |
|---|---|
| 빈 상태 | 최근 파일과 `새 문서`/`파일 열기`만 보인다. 중앙에 빈 3D나 거짓 결과를 만들지 않는다. |
| 로딩 | 대상 이름/파일 크기/진행, 취소 가능한 단계와 불가능한 단계를 나눠 표시한다. 원본은 읽는 동안 수정하지 않는다. |
| 편집 중 | 제목의 변경 표식과 상태막대의 dirty, 취소 스택을 보인다. 선택은 트리·중앙·속성에서 같은 ID다. |
| 검증 오류 | 명령을 막은 필드/대상 ID와 단위·허용 범위를 하단 진단에 표시한다. 클릭하면 해당 대상으로 이동한다. |
| 저장 완료 | 실제 파일 경로의 문서 ID, 새 revision, 시각을 표시한다. 성공 응답 전에는 저장됐다고 말하지 않는다. |
| 외부 파일 변경/409 | 원본 해시 또는 문서 revision 차이를 표시한다. 자동 덮어쓰기 없이 기존 스냅샷을 열거나 새 파일을 가져온다. |
| 서비스 연결 끊김 | 현재 편집과 실행 ID를 유지하고 재연결/재조회한다. 네트워크 실패를 실행 실패로 바꾸지 않는다. |
| 중단 후 재개 | 문서·뷰 상태·이력을 다시 읽는다. 실행의 checkpoint 여부를 따로 검사해 가능한 경우만 재개한다. |

## 전처리

주 화면은 **곡선/구간**, **모델·메시/영역**, **재료점 이력**, **PDE 식·약형식**이다. CSV/ASCII 매핑, 메시 가져오기, 재료·조건 속성, 품질/입력 진단, Case 내보내기가 보조 화면이다. CAD 없이 데이터 곡선 또는 식에서 곧바로 시작한다. 트리는 데이터셋→채널→점/구간, geometry→mesh→named set→face/node, material, condition, validation으로 구성된다. 중앙의 선택 가능한 점·범위·면은 트리와 한 ID를 사용한다. 오른쪽 속성은 수치·단위·대상 매핑을 편집한다. 메뉴는 파일/편집/선택/재료/조건/검증/보기. 입력은 원본 파일과 조건, 출력은 검증한 Case revision과 원본 참조이며 `.caeprep`이 편집 단위다.

| 명령 | 전제와 조작 | 화면·데이터 변화 | 취소·실패·재시도 |
|---|---|---|---|
| CSV/ASCII 가져오기 | 직접 실행→파일 선택→구분자/헤더/축·응답 열/단위 미리보기 | 원본 해시·매핑 보존, 중앙에 곡선, 트리에 데이터셋/채널/점 생성 | 행 번호별 비숫자·역전 시간·중복 진단. 오류 시 기존 문서 유지, 매핑 수정 후 재시도 |
| OBJ/mesh 가져오기 | 형식·좌표계·단위 확인 후 열기 | 실제 정점/면 ID와 named set 후보를 트리/중앙에 표시 | 지원 안 되는 요소는 부분 지원 경고. 원본 보존, 다른 reader 선택 가능 |
| 구간 만들기 | 곡선의 시작/끝 점 또는 X 범위 선택→`구간` | 음영 범위와 트리 구간 노드 생성, 속성에 가중치/유효범위 | 역전/빈 범위 거부. Undo로 생성 취소, 수정 후 재검증 |
| 재료·조건 배정 | 면/구간 선택→트리·중앙 강조→`조건 배정`→값·단위·대상 확인 | 조건 노드와 대상 표시가 동시 갱신. 저장 후 재열기 때 선택/배정 복원 | 존재하지 않는 대상/차원 불일치/필수값 누락 거부. 적용 전 취소, 적용 후 Undo |
| 검증·Case 만들기 | 재료·조건·단위·필수 set 검사→`Case 고정` | 오류 0이면 Case ID/revision·입력 지문 생성, 실행기에서 정확한 버전 열기 | 오류 클릭으로 대상 복귀. 미저장 편집은 저장을 먼저 요구; 재검증은 새 revision |

네이티브 시안은 CSV 곡선의 점·축 단위 편집과 구간 생성, 12×6 검토용 판 메시의 72면·세 명명 영역, OBJ 정점·면의 2D 투영, 면·영역 선택과 재료·조건 배정, 재료점 이력 및 PDE 식·약형식 입력을 제공한다. 메시·PDE 값은 문서에 저장하고 검증하지만 실제 3D 구조/PDE 풀이에 전달하는 reader·solver 연결은 후속 작업이다. 실험 데이터 작업은 그 전에 사용 가능해야 한다.

CSV/ASCII 매핑 대화상자는 구분자·헤더·X/응답 열·물리량·단위를 확인해 선택 열만 읽는다. 차원 변환이나 임의 solver field reader는 아직 없다. 최적화에서 전달한 후보는 별도 트리 항목과 속성 표에 변수값·단위·출처를 표시한다. 기본 판/곡선은 시연 예제로 구분하며 후보값을 실제 모델에 적용한 것으로 보이지 않도록 명시한다.

## 솔버 실행기

주 화면은 **케이스/큐/이력과 선택 실행의 로그·수렴**이다. backend 환경·자원, 입력 검토, 실패 상세, 부분 결과 목록이 보조 화면이다. 트리는 Case→revision→queued/running/history Run→Result/원본 로그다. Run 선택 시 중앙의 수렴, 오른쪽의 입력 revision·backend·종료 원인, 하단의 해당 로그가 함께 바뀐다. 메뉴는 파일/케이스/실행/중단/결과/보기. 입력은 고정 Case revision, 출력은 Run과 Result manifest다. `.caerun`이 실행 묶음이며 실제 결과는 Run 소유 디렉터리에 남는다.

| 명령 | 전제와 조작 | 화면·데이터 변화 | 취소·실패·재시도 |
|---|---|---|---|
| 케이스 연결 | 독립 실행 또는 Workbench 링크→저장 Case ID/revision 선택 | 원본 변경 여부와 backend 호환 진단 표시. 선택된 정확한 revision 고정 | 파일/버전 없음이면 원본 찾기. 최신으로 묵시 교체하지 않음 |
| 입력 검증 | `검증`→필수 조건·단위·backend 실행 준비·자원 검사 | 하단 오류에서 조건 객체로 이동; 통과 시 제출 가능 | backend만 없으면 그 실행만 비활성. 결과 조회·다른 케이스는 계속 가능 |
| 실행 제출 | 검증된 revision→자원/실행기 확인→`실행` | idempotency key로 단일 Run 생성; validating→queued→running, 실시간 로그·수렴 | 중복 클릭은 같은 제출. 전송 실패는 job ID 재조회; 무확인 재제출 금지 |
| 중단 | queued/running Run 선택→`중단` | cancel_requested 표시, 프로세스 확인 후 cancelled terminal state | 완료와 경합하면 실제 완료 상태 유지. 불명확하면 unknown/재조회, 즉시 cancelled 표시 금지 |
| 실패 분석/재실행 | 실패 Run 선택→원인·partial 파일 보기→Case 수정 또는 같은 입력 재시도 | 과거 Run 보존하고 새 Run ID 생성, 이전/새 로그 나란히 비교 | checkpoint 지원 시만 이어가기, 미지원은 새 실행. 실패 원본/부분 출력 삭제 금지 |
| 결과 열기 | succeeded/partial Run의 응답 선택→`후처리에서 열기` | Result manifest와 Run 입력 revision을 전달 | 누락 채널은 가능한 채널 제시. 실패 로그는 후처리 없이도 열림 |

네이티브 시안의 큐·수렴·완료 결과는 **시연**이다. 실행·중단·재시도의 상태 조작을 검토하기 위한 값이며, 실제 계산을 호출했다는 표시는 backend 서비스가 원본 명령과 결과 파일을 반환할 때만 쓴다.

## 후처리

주 화면은 **필드 또는 곡선**, **나란히/겹침 비교**이며 외부 ASCII 매핑, component/location/frame, 범례/단위, probe/추출, 보고서 미리보기는 보조 화면이다. 트리는 Result→field/component/frame, channel/probe, derived, comparison이다. 중앙 필드 셀/노드 선택 또는 곡선 점 선택이 트리·속성과 일치한다. 프레임 변경은 같은 위치를 유지하고 값/범례를 갱신한다. 메뉴는 파일/선택/표시/비교/분석/내보내기. `.caepost`는 원 Result를 읽기전용 참조하고 표시·probe·파생 분석을 저장한다.

| 명령 | 전제와 조작 | 화면·데이터 변화 | 취소·실패·재시도 |
|---|---|---|---|
| Result 또는 외부 ASCII 열기 | Run 결과 ID 또는 직접 파일 선택→축/응답/단위/위치 매핑 미리보기 | 원 solver 없이 실제 값/원본 참조를 표시; 채널 트리 생성 | 결측·중복 시간·비숫자·단위 미확정은 행/열 진단. 매핑 재편집 가능 |
| 위치·시간·성분 탐색 | 필드 셀/노드·시간 슬라이더·성분 선택 | 같은 대상 ID의 값과 범례/단위/속성이 갱신 | 요청한 부분 파일 없음이면 범위 표시 유지, 가능한 프레임/채널 목록 제공 |
| 범례·단위·범위 | 최소/최대·단위 변환·축 범위 편집 | 화면 표시만 변경하며 Run 원본은 불변. view state 저장 | 차원 다른 단위나 최소≥최대 거부. Undo와 기본값 복원 |
| 비교 | 두 결과 선택→채널/위치/시간축·단위 대응 확인 | 동기 곡선/필드와 차이·조건 표; 각 출처/입력 revision 유지 | 대응 불가한 위치·성분/미확정 단위 거부. 원본별 독립 표시로 복귀 |
| Probe/추출 | 필드 위치 또는 곡선 범위 선택→CSV/이미지/보고서 추출 | 파생 응답과 파일에 위치·시간·단위·원본 ID 포함 | 빈 범위/부분 결과 경고; 다른 구간 선택 후 다시 추출 |

네이티브 시안은 작은 셀 필드와 실제 CSV 곡선 가져오기·비교·추출을 제공한다. CSV에 필드가 없으면 곡선만 표시하며 임의 3D solver 필드를 그린 것처럼 표시하지 않는다. 제품 viewer는 저장 원본 field reader와 좌표/element ID 선택을 연결해야 한다.

## 최적화

주 화면은 **평가 절차 노드 그래프**, **설계 공간·Pareto/수렴**, **후보 비교**다. 변수/목적/제약/분포, DOE·예산, 평가 실패, 대리모델·UQ가 보조 공간이다. 트리는 Study→evaluator/step/typed port→variable/objective/constraint→candidate/run. 중앙 노드와 후보 점 선택이 트리·속성·상세 결과를 동시 전환한다. 메뉴는 파일/절차/연구/실행/탐색/비교. `.caestudy`는 입력 revision, 절차, 실제 run 참조, 후보와 연구 설정을 저장한다.

| 명령 | 전제와 조작 | 화면·데이터 변화 | 취소·실패·재시도 |
|---|---|---|---|
| 평가기 연결/노드 배선 | 저장 Case/외부 실행 profile→포트 타입 확인→노드 연결 | 선·입출력 속성·검증 오류가 그래프에 나타남 | 포트 불일치·순환·단위 불일치 거부. Undo/다른 연결 재시도 |
| 변수/목적/제약 편집 | 실제 입력 path/지원 범위와 응답 채널 선택→한계·단위 편집 | 트리 항목·노드 포트·설계 공간 축/검증 동시 갱신 | 하한≥상한/없는 채널/응답 미측정 거부. 수정 후 검증 |
| DOE/최적화/UQ 제출 | 평가기·예산·방법·시드·자원 확인→제출 | 실제 평가 run ID별 상태, 실패 후보와 결과/예측 구분 표시 | 실패 후보 값은 결측, 0 대체 금지. 중단은 진행 후보만 취소, 완료 후보 보존 |
| 후보 선택·비교 | 설계 공간/Pareto 점 또는 트리 후보 선택 | 변수·목적·제약·원본 Run/Result·곡선 동시 갱신 | 실제 run 없는 예측 후보는 명시. 새 실제 평가는 사용자 명령에서만 시작 |
| 최종 후보 전달 | 후보→`전처리/실행기/후처리에서 열기` | frozen parameter set와 정확한 Case/Study/Run revision 전달 | 원본 없음/버전 손실 시 자동 최신 교체 금지; 재연결 진단 |

네이티브 시안의 절차 그래프는 평가 순서를 설명하는 화면이며, 자동 DOE 후보는 **시연 값**이다. 변수·목적·제약 표를 편집하고 실제 후보 CSV를 가져온 경우에는 가져온 값을 출처와 함께 표시한다. 본 제품 평가기는 기존 SciPy/solver 경로를 사용한다.

자문에서 넘긴 제안은 별도의 편집 가능한 검토 초안이다. 예제 변수 그룹·범위·목적·예산은 물리적으로 검증되지 않았으며 케이스/평가기 미연결 상태에서는 시연 DOE도 차단한다. 제안·근거 탭은 지정 ID/revision의 `.history` 또는 일치하는 파일에서 발언과 근거를 읽는다. 해당 버전이 없으면 원문 없음으로 표시하며 최신 발언으로 바꾸지 않는다. 임의의 새 질문에는 실제 모델 제안이 없으므로 예제 DOE 버튼을 비활성화한다.

## 전문가 자문

주 화면은 **메시지 타임라인과 하단 고정 입력**이며 논점 지도, 근거 원문, 참여자/모델·자료/전송 허용 범위, 실행 제안/결론은 보조 패널이다. 트리는 Session→issue/evidence/proposal/job와 발언 순서다. 메시지 클릭은 reply-to·근거·관련 논점을 강조하고, 논점 클릭은 관련 발언을 강조한다. 진행자·전문가·사용자·도구 결과는 저자/시간/상태로 구분한다. 메뉴는 세션/자료/참여자/일시중지/이어가기/결론. `.caechat`은 실제 발언 순서·관계·근거 revision·제안을 저장한다.

| 명령 | 전제와 조작 | 화면·데이터 변화 | 취소·실패·재시도 |
|---|---|---|---|
| 질문/중간 개입 | 새 세션 또는 발언 선택→하단 입력→보내기 | user 메시지 순서/답변 대상 기록; 진행자·전문가 후속 발언이 이를 참조 | 전송 전 draft 보존; 실제 모델 없으면 저장/시연만 가능. 전송 실패는 failed attempt 표시 |
| 생성 일시중지/이어가기 | streaming 중 중단→현재 부분 발언 상태 확인→추가 관측 입력 | 기존 발언을 몰래 수정하지 않고 interrupted 상태와 새 user sequence 추가 | 중단 경합은 실제 완료 상태 확인. 이어가기 시 같은 사실을 중복 생성하지 않음 |
| 근거 열기 | 인용/메시지의 source ID·revision 클릭 | 원본 위치와 앞뒤 문맥, 접근 상태를 패널/별도 앱에 표시 | 원문 접근 해제/파일 변경은 해당 사실 명시. 인용한 과거 revision 유지 |
| 논점 지도·결론 | 메시지/논점 선택→찬반 근거·미확정·판별 시험 묶기 | 채팅과 논점 선택 동기. 결론은 합의/불일치/필요 시험 구분 | 다수 발언만으로 원인 확정 금지; 미해결 유지 |
| 실행 제안 | 제안 대상·변수·예산·전송 범위 검토→사용자가 기존 도구에서 편집/실행 | proposal 상태와 실제 job/result ID를 원 세션에 다시 연결 | 발언 자체로 계산 시작 안 함. 범위 변경 시 재검토/재승인 |

시안의 전문가 후속 발언은 고정 **시연 답변**이며 실제 LLM 연결이 아니다. 사용자가 입력한 메시지/답변 관계와 근거 ID는 파일에 저장·재개된다.

## Workbench

주 화면은 **프로젝트 연결도**이며 객체 등록, 포트 연결/오류, 변경 영향, 이전 실행 이력은 보조 패널이다. 트리는 Project→system→문서/버전→link→Run/Result 참조다. 노드/선 선택은 입력·출력·버전·소유 앱·영향을 속성에 표시한다. 노드 더블클릭은 정확한 ID/revision으로 해당 독립 앱을 시작한다. 메뉴는 파일/추가/연결/열기/갱신/이력. `.caeproject`는 연결/레이아웃만 소유하며 대상 앱 파일이나 Run 결과를 복제 소유하지 않는다.

| 명령 | 전제와 조작 | 화면·데이터 변화 | 취소·실패·재시도 |
|---|---|---|---|
| 저장 객체 등록 | 각 앱 문서가 저장됨→파일/최근에서 선택 | 타입별 노드와 출력 포트 생성, 문서 ID/revision 고정 | 파일 없음·schema 불일치 표시, 다시 찾기 가능 |
| 포트 연결 | 출발 출력→도착 입력 드롭 전 미리보기/호환 검사 | 호환 선과 source revision, binding latest/pinned 표시 | 타입·단위·순환 거부. 왜 연결 불가인지 선/속성에 설명, 취소 가능 |
| 도구에서 열기 | 노드 선택/더블클릭→LaunchRequest 전달 | 정확한 객체 ID/revision의 앱 문서 열기. 기존 창이 같으면 포커스 | 과거 revision은 읽기전용, 없음은 오류/재연결. 임의 최신 버전 대체 금지 |
| 변경 영향·갱신 | upstream 저장 이벤트 수신→입력 fingerprint 비교 | 관련 Case/Study 선만 stale, 이전 Run/Result는 pinned 유지 | UI 배치/라벨 수정은 계산 stale로 보지 않음. 연결 오류와 최신 여부 재조회 |
| 재실행 | stale Case 선택→새 revision 검토→사용자가 실행 명령 | 새 Run/Result와 선 추가, 이전 결과 유지 | 자동 재실행 없음. 실행 실패 후 기존 결과 계속 열기 |

네이티브 시안은 로컬 파일 문서 등록·타입 제한 연결·revision과 입력 내용 지문 기반 stale·정확한 과거 버전의 독립 창 열기를 구현한다. `파일 위치 다시 연결`은 같은 ID/종류/고정 revision/내용을 확인하고 위치만 복구하며 프로젝트 링크를 보존한다. 최종 제품은 포트별 실제 단위/응답 계약과 문서 저장 이벤트에 연결해야 한다. 시안의 수동 영향 확인이 전체 자동 갱신 구현을 뜻하지 않는다.

### 화면별 보충 동작: PDE/메시/확률/대리모델/비교

**P02/P03 메시 배정과 PDE 약형식.** 메시를 가져오면 reader가 element/face/node의 원본 ID·차원·좌표계·단위·named set을 제시한다. 사용자가 면 또는 set을 선택해 재료/경계조건을 지정하면 선택 ID가 트리와 중앙에 함께 강조되고 대상 개수·정상 방향·해석 영역이 속성에 표시된다. 같은 set에 충돌하는 Dirichlet/Neumann 조건이 있거나 벡터 field에 스칼라 값을 잘못 배정하면 저장 전 검증에서 거부한다. PDE 편집은 field의 scalar/vector 및 단위, 도메인 Ω, weak term(적분 영역·피적분 함수·계수), source, boundary set, initial value를 별도 객체로 만든다. 식 문자열만 저장하지 않고 테스트/시험 함수와 경계 적용 범위를 기록한다. 식/약형식 노드를 클릭하면 중앙 해당 항을 강조하며 차원·지원 backend·필수 경계조건 진단을 보인다. 오류는 관련 항/면으로 직접 이동하고 이전 유효 Case는 그대로 남긴다.

**P03 재료점 법칙·시험 이력.** 사용자가 구성 법칙을 선택하면 속성에 그 법칙이 실제로 받는 계수와 단위, 초기 내부 상태(예: 소성 변형·점탄성 branch 상태)를 펼친다. 다른 법칙으로 바꿀 때 기존 계수를 조용히 재해석하지 않고 호환 가능한 값만 명시적으로 이관하며, 나머지는 보존된 이전 초안에서 확인하게 한다. 트리의 각 시험 아래 load-history를 시간/변형/온도 등 해당 evaluator의 필드로 편집하고, 각 시점의 순서·단위·필수 경계값을 검증한다. 시험마다 `train` 또는 `holdout` 역할과 weight, 관측 곡선/채널 ID를 정한다. 저장값은 법칙 ID와 backend capability, 계수/초기 내부 상태, 시험별 원본·load-history·train/holdout, 채널 매핑, 단위를 포함한다. Holdout은 계수 적합에 쓰지 않고 적합 결과를 별도로 검사한다.

**O03/O06 UQ 호환.** 분포 객체에 변수 path/단위/근거(측정·문헌·가정), 지지 범위, 상관 선언을 기록한다. 독립 균일 분포로 선택한 방법은 해당 변수 bounds가 유효하고 독립 가정이 명시돼야 제출 가능하다. Latin hypercube, Sobol, Morris, Monte Carlo 등 방법별 필요한 표본 수/분포·상관 지원을 capability로 검사해, 맞지 않는 전략은 실행 전 비활성화하고 이유를 보여준다. 실패/누락 평가 표본은 별도 상태로 두고 통계에 0으로 넣지 않는다. 샘플 생성과 평가 실행은 분리하며 예산과 시드를 재개 때 유지한다.

**O06 대리모델.** 실제로 평가한 후보만 학습 집합에 넣고, 별도 holdout을 평가 전에 고정한다. 적합 화면은 입력 변수 스케일, 학습/검증 오차, 불확실성 추정이 가능한 모델이면 그 범위를 표시한다. 후보의 원래 관측/실제 solver 값과 대리 예측은 컬러뿐 아니라 텍스트/타입으로 구분한다. 학습 bounds 바깥 점은 외삽 배지를 붙이고 최적 후보로 바로 확정하거나 실제 값처럼 후처리에 전달하지 않는다. 새 후보의 실제 계산은 사용자가 평가기 제출을 누를 때만 Run으로 만든다.

**S04/R03/O05 다중 실행 비교.** 두 Run을 고를 때 입력 Case revision, backend/solver version, 시간축·좌표계·unit, channel component/location을 먼저 나란히 보여준다. 같은 물리량의 호환 단위만 명시 변환하고 변환 전/후 단위를 기록한다. 접촉력과 응력처럼 차원이 다른 채널은 비교 대상으로 선택할 수 없다. 위치 매핑이 다르면 공통 set/좌표 대응을 사용자가 확정하기 전까지 차이장을 만들지 않는다. 실패/partial 결과는 해당 범위만 음영 처리하고 전 구간 완료로 보이지 않게 한다. 비교의 선택과 표시 범위는 `.caepost`, 실제 Run의 로그/결과는 각 실행 기록에 남는다.

두 시계열 비교의 기본 시간 범위는 **양쪽 모두 실제 표본이 있는 공통 겹침 구간**이다. 해당 범위 안에서만 명시적 선형보간을 적용하고, 양 끝 바깥에는 외삽하지 않는다. 원본 표본과 보간 표본을 구별하고 축/단위 변환을 먼저 확정한다. 필터, 사건(event) 정의, 시간 정렬, 채널별 weight와 잔차 scale은 하나의 comparison spec revision에 고정한다. 이 설정 중 계산 의미가 있는 항목을 바꾸면 기존 오차/후보 점수를 그대로 표시하지 않고 새 spec revision에서 재평가를 요청한다. 표시 전용 범례·색상 변경은 재평가 대상이 아니다.

**E05 자료·전송·계산 권한.** 자문은 기본적으로 로컬 초안이며 모델·네트워크 전송을 하지 않는다. 공개 문헌 검색 허용과 회사/개인 자료의 외부 모델 전송은 별도 체크와 별도 출처 목록이다. 공개 조사 범위(주제·출처·예산·만료)를 한 번 허용하면 그 범위 안에서 전문가는 새 검색어 생성과 논문 읽기를 자율 반복할 수 있다. 매 질의마다 승인을 요청하지 않는다. 범위 밖 주제·사이트·비용에는 새 검토를 요구한다. 공개 검색 허용만으로 로컬 PDF나 회사 자료를 전송할 수 없다. 자료마다 원문/발췌/메타데이터 중 전송 범위, 모델/provider, 세션 만료, 문서 ID/revision을 보여준다. `계획만`은 계산 제안까지만 허용하며 실제 작업 제출은 막는다. `범위 내 계산 허용`을 선택하면 허용 backend/변수 path와 bounds, 최대 평가 횟수, CPU 스레드, 시간·메모리, 한 번에 실행할 job 수를 명시한다. 제안의 범위가 하나라도 초과하면 실행 버튼을 비활성화하고 어떤 항목을 줄일지 표시한다. 사용자가 `권한 철회`를 누르면 이후 외부 전송과 미제출 계산을 즉시 막고 권한 버전을 증가시킨다. 이미 완료한 발언·job은 이력으로 보존하고 현재 running 작업의 취소 가능 여부와 실제 terminal state를 별도로 표시한다. 재개 세션은 권한을 자동 재승인하지 않고 만료/철회 상태를 먼저 검사한다.
