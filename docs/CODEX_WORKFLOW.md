# Codex와 Pro의 확정 작업 방식

확정: 2026-10-12. 사용자 요청에 따라 실제 Pro와 토론한 운영 결정을 적용한다.
이 문서는 개발 협업과 문서 관리의 원본이다. 제품 내부 Expert의 계산 권한·모델 인증과
개발 담당자의 역할을 혼동하지 않는다. 전체 제품 목적은 [PRODUCT_PLAN](PRODUCT_PLAN.md),
지금 맡긴 일과 다음 행동은 [CURRENT_STATE](../CURRENT_STATE.md)에 둔다.

## 역할과 결정

| 담당 | 책임 |
|---|---|
| 사용자 | 제품 목적, 우선순위, 중요한 외부 권한·비용과 실제 수용 판단. 이미 정한 선택은 다시 묻지 않는다. |
| Pro | 의미 있는 제품 단위의 설계·구현·관련 테스트/CI 수정과 확인, 관련 설계·사용법·지원 범위의 문서 변경. 기존 구현을 재사용하고 대안을 검토한다. |
| Codex | 전체 목적 유지, 독립적인 반론·코드/동작 검토, 실제 환경 확인, 결과 통합·Git 작업, 현재 상태와 Space 안내 갱신. 단순 전달자로 끝내지 않는다. |
| Astra 독립 검토 | 최신 요구·기준 소스·실제 설계 산출물을 함께 받아 핵심 제품/GUI의 누락, 작업 완결성, 실패·복구와 무료 native 구현 가능성을 읽기 전용으로 검토한다. 실제 화면 확인이나 사용자 수용을 대체하지 않는다. |

상세 기획과 Qt 시제품 이후 2026-10-13 사용자가 전체 명세의 독립 도구와 전체 연계
구현·통합을 지시했다. 현재는 본구현 단계다. Codex가 배정하고 시작시키며 MoAI는
SPEC·작업 관리를 위한 도구다. 화면 피드백은 구현 중에도 이어간다. 실제 Pro가 설계·
제품 코드의 주 작성자이며 연결 장애를 다른 작성자로 몰래 대체하지 않는다.
전달/응답/실제 반영/실행 확인은 따로 기록한다.

Pro 응답이 실패로 종료되면 사용자의 다음 지적을 기다리지 않고 연결을 복구한다.
2026-10-14 사용자 지시로, 기존 대화를 이어갈 수 없을 때 새 실제 Pro 대화를 열어
최신 요구·기준 코드·남은 작업·결함·완료 조건·소유 파일을 직접 전달할 수 있다.
Space는 맥락 자료로 연결하되 읽었다고 가정하지 않는다. 진행 중 응답에는 중복 요청을
보내지 않으며, 새 대화의 Pro 선택과 요청 본문 수신을 확인한다. 대화 길이만으로
실패 원인을 단정하거나 기존 산출물을 버리고 처음부터 다시 시작하지 않는다.

사용자 진행 보고는 사용할 수 있게 된 기능, 남은 개발, 직접 써볼 수 있는 시점으로
한다. 픽셀 치수·검사 개수·내부 명령·커밋 식별자를 일상 보고의 중심으로 삼지 않는다.
이 세부사항은 담당자끼리 검토하고 저장소의 근거 기록에 남긴다. 실제 진행을 묻는
질문에는 먼저 답한 뒤 작업을 계속하며, 모르는 완료 시점을 꾸며내지 않는다.

사용자가 명시적으로 요청하지 않는 한 Pro·에이전트의 대화 캡처, 요청 전달 내역,
수신 확인을 사용자에게 증거 또는 결과물로 제출하지 않는다. 협업 확인은 내부 작업에
필요한 기록이며 제품 성과가 아니다. 이 지침은 맥락 압축 후에도 유지한다.

2026-10-14 사용자 지시: Pro는 복잡한 제품 설계와 의미 있는 핵심 기능 구현에 집중한다.
단순 문구·배치 교정과 원인·범위가 명확한 연결 버그는 Sol 또는 Codex가 맡는다.
작은 수정마다 Pro에게 새 작업을 보내지 않는다. 진행 중인 작성 파일은 먼저 책임을
분리한 뒤 수정하고, 보조 작성분을 Pro가 작성한 코드로 표시하지 않는다.

사용자 모델 배정: 주 Codex `gpt-6.1-sol/xhigh`, 핵심 독립 검토 `gpt-6-astra/xhigh`,
범위가 제한된 검토/기술 확인 `gpt-6.1-sol/high`, 코드 탐색 `gpt-6-luna/high`.
ChatGPT Pro 모드는 실제 UI에서 확인한다. Codex effort를 Pro 설정으로 표시하지 않는다.
설정 파일은 활성 런타임의 증명이 아니며 사용할 수 없는 지정 모델은 명시한다.
추가 유료 API/구독/크레딧/플러그인/호스팅/결제수단 요구 체험판은 사용하지 않는다.
MoAI는 기존 문서에 연결한 SPEC/인계 관리에 쓰며 모델·공급자·구현 진입을 자동 변경하지 않는다.

Codex와 Pro는 맡긴 범위에서 충돌을 해결하고 결정을 적용한다. 사용자에게 같은 문제의
선택지를 반복해서 돌려주지 않는다. 사용자 취향·외부 계정·새 비용처럼 실제로 사용자가
결정해야 할 사실만 질문하고, 답에 의존하지 않는 작업은 계속한다. 이미 허용된 문서 수정,
구현·검토·일상 수정·기록에 단계별 재승인을 요구하지 않는다.

제품 코드 작성자를 Codex로 몰래 바꾸지 않는다. Codex는 이번 문서 정리와 합의된
통합 작업을 직접 수행한다. Pro 결과가 틀리면 근거와 기대 동작을 제시해 교정받고,
단순 수신을 구현 반영이나 실행 성공으로 기록하지 않는다.

공통 schema/Core/registry/provenance 변경은 한 소유자가 조정한다. 보조 에이전트는
필요한 조사·분리 가능한 구현·독립 검토에만 쓰고 파일 소유 범위를 명시한다. 같은 파일을
동시에 수정하거나 전체 기록을 여러 에이전트에게 중복 조사시키지 않는다. 현재 사용자가
고른 모델·추론 설정을 존중한다. `.codex/` 설정은 환경 기본값이며 현재 앱의 활성화나
Pro의 실제 모델 선택을 보증하지 않는다. 새 계정·결제·자동 대체 모델을 도입하지 않는다.

병렬 담당자는 [프로젝트 Space](https://chatgpt.com/space/page_6ac6e5e8d7688191a58c5760fda2d2d9)의
공동 댓글에서 서로 질문하고 답한다. Codex를 모든 메시지의 전달자로 삼지 않는다.
상태 보고뿐 아니라 실제 화면과 사용자 작업을 놓고 설계 대안과 불편을 토론한다.
예상 사용자 지적은 화면·조작의 근거를 붙여 제시하고, 상대의 반론을 읽고 답한 뒤
선택 이유와 남은 이견을 정리한다. 검토자의 합의를 사용자 수용으로 대신하지 않는다.
해당 요구·소스·관측과 원하는 다음 행동을 짧고 읽기 쉽게 적고, 다른 담당자의 파일은
덮어쓰지 않는다. Pro가 제품 코드를 작성하고 Codex가 통합하는 책임은 그대로다.
MoAI의 팀 작업 분해·배정 절차와 현재 제공되는 Codex 실행·메시지 도구를 함께 사용한다.
실제로 제공되지 않는 Claude Code 팀 실행 도구를 호출했다고 보고하지 않는다.

## 작업을 끝내는 순서

1. CURRENT_STATE에서 같은 Git 기준, 현재 목표, 담당·중단점, 미반영 산출물을 확인한다.
2. Pro에게 전체 제품 목적과 이번에 사용자가 끝낼 작업, 관련 코드·설계·실제 근거,
   바꾸면 안 되는 계약, 원하는 산출물과 종료 범위를 한 번에 전달한다. 접근하지 못한
   링크나 이전 대화를 읽었다고 가정하지 않는다.
3. Pro와 설계의 실질적인 쟁점을 토론한다. 코드면 적용 가능한 변경물과 관련 문서,
   확인한 동작·남은 한계를 받는다. 확인만 반복하는 대화나 새 관리 체계를 만들지 않는다.
4. Codex가 기준 버전·변경 범위·사용자 변경과의 충돌을 검토하고 필요한 실제 검사를
   수행해 통합한다. 소스 검토, 대역을 쓴 검사, 실제 solver/AI/GUI 실행을 구별한다.
5. 관련 문서와 CURRENT_STATE를 같은 작업으로 갱신하고 의미 있는 단위로 커밋한다.
   허용된 게시·통합은 직접 수행하고 원격 커밋을 확인한다. 보호 규칙 우회·강제 push·
   사용자 변경 폐기는 금지한다. 게시 실패 시 로컬 커밋과 실제 장애를 기록한다.
6. 사용자가 할 수 있게 된 일과 남은 한계를 보고한다. 계획·문서 수·검사 수·PR 병합을
   전체 제품 완성으로 바꾸지 않는다. 배정된 결과가 남아 있으면 같은 목표로 계속한다.

native 확인을 위한 새 FreeCAD·pvpython 프로세스는 Windows의
`scripts/native_check.py`로 실행한다. 예:
`python scripts/native_check.py --timeout 180 --output-dir runs/<새 확인>/process -- <실행 파일> <인수>`.
실행기는 자신의 root/자식 프로세스만 Job에 묶고 성공·실패·시간 초과에 정리한다.
출력 폴더는 새 폴더이며 기존 기록을 덮지 않는다. 매크로는 결과를 저장한 뒤 해당
테스트 창을 정상 종료하고, 종료되지 않으면 실행기가 정리한다. 기존 사용자 창에
연결하는 single-instance 옵션을 쓰지 않는다. 실제 UI 조작 확인이나 사용자가 요청한
열린 결과창은 별도 소유를 명시하되 확인이 끝나면 직접 닫는다. 남은 native 프로세스도
정확한 실행 소유를 확인하고 정리하며 이름을 기준으로 일괄 종료하지 않는다.

MoAI의 Python 코드 검사는 `moai ast-grep <수정 파일> --lang python --format json`으로
실행한다. 현재 프로젝트 규칙은 동적 eval/exec와 subprocess의 shell=True 사용을
검토 대상으로 찾는다. 이 제한된 검사를 독립 검토나 해당 기능의 동작 확인으로 대신하지
않는다. `sg`가 없는 새 개발 환경에서는 무료 공식 ast-grep 배포를 준비해야 하며,
현재 Windows 설치 위치는 `%LOCALAPPDATA%\Programs\ast-grep\0.45.3`이다.
이미 실행 중인 셸이 새 PATH를 못 읽는 경우 해당 명령의 process PATH만 연결한다.
MoAI 설정과 두 규칙 파일은 저장소에 있고 일반 제품 사용자의 설치 조건은 아니다.

한 연결/조작 경로가 막히면 해당 입력을 중단하고 원인·남은 결과·진행 중인 대체 경로를
즉시 알린다. 이미 허용된 공식 연결·저장소·Space·로컬 파일 경로로 회수/통합을 계속하며,
특정 GUI 도구의 중단을 전체 작업의 중단으로 확대하지 않는다. 보안 정책·인증·유료 제한은
우회하지 않는다. 직접 조작이 꼭 필요하면 필요한 한 가지를 바로 요청하고 독립 작업은 계속한다.

도구와 연계 기능 개발을 우선한다. 개발 중에는 실행 가능 여부와 필요한 단위 검사만
수행하고 넓은 통합·수치 검증은 관련 기능이 준비된 뒤 수행한다. 확인된 동작 결함은
같은 사용자 작업 묶음에서 모아 교정한다. 작은 수정 하나마다 검사 통과를 기다리며 다음
기능 구현을 멈추지 않는다. 데이터 손실·다른 결과 표시·잘못된 계산은 즉시 처리하고,
비치명적 화면 결함은 연결된 기능 묶음의 구현과 함께 고친다. 그대로인 전체 suite나
native 계산을 반복하지 않는다.
작은 UI 수정마다 별도 ADR·승인·전수 검토를 만들지 않는다. 수치
의미나 공통 경계의 중요한 변경에는 결정 이유·대안·요구 영향·의미 있는 검증을 남긴다.

| WORKBENCH_REDESIGN·USE_CASES·REUSE, PREPOST_APP_SPEC, 원 도면/자료 | 보존할 설계 근거·사용 사례·세부 계약. 현행 제품 계획/후속 ADR과 충돌하는 옛 순서·호스트 구분은 적용하지 않는다. |

문서가 있다는 이유로 모두 매번 읽거나 갱신하지 않는다. 현재 작업 선택은 CURRENT_STATE,
기능 설계는 제품 계획, 검증 사실은 날짜별 원근거에서 찾는다. 과거 기록의 정리가 다른
제품 작업의 선행조건이 되지 않는다. 중복 현황을 새 Page·PR 댓글·로컬 파일에 만들지 않는다.

## Space와 Git 갱신

현행 제품 계획·협업 규칙·작업 상태의 원본은 Git이다. [Space](https://chatgpt.com/space/page_6ac6e5e8d7688191a58c5760fda2d2d9)는
사용자 결정, 논의·설계 이유, 원자료와 도면을 보존하고 현행 Git 문서로 안내한다.
같은 현행 기획 본문을 양쪽에서 독립 편집하지 않는다. 과거 첨부·ZIP은 날짜가 있는 사본이다.

사용자의 새 결정은 Git 이관 전부터 유효하다. Codex는 그 결정·이유·출처를 관련 Git
계획/상태에 반영하고, 의미 있는 결정이 바뀌면 같은 작업에서 해당 Page의 안내·요약·
링크를 갱신한다. Page에 남은 과거 지시가 최신 사용자 결정을 되돌리지 못한다.
Pro/Codex의 제안을 사용자 결정으로 위장하지 않는다.

자동 동기화 시스템은 없다. Codex가 양쪽의 저장 결과와 기준을 확인하는 작업 책임으로
연결한다. 모든 코드 수정이나 검사마다 Page 본문을 다시 쓰지는 않는다. 한쪽 접근이
막히면 이미 적용된 부분을 보존하고 미반영 대상·이유·다음 행동을 CURRENT_STATE에 남긴다.
부분 반영을 전체 최신화로 보고하지 않는다. 공유 권한과 계정 설정은 이 작업과 별개다.

## 새 세션과 인계

새 Codex는 AGENTS → CURRENT_STATE → PRODUCT_PLAN → 이 문서를 읽고, 현재 배정의
상세 설계·코드·검증 근거로 들어간다. Git·로컬 변경·서브모듈·필요한 실제 환경을 확인한다.
짧은 시작문은 [CODEX_START](../CODEX_START.txt)를 사용한다. 전체 과거 대화나 모든 ADR를
처음부터 복원하는 작업으로 되돌아가지 않는다.

새 Pro에는 Codex가 아래 정보를 채워 전달한다. 자동으로 다른 Pro 대화·Space·로컬
파일을 기억한다고 가정하지 않으며, 접근 가능한 정확한 Git 버전이나 실제 파일을 제공한다.

```text
Autonomous CAE Lab의 제품 설계·구현 작성자로 작업한다.
기준 저장소/커밋: [Codex가 확인한 URL과 SHA]
제품 목적과 운영: 해당 SHA의 PRODUCT_PLAN, PRODUCT_UI_MCP_PLAN, CODEX_WORKFLOW.
이번 작업: CURRENT_STATE의 확정 목표·범위·사용자 완료 기준과 관련 코드.
추가로 적용할 최신 사용자 결정 / 아직 반영하지 않은 변경: [실제 내용 또는 없음]
기존 구현을 재사용하고 실제 작업 흐름을 완성한다. 설계·구현·관련 문서와 실제 확인 범위,
남은 제약을 반환한다. Codex의 가정에 문제가 있으면 근거를 들어 수정한다.
Codex는 독립 검토·실제 환경 확인·통합·기록을 맡는다. 맡긴 범위의 일상 단계마다
재승인을 요구하지 않으며, 새 비용·권한이나 사용자만 정할 수 있는 선택은 구별한다.
```

인계에는 마지막 통합 기준, 현재 맡긴 범위·중단점, 진행 중인 변경/프로세스와 소유권,
미반영 Pro 산출물, 필요한 외부 조건, 바로 할 다음 행동만 남긴다. 옛 R1–R5 명령이나
과거 실패를 현재 미완료 목록으로 복사하지 않는다. CI는 정확한 소스에 귀속시키고,
로컬에 없는 원시 산출물은 없는 것으로 기록한다.
