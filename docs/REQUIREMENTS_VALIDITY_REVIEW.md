## 사용자에게 먼저 설명할 결론

**52는 과거 요청의 절에 붙인 추적 번호다. 지금 반드시 완성해야 할 동등한 제품 기능 52개라는 뜻으로 사용하면 잘못이다.** 목록에는 연구 기능, 결과를 믿기 위한 원칙, 특정 프로그램 조사, 당시의 개발 순서, 저장소 초기 설정, 개발 담당자 운영 규칙이 함께 들어 있다. 실제로 지킬 내용은 많지만, 모두를 같은 제품 수용 조건으로 유지할 근거는 없다. [S1]

지켜야 할 중심은 분명하다. 사용자가 자기 부품과 지그를 설계·변경하고, 메시와 조건을 고쳐 실제 계산하고, 결과를 비교해 설계로 돌아올 수 있어야 한다. 외부 결과만 열어 분석하거나 CAD 없이 자료·재료·PDE 연구를 시작할 수도 있어야 한다. 전문가와 실제로 토론하고 수치 계산으로 가설을 확인하며, 작업을 저장한 뒤 다른 날 이어갈 수 있어야 한다. 사람과 AI는 같은 열린 문서를 다뤄야 한다. 이 결과들은 번호를 줄이거나 옛 순서를 정리한다는 이유로 제거할 수 없다. [S2 §1–9, S3]

반면 모든 solver 후보를 설치하고, 모든 초기 ADR을 다시 작성하고, 특정 수의 에이전트를 운영하고, 옛 Phase 순서대로 움직이는 일은 사용자 업무의 완료 조건이 아니다. 특히 “기존 browser UI 재사용”, “FEA 전에 CAD-only 연결부터 다시 완성”, “OpenScience-first를 필수 입구로 사용”하는 해석은 후속 사용자 지시와 충돌한다. 해당 문구의 현재 효력을 바꿔야 한다. [S1 R02/R23/R33/R36–R50, S3]

**v2 전체 제품/UI/MCP 설계는 유지한다.** 수정할 곳은 요구 목록의 사용법, 일부 소유·보존 문구, 작업표의 과도한 선행 조건, 실제 시험 자료가 돌아오는 공동 작업 장면이다. 22쪽 PDF를 다시 만드는 사안이 아니다. 앞으로의 진척은 사용자가 새로 끝낼 수 있게 된 작업과 실제 근거로 보고한다.

### 판정 용어

| 판정 | 현재의 의미 |
|---|---|
| 유지 | 실제 사용자 결과 또는 그 결과의 정확성·편집·저장에 필요한 원칙으로 계속 지킨다. |
| 통합 | 같은 의미의 여러 문장을 한 계약이나 개발 규칙으로 관리한다. 기능을 없애거나 테스트를 임의로 면제한다는 뜻이 아니다. |
| 재작성 | 의도는 살리고 현재와 충돌하는 입구·소유·순서·완료 해석을 바꾼다. |
| 조건부 | 실제 사용하는 물리·방법·backend·환경에 맞는 지원 범위와 확인을 정한다. 전체 후보 설치를 공통 선행 조건으로 만들지 않는다. 원래 연구 범위의 삭제도 아니다. |
| 역사로 이동 | 당시의 순서·일회성 초기 작업을 변경 이력으로 보존하고 현재의 반복 의무에서 뺀다. 그 행에 함께 쓰인 연구 기능이 구현 완료됐다는 뜻은 아니다. |

한 행에 “기능 유지·순서 역사 이동”처럼 서로 다른 판정이 함께 올 수 있다. 원 행을 억지로 하나의 기능이나 하나의 상태로 줄이지 않는다.

## 2. 현재 제품의 기준은 사용자가 끝낼 수 있는 업무다

아래는 새로 번호를 세기 위한 요구표가 아니다. 현재 기획이 사용자에게 주어야 할 결과와, 그 결과가 빠졌을 때 발생하는 손실을 설명한다.

| 사용자가 끝낼 업무 | 반드시 남길 실제 기능과 조작 | 원 번호만으로는 부족한 부분 / 현재 v2 연결 |
|---|---|---|
| **부품·지그를 설계하고 계산에 근거해 변경한다** | 같은 FreeCAD 전처리 창의 스케치·구속·치수·피처 이력, 부품/배치·조립·관절·운동·경로, 메시 설정·품질·영역·재료·조건, 변경 뒤 참조 복구, 계산과 Post 비교, 원 설계로 복귀 | R07의 “CAD 등록”, R26의 “지그 해석”만으로 깊은 설계 조작을 대신할 수 없다. v2 §4/§8.1, T05–T11/T16을 실제 조작으로 유지한다. |
| **과거 또는 외부 결과만으로 분석을 끝낸다** | 실제 reader, 시간·성분·단위·위치 확인, 절단·측정·곡선, A/B 원값·차이·변화율, 검증한 다른 메시 대응, 분석 저장·파일 이동 수리 | 원 ledger에는 독립 Post의 깊이가 충분히 드러나지 않는다. CAD·원 solver·AI 없이 여는 v2 §5/§8.2, T12–T15/T14b가 현재 요구다. |
| **자료·재료·PDE를 독립적으로 연구한다** | Data 원자료·열·단위·mask·변환, Material 법칙·계수·초기상태·이력·직접 평가, PDE 식/약형식·space·BC/IC·수치 설정과 실제 기준 비교 | R01/R16/R17을 CAD의 메뉴나 재료 카드로 축소하지 않는다. 각 문서 직접 실행·저장·재개와 공유 편집기를 v2 §6.1–6.4에서 유지한다. |
| **가설을 실제 수치 탐색과 시험으로 구별한다** | 동일 Plan의 fit/holdout·DOE·최적화·지원 UQ/대리모델/다목적, 실제 평가기·실패·채택, 열→구조 등 재사용 평가 정의, 시험 자료를 통한 모델 갱신 | R27/R31의 옛 단계 순서는 제거해도 방법·연성·실험 연결은 남긴다. v2 T19/T24/T25-C1–C4와 해당 방법별 지원 작업에 연결한다. |
| **전문가와 토론하고 다음 연구를 정한다** | 논점 지도·실제 다자 발언·반론/reply·사용자 개입·중단/재개·근거 열기, 편집 가능한 계획 제안과 실제 계산 후속 해석 | 개발용 하위 에이전트 운영(R37–R47)은 제품의 Expert 기능을 대신하지 못한다. v2 §6.6/T22의 실제 토론형 UI가 필요하다. |
| **Windows에서 편하게 시작하고 다음 날 이어한다** | WSL 없는 직접 실행, 파일 열기·여러 문서/창, 전문 UI의 선택·표·차트·키보드 조작, 잘못된 draft도 저장, 새 프로세스에서 재열기·이동 파일 복구 | R13/R21/R35를 단순 설치 성공·공통 파일 형식으로 해석하면 부족하다. v2 §2/§3/§7/§9 및 T03/T04/T26이 해당된다. |
| **사람과 AI가 같은 작업을 하고 결과를 믿는다** | 같은 열린 owner의 실제 값·generation·Undo, 오래된 변경 거절, 정확 입력과 결과 연결, 관측/단위/기저/위치/시간/mask 확인, 과거 결과·실패 보존 | 원 ledger 밖의 후속 요구도 현재 효력을 갖는다. 새 버전과 과거 PASS, 계산 성공과 사용자 수용·공학 승인을 섞지 않는다. |

불량 가설 연구와 제작 전 지그 검토는 우선 연결할 실제 업무다. 범용 PDE, 재료 구성 연구, 낙하/명시적 해석, 외부 batch, 연성, 불확실성 연구를 그 두 업무의 부속 메뉴로 축소하지 않는다. A/B/C는 서로 다른 가설과 입력에서도 도구가 작동하는지 확인할 사례이며 범용 편집기의 고정 모델이 아니다.

## 3. 요구 목록에서 바로잡아야 할 내용

### 3.1 OpenScience의 역할과 제품의 필수 입구를 구별한다

R02/R03은 연구 질문과 수치 계산의 역할 분리에 효용이 있다. R02/R45의 “OpenScience-first”를 사람도 반드시 AI를 거쳐야 한다는 뜻으로 쓰면 직접 GUI·CLI·Python 사용과 충돌한다.

현재 의미는 다음과 같다.

- 사람과 허용된 AI 클라이언트가 같은 문서 명령과 지원 계산 경로를 사용한다.
- AI는 질문·가설·계획 제안·해석을 돕고, 실제 후보 생성과 반복 계산은 수치 엔진이 한다.
- OpenScience가 모든 Study/Plan/domain 원본을 독점 소유하지 않는다. 소유는 v2의 Study·Discussion·Plan·domain 문서 계약을 따른다.
- 연구 명령에서 사용자가 solver deck 문법을 직접 조립하도록 요구하지 않는다. 그렇다고 PDE 식/약형식, Material 법칙, 지원 고급 설정을 편집할 권리를 없애지는 않는다.

AI 경로도 실제로 시험해야 한다. 다만 비AI 경로의 입장권으로 만들거나 전체 Expert UI 완성 뒤에만 확인할 필요는 없다. [R02/R03/R13/R21/R25/R45, S2 §1/§9]

### 3.2 R06의 metadata는 전부 필수인 거대한 등록 폼이 아니다

원문에는 “where applicable”이 있고 실제 발견 뒤 명시적으로 등록한다고 쓰여 있다. 파라미터마다 관련 없는 기본값·기하 효과·상하한을 억지로 채우게 하면 사용성을 해친다. 더 중요한 문제는 같은 “범위”와 “고정”이 모델과 계산 계획에서 다른 뜻이라는 점이다.

| 항목 | 현재 소유와 의미 |
|---|---|
| 연구 ID, 이름, 실제 문서/객체/속성·치수 경로, 단위·타입, 현재값, 해당하는 기본값 | domain의 등록 정보. AI/수치 엔진에는 안정된 연구 ID를 노출하고 native 경로는 연결 경계에서 관리한다. |
| 물리적·기하학적 허용 범위, 읽기 전용/종속 변수, 식의 의존성, 검증 규칙, 실제 효과, 값의 출처 | domain/등록 정보. 모델 자체가 허용하는 조건이며 단순히 Plan에서 자유 변수로 표시한다고 해제되지 않는다. |
| 이번 연구의 탐색 상하한, 고정/자유, 공유/시험별 선택, 목적·가중치·holdout | Numerical Plan. 한 모델을 쓰는 서로 다른 Plan이 독립적으로 정한다. |
| 무효하거나 반응하지 않는 변수 | 실제 native 변경·재계산 또는 평가에 미친 효과와 확인 범위를 표시한다. 등록된 이름의 존재와 연구에 유효한 탐색 변수임을 구별한다. |

무반응은 시험한 입력·변경량·관측 응답 범위의 관찰이다. 그 사실만으로 변수를 전역 무효·고정으로 처리하거나 등록·다른 연구를 차단하지 않는다. 예를 들어 탄성 구간의 시험에서 항복응력이 응답에 영향을 주지 않았다고 항복을 연구하는 다른 경로에서도 그 변수가 무의미하다고 판단해서는 안 된다.

**반례:** 같은 지그 두께를 Plan A에서는 고정하고 Plan B에서는 탐색한다. 등록기의 fixed/free를 전역으로 바꾸면 A의 의미가 몰래 바뀐다. 반대로 모델상 종속 치수를 B에서 자유로 표시한다고 독립 편집할 수 있게 해서도 안 된다.

Core가 임의 CAD 문자열을 실행하지 않는 원칙은 유지한다. 지원 native 표현식은 실제 native 표현식 기능의 제한과 검사를 통해 처리한다. 이 구분은 v2 §4.1에 이미 있는 “수치 탐색 범위는 Plan 소유”를 명확히 하는 보완이다. [R06/R07/R19, S2 §4.1/§6.4]

### 3.3 검사·근거·입력·결과 연결은 묶되 서로 대체하지 않는다

R08–R12/R19/R20에는 중복되는 보존·연결 요구가 있지만 효용이 없다며 지울 내용은 아니다. 역할을 분명히 해 공통 계약으로 관리한다.

- 검사는 “어떤 대상 개정에 어떤 기준을 적용했고 무엇을 확인했는가”를 남긴다. 기준·validator 버전, 근거 참조, 확인 시각, 현재 개정에 적용 가능한지를 함께 둔다.
- 형상 변경 전의 PASS는 그 개정의 기록이다. 새로운 형상에 자동으로 현재 PASS 표시를 옮기지 않는다.
- invalid 형상이나 필수 입력 오류는 해당 내보내기/실행을 막는다. 다른 문서 열기·과거 결과 분석·invalid draft 저장까지 막는 전체 관문은 아니다.
- 공학 기준의 UNKNOWN은 제작/사용 승인에 반영한다. 편집·저장·필수 계산 경로가 고장 난 상태를 UNKNOWN이라는 말로 처리할 수는 없다.
- 메시·로그·곡선·사진·보고서는 근거 종류다. 모든 연구에 이 모든 종류의 첨부를 의무화하지 않는다.
- CAD→mesh→deck→run은 가능한 연결 중 하나다. 외부 결과, 재료점, PDE 연구에 없는 CAD나 Run을 가짜로 생성하지 않는다.
- 공통으로 묶을 것은 식별·개정·참조·입출력·단위·유효성·실행 기록이다. 이를 모든 물리 문법을 넣는 새 universal solver schema로 바꾸지 않는다.

### 3.4 “어느 반복이든 열기”와 탐색 중 임시 계산을 구별해 보존 책임을 정한다

R12의 원자료·native·처리 결과 보존은 타당하다. R27의 후보와 탐색 상태 추적도 타당하다. 다만 이를 “내부 Newton 반복의 모든 배열, 모든 임시 curve와 FCStd 중복본을 영구 저장”으로 읽을 근거는 없다. 반대로 최종 숫자만 남긴 뒤 예전 후보를 열 때마다 새 계산하는 것도 요구를 충족하지 못한다.

현재 v2의 “없는 상세 곡선은 새 evaluation이라고 표시한다”는 정직한 복구 규칙이다. 그 규칙만으로 **어떤 기록을 반드시 남길지**가 정해지지는 않는다. 다음 수준을 구별한다.

| 대상 | 반드시 남길 것 / 사용자에게 보일 상태 |
|---|---|
| Plan의 실제 탐색·동정·DOE 후보와 기록 실행 | 상세 출력 보존 선택과 무관하게 정확한 입력·평가/attempt·순서·방법/설정·상태·실제 응답·진단·존재하는 결과 참조를 남긴다. 실패 후보는 실패 위치와 실제 로그·부분 결과를 연다. |
| 해당 실행에서 보존하기로 정한 출력 | 지정한 raw/native 결과·곡선·field·표를 원 solver 재실행 없이 연다. 같은 내용은 참조로 공유할 수 있다. 보존 실패를 기록 완료로 표시하지 않는다. |
| 비교·채택·holdout·보고의 근거 | 그 판단에 실제 쓴 입력·원값/곡선·진단·구현 버전·처리 정의를 반드시 보존한다. 과거 근거를 새 계산 결과로 몰래 교체하지 않는다. |
| 일시적 직접 평가·미리보기·엔진 내부 작업 | 모든 평가를 durable job이나 영구 curve로 만들지는 않는다. 보존된 결과와 임시 상태를 구분하고, retain_result 및 판단에 쓰는 동작은 필요한 근거의 보존을 완료해야 성공한다. |
| 탐색 자체의 상태 | 방법·seed·예산·후보 순서·반복/세대·중단 상태, 엔진이 제공하는 재개 상태의 보존 범위를 명시한다. 이력 열람을 정확한 탐색 재개라고 표시하지 않는다. |

보존 범위는 실행 전에 출력 설정과 함께 정하고 기록한다. 원자료와 이미 보존된 과거 결과를 덮어쓰지 않는 요구는 이 설정으로 해제되지 않는다. 과거 실행에 상세 출력이 없었다면 부족함을 그대로 표시한다. 추가 계산은 새 evaluation이며 원 실행의 역사적 근거를 소급해서 완성한 것으로 취급하지 않는다. [R10–R12/R20/R27, S2 §6.2/§6.4/§9.5.3]

|---|---|---|
| R14 — Code_Aster/SALOME-MECA, CalculiX/PrePoMax | 비선형 implicit 주력·보조 경로의 실제 물리, 입출력, 자동화·배포 조건을 비교한다. 첫 연결에서 기존 CalculiX를 써도 주력 검토 방향은 남는다. | 모든 배포판·보조 GUI 설치가 첫 업무의 선행 조건, 또는 SALOME-MECA가 같은 FreeCAD 전처리 창을 대체해야 한다는 해석 |

| R17 — MFront/TFEL | 법칙·재료점·상태·접선·유한변형·지원 codegen/interface·동정 연구를 유지한다. | Material을 FE card 목록으로 축소, 모든 solver interface가 준비될 때까지 Material 착수 금지 |

각 후보에 필요한 판단은 “이 연구가 요구하는 기능을 어떤 입력과 결과로 실제 제공하는가”다. 등록 capability, 설치 탐지, adapter 지원, 수치 검증, 사용자 업무 수용은 다른 상태다. 설치되지 않은 후보가 있다는 이유로 이미 지원하는 계산이나 기존 결과 열람을 막지 않는다.

미지원 기능은 연구 범위에서 지우지 않고 해당 T작업의 구체적 지원 과제로 남긴다. 채택한 물리 기능의 실제 검증은 생략하지 않는다. 다른 후보의 미검증을 전 제품의 정지 이유로 사용하지 않는다.

### 4.2 v2 §12.3 — 마지막 요구 대응 문단 교체

현재 문장 “52개 원 요구는 기존 번호를 유지해 owner/작업/수용에 연결한다”는 모든 행에 제품 owner와 수용 시험을 만들게 할 위험이 있다. 뒤의 “완료 기준으로 만들지 않는다”만으로 이 혼합이 해소되지 않는다.

다음으로 교체한다.

> 원 번호는 요청 경과를 찾기 위한 참조로 보존한다. 실제 제품 결과와 정확성·편집·저장 원칙은 관련 owner·작업·실제 수용 장면에 연결한다. backend 후보 조사는 선택 근거와 지원 범위로, 개발 운영 규칙은 개발 절차로, 과거 Phase·일회성 초기 작업은 역사로 관리한다. 서로 다른 성격의 항목에 제품 기능이나 통과 시험을 하나씩 만들지 않는다. 후속 사용자 요구와 실제 업무에서 발견된 필요는 기존 번호 유무와 관계없이 반영한다. 원 번호나 UC/T/G 묶음의 합산 개수는 제품 완료를 판단하는 척도가 아니다.

§12의 “기존 문서에서 바꿀 항목” 표에도 R02/R45의 필수 AI 입구 해석, R06의 모델/Plan 소유, R23/R25–R31/R33/R50의 옛 순서, R36–R49의 개발·역사 분류를 추가한다. 기존 R17/R19 교정은 유지한다.

### 4.3 v2 §1.1 — backend 문단 보완

> backend 이름은 역할별 우선 검토 방향이다. 후보 전체의 설치·통합을 다른 기능의 착수 조건으로 삼지 않는다. 실제 연구가 요구하는 물리 기능·입출력·자동화·배포 조건에 맞는 경로를 선택하고, 그 경로의 등록 정보·설치 상태·adapter 지원·수치 검증을 구별해 확인한다. 다른 후보의 미설치·미검증으로 독립 문서 편집, 과거 결과 분석, 이미 지원하는 평가를 막지 않는다. Code_Aster/SALOME-MECA의 비선형 implicit 주력 후보와 OpenRadioss explicit 방향은 첫 연결에 기존 CalculiX를 사용해도 유지한다.

이는 원래 후보 검토를 취소하는 문구가 아니다. 지금 실제 선택이 필요한 범위의 검토를 수행하고 그 결과를 재사용하라는 뜻이다.

### 4.4 v2 §4.1 / §6.2 / §6.4 — 변수 등록과 연구 설정

§4.1의 변수 등록 문장 뒤와 §6.4 변수표 설명에 다음 의미를 반영한다.

> 등록 정보의 모델 허용 범위·읽기 전용/종속 상태와 Plan의 탐색 범위·고정/자유 선택을 구별한다. 모델의 의미·실제 native 대상·단위·타입·의존성·출처는 원 domain이 소유하고, 이번 탐색의 범위·고정/자유·공유/시험별 선택은 Plan이 소유한다. 한 Plan의 선택이 다른 Plan이나 원 모델의 제약을 바꾸지 않는다. 해당하지 않는 metadata를 필수 입력으로 요구하지 않는다.

Material의 계수·초기상태·protocol과 Plan의 변수·weight·holdout 소유 분리는 그대로 유지한다. 새 Registry나 별도 편집기를 만드는 변경이 아니다.

### 4.5 v2 §4.6 — 검사 표의 과거 결과 적용 범위

> 검사 표는 검사 대상의 정확한 개정, 기준/validator 버전, 근거 참조, 확인 시각과 현재 개정에 대한 적용 여부를 보인다. 이전 개정의 PASS는 과거 기록으로 열 수 있지만 현재 모델의 PASS로 자동 재사용하지 않는다. 영향이 없는 것으로 재사용하려면 그 대상·기준·입력의 동일성 근거를 남긴다. 실제 오류 행은 해당 객체·셀·3D 대상으로 이동한다.

다른 domain/Post에도 같은 검사 기록 의미를 적용한다. 모든 화면에 새 상시 패널을 추가하거나 모든 편집에 전체 검사를 다시 돌리라는 뜻은 아니다.

### 4.6 v2 §6.2 / §6.4 / §9.5.3 및 T19 — 보존 범위

> Plan의 실제 탐색·동정·DOE 후보에는 상세 출력 보존 선택과 무관하게 정확한 입력·평가/attempt·순서·상태·실제 응답·진단을 남긴다. 별도 기록 평가도 같은 최소 기록을 남긴다. 상세 출력/보존 정책은 실행 전에 고정하고, 해당 실행에서 보존하기로 정한 원본·native·곡선·field·표와 판단에 사용한 근거는 재실행 없이 열 수 있어야 한다. 보존 실패나 상세 출력 부재를 완전한 기록으로 표시하지 않는다. 임시 직접 평가와 엔진 내부 작업을 모두 영구 결과나 개별 job으로 강제하지 않는다. 이미 보존된 원자료·과거 결과는 덮어쓰지 않는다.
>
> 검색 이력에는 방법·seed·예산·후보 순서·반복/세대·중단 상태와 엔진의 재개 상태 지원 범위를 남긴다. 내부 상태 재개를 지원하지 않으면 이력 열람과 새 실행을 구별한다. 과거에 없던 상세 출력을 얻는 계산은 새 evaluation이며 과거 근거를 소급 대체하지 않는다.

T19 시험에는 최종 후보뿐 아니라 실제 Plan의 중간 후보와 실패 후보 열기를 포함한다. 임시 evaluation 전부의 영구 저장 여부를 새 수용 기준으로 만들지는 않는다.

### 4.7 v2 §9.3–§9.4 및 T02 — 비AI CLI/Python 경로

v2의 GUI↔MCP 표는 구체적이지만, 새 문서 명령을 CLI/Python에서도 사용할 구현 인계는 그 표만으로 충분히 드러나지 않는다. R21을 유지하려면 같은 명령 체계의 노출을 T02에 명시한다.

> CLI·Python API도 GUI/MCP와 동일한 domain 명령과 조회를 호출한다. 얇은 진입 wrapper가 문서/대상/단위와 실행 상태를 전달하고, 편집·검사·계산 로직을 다시 구현하지 않는다. 열린 native 문서를 대상으로 하면 동일 host/session/generation 계약을 사용한다. headless 실행은 자신의 명시적 문서·snapshot을 대상으로 하며 열린 GUI 문서를 제어한 것으로 표시하지 않는다. 비AI 사용에는 OpenScience·LLM 계정·MCP 클라이언트가 필요 없다.

T02에서 실제 제공하는 명령마다 해당 비AI 진입을 연결한다. 모든 명령의 CLI wrapper가 끝날 때까지 첫 native UI 작업을 멈추는 공통 관문으로 만들지 않는다. 새 명령 문자열 전체를 다시 설계할 사안도 아니다.

### 4.8 v2 §11.1–§11.2 — 옛 Phase와 현재 선행의 관계

§11.1에 추가한다.

> 원 ledger의 Phase 0–7과 R50의 초기 착수 순서는 당시 구축 순서로 보존한다. 현재 선행 조건은 해당 업무에 실제 필요한 문서 명령·파일·입력·adapter·결과 연결이다. T 번호의 앞뒤를 전체 완료 순서로 사용하지 않는다. 각 도구의 최소 편집·저장 계약이 준비되면 native 작업, 외부 결과 분석, 자료/재료/PDE 연구와 전문가 논의를 병행한다.

§11.2 마지막 “G0·G1은 작업 착수 순서” 문단은 다음으로 교체한다.

### 4.9 v2 §8.3 / T17·T19·T22 — 실제 시험 자료가 돌아오는 장면

> 사용자가 받은 실제 시험 자료를 시편·제작/장착 조건·측정 위치/방향·장비 및 교정 정보·시험 이력과 연결해 등록한다. 제공되지 않은 정보는 모르는 상태로 남긴다. 기존 예측과 정확한 관측량·단위·시각/위치를 맞춰 비교하고, 어떤 가설과 계수를 구별할 수 있는지 확인한다. 동정에 사용할 경우 학습/holdout 사용을 명시하고 새 모델 개정으로 채택한다. 이전 예측·원 시험자료·모델·판단은 유지한다. Expert는 이 결과를 열어 다음 구별 시험과 근거를 제안하며, 저장 후 같은 자료와 판단을 다시 연다.

Data는 자료·시험 metadata, Post는 관측/예측 비교, Numerical은 동정·holdout/채택 제안, 원 domain은 새 모델 개정, Expert/Study는 논의·채택 판단을 맡는다. 선택 Workbench가 없어도 이 연결은 가능해야 한다. 장비 직접 구동이나 모든 센서 수집 기능은 이 파일 기반 연구의 선행이 아니다. 실제 장비 연동은 별도 지원 경로로 남긴다.

### 실제 착수에 대한 권고

최소 공통 명령·파일 참조·저장과 Windows 시작을 해당 도구의 구현에 붙이고, FreeCAD–Runner–ParaView 왕복과 외부 Post 분석을 먼저 사용자에게 보여줄 연결로 유지한다. Data/Material 직접 평가, PDE 문서와 실제 지원 평가, Expert 토론은 각 선행이 준비되는 대로 병행한다. Numerical은 이미 준비된 평가기부터 사용한다.

선택한 law·접촉·열·explicit 기능의 정확성 확인은 그 기능을 실제 연구에 쓰는 작업과 함께 진행한다. 모든 backend 조사를 먼저 끝내거나 모든 물리 검증을 가장 뒤로 몰지 않는다. 첫 구현의 편집·저장·실제 명령 연결을 미루고 공통 framework나 참조 시안만 반복하는 흐름으로 돌아가지 않는다.

이 변경은 v2의 여섯 연결 보완을 재개방하지 않는다. command 상태/취소, 파일 등록, readiness/probe, 운동 자세 복원, 다른 mesh의 검증된 성공 경로, 재사용 연성 정의는 그대로 실행 작업에 남는다.

## 6. 실제 업무가 끝났는지 판단할 연속 장면

아래 장면은 설명용 수용 경로다. 또 다른 고정 개수의 완료표가 아니며 모든 독립 도구를 하나의 wizard로 묶지 않는다. 실제 사용자는 준비된 자료·문서·결과에서 시작한다.

### 지그를 고친 뒤 계산과 비교를 보고 다시 설계한다

사용자는 자신의 편집 가능한 부품/조립을 같은 FreeCAD 창에서 연다. 치수·피처나 지지/체결 대상을 수정하고, 관절·운동 미리보기에서 경로를 확인한 뒤 설계 자세로 돌아온다. 국부 메시 설정을 바꾸고 실제 품질과 영역·조건의 유효성을 확인한다. 끊긴 참조는 오류 행과 3D 선택으로 복구한다.

실제 지원 계산을 제출한 뒤 그 결과를 ParaView에서 연다. 기준 지그와 변경안의 같은 시험 응답·측정 위치를 비교하고, 허용되는 경우 실제 차이/변화율을 계산한다. 서로 다른 mesh의 field 차분은 검증된 명시 mapping을 사용하거나 차단한다. 판단 근거를 남기고 원 설계로 돌아가 한 번 더 수정한다.

저장·종료 후 새 프로세스에서 피처·조립·메시 설정·조건과 두 결과를 다시 열어 편집을 잇는다. 그림 두 장, STEP 하나, 고정 fixture script의 성공은 이 장면의 완료가 아니다. 실제 기준이 없는 강도/제작 판정은 UNKNOWN으로 남기되 저장과 비교 기능의 완료는 분명히 확인한다.

### 계산 프로그램 없이 외부 시계열을 분석한다

사용자는 승인된 폴더의 결과와 의존 파일을 등록해 Post에서 직접 연다. 실제 시간·필드·성분·단위·원 ID를 확인하고, 절단·원 지점 선택 또는 보간 probe·시간곡선을 만든다. 두 번째 결과를 추가해 위치/시간/물리량 대응을 확인하고 원값·차이·변화율을 저장한다.

원 파일 일부를 이동한 뒤 재열면 누락된 참조가 표시된다. 같은 내용의 파일을 새 위치에서 등록해 수리하고, 기존 필터·측정·비교·보기를 복원한다. 파일이 달라졌다면 새 입력으로 처리한다. CAD, 결과 생성 solver, AI 계정이 없어도 이 작업을 끝낸다.

### 자료와 재료 모델을 연구하고 중간 후보까지 다시 연다

열 순서·단위가 다른 시험 자료를 Data에서 정리하고 Material의 실제 law·계수·이력과 연결한다. 직접 평가와 과거 결과 비교를 수행한다. 같은 Numerical Plan으로 동정/holdout 또는 복수 변수 DOE를 실행해 실제 응답·실패·영향의 범위를 본다.

최종 후보뿐 아니라 기록된 중간 후보와 실패 후보를 열어 정확한 입력·응답·진단·보존하기로 한 결과를 확인한다. 선택한 계수를 Material의 새 개정으로 채택하고, 저장 후 이전 모델과 새 모델을 다시 비교한다. 임시 curve가 보존 결과처럼 보이거나, 과거 후보 선택이 숨은 재계산을 일으키면 통과가 아니다.

J2/DP처럼 실제 지원이 추가되는 law는 해당 모델의 기준 검증을 통과해야 연구 계산에 사용한다. 첫 탄성 예제를 재료 연구 전체의 완료로 표시하지 않는다.

### CAD 없이 PDE를 편집하고 필요한 경우 다른 물리로 전달한다

PDE 문서를 직접 열어 식/약형식·수학적 영역·space·BC/IC·계수를 편집하고 잘못된 draft도 저장한다. 선택한 실제 adapter가 준비되면 식이나 경계조건의 변경이 실제 해를 바꾸는지 확인하고 기준해·메시/증분 비교를 수행한다. 고정 예제의 숫자만 바꾸는 UI를 일반 방정식 연구라고 부르지 않는다.

열→구조 연구가 필요하면 저장된 평가 정의에서 단계 입력/출력·단위·기저·위치·시간 전달을 확인한다. 실제 계산한 온도장이 구조 입력에 들어가야 한다. 반복을 쓰는 지원 경로에서는 수렴/최대 반복·실패 단계·취소·재실행 범위를 실제로 구별한다. Plan이나 Workbench가 없어도 직접 평가 정의를 열고 저장·재개한다.

### 전문가와 가설을 논의하고 새 시험 자료로 판단을 바꾼다

사용자는 기존 실험 자료나 Post 결과에서 토론을 시작한다. 서로 구별되는 실제 전문가 발언, 논점별 근거와 반론을 열고 직접 참여한다. 잘못 연결된 자료를 바꾸거나 계산 계획을 편집하고, 실제 수치 엔진의 결과로 후속 질문을 이어간다. 답변 한 개를 여러 이름으로 보여주는 것은 다자 토론의 완료가 아니다.

나중에 실제 시험 결과가 들어오면 시편·장착·장비/게이지·교정·시험 이력을 원자료와 연결한다. 기존 예측과 비교해 재료 가정과 지그 효과가 구별되는지 확인하고, 새 학습 사용은 새 Plan 개정으로 남긴다. 충분한 근거가 없으면 판단을 보류하고 다음 구별 실험을 제안한다. 토론·자료·Plan·결과를 저장하고 같은 근거에서 이어한다.

장비 직접 제어가 없다는 이유로 이 파일 기반 실험 연구를 미뤄서는 안 된다. 실제 자료를 아직 받지 못했다면 공개/합성 자료로 기술 장면을 검증할 수 있으나 사용자 제품의 유효성이나 공학 승인을 입증한 것으로 쓰지 않는다.

### 각 장면에 공통으로 적용할 조작 확인

사람이 치수·계수·필터를 바꾸면 MCP/CLI/Python이 해당 실제 owner의 최신 값을 읽는다. AI가 유효한 변경을 적용하면 같은 열린 창의 실제 대상이 갱신된다. 오래된 입력·미확정 수동 편집·잘못된 단위/대상은 해당 명령과 객체에서 거절된다. 긴 명령·job의 취소 접수와 실제 종료를 구별하고 늦은 결과는 출발 입력에 남는다.

저장 실패, 프로세스 종료, 원 파일 이동 뒤에도 어떤 입력과 결과를 다시 열었는지 확인한다. 이 확인은 모든 도구에 같은 화면 틀을 강요하는 것이 아니라 현재 v2의 공통 계약이 실제 조작에서도 지켜지는지를 보는 것이다.

## 7. 앞으로의 보고와 종료 판단

보고의 첫 문장은 **이번에 사용자가 새로 끝낼 수 있게 된 업무**로 쓴다. 그다음 실제 입력·환경·행동과 결과 근거, 끝내지 못한 위치, 다음 연결 작업을 설명한다. 아래 형식은 보고 틀이며 완료 사실을 주장하는 예시는 아니다.

| 보고할 내용 | 기록 방법 |
|---|---|
| 사용자가 끝낼 수 있는 작업 | 실제 구현된 시작·편집·결과·저장/재개 범위를 평문으로 쓴다. 화면 이름이나 T번호만 나열하지 않는다. |
| 근거 | 해당 코드/버전·입력·환경, 실제 조작·계산·재열기 결과와 실패를 연결한다. 문서 검토·자동 시험·사람의 GUI 조작을 구별한다. |
| 남은 장애 | 미지원 물리, 끊긴 문서 연결, 설치 문제, 사용자 기준 미제공을 각각 구별한다. 전체 제품을 모두 OPEN 또는 모두 완료라고 덮지 않는다. |
| 다음 결과 | 앞선 장애나 사용자 업무를 실제로 해결할 연결을 적는다. 계획 질문 수·문서 수정 수·설치 수를 목표로 삼지 않는다. |

개발 통합 판정, 실제 사용자 업무 수용, 공학적 제작/사용 승인은 별도다. 필요한 사용자 물성·불량/공차·장비 기준이 없으면 공학 판정을 보류하되, 그 자료 없이 할 수 있는 구현·기술 검증·독립 분석은 계속한다.

**이번 요구 타당성 검토는 여기서 실행 인계로 마감한다.** 원 ledger의 현재 효력과 위 작업표만 반영하고 v2의 실제 연결 작업을 진행한다. 원 번호마다 다시 질문하거나 새로운 정기 기획 검토 회차를 만들 필요는 없다.

## 부록 B. 수정 범위와 최종 상태

**지금 반영할 문서:** PROJECT_SCOPE.md의 Authority and use와 ledger 현재 효력 표시, 제품 계획/관련 ADR의 겹치는 문구, v2 §1.1/§4.1/§4.6/§6.2/§6.4/§8.3/§9.3–9.5/§11/§12의 위 지정 부분. 같은 계약을 여러 곳에 복제해 서로 달라지지 않도록 주 설명 위치를 정하고 나머지는 참조한다.

**보존할 것:** 원 번호·원 설명 추출본·오래된 실제 실행/검토 이력, v1/v2 산출물, 기존 UI 도면 구조, 미완료 실제 구현 작업. 본 검토는 원본 의미를 지웠거나 새 v3 전체 기획을 완성했다는 기록이 아니다.
