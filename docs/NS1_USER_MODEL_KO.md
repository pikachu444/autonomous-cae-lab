# 사용자 고체 모델의 J2 소성 해석

요청: PRO-NS1-RESUME-20261014-02. 자료무결성 교정: PRO-NS1-CORRECTION-20261014-01. SPEC-PREFE-001 NS1 / AC-12·13.
구현 대상: FreeCAD 1.1.4, CalculiX 2.22, C3D10, STATIC, 등방 탄성/J2 등방 경화,
선택적 NLGEOM 및 기존 surface-to-surface LINEAR/Coulomb 접촉.

이번 제출은 사용자 모델에 적용하는 편집·동결·입력·실행 연결과 결과 읽기 코드다.
**Windows native FreeCAD→CalculiX→ParaView 전체 계산은 이 원격 환경에서 실행하지 않았다.**
아래 Windows 확인이 끝나기 전 NS1 전체 또는 AC-12·13 완료로 처리하지 않는다.
Python/Qt/Fortran 검사와 native API·계산 프로세스 대역 검사는 구분해 기록한다.

## 1. 모델 열기와 기본 재료 선택

기존 `scripts/start_cae_pre.ps1 -Source <모델.FCStd>`로 사용자 모델을 연다.
FreeCAD 안에서 기존 해석 모델과 C3D10 메시를 사용한다. 무접촉은 첫 범위에서
한 고체와 그 고체의 메시 하나다. 접촉은 기존 방식대로 body별 메시를 준비한다.
메시가 이전 형상에 연결돼 있거나 품질 검사를 통과하지 못하면 수정·재생성한다.
실행을 위해 기존 native Analysis, CalculiX 설정, 기본 고체 재료와 하중/구속이 필요하다.

해석 모델 창의 **재료** 탭에서 해석과 기본 재료를 선택한다. **선택 따라가기**는
현재 native 선택에 대응하는 재료를 찾는다. 재료 적용 영역에 표시된 body가
실제로 계산할 body인지 확인한다. 첫 범위는 body 전체의 명시 재료 할당이며,
같은 body를 여러 재료로 분할한 내부 부분영역 지원을 의미하지 않는다.
전체 고체를 대상으로 한 native 기본 재료도 지원하지만 중복·모호한 할당은 거절한다.
기존 E와 포아송비는 **탄성 적용**으로 설정한다. 소성 적용이 E를 다시 추정하지 않는다.

## 2. 소성 표 입력, 저장, 적용

법칙을 **J2 등방 경화**로 바꾸고 진응력과 등가 소성변형률 두 열을 입력한다.
행 추가·삭제와 Ctrl+V 두 열 붙여넣기를 사용할 수 있다. 응력 단위는
Pa/kPa/MPa/GPa, 소성변형률 단위는 무차원 [1]/퍼센트 [%]를 선택한다.
체크 상자로 진응력–등가 소성변형률 정의를 확인한 다음 **재료 적용**을 누른다.
공칭응력을 진응력으로, 전체변형률을 소성변형률로 자동 변환하지 않는다.
단위만 명시적으로 MPa와 무차원 값으로 변환한다.

첫 점의 소성변형률은 0, 항복 진응력은 양수여야 한다. 이후 소성변형률은
엄격히 증가하며 항복응력은 감소할 수 없다. 일정 항복응력의 완전 소성 구간은
허용한다. NaN, 무한대, `1e` 같은 미완성 값, 온도 3열, 행 순서 오류는 실행을 막는다.
**오류 행**은 첫 수정 위치를 선택하고 표 머리글에도 `!`를 표시한다.

**초안 저장**(Alt+S)은 잘못된 값과 201점 이상의 표도 원문 그대로 문서에 보존한다.
그 뒤 기존 문서 저장을 수행하면 `.FCStd` 및 Lab 프로젝트 저장·재열기 경로에 포함된다.
새 창에서 **저장본 읽기**로 확인하고 수정한다. 저장 자체는 native 재료 적용이나
계산이 아니다. 이전에 정상 적용한 표가 있어도 미적용 초안이 있으면 그 옛 표로
몰래 계산하지 않는다. **재료 적용**(Ctrl+Enter) 후에만 실행 입력으로 채택한다.
표·E/포아송비·NLGEOM에 아직 화면 편집이 남아 있으면 입력 생성/실행이 차단된다.

원곡선의 문자열과 단위를 별도로 보존한다. native YieldPoints 및 PLASTIC 입력은
기존 `native_number`의 **유효숫자 13자리, 숫자 토큰 최대 20자** 정책을 사용한다.
13자리 출력에서 서로 다른 소성변형률이 같은 값으로 반올림되면 해당 행을 수정하도록
막는다. 원 입력을 잘라 덮어쓰지 않는다. 좁은 표의 읽기 표시는 지수를 숨기지 않도록
축약할 수 있으며 셀 편집/도움말에는 원문을 유지한다. 화면 축약은 solver 정밀도가 아니다.

**첫 실행은 최대 200점**이다. 201점은 저장·재열기 가능하지만 적용·동결·deck 생성
모두 차단한다. CalculiX의 자동 200점 재보간을 묵시적으로 허용하지 않으며,
제품이 임의로 곡선을 단순화하지 않는다. 사용자가 곡선을 검토하고 직접 줄여야 한다.
명시적으로 등방 탄성으로 바꾸면 native 소성 객체는 삭제하지 않고 억제한다.
따라서 나중에 소성 곡선을 다시 편집할 수 있다.

**native에서 재료를 변경한 뒤:** 같은 기본 재료에 소성 객체를 새로 추가하거나
기존 객체를 교체·억제·삭제한 경우 마지막 적용 상태와 다르면 실행을 차단한다.
특히 등방 탄성을 적용한 뒤 새 활성 J2를 추가해도 그 재료가 몰래 계산되지 않는다.
저장한 원초안은 그대로 남고 적용 상태는 해제와 오류로 표시된다. native 객체의
대상·법칙·곡선을 확인하고 사용할 표를 명시적으로 **재료 적용**해야 한다.
같은 기본 재료의 소성 객체가 여러 개이면 사용할 객체를 사용자가 정리해야 한다.
프로그램은 임의로 하나를 선택하거나 옛 원곡선을 새 객체의 출처로 붙이지 않는다.
다른 기본 재료의 정상 활성 소성 객체까지 이 재료의 오류로 취급하지 않는다.

## 3. 해석 단계, 기하 비선형, 기존 접촉

**기하 비선형 (NLGEOM)**을 선택하고 **기하 설정 적용**을 누른다.
재료 비선형과 기하 비선형은 별개의 설정이다. 첫 J2 경로의 절차는 STATIC이며
기존 해석 단계 편집기의 증분·단계·조건 곡선을 사용한다. 단계별 NLGEOM 혼합이나
J2 동적 해석을 이번 지원으로 간주하지 않는다. 기존 선형 동적 경로는 보존한다.

지원되는 기존 TIME INCREMENTATION 제어의 두 입력 행은 그대로 사용한다.
새 범용 Newton line search 옵션을 추가하지 않았다. Penalty contact에 종속된
line search와 일반 해석의 Newton 옵션은 다르다. CalculiX 2.22가 지원하지 않는
`STATIC,STABILIZE`는 생성하지 않으며 해당 안정화 에너지도 제공되는 것처럼 표시하지 않는다.
그 외 새 수렴 허용오차 편집기나 stdout 잔차 곡선 파서는 이번 제출의 잔여다.

두 물체 접촉에서는 기존 **접촉** 탭의 A/B 면 선택과 LINEAR 압력–간극 강성,
Coulomb 마찰 및 stick 강성을 그대로 사용한다. 소성 재료 때문에 접촉을 삭제하거나
다른 법칙으로 바꾸지 않는다. 기본 재료별 native LinearBaseMaterial 링크를 검사하고
실제 메시의 요소 집합과 연결한다. 선형 재료 body와 J2 body의 혼합도 허용한다.

## 4. 입력 준비, 명시 실행, 실패 수정

기존 입력 준비/내보내기로 동결 입력을 만든다. 입력 준비만으로 계산은 시작하지 않는다.
무접촉 NS1도 별도 solver 없이 기존 freeze/CalculiX adapter/JobManager 경로를 사용한다.
동결 시 설치된 FreeCAD PLASTIC writer를 detached 자료로 호출해 native 재료 입력을
대조하고, 기존 접촉 입력 확인도 유지한다. 원 문서·원곡선은 이 확인 중 수정하지 않는다.
실제 입력에 대상 body의 요소 집합, `*ELASTIC`, `*PLASTIC`, STATIC/NLGEOM,
지원 수치 제어 및 필요한 S/E/PEEQ 출력 요청이 있는지 확인한 뒤 명시 실행한다.

Runner에서 선택 시도의 입력·로그·증분·결과를 연다. **취소 요청**과 실제 계산 종료는
기존 JobManager 상태로 구분한다. 실패한 폴더에 덮어쓰지 않는다.
계산 단계 창의 **이 계산의 조건 수정…**은 현재 다른 작업 중인 원 모델이 아니라
해당 시도에 보존된 편집 입력을 연다. 조건을 수정하고 새 계산을 생성한다.
기존 실패 입력·로그·수렴한 부분결과는 원 시도에 그대로 남는다.

## 5. 결과 의미와 재열기

ParaView용 결과에는 출력된 항목만 연결한다. 응력은 `SXX_MPa` 등 6성분,
전체변형률은 `EXX_1` 등 6성분, 등가 소성변형률은 **`PEEQ_1` 한 성분**이다.
Runner 응답 이름은 `stress`, `total_strain`, `nodal_force`, `PEEQ`다.

TOSTRAIN(E)은 NLGEOM on에서 **Green–Lagrange**, off에서 **미소 변형률**이다.
전단 성분은 공학 전단변형률이 아니라 텐서 전단변형률이다. FRD의 PE는
소성변형률 텐서가 아니라 누적 등가 소성변형률 PEEQ다. 응력/변형률의 위치는
native 적분점 결과를 외삽·절점 평균한 값으로 기록하며 적분점 원값이라고 하지 않는다.
FORC의 FX/FY/FZ는 **절점력**이며 전 절점 값을 모두 반력이라고 부르지 않는다.
반력 판단에는 구속 자유도와 적용 하중을 구분해야 한다.

출력되지 않은 필드는 unavailable이다. 일부 프레임에만 있는 필드는 해당 없는
프레임을 NaN과 `*_valid=0`으로 표시한다. 미출력을 물리값 0으로 채우지 않는다.
필수 출력이 없는 정상 종료는 성공 결과로 승인하지 않고 읽기 실패로 남긴다.
실패 중 출력된 best solution을 수렴 결과로 승격하지 않는다. STA의 수렴 증분과
일치하는 연속 부분결과만 보존하며 잘린 프레임의 값을 보간하지 않는다.

취소/실패 직전 마지막 수렴 증분의 FRD가 EOF에서 잘리면 **그 증분 전체**를
파생 읽기 사본에서 제외한다. 예를 들어 STA에는 1·2증분 수렴이 있지만 2증분
PEEQ 기록이 중간에서 끝났다면 Post에는 완전히 기록된 1증분까지만 연결한다.
2증분의 S/E만 남겨 완전한 결과처럼 표시하거나 PEEQ를 0으로 만들지 않는다.
필드 사이에서 파일이 끝나 필수 채널이 아직 기록되지 않은 경우에도 같은 원칙이다.
반면 모든 요청 필드가 완전히 기록되고 파일의 최종 종료 표식만 빠졌다면 해당
증분까지 보존한다. 원 FRD/STA와 실행 상태는 수정하지 않는다.

이 복구는 EOF 절단에 한정한다. 중간의 잘못된 값·라벨·절점, 닫힌 필드의 누락 행,
잘못된 종료 표식은 읽기 오류로 남긴다. 완전한 첫 증분조차 없으면 부분결과가 없다.
기술 기록의 partial_result.frd_retention에는 원파일 해시/크기, 제외 시작 행과
last_retained_increment가 남는다. STA의 last_converged와 이 값을 혼동하지 않는다.
계산 상태는 여전히 FAILED/CANCELLED이며, 재계산 없이 읽을 파생 사본은
`partial/committed.frd`, 저장 Post는 `partial/post/contact.pvd`다.

증분 표는 단계/증분/시도/반복수/증분 크기와 원 STA 행을 보존한다.
거절 시도와 실제 관측된 증분 축소만 센다. STA에 없는 잔차/안정화 에너지는
0이나 임의 추정값으로 만들지 않는다. 원 stdout 로그는 별도로 열 수 있다.
STATIC의 누적·단계 진행값은 물리시간 [s]나 실행 경과시간이 아니다.
여러 독립 하중 곡선이 있으면 이를 모든 하중에 공통인 하중계수라고 부르지도 않는다.
실행 경과시간(wall time)은 Runner 작업 시각으로 읽는다.

**저장된 결과 열기**는 보존 Post 입력을 연다. 실패·취소 시 이미 만든 부분결과와
`partial/committed.frd`도 새 프로세스에서 solver 재실행 없이 다시 읽는다.
기존 `--rebuild-post-from` 명령의 원출력→Post 재생성은 성공 시도에 한정된다.
실패 시도의 파생 사본이 사라진 경우까지 이 명령이 복구하도록 확장한 것은 아니다.
원 파일의 식별/내용 검사는 유지하며 변경된 원자료를 옛 결과로 몰래 표시하지 않는다.
기존 Post 프로젝트 저장·재열기와 원자료 복구 경로는 변경하지 않았다.

## 6. 공개 모델로 Windows에서 확인할 범위

단일 body는 `examples/material-tests/ns1/create_single_solid.py`로 만든 형상 또는
사용자의 작은 단일 고체로 확인한다. 생성 스크립트는 원격에서 native 미실행이다.
두 body는 기존 `examples/contact/two-feet.FCStd`를 사용한다. 예제 이름으로만
계산되는 분기는 없다. 물성표 예시는 같은 폴더의 `j2_example.tsv`다.

Codex는 두 모델 각각에서 실제 C3D10 메시를 생성하고 재료·구속·하중을 지정한다.
선형 한계, NLGEOM, J2+NLGEOM, 기존 LINEAR/Coulomb 접촉을 구분해 실행하고
입력의 실제 요소 집합과 S/E/PEEQ 결과를 비교한다. 임의 허용치를 만들어 물리
정확성 통과로 처리하지 않는다. 201점 및 미완성 입력 저장→앱 종료→재열기→수정,
실행 차단 행, 실패 조건 수정 후 새 시도, 원 실패 보존, 실행 취소, 새 FreeCAD/ParaView
프로세스에서 재계산 없는 재열기를 확인한다. 해당 native 확인과 Astra 독립 검토는
이번 원격 검사로 대체되지 않는다.

## 개발자 연결과 호환

기존 `schema_version='1'`과 `structure.calculix.contact` 실행 계약을 유지한다.
단일 body에는 선택 필드 `analysis_scope='single_solid_static'`을 추가한다.
기존 접촉/선형 입력에는 필드가 없어도 된다. J2 재료는 law와 plasticity를 추가하고
기존 탄성 E/포아송비 및 body 할당은 유지한다. 문서 metadata의 선택 목록
`plasticity_drafts`는 분석/기본 재료별 원문·마지막 적용 상태를 저장한다.
이번 교정도 기존 applied_draft/applied_native 구조를 그대로 읽는다.
등방 탄성은 활성 소성 객체 0개, J2는 적용 당시 객체 1개와 같은 signature를
요구하며 새 저장 필드나 자동 데이터 변환을 추가하지 않는다. 부분결과의
frd_retention은 선택적 부가 기록이며 기존 성공/실패 상태 계약은 유지한다.
구버전이 J2를 선형으로 조용히 실행하도록 허용하지 않는다.

추가 typed 명령은 `pre.fem.plasticity_read`, `plasticity_save`, `plasticity_apply`,
`nonlinear_settings`이며 GUI와 기존 command owner를 공유한다. 새 스케줄러,
새 solver, 새 결과 소유자를 만들지 않았다. motion/Data/Post 원자료/CAD 복구 파일은
이 NS1 제출에서 수정하지 않는다.
