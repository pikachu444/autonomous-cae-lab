# Backend research gates (official documentation; not yet executed here)

The working roles below are hypotheses for staged benchmark work. The current executable adapter is CadQuery fixture CAD. A feature listed in a manual is not a validated CAE-Lab capability.

| Workload | Candidate and adapter boundary | First proof / gap |
| --- | --- | --- |
| Nonlinear implicit | Code_Aster `run_aster` with `.comm/.export`, MED output; SALOME SMESH/AsterStudy GUI. CalculiX/PrePoMax comparison. | First elastic fixture mesh and balanced reactions, then separate plasticity/contact benchmarks. Preserve command, logs and MED. Contact convergence needs real study. |
| Explicit | OpenRadioss Starter/Engine native deck; tools include `inp2rad`. | Impact benchmark with initial velocity, contact, energy balance and raw/VTK artifacts. Conversion does not establish full card coverage; evaluate rigid, sensors, failure, composites and output controls. |
| General weak-form PDE | FEniCSx UFL forms/AD/PETSc, pinned release; GetDP+Gmsh GUI; FreeFEM/GetFEM alternatives. MOOSE for later multiphysics. | Poisson with analytic error and converged mesh sequence; preserve form source and field results. FEniCSx Windows path is WSL/Docker; verify exact version APIs. |
| Constitutive | MFront/TFEL generated behavior, MTest material-point and tangent checks. | Stress-integration paths, numerical Jacobian comparison, finite-strain assumptions and versioned behavior binary before Code_Aster coupling. |
| DOE/UQ/optimization | DAKOTA external interface as first black-box candidate; OpenMDAO for MDO, pymoo for multiobjective, SciPy/NLopt for small tasks; PETSc TAO/MOOSE for PDE-constrained. | Deterministic seed/state, failed-design penalty policy and replayable two-variable fixture search **after** solver metric is connected. |
