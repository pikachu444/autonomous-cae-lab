# 자료 토론과 인용 보고서

작성 기준: Stanford OVAL STORM fb951af7744dab086e34962e9bc6fe878e145f83의
CoStormRunner, warm_start, step, KnowledgeBase.reorganize, generate_report를
이름 공간이 분리된 MIT 소스로 재사용합니다. 기존 역할 순차 응답은 별도 모드로 유지합니다.

## 이번 제품 연결

선택한 보관 자료 → 배경 조사/여러 관점 → 진행자의 다음 논점 → 사용자 참여 →
실제 자료로 갱신되는 논점 지도 → 인용 보고서입니다. 각 시작/계속/다시 시도/
보고서 작성은 기존 experts.ask JobManager 작업 하나이며, 현재 전송 허용과
한도를 적용합니다. 읽기·저장·재열기는 모델을 호출하지 않습니다.

초기 조사는 한 번의 모델 호출보다 많은 요청이 필요합니다. 한도나 취소로 중단되면
완료된 원문 응답과 마지막 완료 상태를 기존 작업 결과에 보관합니다. 사용자가
다시 시도할 때 같은 중단 작업을 재구성하고, 이미 완료된 동일 요청은 재사용합니다.
한 번의 조작 내부에서 호출 한도를 자동으로 늘리지 않습니다. 새 명시적 조작의
사용량과 토론 전체 누적 사용량을 구별합니다. 모델이 실제 토큰 수를 제공하지
않으므로 토큰 수는 미확인입니다.

질문·역할·자료 선택은 기존 문서에 있습니다. 생성된 관점 이름은 토론 역할이며
학습된 전문 자격이 아닙니다. 선택한 등록 역할의 공통 자료 범위를 사용하고,
첫 등록 역할의 명시된 모델을 공용 모델로 사용합니다. 생성된 역할이 자료 권한,
도구, 모델 또는 계산 실행 권한을 늘릴 수 없습니다. 기존 역할별 모델 호출이
필요한 작업은 '역할별 답변' 모드를 그대로 사용할 수 있습니다.

## 재사용과 경계

- 기존 KnowledgeStore의 정확한 document/revision/locator와 BM25 검색을 사용합니다.
  같은 분류의 선택하지 않은 자료나 최신판을 대신 보내지 않습니다.
- 기존 OpenScience 로그인 호스트의 단일 완료 호출을 명시적 텍스트 어댑터로
  연결합니다. Bing, 유료 임베딩, API key, 다른 공급자 fallback은 없습니다.
- 공식 DSPy2.4.9(OpenAI<2)와 현재 Haystack3.3(OpenAI>=2.6)는 의존성이 충돌합니다.
  core 패키지를 낮추거나 별도 모델 환경을 만들지 않고, 이 upstream에서 쓰는
  Signature/Predict/ChainOfThought의 작은 텍스트 경계만 이름 공간 안에 구현했습니다.
  전체 DSPy 호환을 주장하지 않습니다. 세부 변경·MIT 고지는 vendored NOTICE에 있습니다.
- 논점 배치의 벡터 순위는 로컬 단어/문자 벡터입니다. 의미 임베딩 모델을
  설치·실행했다고 표시하지 않습니다. 논점 생성/삽입/재구성과 진행자 정책은
  실제 upstream 모듈이 수행합니다.
- 모델이 없는 원문 번호를 인용하면 사실인 인용으로 보정하지 않습니다.
  본문/번호/원문 연결은 정확한 저장 자료를 사용하며 보고서의 누락은 표시합니다.
- 프로토콜 상태는 기존 작업 결과와 대화 저장본에 보관합니다. HTTP/model 요청은
  runner state를 직접 주입할 수 없습니다. owner가 준비한 작업 및 이전 작업
  관계를 확인한 뒤에만 복원합니다. 임의의 새로운 저장소/메일함은 없습니다.
- 일시 정지는 현재 응답 이후를 멈추며, 현재 응답 취소는 기존 JobManager 취소입니다.
  프로세스 종료가 미확정이면 기존 CLEANUP_PENDING을 유지합니다.

## 확인 범위

Pro 원격 Python/Qt/provider 실행: NOT_RUN (실행 환경 연결 불가).
tests/test_costorm_protocol.py는 실제 upstream 진행/삽입/보고서와 기존 owner를
명시적 scripted completion 대역으로 검사하도록 작성했습니다. 대역 응답을 실제
AI 토론으로 표시하지 않습니다. 실제 기존 로그인 모델의 이 텍스트 경계 호환,
Windows Qt 배치/조작은 Root 실행 후 별도로 기록해야 합니다.

공식 원본:
https://github.com/stanford-oval/storm/tree/fb951af7744dab086e34962e9bc6fe878e145f83
https://aclanthology.org/2024.emnlp-main.554/


## Qt에서 사용하는 순서

1. 기존 설치의 독립 Expert를 엽니다: Start-CAE-Lab.cmd -Tool expert.
   연결은 기존 OpenScience 설정을 사용하며 연결 확인·파일 열기만으로
   질문을 전송하지 않습니다.
2. 새 대화에서 **자료 토론 (Co-STORM)**을 선택합니다. **참고 자료**에서
   파일 또는 저장 자료를 고르고, **참여 역할**과 **전송 설정**을 확인합니다.
   모든 선택 역할이 읽을 수 있는 공통 자료 분류와 해당 저장본만 사용합니다.
   질문과 선택 자료에 대한 사용자·운영자 전송 허용이 모두 필요합니다.
3. 질문을 입력하고 **토론 시작**을 누릅니다. 초기 배경 조사에는 여러 번의
   모델 호출이 필요합니다. 한도를 자동으로 늘리지 않습니다. 제한에 도달하면
   중단 이유를 확인하고 한도를 명시적으로 편집한 뒤 **다시 시도**할 수 있습니다.
4. 중앙에는 실제 생성된 발언이 나타나고 왼쪽 지도는 원본 Co-STORM이 구성한
   실제 지식 트리입니다. 논점을 선택하면 연결 발언으로 이동합니다. 발언을
   고르면 연결 논점을 보여 줍니다. 번호 인용은 그 번호의 정확한 원자료를 엽니다.
5. 의견을 입력하고 **참여하기**를 누르면 사용자 발언을 보관하고 다음 단계에
   반영합니다. 현재 응답 작성 중이거나 일시 정지 상태이면 다음 명시적
   **다음 발언**까지 의견을 보관합니다. 보낸 입력만 비우며, 요청 처리 중
   새로 쓴 미전송 입력은 보존합니다. 빈 입력에서는 **다음 발언**으로 관찰을
   계속할 수 있습니다. **일시 정지**와 토론 메뉴의 **현재 응답 취소**는 다릅니다.
6. **보고서**에서 **보고서 작성**을 누르면 실제 공유 지식의 재구성과 보고서
   작성을 요청합니다. 인용 자료를 눌러 원문을 열고, **저장**으로 대화와 보고서를
   함께 보관합니다. **내보내기**는 Markdown/HTML을 로컬 파일로 저장합니다.
   출력 참고문헌에는 자료 저장본·위치 또는 계산 입력·선택이 포함됩니다.
   없는 원문은 '원자료 없음'으로 남습니다.
7. 대화를 다시 열면 보관된 발언·논점·보고서를 읽습니다. 재열기·내보내기로
   새 모델 작업을 만들지 않습니다. 기존 순차 역할 모드의 실제 계산 제안,
   편집 가능한 Plan과 원 대화/Study로 결과를 돌리는 경로는 그대로입니다.
   이번 upstream 토론 어댑터가 새 계산 제안을 자동 생성한다고 주장하지 않습니다.

역할·선택 자료·모델 설정을 바꾸어 새로운 자료 범위로 토론하려면 새 대화를 사용합니다.
기존 토론의 자료를 새 최신판으로 조용히 교체하지 않습니다. 계산 결과는 기존
명시적 첨부/전송 허용으로 추가할 수 있고, 과거 토론에서 사용한 결과를 제거하면
그 기록을 전송할 수 없으므로 계속 진행을 차단합니다.

## 작성 파일과 실행 확인

실제 upstream 엔진/모듈은 caelab/assist/_vendor/costorm/에, 기존 host/자료/
한도 어댑터는 caelab/assist/costorm.py에 있습니다. discussion_costorm.py는
기존 DiscussionDocuments의 작업 준비·수집 함수이며 별도 owner가 아닙니다.
Workbench의 owner 작업 확인과 기존 ExpertRuntime 분기만 연결했습니다.

Qt 변경은 apps/research/expert_window.py, discussion_view.py,
costorm_report.py입니다. 기존 문서 명령으로 시작/개입/한 단계 진행/보고서/
재시도를 요청합니다. 전달이 미확정인 HTTP 명령을 다시 누르면 동일 command를
사용하므로 사용자 발언이나 작업을 중복 생성하지 않습니다.

작성한 집중 검사:
python -m pytest tests/test_costorm_protocol.py tests/test_costorm_protocol_ui.py -q

실제 runner와 기존 문서 저장 경계를 사용하되 텍스트 생성/모델 호스트는
명시적 대역입니다. 거절된 응답이 후속 정상 응답보다 먼저 완료된 경우의
정확한 재시도, 자료 권한, 미선택 자료 제외, 개입→논점→인용 보고서, Qt 조작,
저장 재열기/출력을 포함합니다. **Pro 원격 실행은 NOT_RUN**입니다.
실제 로그인 모델로 이 프롬프트 경계가 동작하는지, Windows 실제 Qt 화면의
읽기와 배치가 충분한지는 Root 실행/사용자 검토와 별도입니다.

범위 인계: 기존 Post 관측 자동 읽기의 request_plan_window.py /
result_return.py 수정은 최신 역할 배분에 따라 Root/Sol 소유입니다.
이 묶음은 그 두 파일과 Root의 CURRENT_STATE, SPEC, 한국어 일반 사용법을
수정하지 않습니다. Study의 작은 표시/배치 수정도 포함하지 않았습니다.
