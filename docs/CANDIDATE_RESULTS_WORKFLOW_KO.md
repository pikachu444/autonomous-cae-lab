# 후보 상세와 보존 근거

Numerical에서 원 피팅 실행과 후보를 선택하고 **선택 후보 상세…**를 연다.
RequestPlan의 피팅 후보도 같은 기존 전용 창을 사용한다. 분야별 일반 결과창을
복제하거나 다른 fit·결과 저장소를 만들지 않았다.

## 결과 읽기

왼쪽 시험을 선택하면 곡선과 원값·잔차 표가 같은 후보·상세 실행·시험을 표시한다.
피팅 포함, 관측 유효, 원행, 가중치와 척도는 원 피팅 입력에서 읽는다. 별도 확인
시험은 목적함수에서 제외하며 결과 확인을 공학 승인으로 바꾸지 않는다.

**보존됨**은 원출력이 있다는 뜻이며 성공과 다르다. **미보존**, **미평가**,
**곡선만 보존**, **일부 출력**도 구분한다. 없는 예측·원출력·잔차를 0이나 이웃 값으로
채우지 않는다. 원 후보의 상태와 후속 상세 실행의 상태는 별도로 읽는다.

이전 상세 실행이 있으면 **최신 상세 선택**으로 이미 계산된 결과를 먼저 확인한다.
원계산의 상세가 없다는 이유로 계산을 다시 시작하지 않는다. **미보존분 계산**은
사용자가 명시할 때만 기존 원 입력과 같은 후보 계수로 필요한 미보존 시험을
새 ID에서 평가하는 기존 명령이다. 선택·재열기·새로고침은 실행 명령이 아니다.

## 비교·보고·채택

1. **선택 결과 저장**은 해당 후보의 실제 상세를 기존 계획의 불변 개정에 보존한다.
   성공 결과와 실패·취소 진단은 목적을 구분한다.
2. 비교 후보와 상세 실행을 선택하고 **선택 시험 비교**로 정확한 두 근거를 사용한다.
   선택한 시험의 비교를 모든 시험의 판정이나 자동 후보 순위로 확대하지 않는다.
3. **보고서 열기**는 같은 근거 참조의 원값·예측·잔차·실패를 실제 보고서 자산으로
   보관한다. 요약만 있는 후보 등록을 상세 출력으로 취급하지 않는다.
4. 계수 채택 전에는 원 계획에서 제안을 확인한다. 취소하거나 대상이 변경되어
   거절되면 기존 Material과 이전 후보·실패·결과를 유지한다. 계수 값이 같아도
   열린 원 입력의 개정이 바뀌었다면 현재 상태를 다시 확인하고 명시적으로 연결한다.

확정 HTTP 400 거절은 **요청이 거절되었습니다**로 표시한다. 전송 전에 계획의
session/generation이 바뀐 경우에는 요청하지 않았다고 안내한다. 통신 중 응답이
유실되었거나 접수가 불명확하면 이와 구분해 **처리 결과를 확인하지 못했습니다**로
남긴다. 원 진단은 툴팁에 보존한다. 다시 읽기로 실제 접수 상태를 확인하며 창 닫기나
통신 단절을 취소 성공으로 취급하지 않는다.

## 이번 인수 범위

2026-10-18에는 기존 공개 합성 case02의 원 피팅·C000010과 이미 실행된 C000000
상세를 재사용했다. C000000의 원 피팅 시험은 보존되어 있었고, 원 holdout은
미보존·미평가였다. 기존 상세 실행을 선택하면 둘 다 보존 결과로 읽힌다. 이것을
새 평가나 원 holdout 기록의 소급 변경으로 세지 않았다.

기존 실패 후보는 별도 합성 대수 예제에서 읽었다. 실패 예측은 미제공으로 유지했고
실패 진단 근거를 저장한 뒤 새 owner에서 같은 불변 참조를 확인했다. 이 예제는
재료 물리 계산의 인수 근거가 아니다.

C000010 상세창에서 실제 보고서 자산을 저장하고 별도 프로세스에서 같은 자산·상세
참조·내용 해시를 읽었다. 기존 채택 성공 receipt와 현재 원 Material 변경에 따른
거절은 구분했다. 두 Client의 별도 메타데이터 반례에서는 단위 편집 후 Undo로
동일 계수·동일 초안이 돌아와도 이전 generation의 요청이 HTTP 400으로 거절됐다.
이 반례를 새 후보 채택 성공으로 부르지 않는다.

관련 저장의 부분 실패는 기존 corrected C1 공개 ZIP과 B8의 이미 완료된 cold/재열기
근거를 재사용했다. `PARTIAL`, `all_saved=false`, `link_published=false`와 대상별
SAVED/FAILED/BLOCKED를 그대로 유지한다. 이는 관련 저장의 부분 실패이며 재료점
계산의 부분 출력과 다르다. 현재 B8의 처리 Data 이동 사본 인수를 대신하지 않는다.

새 fit·detail evaluation·native solver·provider 호출은 모두 0이다. 일반/좁은
Windows Qt 창, 선택·읽기·거절 후 복구와 소유 프로세스 정리를 확인했다. 물리 OS
입력 자동화와 실측 물성·공학적 적합성 승인을 주장하지 않는다.
