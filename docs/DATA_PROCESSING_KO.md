# Data 처리 단계와 결과 보관

Data에서 원본 파일의 열·단위를 지정하고 **가져오기**를 마친 뒤 결과를 선택한다.
**편집 → 처리 단계…**에서 입력/출력 채널과 설정을 지정한다. 단계는 추가·수정·삭제하거나
순서를 바꿀 수 있다. 출력 이름은 원본 채널과 구별해야 한다. 단위 변환, 표점 연신량의
공학 변형률, 신장비, 공칭 응력, 영점 이동, Savitzky–Golay 필터, 시간 재표본화는
실제 서비스의 처리 엔진을 사용한다. 측정하지 않은 크로스헤드 보정이나 Cauchy 응력
변환을 추정하지 않는다.

**처리 단계 설정**은 해당 창의 편집만 바꾼다. **설정 적용** 후
**편집 → 처리 미리보기…**에서 단계별 성공·실패, 유효/제외 수, 출력 곡선과 값을
확인한다. 취소하면 처리 결과를 보존하지 않는다. **처리 결과 보존**은 검토한
미리보기를 그 Data 문서에 남긴다. 이후 **저장**으로 원본과 처리 결과를 함께
보관하고, **편집 → 보존한 처리 결과…**에서 다시 연다.

단계가 실패하면 해당 출력의 이유를 표에서 확인할 수 있다. 다른 출력의 성공이
전체 처리 성공을 뜻하지 않는다. 제외된 구간은 곡선을 나누어 표시한다. 표는 처음
1000개 표본을 표시하며 전체 처리 결과는 서비스에 보존된다. 파생 표본에 원본 행
번호를 임의로 붙이지 않는다. 처리 결과 화면의 선택은 Plan의 학습·검증 정책 채택이
아니며 이 변경은 피팅이나 재료 계수 채택을 시작하지 않는다.

## 처리 표본을 피팅에 연결

공통 계산 경로는 보존한 처리 결과의 정확한 표본·좌표·사용 구간·가중치를 받아
피팅과 후보 상세 결과까지 전달한다. 재표본화한 값을 원본 행 번호로 바꾸지 않으며,
같은 원자료를 공유하는 학습·검증 표본은 별도로 검사한다. 정책을 미리 보는 동작과
계산 계획에 명시적으로 적용하는 동작은 구별한다. 자료나 곡선을 읽기만 해서는
피팅을 시작하거나 계수를 채택하지 않는다.

이 공통 연결은 작은 합성 시험과 실제 문서 소유자·작업 관리 경로로 확인했다.
피팅·선택 후보의 상세/검증 결과를 보존하고, 원 입력과 실행 결과를 제거한 뒤
새 경로·새 Python 프로세스에서도 같은 저장 결과를 읽었다. 실제 재료 법칙의
수치 검증이나 표본 정책을 선택하는 전체 GUI의 완료를 뜻하지 않는다. 해당 화면
연결은 Data·Numerical 담당이 이어서 개발한다.

## 확인 범위

2026-10-15 초기 실제 Pro 처리 엔진과 C1 전용 모듈을 격리된 전체 소스에 연결해
검사했다. 실제 LabHTTPServer, Data 소유자와 표 가져오기 작업으로 로컬 단계 편집,
미리보기 취소, 명시 보존, 저장과 재열기에서 같은 값을 확인했다. Windows Qt에서는
단계 설정/순서 표/미리보기의 보통·좁은 창을 읽고 실제 설정→보존→저장→재열기
동선을 실행했다. native_check 실행 프로세스는 종료했다. 수치 엔진의 별도 자격 검증,
임의 원격 파일, 클립보드, 파생 표본 Plan 정책 채택의 GUI 완료를 뜻하지 않는다.

구현은 `data_processing_dialog.py`와 DataWindow의 연결이다. 계산·계보·정책의 작성자는
실제 Pro이며 GUI는 해당 공개 API를 소비한다. 공통 patch 통합은 별도 담당자가 수행한다.
