# 후처리 프로젝트 저장하고 닫기

이 동작에는 현재 ParaView와 같은 빌드의 종료 plugin이 설치되어 있어야 합니다.
현재 공개 기본 ParaView의 File → Exit 전체 보호는 아직 실제 수용을 마치지 않았습니다.
설치되지 않았다는 시작 안내가 나오면 File → Exit가 관리 저장을 확인한다고
가정하지 말고, 명시 저장 후 기존 X/Alt+F4 경로를 사용하세요.

설치된 관리 Post에서는 **Ctrl+S**로 원자료 연결·적용 결과·현재 화면을 분석
프로젝트에 저장합니다. ParaView 자체의 Save State나 Save Data와는 저장 범위가
다릅니다. 저장한 분석 프로젝트를 Post에서 다시 열어 작업을 이어갈 수 있습니다.

**File → Exit**, **X**, **Alt+F4**로 닫을 때 저장하지 않은 변경이 있으면 같은
저장 관문에서 다음 선택을 받습니다.

- **저장**: 현재 프로젝트의 저장 완료를 확인한 뒤 창을 닫습니다.
- **저장 안 함**: 마지막 저장본을 유지하고 현재 창의 변경은 버립니다.
- **취소**: 입력과 결과를 그대로 두고 창으로 돌아갑니다. 기본 선택이며 Esc도 취소입니다.

Properties에 적용하지 않은 값이나 `1e`처럼 입력 중인 숫자가 있으면, 저장을
선택해도 창을 유지합니다. 값을 완성해 Apply하거나 Reset한 뒤 다시 저장하세요.
입력 중인 내용을 임의로 완성하거나 0으로 바꾸지 않습니다.

저장 실패·상태 확인 실패·진행 중인 작업이 있으면 창을 유지합니다. 표시된
원인을 해결하고 같은 창에서 다시 저장하세요. 저장 확인창 안에서 닫기를 다시
눌러도 중복 저장이나 두 번째 종료가 시작되지 않습니다. ParaView의 다른 편집창이
종료를 취소해도 기존 연구 문서와 결과는 열린 상태로 남습니다.

이 설명은 관리 Post의 정상 종료에 관한 것입니다. 프로세스 강제 종료나 시스템
중단에서 저장되지 않은 작업의 복구를 보장하지 않습니다.
