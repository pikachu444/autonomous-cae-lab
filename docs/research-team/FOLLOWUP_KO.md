# 실제 결과로 연구 이어가기

Expert의 연구팀에서 역할별 질문과 자료를 정하고 조사합니다. 발언의 가설과 계산 제안은
관측 결과가 아닙니다. 계산이 필요하면 제안에서 **Plan 열기**를 선택하고 입력·응답·단위와
실행 한도를 확인한 뒤 직접 실행합니다. 이 단계는 기존 Numerical Plan을 사용합니다.

계산을 마치면 원 결과를 저장합니다. **결과로 후속 검토**에서 그 Plan의 실제 계산을 고르고
응답, 성분, 위치, 원행 또는 프레임, 단위와 기저를 확인합니다. 같은 작업에 X변위와 Y변위가
있어도 다른 위치의 성분을 조합해 선택할 수 없습니다. 중복된 시각은 원 프레임으로 구별하며
인접 시각이나 보간값으로 바꾸지 않습니다. 필요한 정보가 없는 결과는 원 자료를 유지하고
해당 선택만 사용할 수 없다고 표시합니다.

네이티브 결과의 원행·프레임 정보가 보존된 응답은 같은 방식으로 선택합니다. 아직 필요한
선택 정보가 없는 지연 네이티브 결과 항목은 현재 연구팀에 첨부할 수 없습니다. 기존 결과
화면에서 확인하세요. 기존 결과 열기와 위치 선택은 계속 사용할 수 있습니다.

결과를 받을 역할을 고르면 다음 질문 **초안**이 열립니다. 질문과 역할별 자료를 검토해
변경을 적용하고, 준비됐을 때 직접 다음 질문을 보냅니다. 초안 열기·저장·재열기에는 새 모델
질문이나 계산이 없습니다. 외부 모델에 질문과 결과를 전송하려면 계속 허가가 필요하며, 결과 선택이
운영자의 전송 정책을 켜 주지는 않습니다.

판단을 따로 정리하려면 원 발언에서 주장을 선택하고 **Study로 판단 작성**을 선택합니다.
가설과 판단은 미확인 상태로 시작합니다. 근거를 읽고 지지·반박 자료와 판단을 직접 작성해
저장합니다. 원 발언의 인용하지 않은 입력까지 연결되므로 인용을 지워도 자료 제한은 남습니다.
허용된 로컬 원문을 읽고 Study를 작성하는 데 참여 모델이나 외부 전송 허가는 필요하지 않습니다.

보고서는 연구팀이 실제로 생성해 보존한 보고서를 선택해 Report로 엽니다. 제목과 본문을
검토하고 저장할 수 있으며, 원 보고서 발언은 고정된 자료로 함께 보존합니다. 보고서를 여는
동작은 새 보고서를 생성하지 않습니다. 현재 공유가 허용되지 않는 원 자료에 의존하면 보고서
전체를 공유하지 않습니다. 보고서 작성과 저장은 공학적 승인을 뜻하지 않습니다.

응답을 받지 못했다면 같은 선택을 유지한 채 **확인**합니다. Study나 Report를 중복 생성하지
않으며, 이미 연 문서의 작성 중인 편집을 덮지 않습니다. 원 대화나 선택이 바뀌었다면 먼저
현재 문서를 다시 읽고 선택을 확인합니다. 사본에서는 보존된 과거 발언을 읽을 수 있지만
새 질문의 자료·결과 전송 허가는 현지에서 다시 명시해야 합니다.

## Python에서 같은 경로 사용하기

기존 `Client.research_team_transfer`를 사용합니다. 문서의 현재 세션과 입력 세대, 명령 식별자를 전달합니다. 같은 요청을
확인할 때는 명령 식별자를 유지합니다. 선택에는 저장된 식별자와 물리 선택만 넣으며,
결과 본문이나 파일 경로, 검증 기록은 보내지 않습니다.

| 작업 | `kind` | `selection` |
|---|---|---|
| 선택 주장으로 Study 열기 | `study` | `claim_ids` |
| 실제 Plan 결과로 다음 질문 준비 | `result_review` | `turn_id`, `proposal_index`, `plan_document_id`, `job_id`, `selector`, `actor_ids` |
| 보존된 생성 보고서 열기 | `report` | `action_id` |

CLI에서는 `python -m caelab documents research-transfer <원 Expert 문서>`에
`--kind`, `--selection selection.json`, `--session`, `--generation`, `--command-id`를
전달합니다. `selection.json`에는 위 표의 선택 객체만 저장합니다. MCP의
`expert_research_transfer`도 같은 여섯 인자를 받아 같은 문서 명령을 호출합니다.
두 경로 모두 새 AI 질문이나 계산을 시작하지 않습니다.

결과 읽기와 작은 통계 분석은 기존 저장 결과·수학 엔진을 사용합니다. 분석에는 허용된 원행,
응답 정의, 입력 크기와 한도를 명시해야 합니다. 지원하는 작은 분석은 한 진행에서 한 번
실행하며 같은 요청의 확인은 보존 결과를 사용합니다. 메모리 예약은 운영체제의 강제 메모리
제한이 아닙니다. 강제 메모리·시간 제한이 필요한 실행은 기존 관리 Plan 경로를 사용합니다.

공개 실행 예제는 다음과 같습니다. 출력 폴더는 새 폴더를 지정합니다.

```powershell
python -m examples.research_team_followup_public --output <새 작업 폴더>
```

이 예제는 공개 합성 관측과 통제된 역할 발언·보고서를 사용합니다. 기존 문서와 실행 관리자,
실제 `numerical.analyze`, 결과 선택, 후속 초안, Study·Report 저장과 새 소유자가 읽는 동작을 확인합니다.
실제 AI 제공자, 구조 솔버, 실제 장비의 공학적 유효성을 확인하는 예제는 아닙니다.

이전 검증 기록에 파일 집합이 없는 결과는 사본의 읽기 권한을 자동으로 복구하지 않습니다.
현재 허용된 원 결과를 결과 선택 창에서 명시적으로 다시 첨부하세요. 저장이나 질문 편집만으로
과거 선택을 새 결과의 권한으로 바꾸지 않습니다. 관련 자료 정책은 [자료 읽기와 공유](EVIDENCE_KO.md)를 참고하세요.
