# 실제 연구 작업을 위한 제품 구성과 화면 구현 계획

작성: 2026-10-11. 대상은 자기 자료·모델·기존 해석 결과로 연구하는 사용자다.
기존 요구 기록과 [ADR0060](../ADR/0060-independent-research-workspaces.md)의
독립 문서 경계를 유지한다. 요구 항목 수는 누락 점검용 기록이며 제품 범위의 상한이나
완성 판정 기준이 아니다. 사용자의 실제 연구를 끝내는 데 필요한 기능은 목록 밖이어도
추가한다. 이 계획은 다음 구현의 기준이며 제품 구현 완료 기록이 아니다.

## 1. 사용자가 끝낼 수 있어야 하는 일

제품의 목적은 **제품 불량이 생기는 조건과 원인 가설을 연구**하고,
**지그를 만들기 전에 원하는 시험이 가능한지 검토**하는 것이다. 재료 동정,
PDE·수치 알고리즘 연구, 이미 계산된 결과 분석, 문헌·VOC 자문도 독립적으로 쓴다.
지그 한 개나 완화 곡선 한 개를 더 정교하게 만드는 일을 전체 제품 개발로 대신하지 않는다.
완성 여부는 사용자가 불량 원인 가설을 실제 근거로 비교하고 다음 시험을 정하거나,
제작 전 지그의 시험 가능성과 수정 필요를 판단할 수 있는지로 평가한다. Codex와 Pro의
합의나 요구표 체크만으로 이를 대신하지 않는다. 확인하지 않은 FreeCAD 기능은 실제
화면의 편집·선택·조립·메시·조건·저장·재열기 확인을 거쳐 채택 이유와 한계를 갱신한다.

사용자는 원하는 도구에서 바로 파일을 열고 실제 대상을 편집한다. 필요할 때 다른
문서·계산·전문가를 연결하고, 작업을 저장한 뒤 다시 열어 계속한다. Workbench를
먼저 만들거나 모든 작업을 CAD에서 시작할 필요가 없다. AI는 같은 문서와 명령을
이용해 계획·해석을 돕고, 표본 생성과 반복 계산은 기존 수치 엔진이 수행한다.

## 2. 제품 구성과 재사용

우선 검증할 구성은 **FreeCAD 기반 CAD/FE, ParaView 기반 Post, 로컬 Research 실행 호스트**다.
FreeCAD 채택의 최종 판단은 아래 실제 작업 검증을 마친 뒤 내린다. 기능 목록과 과거의
치수 수정·메시 사례만으로 일반 설계·관절 운동·조건 편집까지 확인됐다고 하지 않는다.
Research는 Data·Material·PDE·수치 연구·Runner·Expert의 독립 문서와 직접 진입을
공유한다. 이는 기능을 한 메뉴의 긴 폼으로 합친다는 뜻이 아니다. 각 작업공간은
자기 파일·명령·Undo·창·저장·재개를 완결하며 여러 문서를 동시에 열 수 있어야 한다.
OS 바로가기·파일 열기 또는 직접 실행 명령으로 각 도구에 진입한다. 세 호스트를
세 개의 메뉴로 축소하지 않으며, owner가 다르다는 이유로 창 이동을 강제하지 않는다.
Material 옆에서 여는 Numerical Plan과 독립 Numerical 도구는 같은 편집기를 사용한다.
Workbench는 이 도구들의 정확한 문서·입출력 관계를 여는 선택적인 연결 화면이다.

| 부분 | 재사용할 기반 | 구현자가 책임질 연결 |
|---|---|---|
| CAD/FE | 실제 FreeCAD의 Sketcher·PartDesign·Assembly·FEM, 기존 editable FCStd 및 adapter | 같은 창의 설계·조립·운동·메시·조건, 공통 문서/명령 관문, 정확한 native 선택과 저장 |
| Post | 실제 ParaView의 reader·pipeline·Properties·Apply·field/time/selection·분할 보기 | 원 결과 참조, 단위/위치/시간 의미, 비교 연산, 프로젝트 저장/재개와 공통 결과 연결 |
| Research | 기존 Core·evaluation·numerical·reader·JobManager·Expert 서비스 | 작업별 문서 편집기, 직접 실행/파일 열기, 표·곡선·진단·명령, 열린 GUI와 MCP의 같은 상태 |
| Workbench | 기존 Study/Experiment·참조·평가·실행 계약 | 문서/포트/연결 선택, 변경 영향, 정확한 문서 열기. 별도 scheduler나 optimizer를 만들지 않음 |

Windows 로컬 설치를 먼저 완결하며 WSL을 기본 설치 조건으로 추가하지 않는다.
향후 Linux 서버 계산은 별도 실행 대상이다. 계산 backend의 가용성과 Windows UI의
가용성을 구분하며 미지원 backend 때문에 자료·문서·저장 결과 열람을 막지 않는다.

Research의 기술 검증은 Qt Widgets를 우선 후보로 둔다. Python 서비스·로컬 파일·도킹
문서를 연결하기 위한 구현 판단이지 UI 품질의 보증이 아니다. FreeCAD/ParaView와
서로 다른 Qt/Python/VTK 환경을 한 프로세스에 억지로 넣지 않는다. 실제 파일 수명,
다중 창, 큰 표/곡선, native 앱 연결을 확인한 뒤 라이브러리·배포를 확정한다.
기존 웹 서비스는 재사용하고 기존 웹 renderer는 제품 화면의 기준으로 삼지 않는다.

## 3. 화면마다 주 기준을 고정한다

참조는 제품 이름 목록이 아니라 **정확한 화면과 실제 조작의 기준**이다.
아래 작업 배치·정보의 동시 가시성·선택 방식은 유지한다. 색·아이콘만 비슷하게 만든
새 대시보드, KPI 카드, 큰 제목, 긴 설명/입력폼 나열은 이 요구의 구현이 아니다.
독립 앱마다 동일한 세 칸 배치를 강제하지 않는다.

| 작업공간 | 주 기준 | 유지할 화면 구조와 핵심 조작 |
|---|---|---|
| CAD/FE | **FreeCAD native 작업 화면** | Model/Property/Tasks와 실제 3D를 유지. 스케치/구속→피처 치수 수정→부품 instance/관절→운동→메시 설정/품질→조건의 대상 선택→저장·재개. Abaqus 조건 편집과 HyperMesh 품질 선택은 해당 작업의 보조 참고이며 전체 chrome을 섞지 않음 |
| Data | **Origin 워크북·그래프** | 열 이름·단위·역할·수식 행, 자료 표, 그래프 창을 직접 조작. 파일 열기→열 지정→행/범위 선택→변환 설정→처리 전후 보기→설정 재열기→저장·재개 |
| Material | **MCalibration Calibrate/Load Case** | 좌측 시험 목록과 계수 표, 우측 큰 관측/예측 곡선, 하단 실행 출력. 모델 선택→시험/이력 편집→직접 평가→계수/자유 변수 수정→동정→별도 조건 확인→모델 채택 |
| PDE | **COMSOL Model Builder/Settings/Graphics** | 모델 트리→선택한 식/field/domain/BC의 설정→해당 영역·mesh/field가 같은 작업을 가리킴. 식/space·계수·경계 편집→오류 위치 이동→study 수치 설정→실제 평가→해/오차 비교 |
| Numerical | **HyperStudy의 연구 트리·변수/응답 표·후보 비교** | evaluator/변수/응답·방법을 정의하고 실제 후보표와 선택 후보의 곡선·목적·제약을 함께 검사. 실패 후보, DOE, 동정, 민감도, UQ, 대리모델, 다목적을 구분. `Fit`이라는 한 이름에 동정과 대리모델 학습을 합치지 않음 |
| Runner | **Abaqus Job Manager/Monitor** | 작업표→선택 job의 제출 입력·진행·진단/로그·결과. 검사→제출→취소 요청→실제 종료→재접속→같은 결과 열기. 수치 해법을 여기서 새로 정의하지 않음 |
| Expert | **사용자가 지정한 Co-STORM** | 다자 발언 흐름과 사용자 입력이 중심. 발언/답글·논점·근거를 연결하고 사용자 개입·일시정지·재개·계획 제안·결과에 대한 후속 답변을 제공. 요약표나 고정 답변으로 대체하지 않음 |
| Workbench | **Ansys Workbench의 연결 관점** | 문서/시스템과 입출력 관계·상태를 표시하고 정확한 작업 도구를 연다. 노드·포트·연결을 별개 대상으로 선택. 이미 있는 도구의 내부 편집기를 다시 만들지 않음 |

Material의 적분기·초기 내부상태·접선 검증은 MCalibration 화면만으로 설계가
검증됐다고 하지 않는다. 시험/계수/응답을 유지한 채 증분·상태·접선 오차를 검사하고
해당 protocol/설정으로 돌아가는 연구용 세부 보기를 추가한다. PDE에서도 COMSOL의
모든 물리나 상용 파일 호환을 약속하지 않으며 기존 지원 evaluator를 연결한다.

## 4. 연구 흐름은 처음부터 끝까지 연결한다

| 흐름 | 사용자가 이어서 하는 일 | 끝났다고 할 수 있는 증거 |
|---|---|---|
| 기존 자료에서 불량 연구 | Data/Post에서 파일을 열고 관측 위치·채널·단위·조건 확인→Expert에서 경쟁 가설/자료 검토→수치 계획의 실제 변수·응답·예산 수정→기존 결과 분석 또는 허용된 새 평가→비교→다음 시험/모델 제안 | 원 행/결과와 같은 값·단위/위치에 연결된 비교, 실제 평가/실패 기록, 근거로 돌아가는 답변. 맞는 곡선 하나로 원인을 확정하지 않음 |
| 재료 연구 | ASCII/CSV 또는 직접 이력→법칙/구현·계수·초기상태/protocol→단일 평가→다중 시험 동정→holdout/상태·접선 검증→선택 계수를 원 owner의 새 revision으로 채택→종료·재개 | 실제 수치 응답·잔차/가중치·실패 증분, 정확한 입력/구현 버전, 상태 격리. 단순 카드 이름/고정 곡선 성공이 아님 |
| CAD 없는 PDE | 수학적 domain 또는 외부 mesh→field/space·식·계수·BC/IC→수치 설정→평가→기준해·오차/잔차·mesh/설정 비교→저장·재편집 | CAD 미설치에서도 입력/오류 복원과 실제 기준 비교. node/cell/face/적분점 등 위치 의미 유지 |
| 지그와 FE | 같은 FreeCAD 창에서 스케치/피처/조립/관절 편집→mesh 품질/국부 재생성→재료/조건/접촉→검사·고정 입력→Runner→Post 필드/곡선/차이 비교→수정 또는 수치 탐색→저장·재개 | 같은 native model/revision, 실제 조건과 반력/변형 결과, 변경 후 참조 재검사. 장비·강도·제조 UNKNOWN은 실제 근거 전까지 유지 |
| 외부 solver 연구 | 기존 deck/include와 별도 ASCII/CSV 결과부터 시작→입력 변수/실행·추출 도구 등록 또는 파일 교환→DOE/탐색→응답/영향도→Expert 후속 계획 | 결과 읽기는 원 solver 없이 가능. 새 후보에는 실제 평가 필요. imported result·수동 batch·자동 실행을 구별하고 미평가를 성공으로 채우지 않음 |

이 흐름들은 강제 wizard 단계가 아니다. Post 결과부터, PDE부터, 수치 evaluator부터,
Expert의 질문부터 진입해 필요한 문서만 연결한다. 빠른 직접 평가는 Numerical Plan이나
매번 디스크 실험 생성을 요구하지 않으며, 채택·보고할 결과는 재현 가능한 입력/근거를 갖춘다.

후보 순위·채택에 쓰는 관측 집합·mask·가중치·정규화와 필수 응답의 누락 처리 정책은
Plan에서 평가 전에 고정한다. 필수 관측의 예측이 빠지면 실패/무효 목적으로 남기며,
남은 표본만으로 점수를 다시 정규화해 유리한 후보로 표시하지 않는다. 기존 fit의 고정
mask와 명시적 failure penalty 정책은 유지하되 검색용 penalty와 유효한 관측 기반
목적값을 구별한다. 사용/제외 표본 수·이유·시간/영역 범위를 보여주고, 표시용 공통
유효구간과 후보 성능 판정을 구별한다. 큰 오차 구간이 누락된 후보의 순위 시험을 포함한다.

벡터·텐서 차분은 공통 좌표기저·평가 위치·association으로 대응시킨 뒤 허용한다.
방향·필요 성분이 없으면 추정하지 않고 차분을 차단하며 원 결과의 나란히 보기는 유지한다.
적분점 값의 절점 평균·투영도 명시한 파생 연산으로 비교 정의에 남긴다. 좌표기저만
다른 동일 텐서를 올바르게 변환했을 때 차이가 0이고, 변환 정보 누락 시 차분이
차단되는 장면을 수용에 포함한다. 현재 일반 변환 기능이 구현됐다는 뜻은 아니다.

### 첫 업무 수용에 포함할 세 연구 사례

사용자는 **불량 연구와 지그 검토를 모두 수행**하도록 답했고, 재료 모델에 따른
인장·압축 항복과 불량 판단 비교를 추가했다. 아래 A는 사용자 제안, B·C는 Codex가
추가한 연구 제안이다. 세 사례는 전체 17개 UC를 대신하지 않는다. 공개/합성 입력을
이용한 계산 검증과 실제 제품·지그의 타당성 검증은 각각 기록한다.

#### A. 재료 모델 때문에 항복과 불량 판단이 달라지는가

- **질문과 경쟁 가설:** 압력에 무관한 von Mises와 압력 의존 Drucker–Prager 중
  무엇이 관측된 인장·압축·구속 조건을 설명하는가. von Mises도 인장과 압축 모두에서
  항복할 수 있다. 압력 부호와 응력 규약을 고정하고 DP라는 이름만으로 선택하지 않고
  선형/곡선형, 유동법칙·팽창각, 경화·속도/온도 의존성 및 적용 범위를 명시한다.
- **입력:** 같은 형상·하중·경계조건·시험 이력, 단위/응력·변형률 규약, 인장/압축
  관측과 보정 범위. 모델마다 필요한 계수를 같은 값으로 억지 설정하지 않는다.
  같은 학습/검증 자료와 오차 규칙을 사용하고 맞출 수 없는 특징도 오차로 남긴다.
- **처음 실행할 것:** 재료점의 인장·압축·구속압 경로와 제하를 독립 기준과 비교한다.
  이후 같은 FE 시편의 동일 위치·시각에서 두 모델을 비교한다. 한 모델의 응력 이력을
  다른 모델의 항복식에 대입한 그림만으로 실제 소성 이력 비교를 대신하지 않는다.
- **한 화면에서 확인할 것:** 시험별 관측/예측 곡선, p–q 항복면과 응력경로, 항복 시작,
  내부상태·체적/소성변형, 제하 후 잔류변형. 시각·위치를 고르면 곡선과 실제 장이 함께
  같은 대상을 표시한다. 항복/손상/사용자가 정의한 불량 판정은 별도 열로 둔다.
- **반증과 다음 시험:** 인장으로 맞춘 모델이 압축/구속 holdout에서 틀리는지 확인한다.
  두 모델이 모두 설명하면 원인을 확정하지 않고 예측 차이가 큰 다음 압력/하중 경로를
  수치적으로 제안한다. 균열·치수 공차·기능 저하 기준이 없으면 불량은 UNKNOWN이다.

DP 모델은 압력·인장/압축 비대칭과 유동/경화 가정을 구별해야 한다.
[Abaqus의 구성 이론](https://docs.software.vt.edu/abaqusv2025/English/SIMACAETHERefMap/simathe-c-granularpoly.htm)과
[검증 문제](https://docs.software.vt.edu/abaqusv2025/English/SIMACAEVERRefMap/simaver-c-drucker.htm)를
참조하며 재료점, FE, 실제 재료의 세 검증을 합치지 않는다.

#### B. 재료 문제처럼 보이는 현상이 지그에서 생긴 것은 아닌가

- **질문과 경쟁 가설:** 관측 비선형·산포가 재료 자체 때문인지, 지그 마찰·강성·체결력·
  정렬 편심 때문인지 분리한다. 이상적 강체/정렬/마찰 없음과 실제 유연성/접촉을 비교한다.
  지그가 계측값에 섞이는 효과와 시편의 실제 응력경로를 바꾸는 효과를 구별한다.
- **입력:** 편집 가능한 시편·지그 조립, 장착/하중/측정 위치, 지그 강성, 접촉·마찰,
  체결과 편심 범위. 장비 변위와 시편 게이지 변위를 다른 응답으로 등록한다.
- **처음 실행할 것:** 직렬 강성의 독립 계산과 선형 FE로 장비 변위에 지그 변형이
  섞이는 양을 확인하고, 기존 frictionless 접촉 기준을 재사용한다. 마찰·preload·편심은
  지원 adapter와 검증을 추가한 뒤 한 인자와 상호작용 DOE로 확장한다.
- **한 화면에서 확인할 것:** 지그/시편 변형률장, 반력·접촉압·미끄럼, 장비/게이지
  하중–변위, 지그 가정별 추정 재료계수 편향. 같은 시편을 둔 채 지그 설계 후보를 비교한다.
- **반증과 설계 판단:** 재료계수를 재동정하지 않고 지그 조건만 바꾼 예측이 별도 측정과
  맞는지 본다. 잔류변형·허용 측정 오차·장비 한계가 갖춰져야 사용 가능 판정을 내린다.
  지그 가정별 재동정도 따로 비교하되 전체 하중–변위 곡선 하나로 두 원인을 식별했다고
  하지 않는다. 지그 강성·정렬 또는 시편 국부변형의 독립 관측이 필요하다.
  최적화 목표는 단순 최소 질량에 고정하지 않고 측정 오차·강성·제작성의 절충으로 잡는다.
- **P2의 제작 전 지그 검토 통과 장면:** 기준 지그를 열어 같은 CAD/FE 창에서 형상·
  지지·체결 조건을 바꾸고 재메시와 조건 유효성을 확인한다. 같은 시편·시험 조건에서
  기준안/변경안의 간섭·강성·미끄럼·변형과 측정 오차를 Post에서 비교한 뒤 변경안을
  채택하거나 보류하고 저장·재개한다. 과거 기준안과 결과는 유지한다. 미지원 접촉/체결
  계산은 지원·검증 전까지 실행 불가로 표시하고, 공차·장비/강도 기준이 없으면 공학
  판단은 UNKNOWN이다. 연구용 변경안 선택과 제작/사용 승인을 구별한다.

#### C. 벌크 항복이 없어도 열팽창 차이로 박리와 뒤틀림이 생기는가

- **질문과 경쟁 가설:** 이종재료/접착 조립체에서 열팽창 차이와 계면 특성이 관측된
  뒤틀림·박리를 설명하는가. 완전접합/탄성 계면/손상 계면, 등온/열 이력, 벌크 탄성/소성을
  구별한다. 열 한 번으로 얻은 결과를 피로 수명이나 반복 열화로 확대하지 않는다.
- **입력:** 층 두께·접착 두께, 기준 무응력 온도와 온도 이력, 열팽창계수·탄성/점탄성,
  계면 강성·강도·파괴에너지·혼합모드 기준과 조립 이력. 손상 효과만 비교할 때는
  탄성/손상 계면의 초기 강성을 맞춘다. 실제 온도 구배가 필요하면 PDE와 연결한다.
- **처음 실행할 것:** 완전접합 이중층의 열 곡률을 독립 기준과 비교하고, 별도 계면 시험에서
  견인–개구/전단과 에너지 균형을 검증한다. 두 기준을 통과한 뒤 열–구조–계면 문제를 연결한다.
- **한 화면에서 확인할 것:** 온도/곡률·잔류변형, 계면 견인·개구·손상, 벌크 소성의
  나란한 보기. 동일 시점의 값과 변화 원인을 함께 비교하고 알려지지 않은 계면값을 표시한다.
- **반증과 다음 시험:** 열 곡률만 맞는 모델과 실제 계면 손상을 설명하는 모델을 구별한다.
  무응력 상태에서 시작한 선형 가역 열탄성이 같은 온도장·구속으로 복귀했을 때 새로운
  잔류변형이 남지 않는 기준부터 확인한다. 열변형과 비가역 잔류 뒤틀림을 구별한다.
  계면 시험/온도 측정의 어느 조건이 가설을 가르는지 제안한다. 계면강도나 에너지가 없으면
  박리 판정을 보류하며 응력집중만으로 박리를 확정하지 않는다.

계면 손상 시작과 이후 진전에는 서로 다른 정의가 필요하다.
[Abaqus의 cohesive 거동 설명](https://docs.software.vt.edu/abaqusv2025/English/SIMACAEITNRefMap/simaitn-c-cohesivebehavior.htm)을
기준으로 하되 상용 프로그램 기능이 현재 제품에 이미 연결됐다는 뜻은 아니다.

## 5. 화면 구현 전후에 적용할 기준

1. **참조 고정:** 작업별 주 기준의 버전/URL/캡처, 5–10개 실제 명령, 상시 보이는 정보,
   편집/선택/적용/실패 상태를 먼저 적는다. 기존 합성 HTML은 제품의 시각 권한이 아니다.
2. **작업 묶음 구현:** 명령→실제 문서 변경→실제 평가/reader→결과→저장·재개를 함께 만든다.
   연결 없는 버튼·수치·차트로 완성 화면을 채우지 않는다. 미지원은 실제 이유를 보여준다.
3. **참조 대조:** 참조와 구현을 같은 업무 상태·화면 크기·배율에서 나란히 비교한다.
   1440×900, 1920×1080 및 실제 Windows 배율을 포함한다. 필수 패널,
   대상 면적, 정보 밀도, 명령 위치, 선택/속성의 연결이 이유 없이 달라지면 반려한다.
4. **실제 조작 검수:** 타이핑·선택 변경·Undo/Redo·파일 저장·종료·재개·오류 수정·비동기
   완료를 실제 앱에서 수행한다. screenshot 유사성과 기능 동작은 별개로 기록한다.
5. **전체 연구 확인:** 위의 서로 다른 흐름과 원 17개 사용 사례에 결과를 되돌려 본다.
   테스트 개수나 한 예제의 성공으로 전체 제품 완료를 선언하지 않는다.

참조에서 달라질 수 있는 것은 요구상 이유가 있는 부분이다. 원본/과거 결과 보존을 위한
revision, GUI/MCP의 명시적 대상과 충돌, 실행 성공과 공학 승인 구별, 지원되지 않는 기능의
표시가 여기에 해당한다. 차이는 참조 동작·우리 동작·이유·확인 방법을 같이 기록한다.
특히 Post의 프로젝트 저장과 데이터 export, 문서 Undo와 후보 채택 되돌리기와 job 취소를
같은 명령으로 합치지 않는다.

## 6. 구현 묶음과 남은 판단

전체 공통 연결을 먼저 만들되 기능 없는 shell만 납품하지 않는다. 기존 서비스의 실제
작업을 각 도구의 화면에 연결한 뒤 도메인별 깊이를 보완한다. 한 owner가 공통 문서·참조·
명령·Core 변경을 맡고, 나머지는 경계가 정해진 native/연구 UI 작업으로 나눈다.

| 묶음 | 제품 결과 | 통과 기준 |
|---|---|---|
| P0 참조와 실행 경로 고정 | 주 기준 화면·명령 명세, Windows의 실제 host/파일/창 수명 검증 | 임의 목업 대신 참조 대조표, 파일 저장/재개와 native 연결 시연. 기술 후보의 실패는 이 시점에서 교체 |
| P1 공통 연구 연결과 두 업무의 첫 실행 | Data–Material 직접 편집/평가·동정·재개, Data/Post 외부 결과, 기존 Numerical/Runner/Expert의 실제 연결. CAD/FE·Post native 수명과 사례 B의 지그/측정 기초를 병행 | 다른 열 배치·시험 이력의 두 번째 입력까지 전체 왕복. 동정과 별도로 실제 복수 변수 DOE·실패·영향도 비교. 사례 A/B/C의 최소 기술 시험을 추적하며 서비스 재사용과 미지원 확장을 구별 |
| P2 세 사례와 독립 도메인 편집 | A의 DP/J2·B의 지그 접촉·C의 열/계면 검증을 갖춘 실제 비교. CAD 없는 PDE, 같은 창 CAD/조립/mesh/조건, Post/Expert 해석·다음 시험 | 불량 연구와 지그 검토 모두 첫 업무 수용에 포함. 실제 지그 수정→재메시/조건 확인→기준안/변경안 비교→채택/보류까지 수행. E01–E14·V 및 독립 기준 검증을 하고 사용자 실제 입력이 없으면 기술 검증 상태로 한정 |
| P3 전체 요구의 후속 확장 | 다자 Expert 전체 조작, 외부 batch, UQ/대리/MOO, Workbench graph, 규모·배포·원격 계산·남은 물리 기능 | R01–R52·UC01–UC17별 지원/미지원/수용 상태. 첫 사례/기술 성공으로 나머지를 완료 처리하지 않음 |

첫 업무는 **둘 다 수행**하는 것으로 사용자 답을 반영했다. 실제 자료 전에는 공개 또는
명시적 합성 입력으로 위 세 사례의 기술 검증을 진행한다. 실제 재료 종류·인장/압축 시험,
불량 정의/공차, 지그 도면·장비 조건, 열/계면 자료는 해당 업무 수용 전에 확인한다.
없는 값은 가정/UNKNOWN으로 남기며 화면을 꾸미기 위해 채우지 않는다.
파일 형식·대표 규모·상용 runtime은 실제 표본과 접근 가능성이
확인되는 범위에서 확정한다. GUI 프레임워크, 단위/소유 계약, 예시 하나를 제품 경계로
삼을지는 사용자에게 다시 결정하라고 묻지 않는다.

### 첫 구현 묶음의 실제 연결

첫 인도물은 Data에서 연 자료를 Material에서 평가하고, 같은 Numerical Plan으로
동정·후보·실패를 확인한 뒤 계수를 채택하고 저장·재개하는 작업이다. Runner에서
같은 계산을 검사하고 Expert에서 그 자료와 결과를 근거로 다음 시험을 논의한다.
독립 Data/Material/Numerical 진입을 모두 제공하며 Workbench 생성을 선행시키지 않는다.
CAD/FE의 native 수명 연결과 사례 B의 측정·지그 강성 기초를 같은 단계에서 진행한다.

| 사용자 동작 | 재사용하는 현재 코드 | 새 연결과 남은 한계 |
|---|---|---|
| 파일 열기·열/단위 지정·원 자료 확인 | `caelab/workbench.py`의 `upload/register_local_input/input_preview`, `adapters/file_table.py`의 `preview_table/read_table` | Data 문서의 원 행 ID·변환 recipe·품질 사유·Undo·저장. reader는 현재 비유한 값과 비단조 축을 거절하며 일반 표 편집기나 품질 mask 관리기가 아님 |
| 법칙·계수·이력 편집 후 직접 평가 | `caelab/evaluation.py`의 `prepare/evaluate`, `adapters/felupe_material.py` | 정확한 입력을 기존 평가기에 전달하고 곡선·진단을 선택에 연결. FELUPE의 현재 지원은 `linear_elastic`와 `neo_hooke`; DP/J2 지원으로 확대하지 않음 |
| 시험·변수·응답·예산을 수정해 동정/DOE | `caelab/numerical.py`의 `fit_model/run_doe/optimize/load_observations/compare_curves` | Material 옆과 독립 Numerical이 같은 Plan 편집기 사용. protocol revision·관측·변수 binding을 고정하고 기존 잔차·보간·실패 정책을 유지 |
| 후보·관측/예측·실패를 함께 비교하고 계수 채택 | fit의 후보 원장·최종 fit/holdout 곡선, `analyze_candidates`, `evaluation.read_result` | 모든 후보 곡선은 현재 보존되지 않음. 보존된 결과를 열거나 추가 평가임을 명시하고 실제 기록평가. 숨은 재실행이나 만들어 낸 후보 곡선 금지. 채택은 원 Material owner의 새 revision |
| 작업 검사·제출·취소·결과 열기 | `caelab/jobs.py`의 `JobManager`, `Workbench.submit/resource_request` | 고정 입력→제출 receipt→job→결과를 같은 선택으로 연결. 재시작 미종료 job은 현재 `INTERRUPTED`이며 자동 프로세스 재접속·재개 완료가 아님 |
| 근거를 열고 계획을 제안받아 결과로 후속 질문 | `assist/experts.py`의 `ExpertRuntime.plan/ask`, `assist/knowledge.py`와 Workbench callbacks | 반환된 계획을 편집 가능한 Plan 초안으로 연결하고 명시 제출. Co-STORM의 논점·reply·사용자 개입·pause/resume 화면은 새 구현. 기존 제한 자문을 전체 다자 협업으로 표시하지 않음 |
| 닫았다 다시 열어 편집을 계속하고 MCP로 같은 명령 실행 | 기존 evaluation/job/Expert session 저장, HTTP Workbench 및 `openscience/workbench_mcp.py` | Data/Material/Plan 문서 owner·working generation·semantic Undo·invalid draft 저장·충돌 관문은 아직 없음. 기존 input/job/result 저장을 편집 문서의 복원이라고 세지 않음 |

Windows에서 검증된 FELUPE 경로를 첫 Material 실행에 쓴다. 준비형 MFront는 현재
Elasticity E/ν·영 초기상태·Linux `.so`/Singularity 경로이므로 Windows 기본 기능으로
표시하지 않는다. 공통 문서 명령은 Root 한 명이 소유하며 실제 가져오기·평가에 바로
붙인다. 별도 scheduler·optimizer나 동작하지 않는 공통 프레임워크부터 만들지 않는다.

첫 묶음의 통과 장면은 다음과 같다. 이는 **다음 구현의 수용 기준**이며 이번 기획에서
실행했다는 뜻이 아니다.

1. 열 순서·단위가 다른 두 자료를 각각 열고 원 행과 곡선의 같은 지점을 선택한다.
   열 매핑을 수정·Undo하고 invalid draft를 저장·재열기한다. 원본 파일은 보존한다.
2. 기존 지원 탄성 모델의 계수와 이력을 수정해 실제 응답을 계산하고 기존 독립
   기준과 비교한다. 구속 변형률과 측면 자유 인장을 구별해 응력 규약을 표시한다.
3. 같은 Plan으로 다중 시험 fit와 holdout을 실행한다. 실패 후보를 선택하면 실패한
   입력과 원인이 보이고, 곡선이 없는 후보는 보존 여부와 추가 평가 필요를 표시한다.
4. 계수 후보를 채택한 뒤 Material을 닫고 재열어 protocol·계수·출처와 이전 결과의
   revision이 유지되는지 본다. 이후 수정은 기존 실행 입력과 결과를 바꾸지 않는다.
5. Runner에서 같은 job의 입력·진행·취소 결과를 확인한다. Expert가 같은 자료와
   결과를 읽어 제안한 Plan을 편집하고, 사용자가 제출한 뒤 실제 결과로 후속 질문한다.
6. GUI와 MCP가 같은 열린 문서에 순차 명령을 보내 같은 값·진단을 읽는다. 오래된
   generation의 변경은 충돌로 남고, GUI에서 invalid draft를 고쳐 다시 평가한다.
7. 동정과 별도로 지원 평가기의 복수 변수·범위·응답을 정하고 실제 DOE를 수행한다.
   후보별 실제 응답·실패와 영향도를 비교하고 Expert에서 다음 구별 실험을 제안한다.
   기존 `run_doe`와 `analyze_candidates`를 재사용한다. 후자의 표준화 다변수 최소제곱
   영향도는 표본/변수 범위·제외 사유·rank/condition과 함께 표시하며 Sobol 전역
   민감도나 인과 증명으로 표시하지 않는다. 원 결과만 가져와 분석하는 경우와 새
   후보를 실제 평가한 경우를 구별한다. UQ·대리모델·다목적 전체 범위는 P3에 남는다.

### 첫 작업 단위와 구현 인계

P1 전체 중 가장 먼저 끝낼 단위는 **Material 계수·이력 편집→직접 평가→이전 결과
비교→저장·재열기**다. 아래 세 작업으로 인계한다. Data/Numerical/Runner/Expert와
두 업무의 범위를 없애거나 마지막으로 미루는 뜻이 아니다. 첫 단위를 연결한 뒤 같은
P1에서 앞 절의 자료·동정·실패·채택·실행·자문 흐름을 이어서 완성한다.

| 순서 | 구현 책임과 코드 대상 | 종료 장면과 판정 |
|---|---|---|
| 1 문서와 공통 명령 | 신규 제안 `caelab/material_document.py`에 Material owner와 draft/revision 저장, `caelab/document_commands.py`에 대상·generation·중복 명령/충돌 관문. 기존 `storage.py`의 atomic JSON 쓰기를 재사용하되 여러 산출물의 일괄 게시를 이미 지원한다고 가정하지 않음. HTTP·MCP는 기존 `workbench_routes.py`/`workbench_client.py`/`workbench_mcp.py`를 같은 owner로 연결 | GUI와 MCP가 같은 계수·이력 변경을 읽음. stale 명령은 거절. invalid 원문과 진단을 저장·재열기하고 수정/Undo 가능. 잘못된 필수 입력의 실행은 차단 |
| 2 평가와 결과 보존 | 기존 `evaluation.prepare/evaluate/save_evaluation/read_result`와 `material.felupe` 호출. 평가 시작의 정확한 law/settings/values·입력 revision과 producer를 고정. 기존 `JobManager`/Workbench 제출·조회와 연결하고 새 scheduler를 만들지 않음 | E를 바꾼 실제 두 응답과 이전 입력을 함께 확인. 편집 도중 도착한 결과는 자기 입력에 연결되고 현재 결과로 자동 채택하지 않음. 비교/채택/holdout에 쓴 입력·곡선·진단은 다시 열 수 있음 |
| 3 참조 화면에 연결 | 신규 후보 `apps/research/material_window.py`: MCalibration의 시험 목록·계수표·큰 관측/예측 곡선·실행 출력을 유지하고 위 공통 명령만 호출. 기존 Windows 설치/시작·수치 패키지를 재사용하고 Research UI 의존성과 직접 진입은 추가 검증 | 실제 계수/이력 입력·선택·오류 위치·Undo·Run Once·결과 비교·File Save/Close/Open을 이어 수행. 같은 문서를 MCP로 수정했을 때 같은 화면 값. 캡처만 비슷한 mockup은 통과하지 않음 |

**첫 단위의 접속과 저장 계약:** 기존 로컬 서비스가 문서마다 활성 Material owner 하나를
보유한다. Research 시작기는 같은 store·source·설정의 서비스를 시작하거나 재사용하고,
GUI와 HTTP/MCP는 그 서비스의 동일 문서/session에 연결한다. GUI/MCP 프로세스가
편집 owner나 Undo를 별도로 만들지 않는다. 문서별 generation 확인과 변경은 서비스에서
직렬 처리하며 서비스 재시작 후 이전 session의 명령은 거절한다. 이 서비스 사용은
Workbench 화면이나 AI 계정의 사용을 요구하지 않는다. 기존 `apps/lab/server.py`,
`caelab/workbench_client.py`, `openscience/workbench_mcp.py`를 확장하는 계획이며
새 통신 framework나 현재 구현된 문서 명령을 뜻하지 않는다.

저장에는 보존 대상으로 고정한 입력·곡선·진단과 그 참조가 함께 포함된다. 필요한
파일을 완성·검증한 뒤 committed 문서 manifest를 마지막에 게시한다. 중간 실패는
저장 성공으로 반환하지 않고 이전 저장본과 dirty/recovery를 유지한다. 통과 장면은
**owner 프로세스 종료→새 프로세스에서 저장본 열기**까지 포함한다. 같은 메모리 owner에
창만 다시 연결하는 시험으로 대신하지 않는다. invalid draft·이전 결과·정확한 참조가
복원되고, 열기 자체로 재계산하지 않아야 한다. 두 계약까지 반영한 첫 단위는
**기획 완료·구현 미착수**이며, 실제 GUI/MCP 교차 편집·Undo와 저장 중 실패·재시작
검증이 다음 구현의 수용 조건이다.

첫 입력은 기존 탄성 기준을 사용한다. `material.felupe/linear_elastic`, E=1000MPa,
ν=0.25, 시간 [0,1,2]s, F=diag(1+ε,1,1), ε=[0,0.001,0.002]에서 σxx는
[0,1.2,2.4]MPa다. E=1500MPa로 바꾸면 [0,1.8,3.6]MPa다. 기존 기준의 허용치를
유지한다. **횡변형이 구속된 규정 변형 이력**이며 측면 자유 인장이나 항복 검증으로
표시하지 않는다. 다른 열 배치·시간/이력의 두 번째 자료는 P1 전체 통과에 필수다.

Material owner가 `set_parameters`, `set_history`, `undo/redo`, `evaluate`,
`retain_result`, `save/open`의 의미를 소유한다. 이름은 구현할 공통 명령의 제안이며
현재 노출된 MCP 도구가 아니다. 계수/이력 변경과 후보 채택을 Undo할 수 있지만
계산 결과·job을 삭제하거나 재실행하지 않는다. invalid draft는 원 편집값과 진단을
보존하고 실행 입력은 유효한 snapshot만 사용한다. 저장 후 열기 자체로 계산하지 않는다.
결과 비교는 단위·성분·위치·frame·응력 measure와 축 의미를 확인한다. 현재 linear
elastic의 infinitesimal Cauchy와 neo-Hooke의 first Piola 응력을 이름이 같다는 이유로
겹쳐 차이를 계산하지 않는다. 변환은 명시된 분석으로 별도 기록해야 한다.

가벼운 직접 평가는 기존 메모리 API를 유지한다. 비교·채택·holdout·보고의 근거가 된
결과는 그 시점의 입력, 실제 곡선, 진단, adapter/library 버전과 hash를 **사용하는 시점에
보존**하고 문서가 정확한 참조를 갖는다. 단순 탐색 후보는 기존 요약/실패 원장을 유지하며
모든 곡선을 무조건 영구 저장하지 않는다. 상세 곡선이 없는 후보의 추가 평가는 별도
evaluation/attempt로 표시하고 원 후보 실행을 재현한 결과와 혼동하지 않는다.

J2/DP는 기존 registry→adapter의 law/상태/접선/응답 계약에 연결할 확장이다. 지원을
등록하기 전에는 명시적 미지원이며 탄성 계산으로 자동 대체하지 않는다. 사례 A의
정확한 variant·부호/유동/경화·재료점 경로/제하 기준·동일 FE 비교를 별도로 통과해야
한다. 첫 탄성 연결의 성공은 A의 항복/불량 검증이 아니다. Runner의 `INTERRUPTED`는
기존 입력·로그·부분 결과를 여는 상태로 남기고 명시 재실행은 새 attempt로 기록한다.

## 7. 검토와 현재 상태

이 기획은 [실제 ChatGPT Pro 대화](https://chatgpt.com/c/6aca5116-b90c-83ee-82fb-1b0299a87fd3)에서
Codex 제안→Pro 비판→Codex 수정안과 사용자 추가 요구→Pro 최종 합의로 수렴했다.
Pro는 세 진입점 표현을 세 실행 호스트로 정정하고 도구별 독립 진입·공통 Numerical Plan,
Windows 비WSL 경로, 첫 묶음의 수치/실행/Expert 연결과 A/B/C에 합의했다.
기존 요구는 계속 추적하되, 목록에 없는 실제 업무 필요도 새로 반영한다.
Root는 지그의 실제 응력 변화/계측 편향 구분, 독립 관측 필요, 계면 초기 강성 일치와
가역 열변형/잔류변형 구분을 반영했다. 현재 편집자는 Root 하나다.
새 solver·제품 GUI·MCP 연결 시험은 이 문서 작성에 포함되지 않는다. 원 코드와 수치
기록을 보존하며 구현/수용 여부는 각각의 실행 기록으로만 갱신한다.

### FreeCAD 실제 작업 확인 상태

2026-10-11의 로컬 FreeCAD 1.1.4 새 문서에서 원점 구속·지름 20mm 스케치와
Pad를 실제 조작했다. Pad 10→12mm 변경, Undo로 10mm, Redo로 12mm를 확인했다.
이후 저장 단계에서 화면 접근 문제가 다시 발생했고 FCStd 저장은 확인하지 못했다.
사용자 지시에 따라 로컬 조작을 중단했다. 새 검증 문서는 저장 여부가 미확인인 채
남아 있으며 기존 사용자 문서를 대체하지 않았다. 원인 확인이나 모니터 활성화를
제품 기획의 선행 조건으로 삼지 않는다.

사용자가 승인한 클라우드 확인은 Ubuntu 가상 화면의 실제 FreeCAD로 아래 native
객체·명령·저장 참조의 연결을 한 번에 검사한다. 사람의 화면 조작성, Windows 배포,
GUI와 MCP의 같은 열린 문서 상태를 증명하는 시험은 아니다. Pro의 진행 검토에 따라
설정·실행·판정 총 60분(16:30–17:30 UTC), 최초 실행과 단순 환경/스크립트 수정 한 번으로
제한한다. 막힌 기능은 미검증 경계로 기록하며 새 Assembly/FEM 기능을 개발해 통과시키지 않는다.

두 실행은 16:42·16:44 UTC에 끝났고 추가 실행은 중단했다. 두 workflow의 전체 판정은
**FAIL**, 내부 보고서는 **PARTIAL**이다. 첫 저장 검사에서 motion 참조를 객체로 잘못
읽은 오류를 한 번 수정했다. 두 번째는 document의 `Material` 속성과 같은 이름의
객체를 혼동한 검증 코드 오류로 저장 검사 전에 중단됐다. FreeCAD 저장 기능 자체의
실패나 미지원으로 판정하지 않는다.
