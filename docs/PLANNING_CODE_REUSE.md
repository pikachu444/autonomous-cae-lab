# 현재 코드와 재사용 결정 — 상세 기획의 코드 근거

2026-10-08, `main` `fc7c82d`를 기준으로 소스와 로컬 Windows 실행을 확인했다. 이 문서는 상세 기획의 **코드 대응·도구 선택 근거**이다. `WORKBENCH_PROGRESS.md`의 과거 Windows/WSL/CI 성공 기록은 보존하되, 이번 세션에서 재현하지 않은 네이티브 솔버나 AI 호출을 이번 실험의 성공으로 바꾸지 않는다. 현재 사용자가 지시한 순서는 상세 기획과 제한된 연결 검증이며, 독립 프로그램 다섯 개의 본 구현을 이미 끝냈다는 뜻이 아니다. **후속 설계 수정:** 기존 브라우저 시안은 사용자가 거부했다. 아래 웹 라이브러리 조사는 과거 후보 평가로 남기되, 현재 조작 시안의 경로는 Windows PySide6(Qt Widgets)+pyqtgraph로 바뀌었다. 기존 Python 계산/저장 기능의 재사용 가능성과 기존 웹 UI의 채택 여부는 별개다.

## 로컬 실행과 이번에 관찰한 범위

- Windows x64의 개인 설치 스크립트 `Start-CAE-Lab.cmd` → `scripts/start-windows.ps1` → `scripts/install-windows.ps1`은 private Python 3.12, NumPy/SciPy/FELUPE와 현재 패키지를 설치한다. 이번 실행에서 uv가 Python minor-version junction 검증에 실패했지만 기존 스크립트의 검증된 private interpreter 경로로 venv를 만들었고, 설치가 완료됐다. 이 스크립트는 네이티브 Code_Aster/OpenRadioss/FEniCSx/MFront의 설치 완료를 뜻하지 않는다.
- 별도 브라우저 창을 자동으로 띄우지 않도록 현재 private venv의 Python으로 `python -m apps.lab.server --store <작업폴더>/work/local-app-store --port 8766`을 직접 실행했다. `GET http://127.0.0.1:8766/api/overview`는 HTTP 200과 토큰을 반환했다. 화면은 `/workbench`와 `/`이다. 서버는 Windows loopback `127.0.0.1` 전용이며, 다른 기기에서 접근 가능한 배포 경로는 아직 설계/구현 대상이다. 재실행 가능한 사용자용 기본 명령은 `Start-CAE-Lab.cmd`; 무창 시험에는 `scripts/start-windows.ps1 -NoBrowser`도 있다. 로컬 GUI 시각·조작 평가는 별도 화면 기록에 둔다.
- 이번 제한 계산의 입력/출력은 `work/code-reuse-smoke.py`와 `work/code-reuse-smoke/`에 있다. UTF-8 한글 헤더 `시간,하중` CSV를 `files.table`에 열, 시간축 `s`, 힘 `N`, 성분 `z`, 위치 `support`를 명시해 읽었고 `[0,10,20] N`을 얻었다. `material.felupe`는 E=1000 MPa, ν=0.25, 측면 변형률 0인 축변형률 0.001을 계산해 `stress_xx=[0,1.2] MPa`를 반환했다. `run()`으로 저장한 뒤 `read_result(..., selection={"responses":["stress_xx"]})`로 다시 읽었고 응력척도 `infinitesimal_Cauchy`가 남았다. 이는 **코드·파일 연결 시험**이며 재료 물성 식별, 실제 구조 경계값 해석, 네이티브 솔버 적격성 검증이 아니다.

### 권장 실행 구조와 선택 근거

현재 조작 시안은 **Windows PySide6(Qt Widgets) 독립앱**으로 만든다. 기존 `caelab` 계산·저장·작업 서비스는 Python 경계에서 직접 재사용하고, pyqtgraph는 곡선/산점도에 사용한다. 웹 시안이 사용자에게 맞지 않았으므로 기존 HTTP 화면·CSS·React Flow·VTK.js를 현재 UI의 기반으로 간주하지 않는다. 필요 시 기존 서버 API는 선택적 원격 연계로 남을 수 있으나, 새 Qt 화면의 데이터 권위는 기존 Python 계약이다. 독립 GUI의 판정은 실행 파일·창 개수가 아니라 각 도구가 Workbench 없이 자기 파일/객체를 직접 열고, 사용하고, 저장하고, 재시작해 복원하며 실행 경계와 오류를 자체 표시하는지로 한다. 자료/곡선 화면과 mesh/field 화면은 서로 다른 중앙 작업공간을 갖는다. 3D 전/후처리용 Python VTK/Qt 연계와 Windows exe 배포는 이번 Qt+곡선 smoke와 구별해 검증한다.

## 남은 결정을 구현 작업으로 바꾸는 위치

1. **객체 계약/연결:** 기존 `evaluation`의 `format`, backend, settings, responses, SHA와 `JobManager`의 ID를 보존하면서 tool document/schema version, immutable input revision, `source_ref`, `produced_by`, downstream stale state를 통합 설계 문서에 확정한다. 구현 위치는 `caelab/storage.py`, `evaluation.py`, `workbench.py`, `apps/lab/workbench_routes.py`; 화면은 Workbench graph와 각 앱의 열기/저장. 완료 행동은 전처리 조건 변경 뒤 이전 job/result 보존과 새 실행만 갱신 필요 표시.
2. **전처리/뷰어 연결:** 실제 메시 entity ID/집합과 검증된 선택 반환을 `adapters/native_face_catalog.py`, `analysis_conditions.py` 등 기존 도메인 기능에 연결할 얇은 bridge가 필요하다. Python VTK/Qt 등 3D 위젯 선택은 STEP/VTU 한 개에서 시각 선택→tree/property 왕복·저장·재열람 및 라이선스/Windows 배포 확인 후 확정한다. 실험 자료 편집은 `file_table.py`를 이용해 3D 없이 먼저 연다.
3. **후처리/외부 파일:** `file_table.py`와 `native_responses.py`가 반환한 동일 `responses`를 결과의 위치/시간/성분·범위 선택 및 overlay에서 사용한다. 파일만 가진 신규 사용자가 import→두 curve 비교→저장→원래 solver 없이 reopen할 수 있어야 한다. native 블록 파일은 표본+등록 extractor 한 건씩 추가한다.
4. **솔버/최적화:** `jobs.py`의 job/result 경계와 `numerical.py`의 평가를 공유한다. UI는 input revision, 원본 파일/작업 폴더, 로그·수렴 artifact를 조회하고 취소 확인 후 새 job으로 재시도한다. DOE/fit/optimize 후보는 `actual/predicted/pending/failed`를 혼동하지 않으며 Pareto/후보 비교가 원래 response를 열어야 한다.
5. **전문가:** `assist/experts.py`의 source/tool/permission/session을 기반으로 다중 발언과 진행자·중간 질문·논점/결론 문서 단위를 설계한다. 실제 모델 미설정 시 `NOT_CONFIGURED`를 표시하고, 자문이 없는 계산/결과 열기를 막지 않는다.

위 사항은 코드 재사용 후보와 검증 행동을 지정한 것이다. 별도 화면 설계, 실제 3D picking, 다섯 독립 GUI, Workbench graph, 전체 solver qualification을 완료했다고 주장하지 않는다.
