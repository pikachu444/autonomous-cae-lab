# 한글 사용법 — 시험 원값에서 판단·다음 연구로

## Data 시험과 제공 불확실성

기존 Data 창에서 파일·열·축·단위·교정 증빙을 지정해 가져온다. 결과 행을 선택한
뒤 **제공 불확실성 전파…**를 연다. 이때 모델 계산은 실행되지 않는다. 원 교정값과
기존 제공 출력 불확실성은 원 결과에 그대로 있다. 새 전파 창은 별도 Plan이다.

입력·계수 표에서 원행의 입력 불확실성과 기울기 a, 입력 영점 x0, 출력 오프셋 b의
불확실성을 제공한 자료대로 입력한다. 종류는 표준/확장/미확인이다. 확장 U의 k가
없으면 빈칸을 유지한다. 값이 실제로 0이라고 제공된 경우에만 0을 입력한다.
모른다는 뜻으로 0을 입력하면 안 된다.

상관·공분산 탭의 기본은 **상관 미확인**이다. 독립성에 실제 근거가 있으면 근거와
함께 명시한다. 행렬은 표의 원변수 순서·축 단위에 맞춘다. 빈 항목은 미확인이다.
기존 저장 행렬의 단위가 kN 등 다른 경우 재열기에서도 그 축 단위를 보존한다.
축 불확실성이 없다는 자료가 없으면 **축 불확실성 미확인**을 둔다.

**계획 저장**은 계산을 실행하지 않는다. **전파 계산**은 제공 데이터에 대해
1차 값 전파를 계산한다. 이 작업은 추가 모델/AI 호출 0회다. 계산 가능한 표본,
미확인 표본, 범위 초과·포화·품질·Plan 제외를 결과 표에서 구분한다.

전파 실패도 원 파일/원 교정값을 없애지 않는다. 미제공 상관·k를 입력한 뒤 **전파 계산**을
다시 누르면 이전 실패 결과는 원래 job에 남는다. 기존 output uncertainty를
새 전파로 덮거나 합산하지 않는다. 읽기/재열기 때 교정식을 다시 적용하지 않는다.

처리 채널은 Data C1의 **게시된 처리 개정**을 선택한다. 전용 창 생성 API는
`ExperimentAnalysisWindow(client, source=selector)`이며 selector의 정확 모양은
API_KO.md에 있다. 현재 Data raw 메뉴는 연결되어 있고, Data 팀의 처리 채널
선택 화면에서는 이 전용 창을 해당 published revision으로 연결한다. 미게시
preview 폴더/임의 JSON DAG는 실행 원천으로 승인되지 않는다.

## 최종 피팅점의 국소 진단

기존 Numerical 후보 상세 창에서 진단할 계산 결과를 선택하고 **선택 결과 저장**을
누른다. 필요한 상세가 없다면 **미보존분 계산**으로 먼저 계산한다.
**시험 진단 → 최종점 일반 잔차 진단…**을 열면 선택해 저장한 계수와 계산 결과를
읽는다. 이때 추가 평가를 시작하지 않는다.

선택 계수값·단위, 실제 추가 평가 수, 차분 간격과 예산을 확인한다. 자유 계수 2개,
fit 시험 1개의 내부점이면 기준점 포함 9회다. holdout은 이번 진단의 튜닝/차분
대상이 아니며 추가 호출은 0회다. robust fit이나 DE 결과도 같은 명시 경로를 쓴다.
기존 optimizer의 modified J를 일반 J라고 읽지 않는다.

**최종점 진단**을 누르면 기존 등록 evaluator/JobManager가 계산한다. 작업 취소는
요청과 실제 중단 확인이 다르다. 결과는 성공한 국소 rank, 미식별 조합, 경계 방향,
고정 계수, 실패·결측·차분 불일치로 구분한다. ‘국소 독립 방향 충분’은 전역 유일성,
측정 불확실성, optimizer 수렴 또는 공학 승인이라는 뜻이 아니다.

정확히 보존한 일반 J가 있다면 API의 `reuse_result`로 0 평가 검증 작업을 명시할
수 있다. 일반 결과 읽기에는 이 작업도 필요 없다. evaluator가 바뀌거나 상세/원
mask/단위/원행 결합이 달라지면 새 평가를 차단한다. 기존 결과 읽기는 남는다.

## 저장·미확정 응답·재열기

저장·제출 결과를 확인하지 못하면 같은 버튼으로 다시 확인한다. 창은 처음 보낸
내용으로 같은 요청을 확인하며, 다른 창에서 고친 입력을 덮지 않는다. 이전 요청의
결과가 확인될 때까지 새 저장·실행을 기다린다. 편집 중 도착한 결과도 현재 입력을
덮지 않는다.

저장한 분석 계획은 기존 Numerical 열기 경로로 연다. 저장된 원 실행 결과를
읽으며 계산을 다시 실행하지 않는다. 원자료나 포함할 표본이 바뀌었다면 이전
결과를 현재 입력 행에 맞춰 표시하지 않는다. 저장한 결과가 손상되었을 때도
오류를 알리고 다른 최신 결과로 바꾸지 않는다. Python 진입 예제는
`open_analysis.py`의 `--document-id`를 사용한다.

Esc/X/Alt-F4는 같은 창 입력 보호 경로를 사용한다. 저장·실행·취소 요청의 응답을
기다리는 동안에는 창을 유지한다. 읽기만 진행 중이면 입력 보호 후 닫을 수 있으며,
늦게 도착한 응답이 닫힌 창을 다시 바꾸지 않는다. 로컬 입력을 명시적으로 버리고
닫아도 진행 계산을 자동 취소하지 않는다. 후보 상세 창을 먼저 닫을 때도 열린 분석
창의 미저장 입력을 확인하고, 취소하면 두 창을 유지한다. Windows에서 보존 후보의
첫 열기와 정상·좁은 창의 표 선택 및 키 이동을 확인했다. 닫기 취소와 저장 응답
유실을 포함한 전체 동선의 수용과는 구분한다. 실제 확인 범위는
[Windows 검사 기록](WINDOWS_ACCEPTANCE_KO.md)에 있다.

## Study와 보고서

결과에서 **다음 시험 기록…**을 눌러 실제 확인할 질문을 적는다. 기존 Study
owner에 원 결과를 붙여 저장한다. 제안 질문은 사용자가 선택한 연구 항목이며
자동 시험 주문이나 새 계산 승인으로 처리하지 않는다.
이전에 작성한 연구 질문과 메모, 다음 시험은 유지하고 새 질문을 추가한다.
저장 응답이 끊기면 **다음 시험 저장 재시도**로 같은 기록을 확인한다.

처음 원자료를 읽지 못한 경우 **원자료 다시 읽기**로 같은 원자료를 확인한다.
이 버튼으로 새 계획이나 계산을 만들지 않는다.
**결과 다시 읽기**는 같은 저장 작업의 표 선택과 스크롤 위치를 유지한다.

**보고서…**는 기존 Report 창을 연다. 원값/보존 예측/잔차/불확실성/제외와 국소
판단을 넣고 사용자가 내용을 편집한다. 원 입력/원 결과/상세 배열은 해당 report
asset에 동결한다. source가 나중에 없어져도 이미 저장한 report를 읽기 위해
계산하지 않는다. 새 성공 보고를 캡처할 때는 원 evidence 소비 gate를 다시 검사한다.

## Expert가 중단되었을 때

Expert 창에서 중간 응답 읽기를 누르면 정확한 이전 작업의 진행 기록을 연다. 받은 텍스트와
실제 채택 발언/보고서는 다르다. 저장·읽기·polling은 새 모델 호출을 하지 않는다.
현재 허용 한도를 확인한 뒤 **다시 시도**를 명시한다. 유효 journal은 재생하고
완료하지 못한 부분만 현재 예산으로 새 호출한다. 과거 실패는 과거 job에 남는다.

미전송 입력란의 새 의견은 retry에 자동 포함되지 않는다. 재개 후 명시적으로
의견을 전달한다. 계산 결과도 기존 첨부 동선에서 정확한 원 문서/job/입력과 함께
선택한다. 새 시험 분석의 큰 JSON은 원 ref가 붙은 **범위 제한 요약**으로 토론에
들어가며 생략 수·UNKNOWN·미승인을 표시한다. 원 상세가 요약으로 교체되지 않는다.

권한을 취소했거나 source 개정/연결이 달라지면 과거 텍스트는 읽을 수 있어도
그 권한으로 replay/새 호출을 허용하지 않는다. 형식 불량 completion은 원문을
보존하되 다시 사용할 완성 답변에서 제외한다. 취소 요청만으로 중단 확인이라고
표시하지 않는다. 실제 provider 연결/계정 검증은 이 인도에서 수행하지 않았다.

## 공개 실행 예제

저장소 루트에서 `python examples/experiment_expert/analytic_uncertainty.py --output <새 폴더>`.
실제 설치된 Python/NumPy와 기존 file_table/evaluation 저장 형식을 사용한다.
공개 합성 원값 0.5, 2.5, 6.5 N에 대한 표준불확실성은 각각
0.3, 0.31622776601683794, 0.42426406871192857 N이다. 뒤 두 포화/범위 제외
표본은 원값을 보존하고 불확실성은 미계산으로 남는다. 이 숫자는 장비 교정 성적이 아니다.
