# FN05 C1 사용 순서

## 제공 불확실성

기존 Data에서 파일 시험과 처리 개정을 열고 원하는 원 응답/처리 채널을 선택한다. 기존 교정값과 제공 output uncertainty는 그 값 그대로 보인다. 불확실성 전파를 실행할 때만 입력·계수의 표준/확장 불확실성과 실제 제공 공분산/상관을 입력한다. 확장 불확실성의 k나 상관이 없으면 UNKNOWN으로 둔다. fit 잔차를 불확실성으로 사용하지 않는다.

알려진 관련 공분산이 서로 모순이면 이번 전파는 실행 차단으로 저장된다. 원 시험값, 원 mask, 제공 입력, 차단 사유는 유지된다. “각 표본의 u는 양수”라는 이유로 결합 공분산을 승인하지 않는다. 알려진 작은 block은 유효하고 나머지 관계만 미제공이면 가능한 표본별 전파는 유지되며, 미제공 결합 관계는 미확인으로 표시된다. 원자료 읽기·저장과 모순된 전파의 실행 차단은 별개이다.

실패 사유를 다음 연구 질문으로 남길 수 있다. 다만 과거 버전이 비PSD 결과를 계산 완료로 저장한 경우, 원 결과는 일반 읽기로 보존하지만 새 Study/보고서의 정상 계산 근거로 사용하지 못한다. 데이터를 고친 뒤 **새 명시 실행**으로 별도 결과를 만든다. 읽기만으로 다시 계산하지 않는다.

## 파생 시험의 최종 피팅점 진단

Data 처리 결과에 대해 기존 sample policy 미리보기를 읽고 사용자가 포함·제외, fit/holdout, 표본 가중치를 검토해 채택한다. 기존 `data.sample_policy.preview`/`data.sample_policy.adopt`와 현재 Plan owner의 command/session/generation을 사용한다. canonical packet을 수작업 JSON으로 대체하거나 다시 freeze하지 않는다.

원 피팅을 명시 실행하고 정확한 후보를 선택한다. 비교·성공 보고에 필요한 상세가 보존되지 않았다면 기존 상세 평가를 명시 실행하고, **선택한 attempt**의 immutable evidence를 보존한다. 일반 요약만 읽는 것은 허용되지만 상세 없는 성공 진단으로 바꾸지 않는다.

그 evidence에서 최종점 진단을 열고 표시된 평가 수와 예산을 확인한 뒤 명시 실행한다. 자유 계수 하나의 내부점은 base와 ±h, ±h/2의 5개 평가이며, 경계에서는 기존 단측 차분 계획을 사용한다. 실제 fit 시험 개수에 따라 평가 수가 곱해진다. 원 holdout은 이 진단에서 재평가하지 않는다. 취소·실패하면 그 attempt의 실제 평가·미평가·실패 사유를 보존한다.

가중치는 원 Numerical 잔차에 한 번만 적용된다. 비균일 가중치를 쓴 후보도 진단할 수 있다. 포함 행에 0 가중치가 있으면 기존 Numerical 규칙대로 실행을 차단한다. 제외할 표본은 Plan의 실제 포함 정책에서 검토·수정해야 하며, 프로그램이 0을 1로 바꾸거나 mask를 몰래 변경하지 않는다.

결과의 국소 rank 부족, 고정 계수, active bound, 평가 실패와 전역 유일성 UNKNOWN을 구분해 읽는다. robust fit 또는 DE였더라도 최종점의 일반 residual J를 별도로 평가한다. 뒤의 성공으로 원 fit 실패/원 holdout/과거 상세 attempt를 채우지 않는다.

## Study와 보고서, 저장·재열기

보존 결과에서 다음 시험 질문을 선택해 기존 Study 초안으로 넘기고 사용자의 질문·판단을 편집·저장한다. 보고서에는 원 시험 곡선, 표본/단위/가중 잔차, 진단 및 미확인 사항을 함께 보존한다. 원값을 ID/hash 표로 대체하지 않는다. ID와 해시는 상세 진단 및 source 결합을 확인하는 항목이다.

이번 Linux 회귀에서는 원 Data·Material·Numerical 소유 문서를 각각 명시 저장한 뒤 보고서·Study를 저장했다. 휘발성 입력/결과/처리 폴더를 삭제하고 한글 경로로 옮긴 다음 새 Python 프로세스에서 같은 evidence/J/보고서/Study를 읽고 다시 저장했다. 평가기 등록 없이 새 submit을 금지해 호출 0을 검사한다. 이것은 C01 전체 closure나 Windows 앱 재기동 인수가 아니다.

## UI와 장비 범위

이번 패치는 새 GUI를 추가하거나 기존 Sol 창을 교체하지 않는다. 기존 FN05 화면과 root 연결을 사용하며 Sol의 읽기 재시도·Study 편집 보존·한글 표본 표시 교정은 별도이다. 실제 Windows Qt, native solver, FELUPE, provider, 실장비는 이번 교정에서 호출하지 않는다. 장비·드라이버·권한·물리 stop 규약이 없는 FN35 장비 연결, FN30의 다른 잔여, C01 C3를 완료 처리하지 않는다.
