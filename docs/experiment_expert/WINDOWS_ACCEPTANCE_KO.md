# Windows에서 확인한 시험 분석 범위

2026-10-15 현재 통합 중인 소스에서 수행한 작은 확인이다. Pro의 Linux 선택
회귀 76건과 구분하며 전체 인도, 실제 재료법칙·장비·공학 승인으로 확대하지 않는다.

## 저장된 후보 첫 열기와 화면

실제 Data 처리·표본 정책·피팅·상세 평가·후보 저장이 끝난 공개 합성 자료를
재사용했다. 합성 평가기를 등록하지 않고 제출을 금지한 상태에서 정확한 저장
후보를 처음 열었다. 새 Plan, 작업, 모델 평가는 생성하지 않았다.

Windows Qt에서 첫 열기, 1160과 800 너비, 표의 선택과 Tab 다음 열 이동을
확인했다. 첫 읽기는 27.64초 걸렸다. 실제 창 그림을 확인한 뒤 불확실성 종류의
`미확인`이 잘리던 열을 위젯의 필요한 폭에 맞췄다. 보존된 입력만 표시하는 별도
작은 확인에서 같은 두 크기와 포커스, 전체 글자를 다시 확인했다. Qt가 보낸
키 입력 확인이며 사용자 물리 키보드나 다른 native 앱의 입력 수용 주장은 아니다.

- 첫 열기: `_workspace/delivery-expert-study/c1-first-open-qt-20261015-02/`
  (36.95초, exit 0).
- 열 너비 보완: `_workspace/delivery-expert-study/c1-input-fit-20261015-01/`
  (8.44초, exit 0). 그림은 같은 이름의 `c1-input-fit-images-20261015-01/`에 있다.

## 보존된 동일 입력의 최종점 계산

앞선 전체 준비 경로가 240초 상한에 닿았다. 원 저장 자료를 조사하니 import,
fit, detail은 성공했고 최종 작업은 종료 전 약 32초만 실행 중이었다. 이를
최종 읽기 교착이나 성공으로 판정하지 않았다. 전체 fixture를 다시 만들지 않았다.

그 작업에 실제 제출됐던 prepared arguments를 별도 작업 사본의 새 Workbench
작업에 명시 제출했다. 기존 제출 검증과 실행 검증, 성공 후보 소비 검증을 모두
유지했다. 동일한 표본·가중치·마스크·계수와 원자료를 사용했다.

공개 합성식 `P = mu × t`의 5회 평가가 성공했다. 일반 잔차 Jacobian은
`t × sqrt(sample_weight) × sqrt(experiment_weight / n) / scale`과 기존 허용치로
일치했다. holdout 평가는 0회였고 원 fit 결과와 앞선 중단 작업은 보존했다.
이는 실제 FELUPE 실행이나 최종점 Numerical 문서·Study·보고서 저장 수용이 아니다.

실행 기록은 `_workspace/delivery-expert-study/c1-retained-final-20261015-01/`에
있다(72.37초, exit 0). 원자료 검증 세 번은 각각 약 16초였으며, 새 작업 제출은
22.66초에 끝나고 최종 상태는 61.06초에 확인했다.

## 범위와 정리

후속 확인은 중단된 **같은 Numerical 계획**에서 명시 새 실행 한 번만 제출했다.
기존 fit·상세·후보 저장 fixture를 다시 만들지 않았다. GUI의
`ExplicitAnalysisAction`과 owner command를 그대로 사용했고 제출 응답 유실을
주입한 뒤 같은 명령을 다시 확인해 하나의 새 작업만 남겼다. 합성 평가 5회,
holdout 0회와 동일 가중 Jacobian을 확인했다.

분석 계획과 그 정확한 결과의 보고서 자산·본문을 저장했다. GUI가 사용하는
Study 저장 helper에서도 저장 응답 유실 뒤 같은 명령으로 재시도해 질문이
한 번만 추가되는지 확인했다. 원 fit 결과와 이전 Interrupted 실행은 유지됐다.

그 사본의 휘발성 input/result 폴더를 제외한 뒤 새 Python 프로세스에서 합성
평가기 등록 없이 canonical 후보, 일반 J, 보고서 자산, Study를 읽고 다시 저장했다.
제출은 금지했으며 모델·새 작업은 0회였다. 기록은
`_workspace/delivery-expert-study/c1-owner-continuation-20261015-01/`에 있다
(278.26초, exit 0). 전체 Workbench 생성자 대신 기존 owner를 조합한
ServiceHost와 실제 Workbench 메서드를 사용한 확인이다.

별도 새 Windows Qt 프로세스에서 실제 분석·Study·보고서 창을 차례로 열었다.
등록 평가기 없이 GUI의 저장·제출을 금지하고, 세 창의 1200/850 너비와
동일 원자료·질문·진단 본문·보고서 자산을 확인했다. 실제 `app.exec()`를 사용했고
새 작업·모델은 0회였다. 기록은 `c1-cold-apps-20261015-02/`에 있다
(62.85초, exit 0). HTTP/전체 desktop.main 진입이나 Portable 사본의 새 문서
식별자 변환을 검사한 것은 아니다.

첫 Qt 시도의 Study 너비 검사는 splitter 방향을 바꾼 레이아웃이 안정되기 전
실패했다. 안정 후 요청 크기로 다시 조정해 제품 너비 변경 없이 해소했다.
그림에서 확인한 중복 질문 문구와 과거 자동 영문 제목·자료 이름은 표시만
보완하며, 기존 저장 문자열과 사용자 편집을 번역해 덮어쓰지 않는다.

마지막 Study 단독 실행에서는 앞선 분석 창의 글꼴 설정을 물려받지 않을 때의
한글 축 누락을 확인했다. 기존 글꼴 설정을 독립 창과 공통 보고서 그래프에
연결했다. Study 읽기 화면에서는 보고서의 중복 생성 제목 세 블록과 인쇄용
여백을 제외하고, 기존 renderer의 첫 실제 판단 문장과 표·곡선을 유지했다.
첫 문장은 기존 `blocks`가 반환한 첫 문장과 완전히 같은지 검사한다.

`_workspace/delivery-expert-study/c1-cold-study-20261015-03/`의 마지막 실행은
1200/850 화면, 한글 축, 기존 원문·질문·표시, 모델·새 작업 0회를 확인했다
(33.84초, exit 0, job_empty). 관련 실제 사용 그림은
[사용법](WORKFLOW_KO.md)에 있다. 분석/보고서 네 그림과 행동 검사는 변경되지 않아
다시 실행하지 않았다.

모든 위 실행은 `scripts/native_check.py`의 전용 Windows Job으로 종료했고
`job_empty`, `cleanup_error = null`을 확인했다. solver·ParaView·provider·장비는
새로 실행하지 않았다. 앞선 13개 선택 회귀는 12개 완료 표시 뒤 시간 초과했으므로
13개 통과로 집계하지 않는다. 이 결과는 공개 합성식과 선택한 저장 사본의
작업 흐름에 한정한다. 일반 이동 사본, 실제 재료법칙·장비, 통계적 신뢰구간과
전역 유일성 또는 공학적 승인의 수용으로 대신하지 않는다.
