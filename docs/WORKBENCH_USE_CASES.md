# CAE 연구 작업대 — 적용 사용 사례와 개발 인계

2026-10-07 · 외부 파일 연구 연결 보완. `WORKBENCH_REDESIGN.md` 개정 4의 사용 사례 부록이다. 기존 설계와 W1–W5를 대체하지 않는다. 기존 16개 사용 사례를 유지하고 UC17에 이들을 연결하는 공통 사용 패턴을 추가했다. 사례는 사용자 질문·입력·계산·판단을 연결한다. 사례 이름, 숫자, 분야를 새 ResearchProfile이나 허용 목록으로 만들지 않는다.

## 1. 이 부록의 목적

구현의 결과는 사용자가 수행할 수 있는 연구 작업이다. API 이름, 검사 개수, 문서 분량은 그 결과를 대신하지 못한다. 직접 계산과 결과 조회에는 OpenScience·MCP·AI·CAD·Study 등록이 필요하지 않아야 한다. 전문가를 쓰면 같은 자료와 결과를 읽고 같은 계산 경로를 호출한다.

아래 공식 문서와 원논문은 방법의 적용 근거다. 현재 저장소가 모든 기능을 지원한다는 증거가 아니다. 회사 자료가 없는 예시 수치는 합성임을 표시한다. 브라우저 수치 예시, 규칙 기반 자문, 실제 native solver 또는 LLM 실행을 구분한다.

**확정된 외부 연구 경로:** LS-OPT는 사용할 수 없다고 가정한다. 외부/상용 솔버의 ASCII·CSV·텍스트 출력과 계수표를 읽고, 우리 시스템의 기존 수치 라이브러리로 DOE·최적화·영향도를 계산한다. LLM은 변수·범위·DOE·목적을 제안하고 실제 결과에서 다음 탐색을 제안한다. OpenRadioss 전용 변환이나 새 상용 최적화 제품은 필수가 아니다. 자동 실행 연결과 결과만 가져오는 경로를 구분한다. 칩 충격시험은 그중 한 적용 예이며 나머지 연구 범위를 대체하지 않는다.

## 2. 구체적 사용 사례

### UC01 공급사 재료의 시간 의존성 비교

**질문:** 고무·폼·접착재의 이완 특성을 어느 모델과 계수가 설명하는가?

**입력:** 서로 다른 변형률/온도의 이완 또는 DMA 원본, 단위, 시험 이력, 적용 시간 범위.

**흐름:** 자료 열·단위 매핑 → 시험 단위의 동정용/별도 확인 분리 → 계수·범위·모델 선택 → 피팅 → 별도 곡선 확인.

**산출물과 판단:** 계수표, 시험별 예측·잔차, 적용 범위, 추가 시험. 재료 전문가는 모델 가정을, 시험 전문가는 이력·센서·온도를 검토한다. 짧은 시간 자료로 느린 완화시간을 확정하지 않는다. 같은 모델에서 만든 합성 holdout은 실제 재료 검증이 아니다.

**연결:** W1/W2/W4/W5. 방법 근거 S01/S02/S12.

### UC02 반복 소성·히스테리시스 모델 선택

**질문:** 재하·제하·역하중을 어느 법칙이 설명하는가?

**입력:** 인장/압축 반복곡선, 변형 이력·초기 상태·온도, 후보 MFront 법칙 또는 기존 라이브러리.

**흐름:** 같은 초기 상태·이력으로 후보 계산 → 항복/경화 계수 동정 → 다른 진폭 시험 비교 → 복잡한 모델을 추가할 이유 판단.

**산출물과 판단:** 응력–변형률 루프, 상태변수, 소산 에너지, 계수의 식별 한계. 단조 인장 오차 하나로 반복 거동까지 승인하지 않는다. 범용 동정 기능과 개별 법칙 지원은 다르다.

**연결:** W1/W2 기반과 해당 법칙 어댑터. 방법 근거 S01.

### UC03 구성모델 적분·접선·실패 증분 연구

**질문:** 수렴 불량은 응력 적분, 접선 선형화, 입력 경로 중 어디에서 생기는가?

**입력:** 실패 적분점의 초기 응력/상태, 변형 이력, 적분 옵션, 기준 응답.

**흐름:** 실패 증분 분리 → 같은 상태에서 재실행 → 시간증분/공차/접선 옵션 변경 → 수치미분 접선과 비교 → 전체 해석으로 수정 반영.

**산출물과 판단:** 경로별 응력·상태·접선 오차, 반복수·시간, 실패 조건. 후보 간 상태를 공유하지 않는다. 국소 통과가 전체 FE 수렴의 보장은 아니다.

**연결:** W1/W2 기반의 연구 플러그인. 방법 근거 S01/S04.

### UC04 비선형 PDE의 해법·격자 연구

**질문:** 같은 정확도에서 어느 해법·격자가 적절한가?

**입력:** 방정식/약형, 계수, 경계조건, 메시 또는 구간, 기준해, 관심 응답.

**흐름:** 같은 문제·공차로 Newton/Picard 등 실행 → 실제 잔차 비교 → 격자 변경 → 응답·기준 오차·시간 비교.

**산출물과 판단:** 잔차 이력, 장, 오차표, 반복수와 실행시간. 반복 잔차와 공간 오차를 구분한다. 특정 예제의 해법 순위를 모든 PDE에 일반화하지 않는다.

**연결:** W1/W2/W5, 이후 실제 FEniCSx/PETSc 설정 연결. 방법 근거 S03/S04.

### UC05 전자제품 포장 낙하 개선

**질문:** 완충 강성을 낮추면 충격이 줄어드는가, 바닥 접촉으로 더 커지는가?

**입력:** 질량, 낙하 속도/높이, 완충 공간, 압축곡선·감쇠, 상세 FE 덱과 실제 시험 이력.

**흐름:** 기준 보관 → 강성·감쇠·공간 변경 → 시간응답·에너지 비교 → 후보 선별 → 실제 접촉 FE와 시험 확인.

**산출물과 판단:** 힘·압축·시간 이력, 바닥 접촉 여부, 후보표. 회전·각속도·국부 파손은 상세 모델로 확인한다. 1자유도 최초 압축 예시는 패널 응력, 낙하 규격 통과 또는 파손 판정이 아니다. F/(mg)와 순가속도/g를 혼동하지 않는다.

**연결:** W2/W5의 반복·비교 경로와 explicit 어댑터 확장. 방법 근거 S09/S13. 상용 Radioss 문서의 카드가 선택 OpenRadioss 빌드에 모두 있다고 가정하지 않는다.

### UC06 과열 불량의 경쟁 가설과 개선안

**질문:** 열전도율이 높은 패드를 써도 왜 온도가 거의 낮아지지 않는가?

**입력:** 전력, 주변/열원/방열판 온도, 패드 면적·두께·전도율, 조립/접촉 이력.

**흐름:** 관측 입력 → 재료 내부·계면·냉각 저항 분리 → 열/재료/시험 관점의 반론 → 같은 조건의 개선안 계산 → 가설을 구별할 시험 결정.

**산출물과 판단:** 가설–근거–반증 표, 열저항 예산, 개선안 온도표, 다음 시험. 단일 열경로·정상상태·전력·센서 가정이 바뀌면 다시 판단한다. 두 온도만으로 조립 불량을 확정하지 않는다.

**연결:** W1/W2/W4/W5. 방법 근거 S05/S06/S07/S11.

### UC07 접착층·적층체 박리 연구

**질문:** 접착재·두께·표면처리 변경 중 무엇을 먼저 확인할 것인가?

**입력:** 박리/전단/혼합모드 시험, 계면 두께와 모델, 부품 형상/덱, 파손 관찰.

**흐름:** 계면 모델 동정 → 부품 해석 → 법선/전단 응답·손상/에너지 비교 → 확인 시험.

**산출물과 판단:** 계면 분리·미끄럼·손상 이력, 시험 상관, 후보별 영향도. 단일 응력 최대값만으로 반복 수명을 확정하지 않는다. 실제 파괴에너지·손상모델과 solver 지원이 필요하다.

**연결:** 공통 연구 경로와 계면/손상 어댑터 확장. 방법 근거 S01/S09.

### UC08 접촉 이후 수렴 저하 진단

**질문:** 접촉 상태 변화·구속·재료 적분 중 무엇이 실패를 유발하는가?

**입력:** 기존 덱, 증분 로그, 잔차/반력/접촉 결과, 최근 변경.

**흐름:** 실패 직전 상태 읽기 → 경쟁 원인 분리 → 한 요인씩 변경 → 같은 응답과 에너지 비교.

**산출물과 판단:** 설정 수정과 모델 수정의 우선순위, 실패 위치, 변경 전후 로그/응답. 임의 안정화로 종료 코드만 성공시키지 않는다. 수렴했다고 물리적으로 옳다고 하지 않는다.

**연결:** W3/W4와 solver별 진단 확장. 방법 근거 S01/S04/S09.

### UC09 지그·구조 설계 스터디

**질문:** 질량·강성·가공성 제약을 만족하는 치수 조합은 무엇인가?

**입력:** 파라메트릭 CAD 또는 기존 메시/덱, 재료·하중·구속, 목표·제약.

**흐름:** 변수 지정 → 모델 변경 → 실제 해석 → 유효 후보 비교 → 설계자 검토.

**산출물과 판단:** 변경 형상·조건표·질량/응답 절충·제조 제약. 최선 관측 후보와 전역 최적해를 구분한다. 첫 fixture 치수·하중이 모든 연구의 규칙이 되지 않게 한다.

**연결:** 기존 CAD 재사용 + W2/W3/W5. 방법 근거 S07.

### UC10 시험과 기존 결과의 상관 분석

**질문:** 차이는 단위·성분·축 정렬 문제인가, 모델 차이인가?

**입력:** 시험 CSV/지원 결과 파일, 센서/계산 위치, 성분·좌표계, 시간/주파수 축.

**흐름:** 단위·성분 매핑 → 명시적인 축 정렬 → 전체/구간 오차 → 원인 검토.

**산출물과 판단:** 겹친 곡선, 잔차, 구간 오차, 정렬/제외 설정. 비교를 위해 해석을 재실행하지 않는다. 무단 시간 이동이나 피크만 맞추는 처리로 상관이 좋아진 척하지 않는다.

**연결:** W1/W2/W4/W5. 미지원 포맷은 별도 reader 연결. 방법 근거 S01/S07.

외부 솔버가 내보낸 ASCII·공백 표·CSV도 같은 결과 읽기 경로에 넣는다. 계수표와 결과를 후보/시험 ID로 연결하면 UC11·UC17로 이어갈 수 있다. 계수 대응이 없으면 곡선 비교까지만 수행하며 변수 영향도를 안다고 하지 않는다. 읽기 자체에는 원래 솔버 설치가 필요하지 않다.

### UC11 공차·물성 산포와 민감도

**질문:** 평균 입력에서 좋은 설계가 편차에서 기준을 넘는가?

**입력:** 측정 또는 가정한 분포, 상관, 관심 출력·기준, 평가 함수.

**흐름:** 분석에 맞는 표본계획 → 반복 계산 → 실패 행 유지 → 출력 분포·영향도 → 관리할 산포 선택.

**산출물과 판단:** 분위수·초과비율·실패율, 영향도, 분포 출처. 결과 확률은 입력 가정에 조건부다. 최적화 후보를 확률 표본으로 쓰거나 임의 표를 Sobol 표본으로 사용하지 않는다.

**연결:** W2 기본과 고급 UQ 선택. 방법 근거 S07/S08.

### UC12 다음 시험 선택

**질문:** 어떤 시험이 물성 문제와 접촉 문제를 가장 잘 구별하는가?

**입력:** 경쟁 가설/모델, 기존 시험, 변경 인자, 장비 범위·비용.

**흐름:** 후보 조건의 가설별 예측 → 인자 설계 → 예측 차이와 측정 오차 비교 → 실제 시험 → 가설 수정.

**산출물과 판단:** 시험 조건표, 필요한 센서, 가설별 예측와 비용. 계산 횟수를 늘리는 것 자체를 성과로 삼지 않는다. 시험 전 예측은 실제 개선 보장이 아니다.

**연결:** W2/W4/W5. 방법 근거 S07/S11.

### UC13 대리모델·다목적 절충

**질문:** 어느 범위에서 계산 호출을 줄이면서 후보를 비교할 수 있는가?

**입력:** 실제 평가 표, 변수 범위, 목표·제약, 독립 확인 후보.

**흐름:** 기존 회귀/보간 fit → 별도 후보 확인 → 범위 내 탐색 → 최종 후보 native 재계산.

**산출물과 판단:** 확인 오차, 예측 범위, 실제/대리 응답 구분, 절충표. 범위 밖 외삽이나 미검증 예측을 실제 solver 결과로 표시하지 않는다.

**연결:** W2/W5와 고급 모델 선택. 방법 근거 S07/S08.

### UC14 불량 VOC·설계 변경의 전문가 자문

**질문:** 변경한 공급사·재료·설계가 어떤 실패 기구와 연결되는가?

**입력:** 불량 현상·발생조건, 변경 이력, 과거 보고서, 시험/계산 결과, 비용·일정.

**흐름:** 주 담당 전문가 선택 → 관련 근거 읽기 → 다른 분야에 필요한 질문만 위임 → 반대 근거 대조 → 계산/시험 제안 → 실제 결과 재검토.

**산출물과 판단:** 원인 후보·주장별 출처·반론·우선 조치·다음 확인. 자료가 부족하면 필요한 자료를 지정한다. RAG 답변이나 여러 에이전트의 동의는 원인 증명이 아니다. 모든 질문에 전원을 호출하지 않는다.

**연결:** W4/W5, UC06과 같은 실제 계산 경로. 방법 근거 S05/S07/S11. S11은 개발팀의 접근 설명이며 독립 성능 검증이 아니다.

자문은 계산 후 설명으로만 끝나지 않는다. 전문가는 근거를 바탕으로 바꿀 변수·범위·DOE와 관심 응답을 제안한다. 사용자가 편집하거나 사전 허용 범위를 확인한 뒤 수치 엔진이 계획을 실행한다. 전문가는 실제 영향도·오차·실패 자료를 읽고 다음 탐색 또는 추가 시험을 제안한다. UC17의 외부 파일 결과에도 같은 절차를 적용한다.

### UC17 공통 사용 패턴 — 외부 솔버 출력과 LLM의 반복 연구

**질문:** 기존 상용/외부 솔버 모델과 출력파일을 사용하면서, 무엇을 바꾸고 어떤 실험계획으로 탐색할지 함께 연구할 수 있는가?

**입력:** 기준 덱/모델 또는 이미 계산한 후보표, 별도 ASCII·CSV·텍스트 결과, 변수-입력 연결, 채널/단위/조건, 기준 시험 또는 설계 목표. 자동 실행에는 등록한 실행·추출 도구가 필요하다. 결과만 읽을 때는 원래 솔버가 필요하지 않다. LS-OPT는 사용하지 않는다.

**사용 순서**

1. 기존 결과와 입력을 선택한다. 표본 파일의 열·블록·시간/주파수축·채널 의미와 단위를 확인한다. 후보와 시험 ID를 계수표에 대응시킨다.
2. ‘어떤 변수를 바꿀지, 초기 DOE를 어떻게 할지 제안해’라고 전문가에게 요청한다. 전문가는 자료·실제 입력 항목을 읽고 변수·범위·목적·계산 예산과 근거/가정을 편집 가능한 계획으로 제시한다.
3. 사용자가 계획을 수정하거나 허용한다. 기존 수치 라이브러리가 DOE 후보를 생성한다. 직접 실행 연결이 있으면 실행하고, 없으면 후보/입력 묶음을 내보내 회사의 기존 방식으로 계산한다.
4. 후보별 결과를 가져온다. 파일의 숫자를 코드가 읽고 같은 규약으로 곡선·특징값·사건 오차를 계산한다. 누락과 계산 실패는 해당 행에 남긴다.
5. 수치 도구가 계획에 맞는 영향도·상호작용·잔차·실패 분포를 계산한다. 전문가는 어떤 응답에 어떤 변수가 영향을 주는지 근거와 함께 설명한다. 근거 없는 중요도 숫자를 만들지 않는다.
6. 중요한 변수의 추가 DOE, 범위 조정, 최적화, 후보 모델 비교, 추가 시험 또는 종료를 제안한다. 허용된 범위에서는 다음 배치를 실행하고, 범위가 바뀌면 확인한다.
7. 최선 후보를 별도 조건에서 다시 확인한다. 계수·입력·곡선/사건·오차·영향도·계획 변경 이유·한계를 보고서에 남긴다.

**예 A — AP+DRAM 패키지 충격 물성 동정:** 지그·고정부 로드셀로 얻은 하중 이력과 파손 관측을 LS-DYNA 모델의 별도 출력과 비교한다. 먼저 어느 응답이 실제 로드셀 채널인지 정한다. 접촉력을 지지부 전달력과 같은 것으로 취급하지 않는다. 재료/계면·손상 등 선택 변수의 DOE와 영향도를 보고 곡선·파손 사건을 함께 설명하는 후보를 찾는다. 파손 관측이 없거나 해석에서 미발생한 경우와 계산 실패를 구분한다. 지그/계측계·메시·충돌 조건을 물성에 잘못 떠넘기지 않도록 근거와 별도 시험을 확인한다. 특정 카드·칩 치수·변수 목록은 아직 확정하지 않는다.

**예 B — 열모델 동정과 과열 개선:** 상용 열해석에서 센서 위치의 온도-시간 ASCII와 열전도율·계면저항·냉각 조건표를 받는다. 열/시험 전문가가 구별 가능한 변수와 추가 전력 조건을 제안하고, 동일 수치 엔진이 DOE·동정·확인 응답을 계산한다. 칩 충격의 파손 응답이나 특정 force 파일이 이 경로의 조건이 되어서는 안 된다.

**예 C — 구조·접촉 또는 사용자 수치코드 연구:** 기존 해석/사용자 프로그램의 변위·반력·토크·잔차 텍스트와 후보표를 읽는다. 하중·마찰·강성 또는 수치계수의 영향과 비용을 비교한다. 같은 실행/추출 경계와 전문가 계획을 재사용하며 별도 상용 최적화기를 만들지 않는다.

**결과와 한계:** 파일 수집·최적화 엔진·LLM 답변이 따로 노는 것이 아니라, 실제 계획과 숫자가 다음 계산으로 이어져야 한다. 결과만 있고 계수표가 없으면 변수 영향도는 알 수 없다. 새 후보를 실행할 통로가 없으면 미평가로 남기고 다음 배치를 제안한다. 대리모델 예측은 실제 결과와 구분한다. 목적·정렬·가중치를 바꾸면 저장 응답을 같은 새 기준으로 평가하고 서로 다른 기준의 순위를 섞지 않는다. 작은 오차는 원인 확정이나 물성의 유일성 증명이 아니다.

**연결:** 설계 4.4절·7.1절과 W1–W5에 공통 연결을 구현한다. 실제 LS-DYNA 덱·native 출력·회사 실행 연결은 1차 이후의 첫 현업 확장으로 진행할 수 있다. 공통 기능은 그 환경을 기다리지 않는다. 참고 S08/S12/S15–S19. 이 사용 패턴은 UC01–UC16을 대체하거나 지원 대상을 17개로 제한하지 않는다.

## 4. 불량 자문이 받아야 할 정보와 남겨야 할 결과

입력은 문제 설명, 발생 조건, 선택 문서/결과, 변경 이력, 가능한 조치와 실행 예산이다. 주 담당 전문가는 확인한 관측과 추론을 구분한다. 다른 전문가에게는 필요한 질문과 근거만 전달한다. 답변에는 주장, 근거 위치, 반대 근거, 미확인 가정, 계산 또는 시험 제안이 남는다.

계산 제안에는 backend, 입력/결과 참조, 바꿀 변수, 관심 응답, 실행 개수·자원 범위를 넣는다. 사전 허용 범위 안에서는 매 후보를 다시 승인받지 않는다. 범위를 벗어나면 확인한다. 도구 실행 결과를 읽은 뒤 답을 갱신한다. 전문가의 대화가 끝났다는 이유로 아직 실행 중인 solver를 완료로 표시하지 않는다.

DOE 방법·변수 범위·목적/제약·예산과 그 이유도 제안에 남긴다. 수치 엔진은 실제 후보와 영향도를 만들고, LLM은 그 수치와 출처를 읽어 계획을 수정한다. LLM은 매 후보의 파서·수치 평가기로 사용하지 않는다. 회사 파일 전체를 외부 모델이나 문헌 검색 서비스에 자동 전송하지 않는다. 허용한 자료 범위의 요약과 필요한 응답만 전달한다.

원인 결론에는 강도를 구분한다. ‘관측과 일치하는 가설’, ‘비교 시험으로 지지된 원인’, ‘추가 자료가 필요한 가능성’을 한 문장으로 합치지 않는다. 여러 모델의 합의나 검색 점수를 과학적 확률로 표시하지 않는다.

## 5. 예시 자료와 실제 구현의 구분

이전에 별도 제공한 HTML은 값을 바꿔 재료 이완식, 비선형 열전도 유한차분, 최초 압축 축약모델, 열저항 회로를 실제 계산한다. 영상은 그 HTML에서 입력·클릭·계산·스크롤·내보내기를 수행한 화면 기록이다. PPT 도형 이동 영상이 아니다.

다만 HTML은 생산용 어댑터가 아니다. MFront/FEniCSx/PETSc/OpenRadioss를 호출하지 않는다. 불량 자문은 현재 수치와 작성된 규칙으로 생성한 검토 예시다. 실제 다중 LLM 실행은 확인하지 않았다. 선택적인 localhost 모델 요청 코드는 기본 동작과 구분하며 실패 때 작성 예시로 대체하지 않는다.

제품은 기존 수치·검색·에이전트 라이브러리를 연결한다. 브라우저의 작은 동정기·적분기를 복사하여 새 생산용 solver/optimizer를 만들지 않는다. 같은 합성 수식에서 만든 holdout을 실제 재료 검증으로 사용하지 않는다. 18/50 mm, 세 시험, 27조합 등의 예시 수치를 제품의 허용 범위로 고정하지 않는다.

이번 UC17과 개정 4의 파일 응답·LLM 연구 반복은 문서상 보완이다. 기존 HTML/영상이 실제 LS-DYNA 또는 새 자동 연구 기능을 시연한다고 주장하지 않는다. 회사 파일·상용 실행·실제 LLM 반복은 구현과 해당 환경에서 확인한다.

## 6. 개발 시작과 종료 판단

개정 4 W1–W5는 기존 개정 3에 공통 연결을 보강한 구현 기준이다. 이 부록은 작은 형식 작업 대신 실제 연구 산출물을 계속 보게 하는 연결 자료다. 문서만으로 Codex의 구현 품질을 보장할 수는 없다. 실제 사용자 결과를 보고 판단한다.

- 한 묶음을 시작할 때 사용자가 새로 할 수 있는 일을 정의한다. 관련 코드와 재사용 후보를 확인한 뒤 입력·계산/검색·출력·화면을 연결한다.
- 수치 오류, 데이터 손상, 권한 침해, 잘못된 종료는 해결한다. 과거 profile/prompt 문자열 불변성 때문에 새 기능을 막지 않는다.
- 계정·native runtime·회사 자료가 없으면 정확한 미확인 항목을 한 번 기록한다. 관련 없는 구현은 계속한다. 모의 시험을 실제 실행이라고 하지 않는다.
- 성능 비용이 이미 충분히 작다는 측정 결과가 나오면 다음 사용자 기능으로 간다. 개선 배수를 만들기 위해 미세 최적화를 무한히 반복하지 않는다.
- 같은 실패를 변경 없이 재실행하거나 작은 수정마다 새 전체 감사·새 설계문서·새 스킬을 만들지 않는다.
- 전체 개편을 맡았다면 W1만 끝내고 중단하지 않는다. 정의된 의존 관계로 W2–W5를 이어간다. 기존 사용자 자료·미커밋 작업은 보존한다. 병합은 현재 사용자 지시와 AGENTS.md를 따른다.

**시작 지시:** `WORKBENCH_REDESIGN.md`의 전체 W1–W5와 이 부록의 대표 사용자 흐름을 읽고 현재 브랜치를 확인하라. 설계 감사만 반복하지 말고 아직 연결되지 않은 실제 사용자 기능을 구현하라. 사용자가 새 자료와 값을 넣어 실행한 결과, 실제로 사용한 도구, 미확인 환경과 다음 기능을 보고하라. 규칙 기반 데모를 전문가 시스템의 완료 증거로 쓰지 말라. LS-OPT를 전제하지 말고 파일 기반 연구를 기존 기능에 연결하되 칩 사례에 범위를 고정하지 말라.

**완료 범위:** W5까지 실제로 동작하면 정의된 첫 연구 작업대가 완료된다. 모든 물리법칙·native 카드·임의 연성·장비·HPC까지 완료되는 것은 아니다. 실제 연결을 못 한 항목은 남겨둔다. 지원 기능 목록과 실제 사용자 산출물이 기준이다. 개별 상용 솔버 후속 연결은 설계 12.8절을 따른다.
