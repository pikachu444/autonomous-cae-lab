# 2026년 10월 15일 브랜치 정리

현재 제품 코드는 `main`에서 관리한다. 로컬의 `codex/delivery-data-material`,
`codex/delivery-numerical-pde`, `codex/delivery-post`는 현재 담당자의 작업 브랜치다.
원격 작업 브랜치는 모두 정리했으며 원격에는 `main`만 남겼다.

처음 로컬 14개·원격 15개를 정리한 뒤, 사용자의 후속 지시로 남은 로컬 16개와 원격
23개의 실제 변경까지 대조했다. 커밋 번호나 `git cherry`의 차이만으로 미반영이라고
판정하지 않고 현재 함수·문서·테스트와 비교했다. 열린 PR은 없었다.

| 확인한 내용 | 처리 |
|---|---|
| 재료·비선형 PDE·모델 변수·접촉·충격·Post·Co-STORM·보고서 | 현재 main에 통합되거나 확장됨. 구형 코드를 다시 덮어쓰지 않음 |
| 조립 좌표 후보 | `assembly_candidates`, `candidate_recipe`, `candidate_worker`, `occurrence_fem`의 제품 소스가 원격 분기와 동일. 후보 전용 자세·Support 갱신·엄격한 재열기 기능을 실제로 보존 |
| D1 기능 명세·Qt 상세 설계 | 편집 원본은 현재 설계 폴더에 보존. 현재 상태·화면의 후속 갱신 유지 |
| 옛 OpenScience launcher | 독립 도구 전환 커밋에서 의도적으로 제거됨. 현재 host/MCP 설정을 옛 모델·프로필로 되돌리지 않음 |
| fixture refinement 검증기·클라우드 탐색·Gemma CI·조립 checkpoint | 과거 검증·탐색 기록으로 보관. 새 제품 기능이나 현재 선행 검증으로 추가하지 않음 |

추가로 이식할 필수 제품 코드는 찾지 못했다. 이 판단은 현재 제품의 모든 기능이
완료됐다는 뜻이 아니다. 남은 개발은 [CURRENT_STATE](../../CURRENT_STATE.md)의
일곱 인도를 계속 따른다.

정리 전 원 커밋은 먼저 검증한 로컬 Git bundle과 원격의 `archive/2026-10-15/`
태그로 보관했다. 조상 관계로 포함되는 커밋은 중복 태그를 만들지 않았다.
[원래 참조와 커밋 목록](20261015-branch-cleanup.csv)은 이번 추가 정리의 복구 색인이다.

필요한 옛 소스를 확인할 때는 `git fetch origin --tags` 후 목록의 커밋에서
`git show <커밋>:<파일>`로 읽는다. 실제 재개할 필요가 있을 때만 해당 커밋에서
새 작업 브랜치를 만든다. 복구가 현재 main으로의 자동 병합을 뜻하지는 않는다.

작업 폴더를 지우거나 `reset`·`clean`을 실행하지 않았다. 과거 브랜치에 연결된
5개 작업트리의 HEAD만 동일한 커밋에 고정했고 이미 분리된 2개는 그대로 뒀다.
해당 7개 폴더의 변경 상태·index/작업 diff와 미추적 파일 내용이 유지됨을 확인했다.
무시된 실험 폴더도 삭제하지 않았다. 현재 main과 개발 담당 3개는 이 작업에서 제외했다.

누적 정리: 로컬 30개·원격 38개. 정리 직후 로컬 4개·원격 1개.
강제 push와 브랜치 보호 우회는 하지 않았다.
