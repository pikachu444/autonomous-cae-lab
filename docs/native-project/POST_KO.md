# ParaView Post 프로젝트 옮기기와 파일 복구

Post에서 저장한 처리 순서, 입력 파일을 읽는 설정, 분석 이력, 선택, 시간과 카메라를 파일 사본에 포함한다. Workbench 서비스 없이도 설치된 ParaView와 기존 Post 문서의 저장 경로를 쓴다. 해석 솔버를 다시 실행하지 않는다.

## 결과를 열고 작업 사본 만들기

1. 결과를 Post에서 열고 ParaView의 Pipeline Browser에서 대상을 선택한다. Properties의 미적용 변경은 Apply 또는 되돌리기로 정리한다.
2. Post의 프로젝트 저장 동작이나 `Ctrl+S`로 현재 처리 순서와 표시를 저장한다. 가져온 저장본의 첫 저장은 **새 작업 프로젝트로 저장**할지 확인한다. 현재 창의 편집은 같은 창에서 이어지고 원 저장본은 보존된다.
3. 연결 화면에서 저장본의 사본 만들기를 선택한다. 저장본과 필수 입력 파일을 포함한 사본 검사 결과를 확인하고 폴더를 고른다. 저장본을 별도 창에서 열기와 작업 사본 열기는 구분된다.
4. 사본을 다른 폴더나 컴퓨터로 옮긴 뒤 현재 컴퓨터에 설치된 ParaView로 연다. 사본에 적힌 실행 프로그램 경로는 실행 권한으로 쓰지 않는다.
5. 편집 후 저장하고 다시 사본을 만들 수 있다. 재복사한 사본의 최신 저장본과 원본 보존 자료는 별도로 검증된다.

가져온 저장본과 아직 현지 저장하지 않은 작업 사본은 **미저장** 상태로 열린다. 원 저장본의 보존 정보와 현재 창의 저장 완료 상태를 구분한다. ParaView에서 저장을 마친 뒤에만 현재 창이 저장 완료 상태가 된다.

같은 작업 사본이 이미 열려 있으면 연결 화면은 확인된 현재 창을 활성화한다. 다른 저장본은 별도 문서로 열린다. 이전 창의 미저장 편집을 덮어쓰지 않는다.

## 파일이 없거나 바뀐 경우

필수 파일이 없으면 모두 정상으로 열었다고 표시하지 않는다. **일부 복구**를 명시적으로 선택하면 정상인 다른 자료와 화면을 열고 누락된 부분을 안내한다. 저장 당시와 내용이 달라진 파일은 누락과 구별하여 차단한다.

보관한 분석 파일도 없으면 원래 처리 방법과 분석 간 연결, 어떤 결과를 어느 입력에 연결했는지는 남긴다. 저장 당시 결과 파일의 내용을 확인할 정보와 작성 중인 내용, 선택 위치, Undo/Redo 기록도 보존한다. 원값을 대신하는 읽기 설정이나 계산 결과를 만들지 않는다. 저장 시 누락된 분석을 과거 기록으로 함께 보관할지 다시 확인한다. 내용이 확인된 기존 파일과 원 저장본의 확인 정보만 함께 저장하며, 다시 옮겨 열어도 누락 상태가 유지된다. 과거 요약은 **과거 기록·원값 미확인**이며 검증된 수치 입력으로 사용할 수 없다.

파일 위치를 다시 연결할 때는 기존 등록 입력의 파일명 관계, 파일 내용, 묶음 안의 위치와 반복 순서, 읽기 방식과 지정한 정보를 대조한다. PVD의 시각별 데이터나 물리 선언이 바뀌면 새 입력 결과로 추가해야 한다. 위치 복구로 기존 실패나 UNKNOWN을 성공으로 바꾸지 않는다.

처음 등록할 때 원 파일이 없었어도 저장본에 누락 위치와 저장 당시 파일 내용을 정확히 확인할 정보가 남아 있으면, 이미 등록한 같은 내용의 입력 파일로 현재 창에서 복구한 뒤 저장하고 사본을 다시 만들 수 있다. 원 누락 기록과 과거 저장본은 보존한다. 저장 당시 파일 내용을 확인할 정보가 없거나 파일명 관계·내용이 다르면 임의로 추정하지 않는다.

하나의 입력을 같이 읽는 보조 설정과 과거 분석의 읽기 설정도 모든 파일 경로를 먼저 확인하고 한 번에 복구한다. 영향받는 과거 분석의 연결과 입력 대응을 함께 검증한 뒤 문서를 갱신한다. 도중 실패하면 읽기 설정과 문서, 기준 입력을 연결한 상태를 모두 되돌린다. 서로 다른 입력 여러 개를 한꺼번에 복구하는 범용 기능은 제공하지 않는다.

## 복구한 작업 저장하고 계속하기

연결 화면에서 저장을 요청한 경우에도 누락 분석 보관 동의는 현재 ParaView 창에서 받는다. 창이 없으면 저장하지 않고 현재 창에서 확인하도록 안내한다. 취소한 저장 요청은 실패로 남기고 실제 저장을 실행하지 않는다.

저장 전에 요청이 거절됐거나 저장 실패가 확인된 경우에는 사용자가 다음 저장을 요청할 수 있다. 저장을 마친 뒤 응답이 유실되거나 등록에 실패한 경우에는 같은 완료 요청의 저장 결과를 다시 확인한다.

## 지원 범위

실제 파일 읽기는 `XMLUnstructuredGridReader/FileName`, `PVDReader/FileName`, `XMLTableReader/FileName`, `XMLPolyDataReader/FileName` 조합만 허용한다. PVD는 순서, 반복 frame, time/group/part를 보존한다. 파일 연결 관계 검사는 parallel VTK의 `Piece Source`와 복합 데이터 계층도 포함하지만, 실제 ParaView의 읽기 동작이 확인되지 않은 형식은 완전 지원으로 표시하지 않는다.

파일을 읽는 모든 `FileName` 항목, 원 입력의 저장 당시 내용 확인 정보, 분석 이력 전체의 기존 읽기 설정과 명시한 정보를 수집한다. 지원하지 않는 읽기 방식, 실행 기능이 있는 PVSM 설정, 저장 당시 내용을 확인할 정보가 없는 입력은 성공 처리하지 않는다. PVSM 파일을 직접 가져올 때는 상태 읽기를 명시적으로 요청하고 현재 ParaView의 실제 읽기 설정을 확인한 뒤 새 작업 프로젝트로 저장한다. 과거 분석 이력을 새로 만들지 않는다.

과거 분석은 당시 저장본이 참조한 원 입력을 검증한다. 처음 고른 입력으로 분석을 만든 뒤 현재 입력을 다른 저장본으로 바꾸어도 과거 분석은 처음 입력에 연결된다. 현재 입력이 달라졌다는 표시는 별도로 표시한다. 경로 이외의 필터 인자, 읽기 방식, 출력 포트와 물리 선언 변경은 계속 검출한다.

## 확인한 동작과 남은 확인

실제 ParaView를 새로 실행해 원 경로 없는 작업 사본 열기, 분석의 새 Apply/Undo/Redo, 원 입력의 선택 변경 후 후속 분석의 고정 입력 보존, 실제 저장과 최신 저장본 등록, 기존 사본 작성 경로, 첫 사본 없는 두 번째 열기를 확인했다. 가져온 저장본의 첫 저장은 같은 문서를 유지하면서 새 작업 대상에 저장했다. 저장 응답이 유실된 경우 다음 명시 확인에서 같은 완료 저장을 재확인했고 실제 저장은 한 번이었다.

누락된 분석은 실제 일부 복구→명시 보관 저장→재복사→첫 사본 없는 두 번째 일부 복구에서 원 기록과 저장 당시 파일 내용의 확인 정보를 보존하고 정상인 분석을 검증했다. 모든 ParaView 검사는 호출별 Windows Job Object에서 실행하고 종료 후 실행한 프로세스가 남지 않았음을 확인했다.

교정 검사에서는 중간 입력이 처음부터 누락된 상태에서 과거 분석의 정상 입력을 유지하고, 같은 내용의 파일을 복구한 뒤 새 후속 분석을 저장했다. 같은 세션에서 과거 입력 파일의 위치를 복구한 뒤 후속 분석의 고정 입력을 검증하고 물리 인자 변경을 검출했다. 다시 저장·복사한 뒤 원 경로와 첫 등록 폴더 없이 새로 실행한 ParaView에서 다시 열기까지 확인했다. 저장 거절·실패·응답 유실 뒤의 처리는 위의 저장 안내와 같다. 교정 원문은 `_workspace/delivery-native-project-post/correction-01/CORRECTION_KO.md`에 있다.

복구한 일부 사본이 ParaView 창을 여는 도중 종료되던 문제도 수정했다. 원 저장본은 그대로 두고 창에서 읽는 사본만 보완한다. 실제 ParaView 창에서 복구 사본을 저장한 뒤 새 창으로 그 저장본을 다시 열어 시간·카메라·표시 설정과 분석 이력이 유지되는 것을 확인했다. 새 해석 계산은 하지 않았다.

이미지는 실제 ParaView 렌더링이다. 창 시작·문서 연결·저장·새 창 재열기는 확인했지만, 직접 조작 확인 도구는 창 활성화에 실패했고 캡처가 검게 반환됐다. 메뉴 클릭, 한국어 글꼴, 좁은 창과 키보드 초점의 실제 화면 수용은 아직 미확인이다. 확인용 창은 모두 정리했다. 이 결과를 GUI 전체 수용이나 물리적 타당성 승인으로 보지 않는다. 예제 수치는 합성 자료이며 물리적 적합성은 UNKNOWN이다.

검사 원문과 확인에 사용한 소스 목록은 `_workspace/delivery-native-project-post/DELIVERY_KO.md`, 예제 실행 파일은 `examples/native-project-post/`에 있다.
