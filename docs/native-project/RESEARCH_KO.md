# 모델과 연구 문서를 함께 옮기기

저장한 FreeCAD 모델과 Data·Study·Report를 같은 작업 사본에 포함할 수 있습니다.
원 보관소가 없어도 관측 자료를 읽고, 질문과 판단·보고서를 편집해 저장한 뒤 다시 옮깁니다.
사본 만들기는 메시 생성, 솔버 계산이나 새 모델 생성을 실행하지 않습니다.

먼저 FreeCAD에서 모델을 저장합니다. 외부 부품이 있는 조립은 필요한 부품을 함께 열어
프로젝트를 저장하고 누락 파일을 확인하세요. 자세한 조작은 [FreeCAD 모델 옮기기](PRE_KO.md)를
따릅니다. 연구 문서는 Data에서 자료의 열·단위·시간을 확인하고 저장한 뒤 Study의 근거와
Report의 원자료로 선택합니다. 실제 관측이 아닌 합성 자료는 그대로 표시하고, 모델과의
물리적 대응을 확인하지 않았다면 미확인으로 남깁니다.

복사할 문서 목록에 연구 문서와 저장 모델을 함께 고릅니다. 필수 부품이 없거나 저장본이
바뀌었다면 해당 자료를 먼저 복구합니다. 포함 목록을 확인하고 원 보관소와 겹치지 않는 새
폴더에 작업 사본을 만듭니다. 원 모델과 새 작업 모델은 별개이며, 과거 연구가 참조한 저장본을
새 모델의 편집 내용으로 바꾸지 않습니다.

새 폴더의 프로젝트를 열면 기존 Data·Study·Report에서 계속 작업할 수 있습니다.
Data의 원값과 실패한 읽기 기록은 유지됩니다. Study의 질문·가설·판단과 Report의 제목·본문을
수정하고 저장하세요. 다시 옮길 때는 이 사본의 현재 문서와 포함할 모델을 선택합니다.
실패 기록을 지우거나 미확인을 승인으로 바꾸지 않습니다.

Study와 Report에는 선택한 FreeCAD·ParaView 저장본 전체를 정확한 근거로 연결합니다.
같은 폴더의 다른 파일이나 모델의 최신 편집 내용으로 바꾸지 않습니다. 부품·면·배열·성분의
물리적 대응은 저장본 전체 참조만으로 확정되지 않으므로 따로 확인해야 합니다.
보고서에 고정한 원자료는 사본에서도 유지하고, 원자료 열기는 사본에 포함한 저장본으로 연결합니다.

## 공개 Python 예제

기존에 저장한 공개 모델을 사용합니다. 예제는 제공한 모델을 변경하지 않고 새 예제 폴더만
만듭니다. 연구 자료는 힘 N, 시간 s를 명시한 합성 관측이며 한 번의 실제 표 읽기 실패도
함께 남깁니다. 구조·재료 계산이나 FreeCAD·ParaView 실행은 하지 않습니다.

```powershell
python examples/native-project-research/public_mixed.py --native-project "저장한 공개 모델.caepre" --output "새 연구 사본 예제"
```

ParaView 저장본도 함께 포함하려면 기존 결과 프로젝트와 그 자료 폴더를 명시합니다.
결과 파일은 새로 계산하지 않습니다.

```powershell
python examples/native-project-research/public_mixed.py --native-project "모델.caepre" --post-project "결과/project.json" --post-root "결과" --output "새 통합 연구 사본"
```

`.FCStd`도 기존 저장 파일 등록 경로로 검사합니다. 예제는 Data·Study·Report와 모델을 함께
복사한 뒤 예제 자신이 만든 원 보관소를 이름 변경하고, 별도 Python 프로세스가 원 보관소와
제공 모델 폴더를 읽지 못하게 한 상태에서 연구 문서 편집·저장·재복사를 확인합니다.
두 사본에서 Study 근거와 Report 원자료를 실제로 읽고, 보고서에 고정한 자료의 원바이트가
같은지 확인합니다. 다른 저장본으로 바뀐 참조는 거절합니다.
공급한 파일이나 사용자 보관소를 지우거나 이름 변경하지 않습니다.

생성된 **연구와 모델 사본**, **다시 옮긴 사본** 폴더에서 작업을 이어갈 수 있습니다.
네이티브 모델을 실제 프로그램에서 여는 검사는 [FreeCAD 안내](PRE_KO.md)와 해당 Post 안내의
지원 경로를 따릅니다. 이 예제의 파일 검사를 네이티브 화면·형상·강도 또는 전체 제품 완료의
판정으로 사용하지 않습니다.
