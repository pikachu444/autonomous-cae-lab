# 조립 운동 편집과 미리보기

FreeCAD 1.1.4의 Assembly와 설치된 운동학 계산을 사용한다. 운동 미리보기에는
FEM 솔버, AI 또는 별도 운동 솔버가 필요하지 않다. FE 후보를 만드는 별도 흐름은
[ASSEMBLY_CANDIDATES](ASSEMBLY_CANDIDATES.md)를 따른다.

## 부품과 관절

CAE의 조립 운동 패널에서 문서의 조립을 선택한다. **조립 만들기 / 부품 배치**를
펼치면 같은 문서의 부품이나 조립을 배치할 수 있다. 하위 조립은 native
`Assembly::AssemblyLink`로 만든다. **하위 조립을 강체로 배치**를 해제하면
그 안의 관절도 전체 운동 계산에 참여한다. 가동 하위 조립은 내부 부품을 고정한다.

**부품과 관절**에서 관절, 연결 A/B의 부품과 면·모서리·점을 선택한다.
3D 화면 또는 트리에서 선택한 요소는 **화면 선택을 연결 A/B로**로 가져온다.
연결 요소의 빈칸은 부품 원점이다. 면·모서리를 고르면 native 중심,
점을 고르면 그 점을 사용한다. 기존 native 연결의 별도 위치/분리 좌표는
같은 참조를 유지할 때 보존한다. 거리의 단위는 mm, 관절 각도 속성은 deg다.

**관절 적용**은 같은 native 관절을 수정하고 **관절 편집 취소**는 저장된
관절의 참조와 값을 다시 읽는다. 사라진 부품·요소는 본 화면에서 재선택을
요청한다. 다른 부품으로 자동 대체하지 않는다. 가동 하위 조립의 관절 복사본은
원본 조립을 선택해 편집한다. 복사본은 FreeCAD가 원본과 다시 동기화하므로
그 복사본을 직접 수정/삭제하는 명령은 막는다.

### 중첩 조립의 배치 하나만 선택하기

두 단계 이상의 가동 하위 조립도 **최상위 조립**을 선택하여 구동한다.
관절·연결 A/B·경로점의 부품 목록에는 조립 계층을 함께 표시한다.
같은 원부품을 참조하는 서로 다른 Link는 각각 선택할 수 있다.
같은 이름의 형제 배치는 `배치 1`, `배치 2`로 구별하며, 저장에는 실제 native
occurrence·관절 참조를 유지한다. 좁은 구동 관절 셀의 전체 경로는 마우스를 올려 확인하며,
선택한 경로점 행의 전체 대상은 표 아래에도 표시한다.

**시간과 구동**에서 해당 계층의 관절 복사본을 고르고 구동을 적용한다.
**경로점**에는 같은 계층의 실제 배치와 그 배치의 로컬 좌표(mm)를 지정한다.
계산 후 **점 경로**에서 해당 점을 읽는다. 세계 좌표는 최상위부터 실제 배치까지의
이동·회전 곱으로 구하며, 여러 부모에 걸친 native 객체의 로컬 좌표를 세계 좌표로
추정하지 않는다. 같은 source를 참조한다는 이유로 다른 Link나 원부품을 움직이지 않는다.

**하위 조립을 강체로 배치**하면 전체 배치가 하나의 native body다.
그 내부 부품은 개별 연결·고정 대상으로 고르지 않는다. 강체 내부의 경로점은
선택할 수 있고 해당 강체의 자세를 따라 세계 좌표로 읽는다. 가동 배치는 내부의
관절과 부품을 개별 선택하며 내부 부품을 고정한다. 원본 조립의 관절을 수정하면
FreeCAD의 관절 복사본도 동기화되므로, 배치 한 곳의 운동은 원 관절을 몰래 수정하는
대신 최상위의 구동 정의에서 그 배치의 관절 복사본을 선택한다.

사라진 배치·모호한 다중 소속은 해당 연결/경로점에서 **참조 없음** 또는 행 오류로
표시한다. 같은 원부품의 다른 Link로 자동 대체하지 않는다. 실제 CAD 트리에서
그 위치의 배치를 다시 만들거나 선택한 뒤 관절/구동을 명시 적용한다.
재지정을 취소하면 이전 참조와 경로점 입력으로 돌아간다. 잘못된 초안도 저장할 수
있으며 적용 전에는 실행을 막는다. 일반 저장과 새 owner 재열기는 정확한 참조·행 선택과
보존 경로를 유지하고 운동을 자동으로 다시 계산하지 않는다.

FreeCAD 1.1.4의 깊은 관절 수집 경계를 보완하기 위해 계산/자세 갱신 중에는 실제
관절 복사본을 native root 관절 그룹에 잠시 이동한다. 새 관절·solver를 만들지 않는다.
동기 호출 종료·실패 후 기존 모든 그룹의 멤버와 순서를 대조하여 복원한다.
가동 부모의 비항등 자세는 native 독립 body의 최상위 로컬 좌표로 변환하고,
호출 뒤 원 부모 좌표로 되돌린다. 강체 내부 leaf를 다시 변환하지 않는다.
이 과정에는 저장·recompute·이벤트 양보가 없고, 복원이 실패하면 저장과 전환을 막는다.
근거는 [native 관절 수집](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/App/AssemblyObject.cpp#L600)과
[Group 소유권 이동](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/App/GroupExtension.cpp#L94)이다.

작은 공개 두 단계 모델에서 한 가동 배치의 이동과 경로, 다른 반복 배치/강체 배치 및
원 정의 보존을 확인했다. 최상위와 두 가동 부모에 각각 이동·3축 회전을 지정한 경우
고정한 로컬점의 기대 세계 좌표와 native 경로를 대조했다. 실제 계층 삭제 후 재지정
취소·적용·`.caepre` 새 owner 재열기도 확인했다.
실행 자료는 `runs/motion-nested-native/transform-receipt.json`과 두 크기의 실제
FreeCAD Qt 화면이다. 초기 실패와 그룹 복원 실패도 같은 폴더에 보존했다.
기존 출력격자 시간과 실제 시각의 대응 미확인, M1 일반 관계식 잔여,
M3 닫힌 기구·M4 FE 후보 및 전체 OS 마우스 작업 수용은 별도 범위다.

## 시간과 복수 구동

**시간과 구동**에서 시작·끝·출력 간격을 초로 입력하고 구동을 추가한다.
회전 관절은 회전(rad/deg), 직선 이동 관절은 이동(mm), 원통 관절은 두 종류를
사용할 수 있다. 관절을 바꾸면 단일 운동 종류와 단위가 함께 바뀐다.
한 관절의 같은 종류 구동을 중복 지정하거나 누락된 관절을 선택한 행은
적용 전에 행별로 알린다. 삭제된 관절 대신 새 관절을 선택하고 적용하여 복구한다.

시간곡선은 native 식을 그대로 사용한다. `time`의 단위는 초다. 예를 들어
`0.2*time`은 초당 0.2 rad의 회전, `2*time`은 초당 2 mm의 이동이다.
1..32개 구동, 최대 2,001개 프레임과 8개 경로점의 기존 제한을 유지한다.
경로점은 선택 부품의 로컬 좌표(mm)이며 읽은 경로는 문서 전체 좌표(mm)다.

### 한 구동을 따라 움직이는 관절

구동 행을 선택하면 **선택한 구동의 관계와 허용 한계**에서 이름·출력 단위와
구동 방식을 편집한다. 회전의 출력은 rad 또는 deg, 이동은 mm다.
**다른 구동 따라가기**는 명시적으로 구동된 기준 관절의 회전 또는 이동을
선택하여 `종속 값 = 기준 값 × 비율 + 영점 이동`으로 연결한다.
기준값은 그 구동의 선언 단위 값이며 미구동 관절의 자세를 추정한 값이 아니다.
원통 관절의 회전과 이동은 서로 다른 구동으로 선택한다.

예를 들어 기준 회전을 `90*time` deg, 종속 이동의 비율을 `2` mm/deg,
영점 이동을 `0` mm로 설정하고 끝 시간을 1초로 지정하면 native 끝 자세는 180 mm 이동이다.
기준 시간식을 `45*time`으로 수정하고 **구동 적용 → 운동 계산**을 하면
native 끝 자세의 종속 이동도 90 mm가 된다. 저장된 관계는 기준 관절과 운동 종류로 유지하며,
native 실행식만 관계를 전개하여 만든다. 각도는 native 경계에서 rad로 변환한다.
기준 단위를 바꾸어 기존 비율 단위와 맞지 않으면 오류를 표시한다.
비율이나 영점 이동을 새 단위의 값으로 다시 지정하며 자동 환산하지 않는다.

순환 관계·같은 관절/운동 종류의 중복 구동·누락되거나 억제된 기준 관절·
미완성 식·단위 불일치는 해당 행에서 표시하고 적용을 차단한다.
`1e`, 빈 기준 선택, 미완성 수식은 기존 미적용 편집으로 저장·재열기할 수 있다.
계산과 자세/경로 실행은 해당 초안을 적용하거나 취소할 때까지 막는다.
일반 다변수·비선형 종속 관계식은 M1의 남은 개발이며, 이번 인도는
한 기준 구동에 대한 비율·영점 이동 관계를 지원한다.

허용 하한·상한은 비워 두면 사용자 구동 한계가 없다. 한계를 선언하면 지정한
시작~끝 시간의 보수적 식 범위를 검사한다. native 관절의 각도·길이 한계가 있으면
두 한계를 모두 충족해야 한다. 한계는 자동 제한하거나 출력 격자의 몇 점만
검사하여 준수한 것으로 표시하지 않는다. FreeCAD 1.1.4는 운동 계산 중 native
관절 한계를 넣지 않으므로 이 검사는 실행 전에 수행한다.
이 경계는 [FreeCAD 1.1.4의 운동·관절 한계 처리](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/App/AssemblyObject.cpp#L1275)에 따른다.
한계가 있는 미구동 좌표는 이번 범위에서 전체 운동을 확인할 수 없어 계산을 막는다.
해당 좌표의 구동을 추가하거나 FreeCAD 관절 속성에서 한계를 편집한다.

구간검사는 덧셈·뺄셈·곱셈·나눗셈과 일부 단조 함수, sin/cos의 보수적 범위를
지원하며 반올림을 바깥쪽으로 처리한다. 범위가 넓게 추정되거나 분모가 0을
포함할 수 있는 식, 거듭제곱·tan 등 범위를 확인할 수 없는 식은 한계 준수를
확인하지 못했다고 알린다. 허용치를 늘려 통과시키지 않는다. 이는 일반 식의
형식적 증명기나 FEM 물리 검증이 아니다. 한계가 없는 기존 자유 시간식은
native 문법·기존 저장 정의를 유지하며, 읽기만으로 관계나 한계를 추가하지 않는다.

기존 공개 작은 native 모델에서 위 180 mm → 90 mm의 명시 수정·운동·경로,
설계 자세 복원과 `.caepre` 새 owner 재열기를 확인했다. 관계·선택·보존 경로와
`1e` 초안은 재열리며 자동 계산하지 않는다. 실제 FreeCAD Qt 화면을 확인했고,
읽기/편집 확인은 추가 운동 계산 없이 수행했다. 실행 근거는
`runs/motion-dependent-native/receipt.json`과 `ui-receipt.json`이다.
전체 Windows 마우스 작업의 사용자 수용과 M2–M4는 이번 범위에 포함하지 않는다.
위 수치는 지정 시간 구간의 native 끝 자세와 구동 관계의 확인이다. 기존 native
프레임에는 설계 자세와 초기 자세가 함께 들어갈 수 있어 출력격자 시간은
실제 시각과 일치한다고 확인되지 않았다. 이 예제에서 프레임 표의 출력격자
1.0초 행이 180 mm라고 해석하지 않는다. 프레임–실제 시각 대응은 별도 잔여다.

**구동 적용** 후 계산한다. 미적용 편집은 **구동 편집 취소**로 마지막 적용
정의와 선택으로 돌아갈 수 있다. 적용 응답이 늦게 도착하더라도 그 뒤에 입력한
초안은 지우지 않는다. 미적용 편집이 있는 상태에서는 계산/자세 확인을 먼저 막는다.

## 미완성 편집을 저장하고 이어 쓰기

프로젝트 저장은 관절 연결·종류·거리, 시간·구동식·경로점의 미적용 편집도 같은
`.caepre`에 보존한다. `1e`, 빈 참조, `Face99`처럼 아직 고치지 않은 입력도
그대로 다시 읽는다. 처음 운동 정의를 적용하기 전에도 저장할 수 있다.
미적용 편집은 적용된 native 관절·운동 정의와 분리되며 저장이 곧 적용이나 계산은 아니다.

프로젝트를 다시 열면 같은 편집을 이어 쓸 수 있다. 미적용 편집이 있으면 운동 계산,
프레임 보기·재생, 경로 읽기·자세 채택을 거절한다. 관절과 구동의 **적용** 또는
**편집 취소**를 각각 마치면 다시 실행할 수 있다. 취소는 저장된 편집 초안도 지우며
다른 종류의 초안과 다른 조립의 편집은 보존한다. 취소 실패 시 편집을 유지한다.

닫기와 모두 닫기는 미저장 편집에 대해 **저장 / 버리기 / 취소**를 묻는다.
다시 연결할 때도 같은 선택을 제공한다. 여러 문서 중 뒤에서 취소하면 앞에서 버리기를
골랐던 편집도 아직 남아 있다. 저장 실패, 저장 응답 이후의 새 편집, 재연결 응답을
기다리는 동안의 새 편집이 있으면 닫기나 재연결을 중단하고 현재 창을 유지한다.

연결이 끊겨도 열린 문서의 저장과 편집 취소는 할 수 있다. 다만 이전 작업의 완료
여부가 불명확하면 먼저 **다시 확인**을 누른다. 계산이나 형상 편집을 계속하려면
연결을 복구해야 한다.

## 미리보기, 자세 적용과 저장

**운동 미리보기**에서 **운동 계산** 후 실제 프레임 번호를 골라 **자세 보기**,
재생·역재생을 사용한다. 일시정지는 현재 자세를 유지하고 정지/미리보기 취소는
설계 자세를 복원한다. **현재 자세를 설계에 적용**만 현재 미리보기 자세를
설계 transaction으로 채택한다. 일반 저장·닫기·FEM 전환은 기존
restore-first 경로를 사용한다.

운동 계산은 동기 native 호출이며 시작한 뒤 중단할 수 없다. 재생은 프레임 사이에
중단한다. 표시된 시간은 지정한 출력 격자이며 FreeCAD는 실제 프레임 timestamp를
노출하지 않는다. 계산 실패 시 구동 관절 이름, 종속 구동의 곡선·연결·고정 확인과
native 상태를 표시하고 설계 자세를 복원한다. 닫힌 연결을 임의로 배제하거나
실패한 native 계산을 성공으로 바꾸지 않는다.

CAE 프로젝트 저장은 최근 적용 정의와 관절/구동 행/경로점 행 선택을 보존한다.
선택만 바꾸는 저장은 실행 정의 hash를 바꾸지 않고 같은 선택은 다시 수정하지 않는다.
새 owner에서는 설계 자세로 시작하며 운동 계산을 자동으로 실행하지 않는다.

## 점 경로를 표·곡선과 Data에서 보기

운동 계산 후 **점 경로** 탭에서 경로점을 고르고 **전체 경로 읽기**를 누른다.
이 동작은 이미 계산된 프레임의 좌표를 읽으며 운동 계산을 다시 시작하지 않는다.
**구간 읽기**는 시작 프레임과 개수를 지정한다. 읽은 구간은 같은 계산·경로점 안에서
이어 모으며, 화면의 **읽은 프레임 / 전체 프레임**과 미읽기·누락 개수로 범위를 확인한다.
읽기 중지는 현재 native 페이지가 끝난 뒤 다음 페이지를 읽지 않는다. 일부만 읽은 자료를
전체 경로로 표시하지 않으며 실패한 뒤에도 이전에 읽은 원자료는 남는다.

곡선의 점 또는 표의 행을 선택하면 같은 프레임을 함께 선택한다. **시간–X/Y/Z**와
**공간 경로 X–Y / X–Z / Y–Z**를 바꿔 볼 수 있다. 공간 곡선은 선택한 평면에 투영한
경로이며 축의 mm 눈금 비율을 유지한다. 누락 프레임 사이를 선으로 이어 그리지 않는다.
좌표는 부품에 지정한 로컬 경로점을 문서의 세계 좌표로 변환한 값이다.
`nominal_time`은 시작 시간 + 프레임 번호 × 출력 간격이다. FreeCAD의 실제 프레임 시각은
노출되지 않으며 이 열을 실제 시각 기록으로 해석하지 않는다.

**선택 프레임의 3D 자세 보기**를 눌러야 원 조립을 미리보기 자세로 바꾼다.
표·곡선 선택만으로는 3D 자세를 바꾸지 않는다. 이 버튼은 같은 계산의 프레임이 현재
문서에 남아 있고 미적용 관절·구동 편집이 없을 때 사용한다. 일반 저장·정지는 설계
자세로 복원한다. 재열기 후에는 경로를 계산 없이 읽으며, native 프레임 캐시는 없으므로
보존 경로만으로 3D 자세를 재현하거나 운동 계산을 자동 시작하지 않는다.

**CSV 저장…**은 읽은 프레임 전체와 원 프레임 번호·시간·세계 X/Y/Z를 저장한다.
CSV 첫 줄에는 계산·조립·원 로컬 점·읽은 범위 등 출처를 보존한다. 화면의 숫자는
읽기 편하게 표시하지만 CSV의 좌표는 원값이다. 읽지 않은 프레임 사이에는 값을
추정하지 않은 결측 표시 행을 추가하므로 CSV 행수는 실제 읽은 표본수와 다를 수 있다.
Data는 이 행을 계산에서 제외해 곡선과 보간이 누락 구간을 잇지 않도록 한다.
**Data에서 열기**는 같은 CSV와
시간/좌표/단위 열 설정을 독립 Data 문서에 저장해 연다. 파일을 다시 고를 필요 없이
Data의 **가져오기**로 표·곡선 분석을 이어간다. Data 저장본은 원 CSV를 자체 보존하므로
처음 등록한 파일이 없어도 재열기할 수 있다. Data 열기 또는 저장 실패 시 원 경로와
이미 생성한 Data 문서를 유지하며 같은 버튼으로 재시도한다.

CAE 프로젝트 저장은 읽은 원경로들과 선택한 프레임·곡선 종류를 보존한다. 모델이나
구동이 바뀌면 **모델·구동 변경 — 과거 원자료**로 표시하고 이전 데이터를 지우지 않는다.
원경로가 들어 있지 않은 과거 저장본의 경로를 소급 복구하지는 않는다. native 메타데이터의
기존 저장 용량 제한을 넘으면 저장 실패를 표시하며 현재 경로를 CSV로 내보낼 수 있다.

## 이번 확인과 남은 작업

2026-10-14, FreeCAD 1.1.4 실제 프로세스에서 회전+이동 두 구동의 native 계산,
미리보기와 취소 자세 복원, 가동 하위 조립의 관절 구동을 확인했다.
`.caepre`를 새 프로세스/owner에서 열어 적용 정의·선택과 설계 자세를 대조했다.
native Qt 패널은 같은 저장 자료를 1000×800과 720×520에서 렌더해 읽었다.
이 확인은 OS 마우스/키보드 조작 수용이나 일반 기구의 물리 검증이 아니다.
채택 자세의 별도 저장본도 새 owner에서 읽었다. 정의와 선택은 같았으며
재열기의 quaternion 성분 차이는 최대 약 1.84e-15, 이동 성분 차이는
약 5.55e-17 mm였다. 부동소수점 값의 bit-exact 동일이라고 기록하지 않는다.
실제 화면 선택을 연결로 가져오기, 누락된 면 참조의 취소 보존과 같은 관절에
새 면을 지정하여 복구하는 경로도 확인했다.

후속 인도에서는 신규 운동 정의를 적용하지 않은 native 문서에 미완성 입력을 저장하고,
새 FreeCAD 프로세스에서 모든 입력이 같은 것을 확인했다. 수정하여 관절과 구동을
적용한 뒤 native 운동 계산이 가능했다. 연결 없는 저장·취소, 닫기/재연결 취소,
저장 실패와 늦은 새 편집은 별도 Qt/단위 검사로 확인했다. OS 입력 수용은 아니다.

후속 실행의 교정본 추가 저장은 기존 Windows 임시파일 이름이 긴 내부 경로를 만드는
문제로 한 번 실패했다. 원본과 실패 사본을 보존했고, root의 `20246f3` 경로 수정 후
같은 보존 사본을 저장했다. 임의의 모든 긴 경로 지원으로 확대하지 않는다.
기록은 `runs/product-development/20261014/assembly-editor-drafts/`에 있다.

점 경로 인도에서는 기존 회전·이동 예제 한 개를 명시적으로 계산한 뒤 경로를 두 구간으로
읽어 합쳤다. 선택 프레임의 자세 확인과 `.caepre` 저장 후 새 owner에서 같은 좌표·선택을
읽었으며 재열기에서 native 계산은 시작하지 않았다. 원자료는 `runs/motion-path-native/`에
있다. 해당 경로를 기존 Data CSV 읽기·가져오기·저장·새 owner 재열기로 확인했다.
Qt 화면의 표·곡선 연동은 직접 렌더했다. OS 입력 수용이나 일반 기구 물리 검증으로
확대하지 않는다.

하위 조립의 강체/가동 구성과 원본 관절 편집은 native Assembly 기능을 사용한다.
이번 실제 사례는 가동 하위 조립의 한 관절이며, 여러 깊이의 조립·일반 닫힌 기구와
다양한 종속 곡선의 실제 반복 조작/수치 확인은 남아 있다. FE 후보의 flat/단일 관절
제한이 이 운동 편집 개선으로 해제된 것은 아니다.

구현 근거는 공식 [AssemblyObject.cpp](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/App/AssemblyObject.cpp),
[AssemblyLink.cpp](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/App/AssemblyLink.cpp),
[CommandCreateSimulation.py](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/CommandCreateSimulation.py),
[UtilsAssembly.py](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/UtilsAssembly.py)를 따른다.
실행별 자료는 `runs/product-development/20261014/assembly-motion/`에 둔다.
