# 조립 운동 편집과 미리보기

FreeCAD 1.1.4의 Assembly와 설치된 운동학 계산을 사용한다. 운동 미리보기에는
FEM 솔버, AI 또는 별도 운동 솔버가 필요하지 않다. FE 후보를 만드는 별도 흐름은
[ASSEMBLY_CANDIDATES](ASSEMBLY_CANDIDATES.md)를 따른다.

## 부품과 관절

CAE의 조립 운동 패널에서 문서의 조립을 선택한다. **조립 만들기 / 부품 배치**를
펼치면 같은 문서의 부품이나 조립을 배치할 수 있다. 하위 조립은 native
`Assembly::AssemblyLink`로 만든다. **하위 조립을 강체로 배치**를 해제하면
그 안의 관절도 전체 운동 계산에 참여한다. 가동 하위 조립은 내부 부품을 고정한다.

**부품과 관절**에서 관절, 연결 A/B의 부품과 면·모서리·점을 선택한다.
3D 화면 또는 트리에서 선택한 요소는 **화면 선택을 연결 A/B로**로 가져온다.
연결 요소의 빈칸은 부품 원점이다. 면·모서리를 고르면 native 중심,
점을 고르면 그 점을 사용한다. 기존 native 연결의 별도 위치/분리 좌표는
같은 참조를 유지할 때 보존한다. 거리의 단위는 mm, 관절 각도 속성은 deg다.

**관절 적용**은 같은 native 관절을 수정하고 **관절 편집 취소**는 저장된
관절의 참조와 값을 다시 읽는다. 사라진 부품·요소는 본 화면에서 재선택을
요청한다. 다른 부품으로 자동 대체하지 않는다. 가동 하위 조립의 관절 복사본은
원본 조립을 선택해 편집한다. 복사본은 FreeCAD가 원본과 다시 동기화하므로
그 복사본을 직접 수정/삭제하는 명령은 막는다.

### 중첩 조립의 배치 하나만 선택하기

두 단계 이상의 가동 하위 조립도 **최상위 조립**을 선택하여 구동한다.
관절·연결 A/B·경로점의 부품 목록에는 조립 계층을 함께 표시한다.
같은 원부품을 참조하는 서로 다른 Link는 각각 선택할 수 있다.
같은 이름의 형제 배치는 `배치 1`, `배치 2`로 구별하며, 저장에는 실제 native
occurrence·관절 참조를 유지한다. 좁은 구동 관절 셀의 전체 경로는 마우스를 올려 확인하며,
선택한 경로점 행의 전체 대상은 표 아래에도 표시한다.

**시간과 구동**에서 해당 계층의 관절 복사본을 고르고 구동을 적용한다.
**경로점**에는 같은 계층의 실제 배치와 그 배치의 로컬 좌표(mm)를 지정한다.
계산 후 **점 경로**에서 해당 점을 읽는다. 세계 좌표는 최상위부터 실제 배치까지의
이동·회전 곱으로 구하며, 여러 부모에 걸친 native 객체의 로컬 좌표를 세계 좌표로
추정하지 않는다. 같은 source를 참조한다는 이유로 다른 Link나 원부품을 움직이지 않는다.
조립이 이동·회전한 일반 부품 그룹(App::Part) 안에 있으면 그 상위 배치까지 포함한다.
상위 경로가 여러 위치이거나 해석되지 않으면 위치를 복구하도록 안내한다. 상위 배치를
이동한 뒤에는 기존 경로를 과거 자료로 표시하며 원좌표를 바꾸지 않는다.

**하위 조립을 강체로 배치**하면 전체 배치가 하나의 native body다.
그 내부 부품은 개별 연결·고정 대상으로 고르지 않는다. 강체 내부의 경로점은
선택할 수 있고 해당 강체의 자세를 따라 세계 좌표로 읽는다. 가동 배치는 내부의
관절과 부품을 개별 선택하며 내부 부품을 고정한다. 원본 조립의 관절을 수정하면
FreeCAD의 관절 복사본도 동기화되므로, 배치 한 곳의 운동은 원 관절을 몰래 수정하는
대신 최상위의 구동 정의에서 그 배치의 관절 복사본을 선택한다.

사라진 배치·모호한 다중 소속은 해당 연결/경로점에서 **참조 없음** 또는 행 오류로
표시한다. 같은 원부품의 다른 Link로 자동 대체하지 않는다. 실제 CAD 트리에서
그 위치의 배치를 다시 만들거나 선택한 뒤 관절/구동을 명시 적용한다.
재지정을 취소하면 이전 참조와 경로점 입력으로 돌아간다. 잘못된 초안도 저장할 수
있으며 적용 전에는 실행을 막는다. 일반 저장과 새 owner 재열기는 정확한 참조·행 선택과
보존 경로를 유지하고 운동을 자동으로 다시 계산하지 않는다.

FreeCAD 1.1.4의 깊은 관절 수집 경계를 보완하기 위해 계산/자세 갱신 중에는 실제
관절 복사본을 native root 관절 그룹에 잠시 이동한다. 새 관절·solver를 만들지 않는다.
동기 호출 종료·실패 후 기존 모든 그룹의 멤버와 순서를 대조하여 복원한다.
가동 부모의 비항등 자세는 native 독립 body의 최상위 로컬 좌표로 변환하고,
호출 뒤 원 부모 좌표로 되돌린다. 강체 내부 leaf를 다시 변환하지 않는다.
이 과정에는 저장·recompute·이벤트 양보가 없고, 복원이 실패하면 저장과 전환을 막는다.
근거는 [native 관절 수집](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/App/AssemblyObject.cpp#L600)과
[Group 소유권 이동](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/App/GroupExtension.cpp#L94)이다.

작은 공개 두 단계 모델에서 한 가동 배치의 이동과 경로, 다른 반복 배치/강체 배치 및
원 정의 보존을 확인했다. 최상위와 두 가동 부모에 각각 이동·3축 회전을 지정한 경우
고정한 로컬점의 기대 세계 좌표와 native 경로를 대조했다. 실제 계층 삭제 후 재지정
취소·적용·`.caepre` 새 owner 재열기도 확인했다.
실행 자료는 `runs/motion-nested-native/transform-receipt.json`과 두 크기의 실제
FreeCAD Qt 화면이다. 초기 실패와 그룹 복원 실패도 같은 폴더에 보존했다.
당시 보존 경로의 기존 출력격자 시간은 그대로 유지한다. M1 일반 관계식 잔여,
M3 닫힌 기구·M4 FE 후보 및 전체 OS 마우스 작업 수용은 별도 범위다.

## 시간과 복수 구동

**시간과 구동**에서 시작·끝·출력 간격을 초로 입력하고 구동을 추가한다.
회전 관절은 회전(rad/deg), 직선 이동 관절은 이동(mm), 원통 관절은 두 종류를
사용할 수 있다. 관절을 바꾸면 단일 운동 종류와 단위가 함께 바뀐다.
한 관절의 같은 종류 구동을 중복 지정하거나 누락된 관절을 선택한 행은
적용 전에 행별로 알린다. 삭제된 관절 대신 새 관절을 선택하고 적용하여 복구한다.

시간곡선은 native 식을 그대로 사용한다. `time`의 단위는 초다. 예를 들어
`0.2*time`은 초당 0.2 rad의 회전, `2*time`은 초당 2 mm의 이동이다.
1..32개 구동, 최대 2,001개 프레임과 8개 경로점의 기존 제한을 유지한다.
경로점은 선택 부품의 로컬 좌표(mm)이며 읽은 경로는 문서 전체 좌표(mm)다.

### 한 구동을 따라 움직이는 관절

구동 행을 선택하면 **선택한 구동의 관계와 허용 한계**에서 이름·출력 단위와
구동 방식을 편집한다. 회전의 출력은 rad 또는 deg, 이동은 mm다.
**다른 구동 따라가기**는 명시적으로 구동된 기준 관절의 회전 또는 이동을
선택하여 `종속 값 = 기준 값 × 비율 + 영점 이동`으로 연결한다.
기준값은 그 구동의 선언 단위 값이며 미구동 관절의 자세를 추정한 값이 아니다.
원통 관절의 회전과 이동은 서로 다른 구동으로 선택한다.

예를 들어 기준 회전을 `90*time` deg, 종속 이동의 비율을 `2` mm/deg,
영점 이동을 `0` mm로 설정하고 끝 시간을 1초로 지정하면 native 끝 자세는 180 mm 이동이다.
기준 시간식을 `45*time`으로 수정하고 **구동 적용 → 운동 계산**을 하면
native 끝 자세의 종속 이동도 90 mm가 된다. 저장된 관계는 기준 관절과 운동 종류로 유지하며,
native 실행식만 관계를 전개하여 만든다. 각도는 native 경계에서 rad로 변환한다.
기준 단위를 바꾸어 기존 비율 단위와 맞지 않으면 오류를 표시한다.
비율이나 영점 이동을 새 단위의 값으로 다시 지정하며 자동 환산하지 않는다.

순환 관계·같은 관절/운동 종류의 중복 구동·누락되거나 억제된 기준 관절·
미완성 식·단위 불일치는 해당 행에서 표시하고 적용을 차단한다.
`1e`, 빈 기준 선택, 미완성 수식은 기존 미적용 편집으로 저장·재열기할 수 있다.
계산과 자세/경로 실행은 해당 초안을 적용하거나 취소할 때까지 막는다.
일반 다변수·비선형 종속 관계식은 M1의 남은 개발이며, 이번 인도는
한 기준 구동에 대한 비율·영점 이동 관계를 지원한다.

허용 하한·상한은 비워 두면 사용자 구동 한계가 없다. 한계를 선언하면 지정한
시작~끝 시간의 보수적 식 범위를 검사한다. native 관절의 각도·길이 한계가 있으면
두 한계를 모두 충족해야 한다. 한계는 자동 제한하거나 출력 격자의 몇 점만
검사하여 준수한 것으로 표시하지 않는다. FreeCAD 1.1.4는 운동 계산 중 native
관절 한계를 넣지 않으므로 이 검사는 실행 전에 수행한다.
이 경계는 [FreeCAD 1.1.4의 운동·관절 한계 처리](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/App/AssemblyObject.cpp#L1275)에 따른다.
한계가 있는 미구동 좌표는 이번 범위에서 전체 운동을 확인할 수 없어 계산을 막는다.
해당 좌표의 구동을 추가하거나 FreeCAD 관절 속성에서 한계를 편집한다.

구간검사는 덧셈·뺄셈·곱셈·나눗셈과 일부 단조 함수, sin/cos의 보수적 범위를
지원하며 반올림을 바깥쪽으로 처리한다. 범위가 넓게 추정되거나 분모가 0을
포함할 수 있는 식, 거듭제곱·tan 등 범위를 확인할 수 없는 식은 한계 준수를
확인하지 못했다고 알린다. 허용치를 늘려 통과시키지 않는다. 이는 일반 식의
형식적 증명기나 FEM 물리 검증이 아니다. 한계가 없는 기존 자유 시간식은
native 문법·기존 저장 정의를 유지하며, 읽기만으로 관계나 한계를 추가하지 않는다.

기존 공개 작은 native 모델에서 위 180 mm → 90 mm의 명시 수정·운동·경로,
설계 자세 복원과 `.caepre` 새 owner 재열기를 확인했다. 관계·선택·보존 경로와
`1e` 초안은 재열리며 자동 계산하지 않는다. 실제 FreeCAD Qt 화면을 확인했고,
읽기/편집 확인은 추가 운동 계산 없이 수행했다. 실행 근거는
`runs/motion-dependent-native/receipt.json`과 `ui-receipt.json`이다.
전체 Windows 마우스 작업의 사용자 수용과 M2–M4는 이번 범위에 포함하지 않는다.
위 수치는 지정 시간 구간의 native 끝 자세와 구동 관계의 확인이다. 기존 native
프레임에는 설계 자세와 초기 자세가 함께 들어갈 수 있어 출력격자 시간은
실제 시각과 일치한다고 확인되지 않았다. 이 예제에서 프레임 표의 출력격자
1.0초 행이 180 mm라고 해석하지 않는다. 이 과거 자료의 시간 열을 소급해서 바꾸지 않는다.
새 계산의 시각 대응은 아래 **경로의 계산 시각**을 따른다.

**구동 적용** 후 계산한다. 미적용 편집은 **구동 편집 취소**로 마지막 적용
정의와 선택으로 돌아갈 수 있다. 적용 응답이 늦게 도착하더라도 그 뒤에 입력한
초안은 지우지 않는다. 미적용 편집이 있는 상태에서는 계산/자세 확인을 먼저 막는다.

## 미완성 편집을 저장하고 이어 쓰기

프로젝트 저장은 관절 연결·종류·거리, 시간·구동식·경로점의 미적용 편집도 같은
`.caepre`에 보존한다. `1e`, 빈 참조, `Face99`처럼 아직 고치지 않은 입력도
그대로 다시 읽는다. 처음 운동 정의를 적용하기 전에도 저장할 수 있다.
미적용 편집은 적용된 native 관절·운동 정의와 분리되며 저장이 곧 적용이나 계산은 아니다.

프로젝트를 다시 열면 같은 편집을 이어 쓸 수 있다. 미적용 편집이 있으면 운동 계산,
프레임 보기·재생, 경로 읽기·자세 채택을 거절한다. 관절과 구동의 **적용** 또는
**편집 취소**를 각각 마치면 다시 실행할 수 있다. 취소는 저장된 편집 초안도 지우며
다른 종류의 초안과 다른 조립의 편집은 보존한다. 취소 실패 시 편집을 유지한다.

닫기와 모두 닫기는 미저장 편집에 대해 **저장 / 버리기 / 취소**를 묻는다.
다시 연결할 때도 같은 선택을 제공한다. 여러 문서 중 뒤에서 취소하면 앞에서 버리기를
골랐던 편집도 아직 남아 있다. 저장 실패, 저장 응답 이후의 새 편집, 재연결 응답을
기다리는 동안의 새 편집이 있으면 닫기나 재연결을 중단하고 현재 창을 유지한다.

연결이 끊겨도 열린 문서의 저장과 편집 취소는 할 수 있다. 다만 이전 작업의 완료
여부가 불명확하면 먼저 **다시 확인**을 누른다. 계산이나 형상 편집을 계속하려면
연결을 복구해야 한다.

## 운동 결과, 자세 적용과 저장

**운동 결과 → 다시 계산**은 현재 적용한 정의로 native 운동을 계산한다.
native 출력의 모든 프레임 배치와 설정 경로를 수집한 뒤, 닫힌 기구는 관절·구동 충족을 검사한다.
반환값 0만으로 성공을 게시하지 않는다. 충족한 결과만 최근 성공으로 보존한다.
**최근 성공 / 이전 성공**과 시각 표에서 프레임을 고르고 **자세 보기**를 누른다.
표·곡선 선택만으로 모델을 움직이지 않는다. 재생·역재생·일시정지는 미리보기다.
**설계 자세 복원**, 일반 저장·닫기·FEM 전환은 기존 restore-first 경로를 사용한다.

새 owner에서도 저장한 성공의 자세·경로를 계산 없이 읽을 수 있다. 3D 표시는
native `updateForFrame`으로 읽어 둔 실제 occurrence 배치를 적용하며 보간하거나
solver를 호출하지 않는다. 정확한 계층·부품·형상을 먼저 확인하고 다른 Link나
원부품으로 대체하지 않는다. 바깥 부모 이동·회전은 보존된 세계 루트 배치를 현재
부모 좌표로 바꿔 표시하며 부모·형제는 움직이지 않는다. 복원은 옛 결과의 설계가
아니라 **지금 편집 중인 설계 자세**로 돌아간다. 사람의 새 편집은 복원으로 덮지 않는다.
형상이나 실제 참조가 바뀌어 3D 표시를 거절해도 원래 표·시각·경로는 남는다.

**현재 자세를 설계에 적용**은 지금 계산한 유효한 미리보기만 명시 채택한다.
저장 후 재열기한 보존 결과의 자세는 읽기 전용이다. 이를 현재 설계로 채택하려면
현재 관절·구동을 확인하고 다시 계산한다. 기존 저장본에 자세 배열이 없다면 읽었던
경로만 보존하며 잃어버린 프레임을 만들지 않는다.

native 계산은 시작 후 중단할 수 없다. 모든 프레임 수집도 같은 동기 작업에 포함된다.
계산 반환값이 실패이거나 관절·구동의 불일치/충족 미확인, 전체 배치·경로 수집/보존 실패이면
새 성공을 게시하지 않는다. 반환값 0인 불일치 출력도 원좌표 그대로 별도 실패 시도에 보존한다.
직전 성공 전체와 이번 실패 시도를 따로 남긴다. 부분 실패 출력과 이전 성공을 연결한
정상 곡선을 만들지 않는다. 허용치를 늘리거나 닫힌 관절을 제거하여 통과시키지 않는다.

**계산 이력**에는 입력 시간 범위와 성공/실패/종료 미확인을 표시한다. 동일 관절 중복은
해당 입력 행으로 특정한다. FreeCAD가 제공하지 않는 원인 관절과 실패 시각은
**미확인**이며 모든 구동 관절을 원인으로 나열하지 않는다. 결과 수집·저장 실패는
native 계산 실패와 구분한다. 시도에는 당시 구동·관절·연결·설계 배치와 native 상태를
보존한다. 종료 전에 프로세스가 끊긴 시도는 성공이나 native 실패로 추정하지 않는다.

**저장**은 기존 CAE 프로젝트 저장을 호출한다. 적용 정의, 미완성 편집, 관절/구동/경로
행, 결과 프레임과 곡선 투영 선택이 같은 native 문서에 보존된다. 새 owner는 설계
자세에서 시작하며 자동 계산하지 않는다. 미완성 편집의 적용·취소 요구는 유지하고,
보존 표·경로 읽기는 허용한다. 이 예외는 현재 조립에 실제 보존된 결과와 그 결과의 경로점에만
적용한다. 저장하지 못한 새 경로/누락된 경로점은 편집 검사를 우회하지 않는다.
자세 보기·재생·채택·계산은 결과 선택 상태를 바꾸기 전에 미적용 편집을 차단한다.
문서 저장 전 성공 기록은 **미저장**이다.

### 경로의 계산 시각

새 FreeCAD 1.1.4 계산은 첫 프레임을 **설계 자세 (시각 없음)**로 표시한다.
그다음 프레임은 native가 반환한 초기조건 자세다. 구동식 충족 여부는 별도 검사하며 이후 프레임은
운동 계산의 출력 시각이다. 예를 들어 0–1초, 출력 간격 0.5초이면 설계 자세와
0 / 0.5 / 1초 자세를 구별한다. 설계 자세는 시간 곡선에서 제외하며 표와 공간 경로에서는 읽을 수 있다.

시작이 0이 아니어도 같은 원칙이다. 끝이 출력 간격의 정수배일 필요는 없다.
FreeCAD의 운동 계산은 출력 시각을 반복 덧셈으로 진행하고 끝의 0.1 출력 간격까지
허용하므로 마지막 출력은 설정한 끝보다 이르거나 조금 늦을 수 있다. 표시한 시각을
끝 값으로 반올림하거나 좌표를 보간하지 않는다. 허용 한계 검사는 설정 구간과
실제 출력 구간을 모두 포함한다.

Python API에는 실제 solver 시각 배열 getter가 없다. 따라서 확인한
[FreeCAD 1.1.4 시간 전달](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/App/AssemblyObject.cpp#L1010)과
[Ondsel 출력 순서](https://github.com/FreeCAD/OndselSolver/blob/4be80eef02a3486cda0d78f3ccbb308d207a9639/OndselSolver/System.cpp#L73),
[출력 경계](https://github.com/FreeCAD/OndselSolver/blob/4be80eef02a3486cda0d78f3ccbb308d207a9639/OndselSolver/QuasiIntegrator.cpp#L178)의
규칙으로 시각을 대응하고 native 프레임 수와 전체 대조한다. 노출된 solver 시각 배열을
읽었다고 주장하지 않으며 버전·규칙 출처를 저장한다. 다른 버전 또는 프레임 수 불일치는
**시각 미확인**으로 표시한다. 좌표·프레임은 공간 곡선과 표·CSV에 남기며 시간 분석에
가짜 값을 넣지 않는다. 이전에 저장한 출력격자 시간은 **출력격자 시간**으로 그대로 읽는다.
FreeCAD 속성창에서 시작·끝·출력 간격을 직접 바꾸면 적용한 운동 정의와 먼저 대조한다.
다르면 계산 전에 **시간과 구동에서 다시 적용**하도록 안내한다. 변경된 속성을 몰래
덮어쓰지 않으며 이전 경로는 원좌표·시각을 유지한 과거 자료로 표시한다.

기존 공개 2 mm/s 모델에서 0 / 0.5 / 1초의 0 / 1 / 2 mm 이동을 native 좌표와
대조했다. 0.5–1.5초·간격 0.4초에서는 0.5 / 0.9 / 1.3초를 읽었으며 임의의
1.5초 표본을 만들지 않았다. 원설계·다른 배치 복원, `.caepre` 새 owner 재열기의
같은 시각·좌표와 무재계산, 원 CSV의 Data 가져오기·저장·재열기를 확인했다.
실행 기록은 `runs/motion-frame-time/native-retry/native-receipt.json`과 `data-receipt.json`이다.
기존 종속 구동 모델도 90°/s 입력과 2 mm/° 관계로 한 번 계산하여 0 / 0.5 / 1초에서
회전 0 / 45 / 90°와 이동 0 / 90 / 180 mm를 같은 경로 시각과 대조했다.
설계 복원과 무재계산 재열기 기록은 `runs/motion-frame-time/dependent-time/receipt.json`이다.
시간 규칙·불일치·과거 기록과 Qt 연결은 관련 단위 검사로 확인했다. 전체 물리 검증이나
일반 비선형 관계식 지원을 이 시각 대응 인도에 포함하지 않는다.

## 점 경로를 표·곡선과 Data에서 보기

운동 계산 후 **점 경로** 탭에서 경로점을 고르고 **전체 경로 읽기**를 누른다.
새 계산은 계산 직후 모든 설정 경로를 수집하므로 이 탭을 열기 전의 성공도 보존된다.
읽기는 보존된 경로를 사용하며 운동 계산이나 native 프레임 갱신을 다시 시작하지 않는다.
**구간 읽기**는 시작 프레임과 개수를 지정한다. 표시 구간을 읽어도 저장된 전체 경로는
잘리지 않는다. 경로 읽기는 재생 타이머부터 멈추고 미리보기 자세를 복원한다.
재생 시작 직후 첫 tick 전이라도, 이미 대기 중인 tick이 뒤늦게 도착하더라도 자동 이동하지 않는다.
읽기 중지는 다음 페이지를 읽지 않는다. 과거 저장본의 일부 경로는
읽은 범위와 누락 수를 그대로 표시하며 소급하여 전체 자료로 만들지 않는다.

곡선의 점 또는 표의 행을 선택하면 같은 프레임을 함께 선택한다. **시간–X/Y/Z**와
**공간 경로 X–Y / X–Z / Y–Z**를 바꿔 볼 수 있다. 공간 곡선은 선택한 평면에 투영한
경로이며 축의 mm 눈금 비율을 유지한다. 누락·불일치·충족 미확인 프레임을 정상 선으로
이어 그리지 않는다. 표의 **검사** 열에서 충족/불일치/미확인을 구별한다. 불일치 점도
좌표를 삭제하거나 보간하지 않고 원자료로 읽는다.
좌표는 부품에 지정한 로컬 경로점을 문서의 세계 좌표로 변환한 값이다.
새 경로의 표·시간 곡선·CSV·Data는 같은 계산 시각 배열을 사용한다.
기존 `nominal_time`은 시작 시간 + 프레임 번호 × 출력 간격인 과거 기록이며
실제 시각으로 소급 확정하지 않는다.

**선택 프레임의 3D 자세 보기**를 눌러야 원 조립을 미리보기 자세로 바꾼다.
표·곡선 선택만으로는 3D 자세를 바꾸지 않는다. 전체 자세가 보존된 성공은 새 문서에서도
계산 없이 표시한다. 미적용 관절·구동 편집이 있으면 적용하거나 취소한 뒤 자세를 본다.
일반 저장·정지는 현재 설계 자세로 복원한다. 옛 경로에 3D 배치가 없는 경우에는
자세 보기만 비활성화하고 표·곡선은 계속 읽는다.

**CSV 저장…**은 읽은 프레임 전체와 원 프레임 번호·시간·세계 X/Y/Z를 저장한다.
CSV 첫 줄에는 계산·조립·원 로컬 점·읽은 범위 등 출처를 보존한다. 화면의 숫자는
읽기 편하게 표시하지만 CSV의 좌표는 원값이다. 읽지 않은 프레임 사이에는 값을
추정하지 않은 결측 표시 행을 추가하므로 CSV 행수는 실제 읽은 표본수와 다를 수 있다.
Data는 이 행을 계산에서 제외해 곡선과 보간이 누락 구간을 잇지 않도록 한다.
설계 자세와 시각 미확인 행은 CSV에 원 프레임·좌표와 결측 시간으로 저장한다.
Data 시간 분석에서는 같은 물리 행을 모든 채널에서 명시 제외하고 이유를 보존한다.
관절·구동 불일치/미확인 행도 동일한 제외·품질 표시에 포함한다. CSV 숫자는 원값이며,
계산 결과의 유효성 표시를 없앤 정상 데이터로 자동 전달하지 않는다.
**Data에서 열기**는 같은 CSV와
시간/좌표/단위 열 설정을 독립 Data 문서에 저장해 연다. 파일을 다시 고를 필요 없이
Data의 **가져오기**로 표·곡선 분석을 이어간다. Data 저장본은 원 CSV를 자체 보존하므로
처음 등록한 파일이 없어도 재열기할 수 있다. Data 열기 또는 저장 실패 시 원 경로와
이미 생성한 Data 문서를 유지하며 같은 버튼으로 재시도한다.

CAE 프로젝트 저장은 전체 native 자세·설정 경로들과 선택한 결과·프레임·곡선 종류를 보존한다. 모델이나
구동이 바뀌면 **모델·구동 변경 — 과거 원자료**로 표시하고 이전 데이터를 지우지 않는다.
원경로가 들어 있지 않은 과거 저장본의 경로를 소급 복구하지는 않는다. native 메타데이터의
기존 저장 용량 제한을 넘으면 저장 실패를 표시하며 현재 경로를 CSV로 내보낼 수 있다.

## 기존 M1/M2 확인 기록과 남은 native 확인

아래는 첨부 기준 소스에 있던 선행 실행 기록이다. 이번 M3 작성 환경에서
재실행한 기록이 아니며 M3 4R의 native 수용 근거로 확대하지 않는다.

2026-10-14, FreeCAD 1.1.4 실제 프로세스에서 회전+이동 두 구동의 native 계산,
미리보기와 취소 자세 복원, 가동 하위 조립의 관절 구동을 확인했다.
`.caepre`를 새 프로세스/owner에서 열어 적용 정의·선택과 설계 자세를 대조했다.
native Qt 패널은 같은 저장 자료를 1000×800과 720×520에서 렌더해 읽었다.
이 확인은 OS 마우스/키보드 조작 수용이나 일반 기구의 물리 검증이 아니다.
채택 자세의 별도 저장본도 새 owner에서 읽었다. 정의와 선택은 같았으며
재열기의 quaternion 성분 차이는 최대 약 1.84e-15, 이동 성분 차이는
약 5.55e-17 mm였다. 부동소수점 값의 bit-exact 동일이라고 기록하지 않는다.
실제 화면 선택을 연결로 가져오기, 누락된 면 참조의 취소 보존과 같은 관절에
새 면을 지정하여 복구하는 경로도 확인했다.

후속 인도에서는 신규 운동 정의를 적용하지 않은 native 문서에 미완성 입력을 저장하고,
새 FreeCAD 프로세스에서 모든 입력이 같은 것을 확인했다. 수정하여 관절과 구동을
적용한 뒤 native 운동 계산이 가능했다. 연결 없는 저장·취소, 닫기/재연결 취소,
저장 실패와 늦은 새 편집은 별도 Qt/단위 검사로 확인했다. OS 입력 수용은 아니다.

후속 실행의 교정본 추가 저장은 기존 Windows 임시파일 이름이 긴 내부 경로를 만드는
문제로 한 번 실패했다. 원본과 실패 사본을 보존했고, root의 `20246f3` 경로 수정 후
같은 보존 사본을 저장했다. 임의의 모든 긴 경로 지원으로 확대하지 않는다.
기록은 `runs/product-development/20261014/assembly-editor-drafts/`에 있다.

점 경로 인도에서는 기존 회전·이동 예제 한 개를 명시적으로 계산한 뒤 경로를 두 구간으로
읽어 합쳤다. 선택 프레임의 자세 확인과 `.caepre` 저장 후 새 owner에서 같은 좌표·선택을
읽었으며 재열기에서 native 계산은 시작하지 않았다. 원자료는 `runs/motion-path-native/`에
있다. 해당 경로를 기존 Data CSV 읽기·가져오기·저장·새 owner 재열기로 확인했다.
Qt 화면의 표·곡선 연동은 직접 렌더했다. OS 입력 수용이나 일반 기구 물리 검증으로
확대하지 않는다.

하위 조립의 강체/가동 구성과 원본 관절 편집은 native Assembly 기능을 사용한다.
초기 사례는 가동 하위 조립의 한 관절이었다. 후속 중첩 조립 인도에서 두 단계 가동
조립과 반복 부품의 개별 구동·참조 복구·저장/재열기를 확인했다. 일반 닫힌 기구와
다양한 종속 곡선의 실제 반복 조작/수치 확인은 남아 있다. FE 후보의 flat/단일 관절
제한이 이 운동 편집 개선으로 해제된 것은 아니다.

구현 근거는 공식 [AssemblyObject.cpp](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/App/AssemblyObject.cpp),
[AssemblyLink.cpp](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/App/AssemblyLink.cpp),
[CommandCreateSimulation.py](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/CommandCreateSimulation.py),
[UtilsAssembly.py](https://github.com/FreeCAD/FreeCAD/blob/1.1.4/src/Mod/Assembly/UtilsAssembly.py)를 따른다.
실행별 자료는 `runs/product-development/20261014/assembly-motion/`에 둔다.


## M3 공개 4R: 정상, 실패, 복구, 재열기

`examples/assembly_closed_loop/create_four_bar.FCMacro`는 FreeCAD 1.1.4에서
고정 링크 하나와 회전 관절 네 개의 닫힌 기구를 만든다. 한 독립 구동과 연결봉 중앙
경로점을 설정하며 계산은 사용자의 **다시 계산**으로 시작한다.
처음 여는 방법과 정상→중복/과구동→도달 불가능→수정→저장/새 문서 읽기는
[4R 예제 사용법](../examples/assembly_closed_loop/README.md)에 있다.

실패 직전에 경로 창을 읽지 않아도 이전 성공의 자세·시간·설정 경로가 남는다.
실패 후 저장한 문서를 새 owner에서 열고 **이전 성공 → 프레임 → 자세 보기**를
사용한다. 실패 입력은 그대로 고쳐 **구동 적용 → 다시 계산**한다. 새 성공이 생겨도
실패 시도와 앞선 성공을 삭제하지 않는다. 특이 자세 생성과 native 결과 확인은
같은 예제의 `native_check.py`에 있으며 typed 진단을 만들어 내지 않는다.

### 구현 선택과 호환 경계

기존 `motion_paths`가 유일한 전체 출력 저장소다. 성공 출력과 불일치 원출력을 서로 다른
기록으로 보존한다. `last_completed`는 검사된 성공의 호환 요약만 가리키며 큰 배치 배열을
중복 저장하지 않는다. `motion_attempts`는 성공
출력 저장소가 아니라 당시 입력과 실행 상태의 이력이다. 기존 공통 schema와 명령명은
바꾸지 않았고 `motion_editors`에 선택한 결과/프레임을 선택 필드로 추가했다.
`motion_history.py`는 크기 제한·무손실 직렬화·검사 함수뿐이며 새 controller나
콜백 프레임워크가 아니다. 신규 프레임은 기존 `_show_frame`과 M2 scope로 실제
`updateForFrame` 출력에서 수집하며 경로는 기존 세계 좌표 변환을 사용한다.

외부 결과 파일이나 새 DB를 도입하는 대신 현재 FCStd 메타데이터 저장을 선택했다.
별도 파일의 누락·복사·새 schema 연결을 피하고 기존 `.caepre` 저장을 그대로 쓴다.
기존 8 MiB 메타데이터 상한은 유지하며 초과 시 새 결과 게시를 거절한다. 이전 결과를
자동 삭제하지 않는다. 용량이 찬 경우 실패 이력 자체가 문서에 쓰이지 않을 수도 있어
메모리의 미저장 시도로 남기고 저장 실패를 알린다. 디스크/프로세스 장애의 무조건
영속 보존을 주장하지 않는다. 성공 처리 뒤에도 사용자의 저장 전에는 파일 미저장이다.

형상 참조는 native BREP 복사본의 저장/읽기 표현을 대조한다. 최초 읽기에서 정규화되는
표현만 복사본으로 확인하며 CAD healing, 형상 단순화, 좌표 양자화, 허용치 변경은 없다.
기존 `_scene` 판정과 이전 경로의 출처 상태를 바꾸지 않는다. 실제 소유 관계/형상이
바뀌면 과거 결과를 현재 모델의 성공이라고 표시하지 않는다.

GUI는 프로젝트 스킬의 WIN-COMMAND와 PV-VIEW를 적용해 다시 계산·설계 자세 복원·저장을
구분했고 결과 선택과 실제 3D 적용을 분리했다. 모델 옆에는 프레임 표와 계산 이력,
기존 경로 탭에는 표·곡선을 유지한다. 내부 식별자·압축 데이터·로그 전문을 기본 제목에
넣지 않는다. 기존 스크롤/키보드/도킹 경로를 재사용한다.

### 반환값과 실제 충족을 구분하기

첨부 Windows FreeCAD 1.1.4 실행에서 정상 4R은 22프레임의 native 직접 읽기와 보존
자세/경로 차이가 0이었다. FCStd 새 owner 재열기와 무재계산 읽기도 실행됐다.
반면 세 실패 입력은 반환값 0이었다. 첨부 원출력의 관절 원점 검사는 과구동에서
회전 B의 최대 9.74279837397 mm, 특이 입력에서 출력 회전 D의 최대 9.42788591015 mm
벌어짐을 확인했다. `pi` 입력은 사실상 정지했고 구동 상대각과 약 3.14159265359 rad
차이가 있었다. 이 수치는 이번 환경의 재계산이 아니라 첨부 원출력의 읽기 전용 대조다.

계산 이력에서 **실패**를 선택하면 실제 관측 관절, 표본 시각, 오차와 허용값을 읽는다.
관측 표본의 시각은 native가 보고한 실패 시각이나 특이 시각이 아니다. 내부 원인 진단은
`UNKNOWN`, 원인 관절 목록은 빈 목록으로 보존한다. 모든 구동 관절을 범인으로 나열하지
않는다. 반환값도 0을 그대로 남기며 native가 -1을 반환한 것처럼 바꾸지 않는다.

결과 목록의 **불일치 원자료 / 충족 미확인 원자료**에서 원출력의 표·곡선·저장 자세를
읽을 수 있다. 이는 읽기 전용 검사이지 성공 결과 채택이 아니다. 최근/이전 성공과 구분하며
원자료 자세를 설계에 적용하지 않는다. 이전 status-only 버전으로 저장한 문서도 계산 당시
관절·입력과 보존 자세로 다시 검사한다. 여는 동작은 원래 기록·입력·좌표·예전 상태 문자열을
덮어쓰지 않으며, 화면에는 재검사 결과와 직전 유효 성공을 사용한다. 다음 명시 저장에서는
직전 성공 포인터를 유효 성공으로 유지하되 옛 원출력과 시도는 삭제하지 않는다.

### 검사식과 범위

native에 실제 전달된 관절·구동 객체의 연결을 대조하고, native `getJoints` 갱신 이후의
Reference-local `Placement1/2`를 기록한다. M2 계층으로 표본 부품 배치와 JCS를 합성해
회전 관절의 원점 거리(mm), 축 불일치(rad), 실제 상대각과 구동식의 차이(rad)를 검사한다.
`Offset1/2`를 이중 적용하지 않는다. 상대각은 `atan2`로 측정한 방향 차이를 사용하므로
사인 잔차가 모두 0인 0과 π를 같은 구동값으로 통과시키지 않는다. 원기구를 풀거나
잘못된 자세를 수정하는 계산은 하지 않는다.

허용값은 적용 당시의 **fGlobalErrorTolerance**를 그대로 사용한다. 이 pin에서는
`seterrorTol`이 위치 계산 허용값을 설정하고 native 길이/각도 단위가 최종적으로 1이므로,
명시 출력 검사에 `epsilon × 1 mm`와 `epsilon × 1 rad`를 쓴다. 예제는 각각 `1e-6 mm`,
`1e-6 rad`다. 크기 비례 완화, 측정 오차에 맞춘 조정, 새 임의 epsilon은 없다.
이는 native 비선형 잔차 norm과 동일하다는 주장이 아니라, 원 허용값에 기반한 **표본 자세
수용 검사**다. 사용자 허용값을 바꿀 경우 기존과 같이 다시 적용한 새 계산으로만 반영한다.

현재 닫힌 연결 그래프의 회전/직선/원통/고정/구면 관절 및 고정 배치를 검사한다.
같은 두 부품의 복수 관절도 닫힌 구속으로 검사하며 시험을 통과시키려고 제외하지 않는다.
열린 M1/M2 연결은 기존 계산 계약을 유지하며 닫힌 기구 검사를 했다고 표시하지 않는다.
다른 닫힌 관절 종류, 보존되지 않은 하위 요소 JCS, 크기 변환, 반대 방향 축의 구동각,
당시 적용 JCS가 없는 옛 attached 연결, 시각/버전 대응 미확인은 성공이 아닌 **미확인**이다.
사칙연산·time·pi·sin/cos/arctan의 표본 목표값을 확인한다. native 의미를 확인하지 않은
거듭제곱 및 다른 함수는 Python 함수와 같다고 추측하지 않는다. 기존 입력 편집기 문법과
종속 구동 컴파일은 바꾸지 않는다.

검사 시각은 저장된 출력 표본이다. 구간 사이의 폐합, 회전 누적 횟수, Jacobian rank와
특이점 도달 여부를 증명하지 않는다. 설계 프레임 0은 구동 시각이 없으므로 수용 검사에서
분리하며 초기조건 프레임부터 판정한다. 특이성의 native 원인/시각 진단은 여전히 UNKNOWN이다.
