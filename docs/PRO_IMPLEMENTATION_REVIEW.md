4. 필요한 검증과 반복 낭비의 경계

보고한 bool·문자 강제 변환, 숨은 입력 불일치, 제출 뒤 기록 손실, stale 처리, GUI 정지와 polling 구분, 거절 명령의 부작용 수정은 필요했습니다. 잘못된 계산과 작업 손실을 막는 검증까지 줄이라는 결론은 아닙니다.

문제는 그 위험을 해결한 뒤에도 같은 작은 장면을 다시 확인하면서 새 사용자 연결을 늦춘 것입니다. 앞으로는 다음 기준을 적용하십시오.

바뀐 부분	필요한 최소 확인	멈출 지점
Pre 입력·메시 연결	실제 치수·면 조건·메시 설정을 바꾸고, 화면과 소비된 입력·메시가 일치하는지 확인합니다. 끊긴 참조가 실행을 막는지도 봅니다.	같은 연결의 정상·거절 동작이 확인되면 다음 기능으로 갑니다. 스케치·Pad·Gmsh 자체 기능을 다시 시연하지 않습니다.
native GUI 명령·저장	실제 GUI에서 사람 변경→MCP 읽기→MCP 변경→화면 갱신→같은 저장→재열기를 확인합니다.	해당 이벤트·저장 경로가 확인되면 종료합니다. headless 재실행을 반복해 live GUI 확인을 대신하지 않습니다.
새 Runner 연결	정확한 부모 입력, 실패·취소 상태 변환, 실제 실행 종료, 결과 참조를 확인합니다.	새 연결의 상태 위험이 해소되면 전체 solver benchmark로 넓히지 않습니다.
Data/Plan 연결	열·단위가 다른 지원 자료, 물리 의미가 맞지 않는 자료의 거절, 실제 fit/DOE·실패·채택을 이어서 확인합니다.	기존 탄성 숫자를 반복하는 대신 새 연결이 쓰인 연구 장면을 확인하고 넘어갑니다.
저장 형식·문서 수명 변경	바뀐 저장 대상과 참조가 새 프로세스에서 복원되는지 확인합니다.	저장 의미나 실행 환경이 바뀌지 않았다면 commit 후라는 이유만으로 같은 cold reopen을 재실행하지 않습니다. 기존 확인 범위는 정확히 남깁니다.
Windows 진입 변경	준비된 Windows 환경에서 직접 시작·파일 열기·종료가 되는지 실제로 확인합니다.	지원 경로를 확인하면 다음 작업으로 갑니다. 모든 backend 설치 조사로 확대하지 않습니다.

공통 중단 기준은 “이 변경이 만든 위험을 확인했고, 정한 사용자 장면이 이어진다”입니다. 테스트 개수나 문서 갱신 개수가 아닙니다. 실제 원인 없이 범위를 넓히지 말고, 기존 필수 통합 검사는 적절한 통합 시점에 유지하십시오.

5. 이번 판단의 확인 범위
직접 확인: 지정 SHA의 핵심 소스·관련 호출 경로·커밋 변경·Qt 이미지. 위 연결 누락과 재사용 판단은 여기에 근거합니다.
Codex의 실행 보고로 받은 사실: 실제 FELUPE 계산, GUI/MCP Undo, headless native 명령, 결과 등록·재열기, 이전 작업 소스의 새 owner 프로세스 재열기. 이번에 제가 재실행해서 확인한 사실은 아닙니다.
여전히 미확인: 실제 Windows 첫 설치·사람의 GUI 조작, live ParaView QVTK 명령 처리, 전체 Pre–Runner–Post 왕복, 조립/FEM 통합 저장·재열기. 과거 FAIL/PARTIAL과 공학적 미승인 상태는 그대로입니다.

“실제 편집기와 native 결과 연결을 구현하며 전진했다”는 말은 할 수 있습니다. “사용자가 원하는 전체 제품 흐름을 우선순위대로 완성하고 있다”는 평가는 아직 부족합니다. 그 차이를 줄일 다음 행동은 추가 승인 질문이나 동일 검증 반복이 아니라, 열린 FreeCAD의 입력을 실제 계산과 ParaView 판단에 연결하는 코드 작업을 주 작업으로 진행하는 것입니다. Data·Plan 연구 연결을 병행하면서, 기존 구현을 버리지 않고 그 사이의 끊긴 작업을 이어가십시오.
